#+TITLE: Design: Query Manager with Live Output Monitoring
#+DATE: 2026-03-21

* Goal

Enhance the Query Manager (=claude-org-menu → m=) to show live terminal
output from all running Claude Code sessions in a unified scrollable view,
enabling real-time monitoring of multiple agents without switching windows.

* Current State

- =*Claude Queries*= buffer: table of active queries (session key, elapsed, status)
- Per-session =*cmux: story*= verbose buffer: live terminal mirror
- Mode-line: =[C:◐×3]= activity indicator
- No unified view across all sessions

* Design: Three-Layer Monitoring Model

Based on patterns from Stern (K8s), prodigy (Emacs), tmux, and docker-compose.

#+begin_example
  Layer 1: Mode-line  [C:◐×3]                    ← always visible (existing)
  Layer 2: *Claude Queries* dashboard             ← overview (existing + enhanced)
  Layer 3: *cmux: story-name* verbose buffer      ← per-session detail (existing)
#+end_example

* Layer 2 Enhancement: Activity Badges

Add "new output" indicators to each row in =*Claude Queries*=:

#+begin_example
  Active Queries (3)
  ▶ ● claude-agent-dev        Running   2m 15s  [+23 lines]
    ● skills-network-dev       Running   45s     [+8 lines]
  ▶ ● mega-code-dev           ⚠ Permission      [+1 lines]
#+end_example

- =▶= — has new output since last viewed
- =[+N lines]= — line count of verbose buffer changes
- Press =RET= on a row → opens that session's verbose buffer
- Press =v= on a row → opens verbose buffer in a side window

Implementation: track =last-viewed-line-count= per session; compare with
current verbose buffer line count on each refresh.

* Layer 3 Enhancement: Verbose Buffer

Already implemented:
- ✅ Live terminal mirror via =capture-pane=
- ✅ Scroll preservation (don't move if user is reading)
- ✅ Transient command menu (=,=) with Ctrl+B, Escape, Enter, etc.
- ✅ Raw ASCII control characters for TUI compatibility

Add:

** =header-line-format=

Sticky header showing story name, status, and keybindings:

#+begin_src elisp :load no
(setq-local header-line-format
  (list "  "
        (propertize story-name 'face 'bold)
        "  "
        '(:eval (if busy "Running" "Done"))
        "  "
        (propertize "[,]menu [G]follow [q]quit" 'face 'shadow)))
#+end_src

* Unified All-Output View (Future)

For monitoring all sessions in one scrolling buffer, like =docker-compose logs=:

#+begin_example
  *Claude All Output*
  ── claude-agent-dev (2m 15s) ────────────────────
  ⏺ Reading file tests/test-structural.el
    Read 1 file
  ✳ Thinking...

  ── skills-network-dev (45s) ─────────────────────
  ⏺ Here are the results:
    1. Found 3 endpoints...

  ── mega-code-dev (⚠ permission) ─────────────────
  ⚠ Permission needed: Edit auth.py
#+end_example

- Color-coded headers per session (using SDD_COLOR)
- Aggregates from all per-session verbose buffers
- Same scroll preservation + follow-mode toggle (=G=)
- Same transient menu (=,=) — sends to session under cursor
- Same =header-line-format= showing aggregate status

Implementation: dispatcher in verbose tick that also inserts into
the unified buffer with source prefix.

* Patterns Applied

| Pattern | Source | How we use it |
|---------+--------+---------------|
| Color-coded prefixes | Stern, docker-compose | Session headers with SDD_COLOR |
| =monitor-activity= badge | tmux | =▶= indicator for unread output |
| =at-end= auto-scroll | comint-mode | Only scroll if user is at bottom |
| Dashboard → detail drill-down | prodigy | Query Manager → RET → verbose buffer |
| =header-line-format= | compilation-mode | Sticky status bar in verbose buffer |
| Follow-mode toggle | compilation-scroll-output | =G= to follow, scroll up to pause |
| Raw control characters | Terminal stdin convention | Ctrl keys sent as ASCII bytes |
