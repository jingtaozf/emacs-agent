#+TITLE: Design: iTerm2 Backend Mode-Line and Query Manager Integration
#+DATE: [2026-03-08]
#+STATUS: removed (iTerm2 backend deleted in commit 1038144)

* Reality check (2026-04-27)

The iTerm2 backend was removed in commit 1038144 ("refactor: remove iTerm2 and
native (eat/vterm) backends").  cmux (and now tmux) replaced it as the
multiplexer-family backend.  The mode-line + Query Manager integration
described below shipped, then was deleted along with the iTerm2 backend.

The patterns here (active-queries registry, mode-line spinner, click-to-list
buffer) survive in `claude-agent--active-queries` and `*Claude Queries*` —
those still drive the cmux + tmux backends today.  The doc is preserved for
historical reference; do not implement against it.

* Problem

The JSON stream (native) backend has two rich status displays:

1. **Global mode-line indicator** — =claude-agent-activity-string= shows =[C:◐ dev.org#5]= with
   spinner, click-to-list, and tooltip showing elapsed time per query.
2. **=*Claude Queries*= buffer** — lists all active queries with source buffer, instruction
   number, elapsed time, and navigation (=RET= to jump, =k= to cancel).

The iTerm2 backend has none of this. It has a minimal =[iT:◐]= spinner via
=claude-org-iterm2--activity-string= and a =busy-count= integer, but:

- =claude-org-iterm2--set-busy= / =set-ready= are never called by the Python hooks
- No registration with =claude-agent--active-queries= means no =*Claude Queries*= buffer entry
- No =source-buffer=, =query-context=, or =start-time= tracking — no navigation or elapsed time
- No tooltip, no click-to-list, no cancellation support

* Goals

- Show iTerm2 queries in the *same* global mode-line indicator (=[C:◐ dev.org#5]=)
- Show iTerm2 queries in the *same* =*Claude Queries*= buffer alongside native queries
- Support navigation from the query list back to the org instruction heading
- Show elapsed time in tooltip and query list
- Support cancellation (=k= in query list sends interrupt to iTerm2 session)

* Non-Goals

- Per-buffer header-line activity badge (the iTerm2 backend doesn't have persistent
  session objects the way the native backend does — this can be added later)
- Streaming status (thinking/generating) — Claude CLI hooks only report prompt/stop events
- Replacing the existing =claude-agent--active-queries= infrastructure (we reuse it)

* Design

** Strategy: Register iTerm2 queries into =claude-agent--active-queries=

Rather than building a parallel tracking system, we register iTerm2 executions into
the existing =claude-agent--active-queries= hash table. This automatically enables:

- Global mode-line spinner with source buffer and instruction number
- =*Claude Queries*= buffer display with elapsed time
- Navigation via =source-location-fn= + =source-location-args=
- Tooltip with per-query detail

** Data Flow

Two paths lead to query registration — Emacs-originated and iTerm2-originated:

#+begin_src text
  Path A: Emacs-originated (C-c C-c on AI block)
  ─────────────────────────────────────────────
  claude-org-iterm2--execute-ai-block
    │  ① Write from-emacs flag (so Python prompt hook skips insertion)
    │  ② Register in claude-agent--active-queries
    │  ③ Send prompt to iTerm2

  Path B: iTerm2-originated (user types directly in terminal)
  ──────────────────────────────────────────────────────────
  [User types prompt in iTerm2 Claude Code]
    │
    ▼  UserPromptSubmit hook → sdd-bridge prompt
    │  No from-emacs flag → calls MCP:
    │  claude-org-sdd-bridge-insert-prompt
    │    ① Insert new AI block in org buffer
    │    ② Register in claude-agent--active-queries
    │    ③ Return CUSTOM_ID for response correlation

  Both paths converge:
  ───────────────────
  [Claude CLI processes query in iTerm2 terminal]
    │
    ▼  Stop hook → sdd-bridge response
    │  ④ MCP evalElisp: claude-org-iterm2--query-completed
    │     → unregister from claude-agent--active-queries
    │     → insert response (existing flow)
    │
    ▼
  Mode-line and *Claude Queries* auto-update via existing 0.2s timer
#+end_src

** Changes

*** 1. Register query on execute (Elisp)

In =claude-org-iterm2--execute-ai-block=, after sending the prompt:

#+begin_src elisp
;; Build a process-state for the active-queries table
(let* ((req-id (claude-agent--generate-request-id))
       (custom-id (org-entry-get nil "CUSTOM_ID"))
       (instr-num (claude-org--extract-instruction-number))
       (ctx (make-claude-agent-query-context
              :instruction-num instr-num
              :custom-id custom-id))
       (state (make-claude-agent--process-state
                :request-id req-id
                :start-time (float-time)
                :source-buffer (current-buffer)
                :query-context ctx
                :source-location-fn #'claude-org-goto-custom-id
                :source-location-args (list custom-id))))
  (claude-agent--register-query req-id state)
  ;; Save req-id so the response hook can unregister it
  (claude-org-iterm2--save-request-id sdd-session-id req-id))
#+end_src

The =request-id= is saved to a status file (=/tmp/claude-agent-status/<sdd-id>.request-id=)
so the Python response hook can pass it back when the query completes.

*** 2. Register query on prompt insertion from Python (Elisp)

In =claude-org-sdd-bridge-insert-prompt=, after inserting the AI block heading,
register as active query so prompts typed directly in iTerm2 also appear in the
mode-line and =*Claude Queries*= buffer:

#+begin_src elisp
;; Register as active query for mode-line and query manager
(goto-char heading-marker)
(let ((iterm2-id (gethash session-id claude-org-iterm2--sdd-to-iterm2)))
  (claude-org-iterm2--register-query session-id iterm2-id))
#+end_src

This reuses the same =register-query= function used by =execute-ai-block=, ensuring
both Emacs-originated and iTerm2-originated prompts share the same tracking.

*** 3. Unregister query on completion (Elisp)

New function called by the Python =response= hook via MCP:

#+begin_src elisp
(defun claude-org-iterm2--query-completed (sdd-session-id)
  "Mark the iTerm2 query as completed, removing it from active queries."
  (let ((req-id (claude-org-iterm2--read-request-id sdd-session-id)))
    (when req-id
      (let ((state (claude-agent--get-active-query req-id)))
        (when state
          (setf (claude-agent--process-state-closed state) t)
          (claude-agent--unregister-query req-id))))))
#+end_src

*** 4. Python hook calls completion (Python)

In =handle_response=, add an MCP call before the existing =insert-response=:

#+begin_src python
# Signal Emacs to unregister the query from active-queries
mcp.eval_elisp(
    f'(claude-org-iterm2--query-completed "{_escape_elisp_string(session_id)}")'
)
#+end_src

*** 5. Persistence helpers (Elisp + Python)

Elisp side: =claude-org-iterm2--save-request-id= / =claude-org-iterm2--read-request-id=
write/read =/tmp/claude-agent-status/<sdd-id>.request-id=.

Python side: =_write_request_id= / =_read_request_id= for cross-process access.

*** 6. Remove standalone iTerm2 mode-line spinner

With iTerm2 queries registered in =claude-agent--active-queries=, the existing global
=claude-agent--update-activity-string= timer handles everything. We can remove:

- =claude-org-iterm2--activity-string= / =claude-org-iterm2--activity-timer=
- =claude-org-iterm2--busy-count= / =claude-org-iterm2--spinner-index=
- =claude-org-iterm2--set-busy= / =claude-org-iterm2--set-ready=
- =claude-org-iterm2--update-mode-line=

These are currently dead code (never called by Python hooks).

*** 7. Cancellation support

=claude-agent-queries-cancel-at-point= calls =claude-agent-backend-cancel= which expects
a =query-handle=. For iTerm2 queries, the handle can be a plist containing the iTerm2
session UUID:

#+begin_src elisp
;; In execute-ai-block, set :query-handle for cancellation
(setf (claude-agent--process-state-query-handle state)
      `(:iterm2-session ,iterm2-id :sdd-session ,sdd-session-id))
#+end_src

A new =claude-agent-query-interrupt= method for iTerm2 sends Escape via
=iterm2_ctl.py send --session <id> --escape= to trigger Claude Code's cancel.

*** 8. Permission notification: auto-focus and dock bounce

When Claude Code needs interactive permission (=AskUserQuestion=, =ExitPlanMode=),
=claude-org-iterm2--permission-needed= now:

1. Focuses the correct iTerm2 tab via =claude-org-iterm2--focus-by-sdd-session=
2. Activates iTerm2 app via =osascript "tell application \"iTerm2\" to activate"=
3. Activates Emacs via =osascript= + =raise-frame=
4. Bounces Emacs dock icon via =(x-focus-frame nil)= (=NSInformationalRequest=)
5. Sends macOS desktop notification with sound

With multiple monitors, both iTerm2 and Emacs come to foreground on their
respective displays. The dock bounce draws attention when Emacs is not focused.

** What Doesn't Change

- =*Claude Queries*= buffer rendering — already reads =claude-agent--active-queries=
- Global mode-line timer (0.2s) — already calls =claude-agent--update-activity-string=
- =claude-agent--format-query-identity= — already reads =source-buffer= and =query-context=
- Navigation (=RET=) — already uses =source-location-fn= + =source-location-args=
- Python hook structure — only one new MCP call added to =handle_response=

** Implementation Order

1. Add =request-id= persistence helpers (Elisp + Python)
2. Register process-state in =execute-ai-block=
3. Register process-state in =insert-prompt= (iTerm2-originated prompts)
4. Add =claude-org-iterm2--query-completed= and wire from Python
5. Remove dead iTerm2 mode-line code
6. Add cancellation support
7. Tests: simulated E2E test for register/unregister lifecycle
