#+TITLE: Design: Codebase Review — Architecture, Quality, and Harness Improvements
#+DATE: [2026-03-12]
#+STATUS: proposed

* Overview

Comprehensive review of the claude-agent codebase across three dimensions:
architecture, code quality, and test harness engineering. Findings are
ranked by severity and grouped into actionable proposals.

* Architecture Findings

** A1. Parallel State Tracking Structures (HIGH)

=claude-agent--active-states= (module-level list at =claude-agent-backend.org:979=) exists
alongside =claude-agent--registry= (struct at line 993) which has its own =active-states= field.
The sentinel cleanup updates the module-level list; =claude-agent-registry-cleanup-process= updates
the registry version. Similarly, =claude-agent--pending-background-tasks= (line 1853) and
=claude-agent--pending-control-requests= (line 1914) duplicate the registry struct's fields.

*Proposal*: Consolidate all state into the unified =claude-agent--registry=. Remove the standalone
variables. All reads/writes go through registry accessors.

** A2. Backend References MCP Server Variable (MEDIUM)

=claude-agent-backend.org= declares and mutates =emacs-mcp-server-path-mappings= (lines 1603,
2244, 2352), violating the stated invariant that =emacs-mcp-server.org= has zero =claude-*=
dependencies. The backend couples to a peer module's global state.

*Proposal*: Move path-mapping ownership to the backend. MCP server reads from backend, not the
reverse.

** A3. Dual Load Paths (MEDIUM)

Both =claude-agent.org= (lines 111–115) and =claude-code.el= (lines 58–61) load sub-modules
independently. =claude-org.org= (lines 219–231) has the same issue. Load order is enforced in two
places with no synchronization.

*Proposal*: Single authoritative load path in =claude-code.el=. Remove =dolist= self-loading from
=claude-agent.org= and =claude-org.org=, or make it clearly conditional (only when loaded
standalone for development).

** A4. Session-to-Backend Mapping is a Fourth Tracking Structure (MEDIUM)

=claude-agent-claude-backend--session-registry= (line 4287) maps =session_id → backend=,
overlapping with the unified registry's =sessions= field and =claude-agent--session-mapping=.

*Proposal*: Integrate into the unified registry. Document the relationships between session-key,
sdk-uuid, and backend handle.

** A5. Native Terminal Calls Private Backend Function (MEDIUM)

=claude-org-native.org:171= calls =claude-agent-claude-backend--build-switches= (double-dash =
private).

*Proposal*: Create a public =claude-agent-build-cli-switches= wrapper.

** A6. =claude-ide.org= Has No Dedicated Test Suite (MEDIUM)

2,212-line module with WebSocket lifecycle, MCP protocol, deferred responses — only tested
incidentally via =test-iterm2-e2e-simulated.el=.

*Proposal*: Create =tests/test-claude-ide.el= with unit tests for session lifecycle, ping timer,
deferred response handling, and lockfile management.

** A7. Stale TOC Entries After Backend Extraction (LOW)

=claude-org.org= (lines 132–142) contains a full "Native Terminal" outline from before the
extraction to =claude-org-native.org=.

*Proposal*: Remove stale TOC entries. Each file documents itself.

** A8. iTerm2/Native Backends Bypass the Backend Protocol (MEDIUM)

The =cl-defgeneric= protocol (=backend-query=, =backend-cancel=, etc.) is well-designed but only
the JSON stream backend implements it. iTerm2 and native terminal backends dispatch through ad-hoc
function calls, reaching directly into =claude-agent--active-queries= to register stub
process-states. A new backend implementer would follow the documented protocol but find it
insufficient for mode-line integration.

*Proposal*: Create =claude-agent-iterm2-backend= and =claude-agent-native-backend= structs that
implement the =cl-defgeneric= protocol. Route =claude-org-execute= through protocol dispatch
instead of backend-specific branching.

** A9. iTerm2-Specific State in SDK Layer (MEDIUM)

=claude-agent--pending-permissions= (=claude-agent.org:181=) maps SDD session-ids to tool names.
The mode-line code in =claude-agent.org= parses SDD session-id format strings
(=sdd-YYYYMMDD-HHMMSS=) — an iTerm2 implementation detail at the wrong layer.

*Proposal*: Replace with a generic =claude-agent-pending-alerts= alist of =(label .
click-action-fn)= entries. Move SDD-specific label formatting to =claude-org-iterm2.org=.

** A10. =:org-section= Concept Leaked Into Core SDK (LOW)

=claude-agent-query= at =claude-agent-backend.org:2263= accepts =:org-section=, an org-layer
concept. The SDK should not know callers organize work into "org sections".

*Proposal*: Rename to =:context-label= (generic opaque string).

** A11. Backend Capability Enum Undocumented (LOW)

=claude-agent-backend-supports-p= accepts capability symbols, but valid values are scattered across
method implementations.

*Proposal*: Add a =defconst= listing all valid capability keywords. Add a structural test that
validates new backends declare capabilities.

* Code Quality Findings

** DONE Q1. Process Filter Has No =condition-case= (HIGH) :done:

*Status*: Implemented [2026-03-29]

Both =claude-agent--process-filter= and =claude-agent--process-sentinel= now have
=condition-case= guards. Structural test =test-structural-process-filters-guarded=
(F36 in =test-structural.el=) enforces that all functions named =*process-filter*=
or =*process-sentinel*= in source .org files contain =condition-case=.

*Proposal*: Wrap process filter, sentinel, and cleanup timer in =condition-case= with error
logging. Add a structural test that verifies all process filters are guarded.

** Q2. =McpClient.eval_elisp= Returns =None= for All Failures (MEDIUM)

=mcp_client.py:50–66= — network failure, malformed JSON, and Emacs-reported errors all return
=None=. Callers in =sdd_bridge.py= cannot distinguish "Emacs errored" from "connection refused".

If =insert-prompt= raises (org buffer read-only, session not found), Python continues silently,
writes no custom-id, and the response insertion later fails with "Instruction not found".

*Proposal*: Return structured result — ={"success": True, "result": ...}= vs ={success: False,
"error": ...}=. Raise distinct exceptions for connection failures vs Emacs errors.

** Q3. =query-completed= Fires Before Response Insertion (MEDIUM)

=sdd_bridge.py:130= — =claude-org-iterm2--query-completed= runs unconditionally at the top of
=handle_response=, before transcript parsing and response insertion. If response extraction fails,
mode-line shows "idle" while the query is still unresolved.

*Proposal*: Reorder — insert response first, then mark complete.

** Q4. Status Set to "busy" With No Reset on MCP Failure (MEDIUM)

=sdd_bridge.py:84= — =write_status(session_id, "busy")= runs before the MCP call. If MCP fails,
status stays "busy" forever. No cleanup path exists.

*Proposal*: Wrap MCP call in try/except; reset status to "ready" on failure.

** Q5. Hash Tables Never Cleaned Up (MEDIUM)

=claude-org-iterm2--sdd-to-iterm2= and =claude-org-iterm2--sdd-to-session-key= (lines 902, 905)
grow forever. No =remhash= exists for these tables. Long-running Emacs sessions accumulate stale
entries.

*Proposal*: Add cleanup in =claude-org-iterm2--query-completed= or a periodic sweep that removes
entries for dead sessions.

** Q6. =error= Inside =maphash= in =claude-ide= (MEDIUM)

=claude-ide.org:483= — =claude-ide--complete-deferred-response= calls =error= inside a =maphash=
lambda when client is nil. The deferred response entry is not removed before the error, causing a
leak. Behavior of =error= inside =maphash= is undefined in older Emacs versions.

*Proposal*: Replace =error= with =message= + =remhash= + early return.

** Q7. Global Ping Timer Not Per-Session (MEDIUM)

=claude-ide--ping-timer= (line 418) is a single global variable. Starting a second IDE session
steals the ping timer from the first, whose connection may time out.

*Proposal*: Store ping timer in the =claude-ide--session= struct.

** Q8. =_escape_elisp_string= Missing Tab/Null Escaping (LOW-MEDIUM)

=sdd_bridge.py:53–60= — tab characters and null bytes are not escaped. Claude responses containing
tab-indented code will produce valid but potentially misaligned org properties.

*Proposal*: Add =\t= and =\x00= escaping.

** Q9. =atexit= + Manual Cleanup Double-Call Risk (LOW)

=claude_sdd.py:282–289= — =cleanup_ide_server= can fire twice: manually after =subprocess.run=,
then again via =atexit= if =unregister= is skipped due to an exception.

*Proposal*: Move =atexit.unregister= before the manual call, or use try/finally.

** Q10. =save-cli-session= Not Persisted (LOW)

=claude-org-sdd-bridge-save-cli-session= writes a property but doesn't call =save-buffer=. Python
callers have no way to trigger save afterwards. Property is lost on unexpected Emacs exit.

*Proposal*: Add =save-buffer= call (with =inhibit-message= t) inside the function.

** Q11. Duplicate =claude-agent--extract-error-message= (MEDIUM)

Both =claude-agent-backend.org:2417= and =claude-org.org:4260= define this function with
overlapping but different behavior. The =claude-org.org= version silently shadows the backend
version with two extra =cond= branches (symbol error and =(error "message" ...)= list).

*Proposal*: Remove the =claude-org.org= duplicate. Extend the canonical backend version.

** Q12. =emacs-mcp-server-path-mappings= Not Cleared on Abnormal Exit (MEDIUM)

=claude-agent--sentinel-cleanup= (normal exit) clears path mappings, but
=claude-agent--sentinel-handle-abnormal-exit= does not. If a Docker query is OOM-killed, stale path
mappings persist and corrupt the next MCP request.

*Proposal*: Clear path mappings in both exit paths, or extract a shared cleanup helper.

** Q13. Loop Timer Fires After Buffer Kill (MEDIUM)

=claude-org--maybe-continue-loop= schedules a =run-at-time= timer. If the buffer is killed between
timer arm and fire, the marker check prevents a crash but =claude-org--cleanup-session= may not
cancel an already-armed timer in time.

*Proposal*: Add a cancelled-session guard in =claude-org--execute-loop-iteration=.

** Q14. Stdin Close Timer Not Cancellable (LOW)

=claude-agent--maybe-close-stdin= (=claude-agent-backend.org:2047=) creates a 0.1s timer with no
stored handle. If the process is killed while the timer is pending, it fires uselessly.

*Proposal*: Store timer in process state; cancel in kill/interrupt functions.

** Q15. =sleep-for= Blocks Emacs 30s for Docker Startup (LOW-MEDIUM)

=claude-agent--ensure-docker-container= loops with =sleep-for 1= up to 30 times synchronously,
freezing the Emacs UI.

*Proposal*: Convert to timer-based async retry with progress display.

** Q16. Missing =lexical-let= in =claude-org--send-request= (LOW)

The =mk= helper lambda is defined via plain =lambda= inside a =let*=. Works today because it is
called immediately, but fragile — any refactor to async invocation would break under dynamic
binding.

*Proposal*: Wrap =mk= in =lexical-let= for defensive correctness.

** Q17. Three Near-Identical "Find Previous Section Level" Functions (LOW)

=claude-org--find-previous-chat-level=, =--find-previous-story-level=, =--find-previous-sdd-level=
each implement the same backwards-scan with different predicates.

*Proposal*: Unify into =claude-org--find-previous-section-level (predicate)=.

** Q18. Public iTerm2 Functions Use Internal Double-Dash Naming (LOW)

=claude-org-iterm2--query-completed= and =--loop-send= are called from Python via MCP (external
contract) but use the internal =--= prefix.

*Proposal*: Promote to single-dash public names.

* Test Harness Findings

** T1. No Error Injection in Mock CLI (HIGH)

=tests/mock-claude-cli.sh= only produces well-formed JSON streams. No scenarios test:
- Mid-stream crashes (process killed during response)
- Malformed JSON (truncated lines, invalid UTF-8)
- Oversized messages (multi-MB tool results)
- Rate limit responses
- Timeout / hung processes

*Proposal*: Add mock scenarios: =crash-mid-stream=, =malformed-json=, =rate-limited=,
=oversized-message=. Add corresponding tests that verify graceful degradation.

** T2. MCP Round-Trip Has Zero Tests (HIGH)

The Python → MCP → Emacs → org buffer pipeline has no automated tests. The only verification is
manual E2E testing. Bugs in =sdd_bridge.py= ↔ =emacs-mcp-server.org= interactions (escaping,
error handling, timeout) are discovered only in production.

*Proposal*: Create an integration test harness that:
1. Starts the MCP server in a subprocess
2. Sends structured MCP requests via HTTP
3. Verifies Emacs state changes (buffer content, properties)
4. Covers error cases (invalid session ID, read-only buffer, missing heading)

** T3. Protocol Conformance Fuzzer for JSON Stream Parser (HIGH)

The JSON stream parser (=claude-agent--process-json-buffer=) handles real-world protocol variations
but is only tested with hand-crafted fixtures. No fuzz testing for:
- Partial JSON split across process filter calls
- Interleaved system/assistant/result messages in unexpected order
- Unknown message types (forward compatibility)
- Empty lines, whitespace-only lines

*Proposal*: Create a protocol fuzzer that generates random valid and semi-valid JSON streams, feeds
them to the parser, and verifies no errors are signalled.

** T4. Fixture Capture Mode for Systematic Test Data (MEDIUM)

Test fixtures are manually created. There is no recording mode to capture real Claude Code sessions
for replay.

*Proposal*: Add a =CLAUDE_RECORD_FIXTURE= env var that:
1. Wraps =claude-agent--process-filter= to log raw process output
2. Wraps =claude-agent--process-sentinel= to log exit status
3. Saves timestamped fixture files to =tests/fixtures/recorded/=
4. Includes a replay tool that feeds recorded data into the parser

** T5. Regression Tag + Dedicated =make test-regression= (MEDIUM)

Bug-fix tests are scattered across test files with no easy way to run "just the regression tests".

*Proposal*: Add =:regression= tag to all bug-fix tests. Add =make test-regression= target.

** T6. E2E Test Infrastructure for CI (MEDIUM)

Real E2E tests (iTerm2 + Claude Code + Emacs) can only run on macOS with a GUI. No CI pipeline
exists.

*Proposal*:
1. Create a macOS GitHub Actions runner with iTerm2 installed
2. Use =MOCK_SCENARIO= for Claude API calls (no real API key needed)
3. Run headless Emacs with =make test-integration=
4. Record session transcripts for debugging failures

** DONE T7. Process Sentinel Has Zero Explicit Tests (HIGH) :done:

*Status*: Implemented [2026-03-29]

=tests/test-claude-agent-sentinel.el= now has 19 tests covering all sentinel paths:
- Normal exit (exit 0): state cleanup, complete callback fires with nil
- Crash exit (mock crash-mid-stream): state closed, process dead
- OOM kill (SIGKILL): state fully cleaned up after signal death
- Filter error recovery: malformed JSON handled gracefully
- Error exit code: rate-limited scenario with exit code 1
- Output buffer killed: sentinel-cleanup kills process output buffer
- Error plist structure: verifies =:message= and =:exit-code= in error plist
- Cancelled query: sentinel skips complete callback for cancelled queries
- Docker path-mappings: cleared on Docker exit, preserved on non-Docker exit
- Full sentinel dispatch: direct invocation of =claude-agent--process-sentinel=
  for both normal (exit 0) and abnormal (exit 1) events

*Proposal*: Create tests that start a mock CLI process, kill it, and verify session state
transitions (=:busy → nil=), marker freeing, and error callback invocation.

** T8. Mock CLI is One-Way Only — No Bidirectional Protocol (MEDIUM)

The mock reads stdin once then replays a static JSONL file. It cannot respond to =control_request=
messages (permission prompts, ask-user-question). The permission round-trip is completely untested.

*Proposal*: Extend =mock-claude-cli.sh= to support a state machine that waits for
=control_response= on stdin before continuing output. Add =WAIT_FOR_INPUT= directive.

** T9. Buffer-Killed-During-Streaming Untested (MEDIUM)

No test kills the org buffer while a query is actively streaming. This is a common user action.

*Proposal*: Start a slow-response mock scenario, kill the buffer mid-stream, verify no errors are
signalled and the process is cleaned up.

** T10. =claude-agent-chat= Has Zero Tests (MEDIUM)

The comint-based chat mode (=claude-agent-chat=, =chat-send=, =chat-interrupt=, =chat-quit=,
=chat-clear=, =chat-new-session=) is listed in the public API with no test file.

*Proposal*: Create =tests/test-claude-agent-chat.el= with mock CLI tests for the chat UI.

** T11. Three Expected-Failure Tests Represent Known Debt (LOW)

Tests marked =:expected-result :failed= in cancel, marker lifecycle, and integration suites.

*Proposal*: Track count in a structural test that fails if the count increases without
documentation. Periodically revisit and fix.
