#+TITLE: Deep cmux Integration — Richer UI and Architecture Fixes
#+DATE: 2026-03-16
#+STATUS: draft

* Goals

- Fix architectural issues in the cmux backend (permission routing, session recovery)
- Leverage cmux's sidebar as a real-time agent dashboard (logs, progress, metadata)
- Replace polling with event-driven mechanisms (=pipe-pane=, =wait-for=)
- Clean up stale resources (old workspaces, dead sessions)
- Provide richer feedback in both Emacs mode-line and cmux sidebar during AI block execution

* Non-Goals

- Replacing the SDD bridge hooks with cmux's =claude-hook= (they coexist)
- Browser automation integration (future story)
- Changing cmux itself (upstream patches)
- Supporting non-macOS platforms

* Background

The research at =docs/research/2026-cmux-codebase-study.org= found that:
- cmux exposes 100+ CLI methods; we use ~15
- The sidebar supports status entries, progress bars, logs, and rich metadata blocks
- =pipe-pane= and =wait-for= enable event-driven I/O (we poll instead)
- Permission notifications incorrectly call the iTerm2 backend for cmux sessions
- No session recovery after Emacs restart
- Stale workspaces accumulate

* Technical Design

** Phase 1: Architecture Fixes (Critical)

*** 1.1 Fix Permission Routing for cmux

*Problem*: =sdd_bridge.py:handle_permission= calls =claude-org-iterm2--permission-needed=
unconditionally. For cmux sessions, this tries to focus a non-existent iTerm2 tab.

*Fix*: Create =claude-org-cmux--permission-needed= and route based on backend:

#+begin_src elisp
(defun claude-org--terminal-permission-needed (sdd-session-id tool-name)
  "Route permission notification to the correct backend."
  (cond
   ((gethash sdd-session-id claude-org-cmux--sdd-to-session-key)
    (claude-org-cmux--permission-needed sdd-session-id tool-name))
   (t
    (claude-org-iterm2--permission-needed sdd-session-id tool-name))))

(defun claude-org-cmux--permission-needed (sdd-session-id tool-name)
  "Handle permission notification for a cmux session.
Focuses the cmux workspace and activates cmux app."
  (puthash sdd-session-id tool-name claude-agent--pending-permissions)
  ;; Focus cmux workspace
  (let ((ws-id (claude-org-cmux--lookup-workspace sdd-session-id)))
    (when ws-id
      (claude-org-cmux--call "select-workspace" "--workspace" ws-id)))
  ;; Activate cmux app
  (when (eq system-type 'darwin)
    (start-process "activate-cmux" nil "osascript" "-e"
                   "tell application \"cmux\" to activate"))
  ;; Bring Emacs to front + macOS notification + mode-line update
  (claude-org-iterm2--activate-emacs)
  (claude-org--notify "Claude: Permission Needed"
                      (format "%s needs approval for %s"
                              sdd-session-id tool-name))
  (claude-agent--update-activity-string)
  "ok")
#+end_src

Also update =sdd_bridge.py= to call the generic dispatcher instead of iTerm2 directly.

*** 1.2 Session Recovery After Emacs Restart

*Problem*: =claude-org-cmux--sdd-to-session-key= and =--sdd-to-surface= hash tables
are lost on Emacs restart. Hooks from running cmux terminals can't find their session.

*Fix*: Scan org buffers for =CMUX_SURFACE_ID= properties on first hook arrival:

#+begin_src elisp
(defun claude-org-cmux--recover-session (sdd-session-id)
  "Try to recover session mapping by scanning org buffers.
Called when sdd-session-id is not found in the hash table."
  (catch 'found
    (dolist (buf (buffer-list))
      (when (and (buffer-file-name buf)
                 (with-current-buffer buf (bound-and-true-p claude-org-mode)))
        (with-current-buffer buf
          (save-excursion
            (widen)
            (goto-char (point-min))
            (when (re-search-forward
                   (format ":CLAUDE_SESSION_ID: %s"
                           (regexp-quote sdd-session-id))
                   nil t)
              (org-back-to-heading t)
              (let ((surface (org-entry-get nil "CMUX_SURFACE_ID" nil))
                    (session-key (claude-org--current-session-key)))
                (when (and surface session-key)
                  (puthash sdd-session-id session-key
                           claude-org-cmux--sdd-to-session-key)
                  (puthash sdd-session-id surface
                           claude-org-cmux--sdd-to-surface)
                  (throw 'found session-key))))))))))
#+end_src

Integrate into =claude-org--terminal-query-completed= as a fallback before
the "session not found" error path.

*** 1.3 Stale Workspace Cleanup

*Problem*: When =ensure-session= creates a new workspace because the old surface
is dead, the old workspace remains running in cmux.

*Fix*: Before creating a new workspace, close the old one:

#+begin_src elisp
;; In ensure-session, when saved-id fails liveness check:
(when saved-id
  (condition-case nil
      (let ((ws-id (org-entry-get nil "CMUX_WORKSPACE_ID" nil)))
        (when ws-id
          (claude-org-cmux--call "close-workspace" "--workspace" ws-id)))
    (error nil)))  ;; best-effort cleanup
#+end_src

** Phase 2: Rich Sidebar Feedback

*** 2.1 Query Progress in Sidebar

Use cmux's =log= and =set-progress= during AI block execution:

| Event | Sidebar Action |
|-------+---------------|
| Execute AI block | =log "Starting query: <prompt-preview>"= |
| Claude Code receives prompt | =set-progress 0.1 --label "Processing..."= |
| Tool use (permission) | =log --level warning "Permission needed: Bash"= |
| Tool use (approved) | =log "Tool: Bash — running..."= |
| Response started | =set-progress 0.5 --label "Generating response..."= |
| Response complete | =set-progress 1.0 --label "Done"=, then =clear-progress= |
| Error | =log --level error "Query failed: <message>"= |

Implementation: Add sidebar calls to the SDD bridge hooks:

#+begin_src python
def _sidebar_log(session_id: str, message: str, level: str = "info"):
    """Write a log entry to the cmux sidebar."""
    try:
        subprocess.run(
            ["cmux", "log", "--level", level, "--source", "sdd-bridge",
             "--workspace", _get_workspace_id(session_id), "--", message],
            timeout=2, capture_output=True)
    except Exception:
        pass
#+end_src

*** 2.2 Rich Metadata Blocks

Use =report_meta_block= to show the current instruction's prompt as markdown
in the sidebar:

#+begin_src python
def _sidebar_meta(session_id: str, prompt: str):
    """Show the current prompt as a metadata block in the sidebar."""
    preview = prompt[:200] + ("..." if len(prompt) > 200 else "")
    try:
        subprocess.run(
            ["cmux", "report_meta_block", "current_query", preview,
             "--priority", "10",
             "--tab", _get_workspace_id(session_id)],
            timeout=2, capture_output=True)
    except Exception:
        pass
#+end_src

** Phase 3: Event-Driven Ready Detection

*** 3.1 Replace Polling with =wait-for=

*Current*: =wait-for-ready= polls =capture-pane= every 1s for up to 30s.

*Improved*: Use =cmux wait-for= to block until a terminal pattern appears:

#+begin_src elisp
(defun claude-org-cmux--wait-for-ready (surface-id)
  "Wait for Claude Code TUI to be ready using cmux wait-for."
  (let ((result (condition-case nil
                    (claude-org-cmux--call
                     "wait-for" "--text" "-- INSERT --"
                     "--timeout" "30"
                     "--workspace" (org-entry-get nil "CMUX_WORKSPACE_ID" nil))
                  (error nil))))
    (unless result
      ;; Fallback: also check for "type a message" pattern
      (condition-case nil
          (claude-org-cmux--call
           "wait-for" "--text" "type a message"
           "--timeout" "5"
           "--workspace" (org-entry-get nil "CMUX_WORKSPACE_ID" nil))
        (error
         (user-error "Timeout: Claude Code not ready in cmux after 30s"))))))
#+end_src

*** 3.2 Explore =pipe-pane= for Output Streaming

*Future*: =pipe-pane= streams terminal output to a command or file. Could enable
real-time response parsing without waiting for the =Stop= hook:

#+begin_src bash
cmux pipe-pane --command "tee /tmp/claude-output.log" --workspace workspace:1
#+end_src

Emacs could watch this file with =filenotify= for incremental response display.
This is a larger change that requires careful design — deferred to a future story.

*** 4.2 Jump-to-Workspace from Emacs

Enhance the transient menu with a "Focus Terminal" command that jumps to the
correct cmux workspace:

#+begin_src elisp
(defun claude-org-cmux-focus-terminal ()
  "Focus the cmux workspace for the current SDD story."
  (interactive)
  (let ((ws-id (condition-case nil
                   (claude-org-cmux--find-session-property "CMUX_WORKSPACE_ID")
                 (error nil))))
    (unless ws-id (user-error "No cmux workspace for this story"))
    (claude-org-cmux--call "select-workspace" "--workspace" ws-id)
    (when (eq system-type 'darwin)
      (start-process "focus-cmux" nil "osascript" "-e"
                     "tell application \"cmux\" to activate"))))
#+end_src

*** 4.3 Sidebar Log Viewer in Emacs

Create a =*cmux-log*= buffer that displays the cmux sidebar log for the
current story, updated periodically:

#+begin_src elisp
(defun claude-org-cmux-show-log ()
  "Show the cmux sidebar log for the current SDD story."
  (interactive)
  (let* ((ws-id (claude-org-cmux--find-session-property "CMUX_WORKSPACE_ID"))
         (json (claude-org-cmux--call "list-log" "--limit" "50" "--tab" ws-id))
         (buf (get-buffer-create "*cmux-log*")))
    (with-current-buffer buf
      (erase-buffer)
      (insert json)
      (json-mode))
    (display-buffer buf)))
#+end_src

* Rejected Alternatives

** Replace sdd-bridge with claude-hook

cmux's =claude-hook= manages sidebar status natively. We considered routing
ALL hook events through =claude-hook= only. Rejected because:
- sdd-bridge manages Emacs org integration (prompt insertion, response capture)
- claude-hook manages cmux sidebar — these are orthogonal concerns
- Both coexist peacefully (different =hooks.json= registrations)

** Embed cmux protocol in Emacs Lisp

We considered implementing the V2 JSON-RPC protocol directly in Emacs (socket
client). Rejected because:
- The =cmux= CLI binary handles socket path discovery, auth, and protocol
- Spawning =cmux= CLI is simpler and more maintainable
- CLI is always version-matched with the running cmux app
