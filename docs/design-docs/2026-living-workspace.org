* Reality check (2026-04-27)
Shipped.  The workspace heading model with `CLAUDE_SESSION_ID`,
`ACTIVE_STORY`, `CMUX_WORKSPACE_ID`, `CLAUDE_CLI_SESSION` properties is the
default flow today.  Story switching renames the cmux pane via
`code-agent-org-active-story-changed-hook` (now also fired by
`org-property-changed-functions` — see commit 6a47852 for the A10 fix).
E2E coverage: tasks A2/A10/A15 in `tests/e2e/E2E_TASKS.org`.

* Goal

Replace per-story Claude Code sessions with a workspace-bound model where
stories are lightweight org subsections sharing a single Claude Code per
cmux workspace. Org-mode remains the primary interface for both organizing
work and interacting with Claude Code.

* Mental Model: The Lisp Image

A living, persistent environment you incrementally modify:
- The org file is the image — program, documentation, and session history
- Workspaces are persistent processes — they outlive any individual story
- Stories are incremental modifications — create, work, archive, repeat
- ~C-c C-c~ is the REPL eval — immediate feedback, always available

* Org Structure

** Workspace Heading Properties

| Property | Who Sets | Purpose |
|----------+----------+---------|
| ~CMUX_WORKSPACE~ | User | Human-readable workspace name, binds to cmux |
| ~CLAUDE_SESSION_ID~ | User or auto | Session identity for routing and inheritance |
| ~CLAUDE_CLI_SESSION~ | Auto | Claude Code SDK UUID for ~--resume~ |
| ~CMUX_SURFACE_ID~ | Auto | Cached surface ID, avoids re-detection |
| ~ACTIVE_STORY~ | Auto | Current story heading, persists after completion |

Stories have *zero required properties*. Everything is inherited from
the workspace heading.

** Rules

- *Heading with ~CMUX_WORKSPACE~ = workspace*: one Claude Code per workspace.
  The workspace heading can be at any level (not necessarily top-level).
- *Sub-headings = stories*: lightweight, just a heading. No properties needed.
- *Stories share the workspace's Claude Code*: all ai blocks under a workspace
  route to the same session. No restart between stories.
- *One active story per workspace*: tracked via ~ACTIVE_STORY~.
  Prevents collision, enables response routing.
- *Story lifecycle in org*: TODO/DONE, tagging, ~org-archive-subtree~.
- *Workspace lifecycle in cmux*: persistent, auto-resume, outlives stories.

* Interactive Mode

Two ways to interact, both routed through the workspace's Claude Code:

** From Emacs (ai block)

Write in ~#+begin_src ai~ block → ~C-c C-c~ → response streams inline.

- Zero ceremony: no session IDs, no backend properties on stories
- Auto-selects workspace's Claude Code via nearest ancestor ~CMUX_WORKSPACE~
- Org file captures prompts + responses under the story heading
- *Liveness*: sub-10-second feedback loop preserves flow state

** From cmux (direct terminal input)

Type instructions directly in the Claude Code terminal in cmux.

- ~ACTIVE_STORY~ tells SDD hooks which story the response belongs to
- Hooks call ~evalElisp~ to read ~ACTIVE_STORY~ and route response
  back to the correct story subsection in org
- If ~ACTIVE_STORY~ is nil, no org routing (terminal-only interaction)
- Verbose buffer mirrors live output in Emacs

Both modes share the same workspace session. Both update ~:busy~ state.
Both modes are available in Phase 1.

** Append AI Block (~claude-org-menu → a~)

Append a fresh ai block at the end of the active story's Workflow subsection:

#+begin_src elisp :load no
(defun claude-org-append-ai-block ()
  "Append a new ai block in the active story's Workflow subsection."
  (interactive)
  (let ((workflow-pos (claude-org--find-active-story-workflow)))
    (when workflow-pos
      (goto-char workflow-pos)
      (org-end-of-subtree t)
      (insert "\n\n#+begin_src ai\n")
      (insert "\n")
      (insert "#+end_src\n")
      (forward-line -2)
      (end-of-line))))
#+end_src

Fast path: ~claude-org-menu → a~ → cursor inside ai block → type → ~C-c C-c~.

Persistent cmux workspaces per project:

| Workspace | Role | Example |
|-----------+------+---------|
| Dev | Write code | claude-agent-dev |
| Review | Review PRs/code | claude-agent-review |

* Story-Aware Routing

** Execution Flow

When user executes ~C-c C-c~ on an ai block:

#+begin_example
  1. Find workspace heading (nearest ancestor with CMUX_WORKSPACE)
  2. Find story heading (nearest sub-heading under workspace at point)
  3. Derive session-key from workspace's CLAUDE_SESSION_ID
  4. Is workspace busy?
     NO  → Set ACTIVE_STORY on workspace heading
           Rename cmux tab to "workspace: story"
           Send to workspace's Claude Code
     YES → Is it the SAME story?
           YES → Queue (existing behavior)
           NO  → WARN: "Workspace busy with 'Fix parser bug'.
                  [w]ait, [q]ueue after current, [i]nterrupt?"
#+end_example

** ACTIVE_STORY Lifecycle

~ACTIVE_STORY~ persists after completion — it is NOT cleared.

This enables direct cmux input to be routed to the correct story:
Claude Code SDD hooks call ~evalElisp~ to read ~ACTIVE_STORY~ and
know which org section to route responses to.

~ACTIVE_STORY~ only changes when:
- User executes an ai block from a *different* story → auto-switches
- User archives the story → cleared on ~org-archive-subtree~
- User manually clears it

** ~claude-org-active-story-changed-hook~

When ~ACTIVE_STORY~ changes, run ~claude-org-active-story-changed-hook~.
This is a normal Emacs hook (list of functions) called with two arguments:
~(workspace-session-id new-story-name)~.

#+begin_src elisp :load no
(defvar claude-org-active-story-changed-hook nil
  "Hook run when ACTIVE_STORY changes on a workspace heading.
Each function is called with (WORKSPACE-SESSION-ID NEW-STORY-NAME).")
#+end_src

Default handlers:

1. *Inject system prompt*: if the new story has a ~System Prompt~
   subsection, send its content to Claude Code as the next message.
2. *Rename cmux tab*: update tab title to ~"workspace: story"~.

*** Per-Story System Prompt

Stories can optionally have a ~System Prompt~ subsection:

#+begin_example
  ** Fix parser bug
  *** System Prompt
  This parser uses recursive descent. Handle nested quotes carefully.
  The tokenizer is in claude-agent.org section "Lexer".
  *** Workflow
  #+begin_src ai
  please fix the parser bug...
  #+end_src
#+end_example

When ~ACTIVE_STORY~ switches to this story, the default hook handler:
1. Finds the ~System Prompt~ subsection under the story heading
2. Sends its content to the workspace's Claude Code (via ~cmux send~)
3. Sends Enter to execute it

This way Claude Code receives the context *once* on story switch, not
on every ai block execution. If the story has no ~System Prompt~
subsection, nothing is sent.

#+begin_src elisp :load no
(defun claude-org--inject-story-system-prompt (workspace-session-id story-name)
  "If the new active story has a System Prompt subsection, send it to Claude Code."
  (when-let* ((prompt-text (claude-org--find-story-system-prompt
                            workspace-session-id story-name)))
    (claude-org-cmux--send-text workspace-session-id prompt-text)
    (claude-org-cmux--send-text workspace-session-id "\n")))

(add-hook 'claude-org-active-story-changed-hook
          #'claude-org--inject-story-system-prompt)
(add-hook 'claude-org-active-story-changed-hook
          #'claude-org--update-cmux-tab-title)
#+end_src

** Response Routing

*** Channel A: ai block execution (Emacs → Claude Code → Emacs)

#+begin_example
  1. Emacs sets ACTIVE_STORY on workspace heading
  2. Emacs sets per-session :marker to the insert-point in the story
  3. Emacs sends prompt to workspace's Claude Code
  4. Response arrives → use per-session :marker for insertion
  5. Insert response under the story heading
#+end_example

The existing per-session ~:marker~ field is sufficient — only one story
is active at a time (collision warning prevents concurrent execution on
different stories).

*** Channel B: Direct cmux input (user types in terminal)

SDD hook calls ~evalElisp~ to read ~ACTIVE_STORY~:

#+begin_src elisp :load no
(defun claude-org-get-active-story (workspace-name)
  "Return the active story heading for WORKSPACE-NAME, or nil."
  (claude-org-terminal--find-session-property
   workspace-name "ACTIVE_STORY"))
#+end_src

- ~ACTIVE_STORY~ set → navigate to that story's Workflow subsection,
  insert prompt/response at the end (same location as ai blocks)
- ~ACTIVE_STORY~ nil → no org routing (terminal-only interaction)

*** Prompt/Response Insertion

Both ~insert-prompt~ and ~insert-response~ target the *Workflow*
subsection of the active story. This applies to both channels:

- *Channel A* (ai block): Emacs already knows the insert point (the ai
  block location within the story's Workflow subsection).
- *Channel B* (direct cmux input): SDD hook reads ~ACTIVE_STORY~ via
  ~evalElisp~, navigates to that story's Workflow subsection, and
  inserts the prompt/response at the end.

The Workflow subsection is found by heading text match under the story
heading (no ~:sdd:~ tag needed). If no Workflow subsection exists,
create one automatically.

#+begin_example
  ** Fix parser bug
  *** System Prompt              ← optional context, sent on story switch
  *** Workflow                   ← all prompts and responses go here
  #+begin_src ai                 ← from Emacs ai block
  ...
  #+end_src
  **** Response                  ← response from ai block
  ...
  #+begin_src ai                 ← from direct cmux input (auto-inserted)
  ...
  #+end_src
  **** Response                  ← response from direct cmux input
  ...
#+end_example

** cmux Tab Title

When ~ACTIVE_STORY~ changes, rename the cmux tab:

#+begin_src elisp :load no
(defun claude-org-cmux--update-tab-title (workspace-name story-name)
  "Rename the cmux tab to show WORKSPACE-NAME and optional STORY-NAME."
  (let ((title (if story-name
                   (format "%s: %s" workspace-name story-name)
                 workspace-name)))
    (claude-org-cmux--call "rename-tab"
      "--workspace" workspace-name title)))
#+end_src

cmux sidebar shows: ~claude-agent-dev: Fix parser bug~.
Combined with workspace color for instant visual status.

** Status Files

Status files keep the existing ~{session_id}~ naming — no change needed.
One workspace = one ~session_id~ = one Claude Code, and only one story is
active at a time (~ACTIVE_STORY~), so there is no concurrent collision.

** State Diagram

#+begin_example
  Workspace States (ACTIVE_STORY persists across idle/busy):

  READY(story=A) ──[C-c C-c on story A]──→ BUSY(story=A)
    ↑                                            │
    │              [response complete]            │
    ←────────────────────────────────────────────←

  READY(story=A) ──[C-c C-c on story B]──→ READY(story=B) → BUSY(story=B)
                   (not busy, just switch)

  BUSY(story=A) ──[C-c C-c on story A]──→ QUEUED, stay BUSY(story=A)

  BUSY(story=A) ──[C-c C-c on story B]──→ WARN dialog
                                              │
                                    [wait]    [queue]    [interrupt]
                                      │         │            │
                                      ↓         ↓            ↓
                                    (noop)  QUEUED(B)   BUSY(story=B)

  READY(story=A) ──[direct cmux input]──→ BUSY(story=A)
                   (ACTIVE_STORY tells Claude Code which story)
#+end_example


* SDD Bridge Adaptation

The SDD bridge (~claude-org-sdd-bridge.org~ + ~sdd_bridge.py~) needs
these changes:

** Python side (~sdd_bridge.py~)

~SDD_SESSION_ID~ env var remains — it identifies the workspace (not story).
Story identification comes from ~ACTIVE_STORY~ read via ~evalElisp~.

| Function | Current Behavior | New Behavior |
|----------+------------------+--------------|
| ~handle_prompt~ | Navigates by session_id to ~Workflow :sdd:~ | Read ~ACTIVE_STORY~ via evalElisp, insert into story's Workflow subsection |
| ~handle_response~ | Navigates by session_id + CUSTOM_ID file | Read ~ACTIVE_STORY~ via evalElisp, insert into story's Workflow subsection |
| ~fetch_session_metadata~ | Gets heading from ~goto-session~ | Gets workspace heading + ~ACTIVE_STORY~ for story name |

** Elisp side (~claude-org-sdd-bridge.org~)

| Function | Current Behavior | New Behavior |
|----------+------------------+--------------|
| ~--goto-session~ | Searches for ~:CLAUDE_SESSION_ID:~ | Same — finds workspace heading ✓ |
| ~--find-workflow~ | Looks for ~Workflow :sdd:~ tag | Find ~Workflow~ subsection under ~ACTIVE_STORY~ heading (no tag needed) |
| ~insert-prompt~ | Inserts into ~Workflow :sdd:~ | Insert ai block at end of active story's Workflow subsection |
| ~insert-response~ | Navigates by CUSTOM_ID | Insert response at end of active story's Workflow subsection |
| ~system-prompt~ | Collects tag-based prompt fragments | Remove — no tag-based prompts in new design |
| ~list-sessions~ | Returns per-story entries | Returns per-workspace entries — acceptable |

* Capture Strategy

| What | How | Where |
|------+-----+-------|
| Interactive work | Org file (prompts + responses) | Per story under workspace heading |
| Live output | Verbose buffer (cmux capture-pane) | Transient (existing) |
| Git history | Git commits | ~git log~ |
| Architecture | Human-written design docs | ~docs/design-docs/~ |

No separate journal file. Verbose buffer provides live output.
Git log is the authoritative history.

* Design Principles

1. *Default to liveness* (Bret Victor): interactive mode is always one
   ~C-c C-c~ away. Never require ceremony to start working.

2. *Preserve thinking time* (Rich Hickey): the system waits between
   tasks. No auto-queue. The pause IS the hammock time.

3. *Flow = verify, not write*: the developer's skill is evaluation speed.
   AI blocks and responses in the same buffer — no window switching.

4. *The harness, not the agent, enforces safety*: test gates and role
   separation are mechanical — not prompt-based. Linters > documentation.

* What Changes from Current SDD

| Current SDD | New Design | Rationale |
|-------------+------------+-----------|
| Per-story Claude Code session | Per-workspace (stories share) | Matches actual usage |
| Story creation ceremony | Just create an org heading | Zero friction |
| ~CLAUDE_SESSION_ID~ per story | ~CLAUDE_SESSION_ID~ on workspace heading | One session shared, ~--resume~ works |
| Backend properties per story | ~CMUX_WORKSPACE~ on workspace only | One property, inherited |
| Per-story system prompt (tag-based) | Removed — not needed | Simplifies design |
| ~SDD_SESSION_ID~ env var for story routing | ~ACTIVE_STORY~ org property via evalElisp | Single source of truth |
| Per-session ~:busy~ tracking | Per-workspace ~:busy~ | Workspace-level busy flag |
| ~:marker~ per session for insert-point | Same — per-session ~:marker~ | One active story at a time, no collision |
| ~remhash~ workspace maps on query complete | Persist workspace maps across queries | Enables workspace reuse |
| ~Workflow :sdd:~ subsection (tag-based) | ~Workflow~ subsection (heading match, no tag) | Same structure, simpler lookup |
| ~{session_id}.custom-id~ status file | Unchanged | One active story at a time, no collision |
| Query Manager | Modeline indicator + notification | Simpler, less overhead |
| Story = session = workspace | Story = org section under workspace | Decoupled |

* What We Keep

- *Stories* — as lightweight org subsections (structure without ceremony)
- Emacs as control plane (MCP server, evalElisp)
- ~#+begin_src ai~ blocks (simplified — no mandatory properties on stories)
- cmux workspaces + socket API + workspace colors
- Org-mode as primary interface and capture
- Phoenix/OTel tracing (observability)
- Pre-commit test gate (656+ tests)
- Cross-workspace communication (~cmux send~)
- ~org-archive-subtree~ for completed story lifecycle
- SDD bridge (adapted for workspace-level routing)
- Session key derivation from ~CLAUDE_SESSION_ID~ with inheritance
- ~goto-session-heading~ navigation (finds workspace heading)
- ~:busy~ tracking per session-key
- Verbose buffer per session-key
- Queue mechanism (+ cross-story collision warning)

* Open Issues

1. *Context quality over time*: does ~--resume~ maintain quality after 2+
   hours? Test empirically. If not, add org-based session summary at
   compaction boundaries.

2. *Cross-workspace reliability*: ~cmux send~ + ~capture-pane~ polling
   works but is fragile. Future: add ~cmux~ event subscription if
   upstream supports it.

3. *Story confusion in shared context*: when switching stories, the
   previous story's context remains in Claude Code's memory. May need
   explicit "context switch" notification to Claude Code.
