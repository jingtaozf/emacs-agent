#+DATE: 2026-03-15
#+STATUS: shipped (template form only, per v3 design)

* Reality check (2026-04-27)
The "templates not custom code" path shipped — yasnippet templates such as
`ai-exit-worktree-keep` (under `snippets/org-mode/`) handle worktree
operations through Claude Code itself rather than through a bespoke Elisp
lifecycle.  That matches the v3 scoping decision in this doc.

* Goals

- Each SDD story can optionally run in its own git worktree
- User instructs Claude Code directly — no automated worktree lifecycle
- Enhance =claude-org-templates.el= with reusable instruction snippets
  for worktree operations and design doc references
- Remove boilerplate from system prompt; make it insertable on demand

* Non-Goals

- Automated worktree lifecycle managed by Emacs
- Emacs-side worktree tracking properties (=WORKTREE_BRANCH=, etc.)
- Custom merge commands in the transient menu
- Modifying =claude-org-insert-sdd= or the system prompt template
- Any new Elisp modules or functions

* Background

** Current State

The SDD system prompt section currently includes hardcoded boilerplate
for docs file paths and shorthand references:

#+begin_example
The current SDD story is "unified tracing"

Docs files for this story:
- *Research*: =docs/research/2026-unified-tracing.org=
- *Design Doc*: =docs/design-docs/2026-unified-tracing.org=
...

*Shorthand references* — when I say:
| I say | I mean | Section inside |
...
#+end_example

This boilerplate is inserted by =claude-org-insert-sdd= into every
story's system prompt section. It's useful as context but takes up
space and the user may want to insert it on demand rather than always.

** Claude Code Native Worktree Tools

Claude Code has built-in =EnterWorktree= / =ExitWorktree= tools.
The user can invoke them directly by saying "enter a worktree" — no
Emacs-side code needed. See Background section of v2 for full tool
documentation.

** Templates System

=claude-org-templates.el= is a data file containing an alist of
=(NAME . VALUE)= pairs. Templates are inserted into AI blocks via the
transient menu. The file is reloaded on every invocation, so edits
take effect immediately.

Current templates:

| Name | Content |
|------+---------|
| Analyze Backtrace | (function — collects backtrace) |
| Code Review | "run code simplifier and code review..." |
| Explain Code | Multi-line explanation prompt |
| Fix Error | Error template with placeholders |
| continue | "Please continue the previous instruction..." |
| Git Commit and Push | Commit with pre-commit hook handling |

* Technical Design

** Approach: Templates Only

No new Elisp code. Just add entries to =claude-org-templates.el=:

*** Worktree Templates

| Template Name | Content |
|---------------+---------|
| Enter Worktree | Instruction to enter a named worktree |
| Exit Worktree (keep) | Instruction to exit and keep for manual merge |
| Exit Worktree (remove) | Instruction to exit and discard |
| Merge Worktree | Instruction to squash-merge a branch |

*** Design Doc Templates

| Template Name | Content |
|---------------+---------|
| Refer to Design Doc | Insert shorthand reference table for current story's docs |
| Research Phase | "Please research X and write findings to the research file" |
| Design Phase | "Please write a design doc with goals, non-goals, technical design" |

** Template Definitions

#+begin_src elisp
;; Worktree templates
("Enter Worktree" . "Please enter a worktree for this story.
All code changes should happen in the worktree.
")

("Exit Worktree (keep)" . "Please exit the worktree and keep it.
I'll review and merge manually.
")

("Exit Worktree (remove)" . "Please exit the worktree and remove it — discard all changes.
")

("Merge Worktree" . "Please merge the worktree branch into master:
1. Exit the worktree if still inside
2. git checkout master
3. git merge --squash <branch-name>
4. Run make check
5. If tests pass, commit with a descriptive message
6. Clean up: git worktree remove .claude/worktrees/<name> && git branch -d <branch>
")
#+end_src

* Rejected Alternatives

** v1: Manual =git worktree add= from Emacs

Rejected: reimplements functionality Claude Code already provides.

** v2: System prompt guidance + Emacs tracking

Rejected: over-engineered. The user can instruct Claude Code directly.
No need for =WORKTREE_BRANCH= properties, merge commands, or
=WorktreeCreate= hooks. Templates are sufficient.

** Hardcoded docs boilerplate in system prompt

The current SDD system prompt always includes the docs file path table.
This is useful but static. A template lets the user insert it when
needed, keeping the system prompt lean.
