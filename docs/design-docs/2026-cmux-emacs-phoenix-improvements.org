* Summary

This design doc synthesizes a debate between Claude Code and GPT-5.3-Codex
about the highest-impact improvements to the cmux-Emacs-Phoenix harness.
The debate surfaced a key tension: *meta-optimization vs execution reliability*.

Claude Code proposed intelligent self-improvement loops (trace-driven prompt
optimization, cross-agent memory, feature pipeline state machines). Codex
countered that these are premature without foundational guardrails — contracts,
evidence-binding, and risk classification should come first.

*Synthesis*: Codex is right about sequencing. Build reliability first,
then intelligence. The final roadmap interleaves both perspectives.

* Architecture Context

Three-layer harness for AI-assisted coding in Emacs:

| Layer | Tool | Purpose |
|-------+------+---------|
| Terminal | cmux | Workspace management, terminal I/O, browser automation |
| Editor | Emacs + org-mode + evalElisp MCP | IDE, session management, system prompt construction |
| Tracing | Phoenix (Arize) | Execution traces, spans, the experience store |

* Agreed Priorities (Both Agents Concur)

** P1: Context Should Be On-Demand, Not Prompt-Stuffed

Claude proposed injecting environment snapshots into the system prompt.
Codex countered: naive prompt stuffing increases noise and token burn.

*Agreed design*: Build context providers with freshness and budgeting.

#+begin_example
Each provider returns: { payload, generated_at, ttl_seconds, token_cost }

Providers:
  - git-state:    branch, modified files, ahead/behind  (ttl: 30s)
  - cmux-topology: workspace tree, active surface       (ttl: 60s)
  - open-buffers:  project buffer list                   (ttl: 30s)
  - failing-tests: last `make check` result              (ttl: 300s)
  - ports:         listening ports (dev servers)          (ttl: 60s)

Assembly rule: strict token budget (e.g., 2000 tokens), rank by relevance
to current query, skip stale providers, always include git-state.
#+end_example

*Why both agree*: The Meta-Harness TerminalBench result proved environment
bootstrapping eliminates 2-4 wasted turns. The disagreement was only about
*how* — static injection vs. on-demand with TTL. On-demand is strictly better.

** P2: Phoenix Must Be Active, Not Passive

Claude proposed trace-driven prompt optimization. Codex proposed failure
taxonomy with remediation playbooks.

*Agreed design*: Both. But failure taxonomy comes first (P2a), then
prompt optimization (P2b) can build on the classified data.

*** P2a: Failure Taxonomy (Codex's proposal — build first)

Define explicit failure classes from Phoenix spans:

| Class | Detection | Remediation |
|-------+-----------+-------------|
| =tool-skip= | Agent made claim without tool call evidence | Force re-execution with tool |
| =stale-context= | Context provider TTL expired during session | Refresh and retry |
| =unsafe-edit= | Edit touched high-risk path without extra checks | Escalate to review |
| =false-completion= | Agent said "done" but postcondition failed | Re-run with contract |
| =session-desync= | CLI session ID mismatch between Emacs and cmux | Auto-recover session |

Parse spans + outcomes nightly (or on-demand). Track recurrence rate.

*** P2b: Trace-Driven Prompt Optimization (Claude's proposal — build second)

Once failure taxonomy exists, use classified outcomes as the reward signal:
- Score each session by failure class counts (not just "user corrected")
- Propose CLAUDE.md edits targeting the most frequent failure class
- A/B test variants

*Why sequencing matters* (Codex's critique): Without proper failure labels,
optimization risks reward-hacking the wrong metric. Fewer user corrections
doesn't mean better outcomes — it might mean the agent got more confident
at being wrong.

* Claude's Proposals (Accepted with Modifications)

** Environment Bootstrap → Freshness-Scoped Context Engine

Upgraded from Claude's original "inject snapshot" to Codex's
"context providers with TTL + budget" design (see P1 above).

*Implementation*: ~2 days. Add =claude-org--context-providers= list,
each returning =(payload . metadata)=. Assemble in
=claude-org--build-system-prompt= under token budget.

** Live Diff in Verbose Buffer → Risk-Gated Diff

Claude proposed showing diffs in verbose buffer. Codex countered:
show diffs AND classify risk level. Gate high-risk edits.

*Agreed design*:
- Show git diff after each file write in verbose buffer (Claude's UX)
- Colorize by risk tier: green (docs/tests), yellow (internal logic),
  red (auth/session/process filters) (Codex's policy)
- Red-tier edits trigger a 3-second "review window" before proceeding

** Cross-Agent Memory → Source-Backed Expiring Memory

Claude proposed shared org properties. Codex warned about "institutionalized
hallucination" without trust/versioning/expiry.

*Agreed design*: Each memory entry has:

#+begin_example
:SHARED_LEARNING_001: Discovered: tests need CLAUDE_SETTING_SOURCES=local
:SHARED_LEARNING_001_SOURCE: Phoenix span abc123, session sdd-20260410
:SHARED_LEARNING_001_EXPIRES: 2026-05-10
#+end_example

Source-backed (cites a span or session), time-bounded (30-day expiry by
default), and auto-pruned. Prevents stale knowledge accumulation.

*Deprioritized for now*: Codex is right that this needs provenance before
scale. Start with manual entries, automate discovery later.

* Codex's Proposals (New Additions)

** Contract-First Execution Gates

*What*: Every agent phase declares pre/postconditions as machine-checkable
contracts, not just prompt instructions.

#+begin_example
Contract for "implement feature":
  PRE:  design doc exists at $PATH
  PRE:  make test-smoke passes (current code compiles)
  POST: make check passes (all tests green)
  POST: git diff --stat shows only expected files
  POST: no TODO regressions in touched modules
#+end_example

*Implementation*: Define contract schemas as org properties or sidecar
JSON. Inject as hard gates in =claude-org-execute= — fail fast with
explicit unmet conditions.

*Priority*: HIGH. This addresses the dominant failure mode: plausible
output without verifiable completion.

** Evidence-Bound Agent Claims

*What*: Any non-trivial claim must cite a concrete artifact.

| Claim Type | Required Evidence |
|------------+-------------------|
| "Tests pass" | =make check= exit code + last line of output |
| "File is correct" | =git diff= snippet or line numbers |
| "Bug is fixed" | Before/after test output |
| "State is X" | =evalElisp= or =cmux read-screen= output |

*Implementation*: This is already partially in our CLAUDE.md Tool-Use
Protocol ("show your evidence"). Strengthen by adding a response validator
in Emacs that flags unsupported assertions in the verbose buffer.

*Note*: Codex and Claude independently converged on this — Claude's
"Tool-Use Protocol" and Codex's "Evidence-Bound Claims" are the same idea
from different angles.

** Risk-Tiered Edit Policy

*What*: Classify edits by risk and enforce progressively stricter controls.

| Tier | Paths | Controls |
|------+-------+----------|
| Low | =docs/=, =tests/=, =README*= | Auto-approve |
| Medium | =claude-org.org= internal functions | Run =make test-smoke= after edit |
| High | Process filters, sentinels, MCP server handlers | =make check= + review gate |

*Implementation*: Add a =claude-org--edit-risk-tier= function that maps
file paths + function names to risk levels. Wire into post-edit hooks.

* Roadmap (10-Day Build Plan)

| Day | Task | Source | Impact |
|-----+------+--------+--------|
| 1-2 | Freshness-scoped context providers with TTL + budget | Both | Fewer wasted turns |
| 3-4 | Failure taxonomy classifier from Phoenix spans | Codex | Active observability |
| 5-6 | Contract-first execution gates (pre/postconditions) | Codex | Reliability jump |
| 7-8 | Risk-tiered edit policy + verbose diff coloring | Both | Safety + UX |
| 9 | Evidence validator for agent claims | Codex | Trust improvement |
| 10 | Trace-driven CLAUDE.md improvement (first iteration) | Claude | Self-improvement |

* What We Deprioritized

| Idea | Why Defer |
|------+-----------|
| Full feature-pipeline state machine | Too heavy before contracts exist |
| Automated cross-agent memory | Needs provenance/expiry design first |
| Feature-pipeline =--resume= | Useful but not before contracts + gates |

* Key Takeaway

#+begin_quote
Build reliability first, then intelligence. Contracts and evidence-binding
are the foundation. Meta-optimization loops (trace-driven improvement,
cross-agent memory) become powerful only when the base execution is
trustworthy. — Synthesis from Claude × Codex debate
#+end_quote
