#+TITLE: Design: Autonomous Mode — TODO-Based Agent Loop with Circuit Breaker
#+DATE: 2026-03-26
#+STATUS: partial (loop primitive shipped; circuit-breaker / TODO-driven flow not yet)
#+DEPENDS: docs/design-docs/2026-living-workspace.org

* Reality check (2026-04-27)
Partial.  The `:loop N :interval S` ai-block header arg lets a single ai
block iterate N times.  The `/loop` skill drives self-paced iteration over a
task file (used in `tests/e2e/E2E_TASKS.org`).  What's NOT yet shipped: the
TODO-with-acceptance-criteria + circuit-breaker model where the agent
auto-decides when to stop; today loops are bounded by N or by user cancel.

* Goal

Enable autonomous agent execution for well-defined tasks. User writes a
TODO with acceptance criteria, agent runs a loop until criteria are met or
a circuit breaker halts execution. Human reviews at the end.

This is Phase 2 of the Living Workspace design — build after Phase 1
(workspace binding, story routing, ACTIVE_STORY) is stable.

* Concept

** User Interface

#+begin_example
  ** TODO Refactor session management
  - [ ] Extract shared code into base module
  - [ ] Update tests
  - [ ] Run make check
#+end_example

~C-c C-c~ on this TODO → system detects checkboxes → launches autonomous
loop → agent works → notification when done → review buffer.

** How It Differs from Interactive Mode

| | Interactive (Mode 1) | Autonomous (Mode 2) |
|---|---|---|
| Trigger | ai block | TODO with checkboxes |
| Agent runs for | seconds | minutes to hours |
| User waits? | Yes (streaming response) | No (do other work) |
| Feedback | Inline response | Review buffer at end |
| Permissions | Normal | Permissive (~acceptEdits~) |

* Agent Loop

** Option A: Claude Code's Built-In Loop (recommended)

Claude Code already runs autonomously — reads files, edits, runs tests,
iterates. Autonomous mode sends the TODO as a prompt with permissive
settings and lets Claude Code handle the loop internally.

Emacs's role:
1. Send TODO text + checkboxes as specification
2. Set ~--permission-mode acceptEdits~ (or similar)
3. Monitor verbose buffer for completion/stall
4. Show review buffer when done

** Option B: Emacs-Driven Loop

Emacs runs the loop:
1. Send TODO as prompt → wait for response
2. Check if checkboxes are satisfied
3. If not → send "continue, these items still unchecked: ..." → repeat
4. Circuit breaker in Emacs

More control but more complex. Option A is simpler.

* Circuit Breaker

Borrowed from distributed systems. Prevents runaway agent loops.

** Three States

- *CLOSED* (normal): agent making progress, let it continue
- *OPEN* (halted): agent stuck, stop loop, notify human
- *HALF-OPEN* (probe): after human feedback, try one more iteration

** Thresholds (configurable, start with Ralph defaults)

| Threshold | Default | Meaning |
|-----------|---------|---------|
| No progress | 3 | Halt after 3 iterations with no file changes |
| Same error | 5 | Halt after 5 iterations with same error |
| Max iterations | 10 | Hard cap on total iterations |
| Token budget | TBD | Max tokens consumed before halt |

** Detection (for Option A)

Monitor verbose buffer output with pattern matching:
- No file edits detected in N captures → no progress
- Same error string repeated N times → same error
- Claude Code exits → completion or crash

* Review Buffer

When autonomous task completes (success or circuit break), Emacs generates
a review buffer:

#+begin_example
  ╔══════════════════════════════════════════╗
  ║  Autonomous Task Review                  ║
  ║  Story: Refactor session management      ║
  ║  Status: Completed (7 iterations)        ║
  ╚══════════════════════════════════════════╝

  ## Changes
  [git diff since task started]

  ## Test Results
  ✓ 650 passed, ✗ 2 failed, ○ 6 skipped

  ## Acceptance Criteria
  - [x] Extract shared code into base module
  - [x] Update tests
  - [ ] Run make check  ← NOT MET

  ## Actions
  [DONE] Accept changes and commit
  [REJECT] Add feedback and re-run
  [DIFF] View full diff in magit
#+end_example

* Mode Detection

How the system knows to use autonomous mode instead of interactive:

#+begin_example
  C-c C-c on:
    ai block without checkboxes → Interactive (Mode 1)
    ai block with checkboxes    → Autonomous (Mode 2)
    TODO heading with checkboxes → Autonomous (Mode 2)
    TODO heading without checkboxes → Interactive (Mode 1)
#+end_example

* Open Questions

1. Should autonomous mode use a fresh Claude Code session (Ralph pattern)
   or reuse the workspace's existing session? Fresh avoids context
   pollution but loses workspace context.

2. How to extract structured data (test results, changed files) from
   Claude Code's output for the review buffer?

3. Should the circuit breaker be in Emacs (monitoring verbose buffer)
   or delegated to Claude Code hooks?

4. How to handle partial success — some checkboxes met, some not?
   Re-run with only the remaining checkboxes?

5. Cost control: should there be a token/dollar budget cap?
