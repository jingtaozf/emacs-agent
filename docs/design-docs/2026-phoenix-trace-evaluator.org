#+TITLE: Design: Phoenix Traces as Automatic Evaluator
#+DATE: 2026-03-27
#+STATUS: partial (Phoenix infra shipped; auto-evaluator agent not built)

* Reality check (2026-04-27)
Partial.  Phoenix infra is operational (see `2026-unified-tracing.org`
shipped) — every AI block produces a root span with rich child spans.
Manual evaluation via the GraphQL API or Phoenix UI works (see
`.claude/rules/e2e-trace-verification.md`).  What's NOT yet built: the
*automatic* evaluator agent that ingests traces and scores quality.

* Motivation

From Anthropic's "Harness Design for Long-Running Application Development":
- "Separation of concerns drives performance" -- dedicated evaluators outperform self-evaluation
- "Tool access matters" -- evaluators should actively test using the real system

We have 30+ OTel spans across Emacs, cmux, and Python. They're exported to
Phoenix but never programmatically verified. A trace-based evaluator can:
1. Assert span trees match expectations after each E2E test
2. Scan for anomalies (errors, orphan spans, excessive latency) automatically
3. Catch regressions invisible to unit tests (cross-process correlation failures)

* Design

** Trace Assertion Library

=tests/e2e/trace-assertions.el= -- reusable functions for querying Phoenix
GraphQL and asserting span structure.

*** Core Functions

| Function | Purpose |
|----------|---------|
| =trace-assert--query-phoenix (graphql)= | Execute GraphQL query, return parsed JSON |
| =trace-assert--recent-spans (n)= | Get last N spans from =emacs-agent= project |
| =trace-assert--spans-by-session (session-id n)= | Filter spans by session-id attribute |
| =trace-assert--find-span (spans name)= | Find span by name in list |
| =trace-assert--assert-parent-child (spans parent child)= | Verify parent-child relationship |
| =trace-assert--assert-no-errors (spans)= | No span has ERROR status |
| =trace-assert--assert-latency-within (span max-ms)= | Latency within bounds |
| =trace-assert--assert-span-exists (spans name)= | Named span exists |
| =trace-assert--assert-span-tree (spans tree-spec)= | Full tree matches declarative spec |

*** Declarative Tree Spec Format

#+begin_example
'(("execute-ai-block" :kind "SERVER"
   :children (("cmux-ensure-session" :kind "INTERNAL")
              ("cmux-execute" :kind "INTERNAL"
               :children (("cmux-send-text" :kind "INTERNAL"))))))
#+end_example

** Per-Test Trace Verification

Each E2E test in =living-workspace-test.org= gains an optional =*** Trace
Assertions= subsection with evalElisp commands that query Phoenix after the
behavioral test passes.

Example for T2 (Execute ai block):

#+begin_example
*** Trace Assertions

| Span Name | Parent | Status |
|-----------|--------|--------|
| execute-ai-block | (root) | OK |
| cmux-ensure-session | execute-ai-block | OK |
| cmux-send-text | execute-ai-block | OK |

evalElisp:
(sleep-for 5) ;; wait for Phoenix ingestion
(let ((spans (trace-assert--spans-by-session "sdd-e2e-test-005" 20)))
  (trace-assert--assert-no-errors spans)
  (trace-assert--assert-parent-child spans "execute-ai-block" "cmux-send-text")
  "trace-ok")
#+end_example

** Standalone Health Check

=make test-trace-health= target that:
1. Queries last 50 traces from Phoenix
2. Checks for: ERROR spans, orphan roots (no children), orphan children
   (parentId not in trace), latency > 60s
3. Outputs summary table
4. Exits nonzero if anomalies found

** Timing Considerations

Phoenix ingestion is async. =SimpleSpanProcessor= exports on span.end() (no
batching), but Phoenix indexing takes time. Existing tests use =(sleep-for 3)=
successfully. We use 5 seconds for safety.

* Risks

- *Phoenix API changes*: Pin version; wrap all queries in one function
- *Timing flakiness*: 5s sleep + retry-once
- *Span naming coupling*: Names map 1:1 to functions, rarely change
