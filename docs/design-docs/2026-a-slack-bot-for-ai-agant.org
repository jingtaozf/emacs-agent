* Goals

Build a Slack bot that bridges an AI agent (Claude) with Slack, enabling:

1. *Real-time awareness*: Detect new messages in configured Slack channels
2. *Intelligent triage*: AI reads messages and decides whether/how to respond
3. *Two response modes*:
   - *Draft & Confirm*: Prepare response, present to human for approval before sending
   - *Auto-Reply*: Send directly with AI attribution and confidence indicator
4. *Seamless integration*: Works with existing Slack skill/reader infrastructure

* Non-Goals

- Replacing Slack AI (the native product)
- Multi-workspace or Marketplace distribution
- Processing file uploads or media
- Training on Slack data
- Building a general-purpose chatbot -- this is a /targeted assistant/

* Technical Design

** Core Stack

| Component | Technology | Rationale |
|-----------+-----------+-----------|
| Slack framework | slack-bolt (Python) | Official SDK, Socket Mode support, async |
| Connection mode | Socket Mode | No public URL, no tunneling, firewall-friendly |
| AI backend | Anthropic API (Claude) | Direct API for speed; Claude Code SDK for tool use |
| Config | YAML + env vars | Channel allowlists, mode settings, tokens |
| State | SQLite | Audit log, pending drafts, conversation context |

** Component Design

*** Event Listener

Uses Slack Bolt with Socket Mode. Subscribes to:
- =app_mention= -- when someone @mentions the bot
- =message.im= -- direct messages to the bot
- =message.channels= / =message.groups= -- for detecting @mentions in channels

#+begin_src python
from slack_bolt import App
from slack_bolt.adapter.socket_mode import SocketModeHandler

app = App(token=os.environ["SLACK_BOT_TOKEN"])

@app.event("app_mention")
def handle_mention(event, say, client):
    """Triggered when bot is @mentioned."""
    router.process(event, say, client, trigger="mention")

@app.event("message")
def handle_message(event, say, client):
    """Triggered for all messages in joined channels."""
    if should_process(event):
        router.process(event, say, client, trigger="passive")

handler = SocketModeHandler(app, os.environ["SLACK_APP_TOKEN"])
handler.start()

*** Message Router

Decides what to do with each incoming message:

#+begin_src python
class MessageRouter:
    def __init__(self, config: ChannelConfig):
        self.config = config

    def process(self, event, say, client, trigger):
        channel = event["channel"]
        channel_cfg = self.config.get(channel)

        # Skip bot's own messages (prevent loops)
        if event.get("bot_id"):
            return

        # Skip if channel not in allowlist
        if not channel_cfg:
            return

        # Determine response mode
        mode = channel_cfg.mode  # "draft" or "auto"
        if trigger == "mention":
            mode = channel_cfg.mention_mode or mode

        # Build context (thread history, user info)
        context = self.build_context(event, client)

        # Get AI response
        response = ai_engine.generate(context)

        # Dispatch based on mode
        if mode == "draft":
            draft_dispatcher.send_for_approval(event, response, client)
        elif mode == "auto":
            auto_dispatcher.send_reply(event, response, say)
#+end_src

*** Draft & Confirm Mode (Mode 1)

The bot prepares a response but sends it to the *operator* (you) for approval
before posting to Slack.

Flow:
1. AI generates response
2. Bot sends response as an *ephemeral message* or *DM to operator* with:
   - Original message context
   - Proposed reply
   - [Approve] [Edit] [Reject] buttons
3. On Approve: bot posts the reply to the original channel/thread
4. On Edit: operator modifies text, then bot posts modified version
5. On Reject: nothing is posted, logs rejection reason
6. After 24 hours with no action: draft is auto-rejected with log entry

#+begin_src python
class DraftDispatcher:
    def send_for_approval(self, event, response, client):
        blocks = [
            {"type": "section", "text": {
                "type": "mrkdwn",
                "text": f"*From* <@{event['user']}> in <#{event['channel']}>:\n>{event['text']}"
            }},
            {"type": "divider"},
            {"type": "section", "text": {
                "type": "mrkdwn",
                "text": f"*Proposed reply* (confidence: {response.confidence}):\n{response.text}"
            }},
            {"type": "actions", "elements": [
                {"type": "button", "text": {"type": "plain_text", "text": "Approve"},
                 "style": "primary", "action_id": "approve_reply",
                 "value": json.dumps({"channel": event["channel"],
                                       "thread_ts": event.get("ts"),
                                       "text": response.text})},
                {"type": "button", "text": {"type": "plain_text", "text": "Edit"},
                 "action_id": "edit_reply"},
                {"type": "button", "text": {"type": "plain_text", "text": "Reject"},
                 "style": "danger", "action_id": "reject_reply"},
            ]}
        ]
        # Send to operator's DM
        client.chat_postMessage(
            channel=self.operator_dm_channel,
            blocks=blocks,
            text=f"AI draft reply for review"
        )
#+end_src

*** Auto-Reply Mode (Mode 2)

The bot replies directly, clearly marking the response as AI-generated
with a confidence indicator.

#+begin_src python
class AutoDispatcher:
    def send_reply(self, event, response, say):
        confidence_emoji = {
            "high": "🟢", "medium": "🟡", "low": "🔴"
        }[response.confidence_level]

        blocks = [
            {"type": "section", "text": {
                "type": "mrkdwn",
                "text": response.text
            }},
            {"type": "context", "elements": [
                {"type": "mrkdwn",
                 "text": f"{confidence_emoji} AI-generated response (confidence: {response.confidence_level}) "
                          f"| Not sent by a human. Verify before acting."},
            ]},
            # Feedback buttons (Slack Oct 2025 feature)
            {"type": "actions", "elements": [
                {"type": "button", "text": {"type": "plain_text", "text": "👍"},
                 "action_id": "feedback_good"},
                {"type": "button", "text": {"type": "plain_text", "text": "👎"},
                 "action_id": "feedback_bad"},
            ]}
        ]

        say(
            blocks=blocks,
            text=f"[AI] {response.text}",  # fallback for notifications
            thread_ts=event.get("thread_ts", event["ts"]),  # reply in thread
        )
#+end_src

*** AI Engine

Wraps Claude API to generate responses with confidence scoring:

#+begin_src python
import anthropic

class AIEngine:
    def __init__(self):
        self.client = anthropic.Anthropic()

    def generate(self, context: MessageContext) -> AIResponse:
        system_prompt = self._build_system_prompt(context)
        messages = self._build_messages(context)

        response = self.client.messages.create(
            model="claude-sonnet-4-20250514",
            max_tokens=1024,
            system=system_prompt,
            messages=messages,
        )

        text = response.content[0].text
        confidence = self._extract_confidence(text)

        return AIResponse(
            text=self._strip_confidence_tag(text),
            confidence=confidence.score,
            confidence_level=confidence.level,  # high/medium/low
        )

    def _build_system_prompt(self, context):
        return """You are an AI assistant responding in a Slack workspace.
Rules:
- Be concise and helpful
- If you're unsure, say so clearly
- Never fabricate information
- Prefix your response with a confidence tag: [CONF:high], [CONF:medium], or [CONF:low]
- Use [CONF:low] when: speculating, topic is outside your knowledge, ambiguous question
- Use [CONF:medium] when: reasonable answer but not 100% certain
- Use [CONF:high] when: factual, well-established information, clear question

Context: Channel #{channel}, User: {user_name}
Recent messages in thread: {thread_context}"""
#+end_src

** Confidence-Gated Escalation

A key safety feature: even in auto-reply mode, low-confidence responses
automatically escalate to draft mode.

#+begin_src python
def dispatch(self, event, response, mode, channel_cfg):
    # Safety: escalate low-confidence auto-replies to draft
    if mode == "auto" and response.confidence_level == "low":
        mode = "draft"

    # Safety: respect per-channel confidence threshold
    threshold = channel_cfg.get("confidence_threshold", "low")
    if mode == "auto" and not meets_threshold(response.confidence_level, threshold):
        mode = "draft"

    if mode == "draft":
        self.draft_dispatcher.send_for_approval(event, response)
    else:
        self.auto_dispatcher.send_reply(event, response)
#+end_src

** Message Edit Handling

When a user edits a message that the bot previously responded to, the bot
re-evaluates the edited content and updates its response accordingly.

#+begin_src python
@app.event("message")
def handle_message(event, say, client):
    subtype = event.get("subtype")

    if subtype == "message_changed":
        edited_msg = event.get("message", {})
        original_ts = edited_msg.get("ts")
        # Check if bot previously responded to this message
        previous_response = db.get_bot_response_for(original_ts)
        if previous_response:
            context = router.build_context_for_edit(edited_msg, client)
            new_response = ai_engine.generate(context)
            if channel_mode == "draft":
                draft_dispatcher.send_for_approval(
                    edited_msg, new_response, client,
                    note="Re-evaluated after message edit")
            else:
                # Update the existing bot reply
                client.chat_update(
                    channel=event["channel"],
                    ts=previous_response.ts,
                    blocks=auto_dispatcher.build_blocks(new_response),
                    text=f"[AI] {new_response.text}",
                )
        return

    if should_process(event):
        router.process(event, say, client, trigger="passive")
#+end_src

** Preventing Bot Loops

Critical safety measure -- the bot must never respond to itself or other bots:

#+begin_src python
def should_process(event):
    # Skip bot messages
    if event.get("bot_id") or event.get("subtype") == "bot_message":
        return False
    # Handle message edits -- re-evaluate the edited message
    if event.get("subtype") == "message_changed":
        return True  # process edits to update bot's response
    # Skip empty messages
    if not event.get("text", "").strip():
        return False
    return True
#+end_src

* Integration with Existing Infrastructure

The existing =scripts/slack_reader.py= and =skills/slack/SKILL.md= provide
read-only Slack access. This design *extends* rather than replaces them:

| Existing | New Bot | Relationship |
|----------+---------+-------------|
| =slack_reader.py= | =slack_bot_daemon.py= | Bot imports reader's utility functions |
| =SKILL.md= (read skill) | New write skill | Complementary -- read + write |
| User token (=xoxp-=) | Bot token (=xoxb-=) | Separate tokens, separate purposes |
| On-demand reads | Real-time events | Different lifecycle |

The bot daemon runs as a *separate long-lived process*, not inside Claude Code.
Claude Code interacts with it through:
1. Direct Anthropic API calls (bot has its own Claude connection)
2. MCP tools for manual Slack operations (existing + new write tools)

* Alternatives Considered

** Alternative 1: MCP-Only Approach (korotovsky/slack-mcp-server)

Use an existing Slack MCP server to give Claude Code direct Slack read/write access.

/Rejected because/: MCP is pull-only. Claude Code cannot receive push notifications
of new messages. Would require constant polling, which is wasteful and slow.

** Alternative 2: Claude Code SDK Wrapper (mpociot pattern)

Run Claude Code as a subprocess for each Slack message.

/Rejected because/: Heavy per-message overhead. Claude Code startup is slow.
Better suited for complex multi-tool tasks, not quick Slack replies.

** Alternative 3: Blocking MCP Tool (claude-slack-bridge)

MCP tool that blocks until a Slack message arrives.

/Rejected because/: Ties up a Claude Code session waiting for messages.
Only practical for mid-task human-in-the-loop, not general monitoring.

* Chosen approach: Standalone Daemon + Claude API

A lightweight Python daemon that:
- Listens to Slack events via Socket Mode (always-on, efficient)
- Calls Claude API directly for fast responses
- Implements both response modes independently
- Can be extended later to invoke Claude Code SDK for complex tasks

This approach is *simple, efficient, and independent of Claude Code's lifecycle*.

* Decisions (Resolved)

1. *Trigger model*: @mentions and DMs only (not all channel messages).
   Bot responds when explicitly addressed or messaged directly.

2. *Draft approval timeout*: Drafts persist indefinitely (no auto-expiry).
   If operator doesn't approve within 24 hours, draft is auto-rejected
   with a log entry. This preserves the core value of draft mode --
   nothing goes out without explicit approval.

3. *Message edits*: Always handled. When a user edits a message that the
   bot previously responded to, the bot re-evaluates and updates its
   response (or creates a new draft for approval).

4. *Slash commands*: Nice-to-have for future. Focus on core @mention/DM
   functionality first. Moved to Phase 3.
