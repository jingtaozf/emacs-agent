#+TITLE: Design: Terminal SDD Bridge
#+DATE: [2026-03-06]
#+STATUS: draft

* Goals

Run SDD stories from a normal terminal via =claude= CLI, while automatically
syncing each prompt/response pair back into the corresponding Emacs org-mode
SDD section as =#+begin_src ai= / =Response= sections.

- Developers who prefer terminal workflow get full SDD structure for free
- Org notebook becomes the persistent record of all AI interactions
- Emacs MCP server provides the bridge — no custom API needed

* Non-Goals

- Replacing the Emacs-native =C-c C-c= SDD workflow (this is complementary)
- Building a general-purpose conversation logger (scoped to SDD only)
- Full real-time streaming into org buffers (batch insert per turn for text;
  PostToolUse hook provides real-time todo checkbox updates only)

* Technical Design

** 1. Launcher Script: =claude-sdd=

A shell script (or Makefile target) that assembles the =claude= CLI invocation:

#+begin_src bash
#!/usr/bin/env bash
# Usage: claude-sdd <org-file> <session-id>
#
# org-file:    path to the org notebook containing the SDD section
# session-id:  CLAUDE_SESSION_ID from the org SDD section

ORG_FILE="${1:?Usage: claude-sdd <org-file> <session-id>}"
SESSION_ID="${2:?Usage: claude-sdd <org-file> <session-id>}"
PLUGIN_DIR="$(cd "$(dirname "$0")/.." && pwd)"
EMACS_MCP_URL="${EMACS_MCP_URL:-http://localhost:9999/mcp}"

# Resolve to absolute path
ORG_FILE="$(cd "$(dirname "$ORG_FILE")" && pwd)/$(basename "$ORG_FILE")"

# Build system prompt by asking Emacs for it
SYSTEM_PROMPT=$(curl -s "$EMACS_MCP_URL" \
  -H 'Content-Type: application/json' \
  -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",
       \"params\":{\"name\":\"evalElisp\",
                   \"arguments\":{\"code\":\"(claude-org-sdd-bridge-system-prompt \\\"$ORG_FILE\\\" \\\"$SESSION_ID\\\")\"}}}" \
  | jq -r '.result.content[0].text')

# Export for hook scripts
export SDD_ORG_FILE="$ORG_FILE"
export SDD_SESSION_ID="$SESSION_ID"
export EMACS_MCP_URL

exec claude \
  --plugin-dir "$PLUGIN_DIR" \
  --mcp-config "{\"mcpServers\":{\"emacs\":{\"type\":\"http\",\"url\":\"$EMACS_MCP_URL\"}}}" \
  --system-prompt "$SYSTEM_PROMPT"
#+end_src

Key decisions:
- Both org file path and session ID are required arguments — no ambiguity
- Org file is resolved to absolute path for reliable cross-process usage
- Both are exported as env vars so hook scripts inherit them automatically
- System prompt is fetched from Emacs (reuses existing prompt-building logic)

** 2. Hooks: Capture Prompts and Responses

*** UserPromptSubmit Hook

Fires when the user submits a prompt. Receives JSON on stdin with:
- =prompt=: the user's text
- =session_id=: Claude CLI session ID
- =transcript_path=: path to transcript file

Action: Call Emacs MCP to insert an AI block with the prompt text.

*** Stop Hook

Fires after Claude finishes responding. Receives JSON on stdin with:
- =session_id=: Claude CLI session ID
- =transcript_path=: path to transcript file (contains full conversation)

Action: Read the latest assistant message from the transcript, call Emacs MCP
to insert a Response section with the text.

*** hooks.json

** 3. Bridge Script: =scripts/sdd-bridge.sh=

Single script handling both events, dispatched by first argument:

#+begin_src bash
#!/usr/bin/env bash
# sdd-bridge.sh - Bridge between Claude CLI hooks and Emacs org SDD
#
# Called by hooks with event type as $1, JSON on stdin

EVENT="$1"
INPUT=$(cat)  # Read hook JSON from stdin

EMACS_MCP_URL="${EMACS_MCP_URL:?EMACS_MCP_URL must be set}"
SDD_SESSION_ID="${SDD_SESSION_ID:?SDD_SESSION_ID must be set}"
SDD_ORG_FILE="${SDD_ORG_FILE:?SDD_ORG_FILE must be set}"

call_emacs() {
  local elisp="$1"
  curl -s "$EMACS_MCP_URL" \
    -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",
         \"params\":{\"name\":\"evalElisp\",
                     \"arguments\":{\"code\":$(echo "$elisp" | jq -Rs .)}}}"
}

case "$EVENT" in
  prompt)
    # Extract user prompt from hook input
    PROMPT=$(echo "$INPUT" | jq -r '.prompt // empty')
    [ -z "$PROMPT" ] && exit 0

    # Insert AI block into org SDD section
    call_emacs "(claude-org-sdd-bridge-insert-prompt \"$SDD_ORG_FILE\" \"$SDD_SESSION_ID\" $(echo "$PROMPT" | jq -Rs .))"
    ;;

  response)
    # Extract latest assistant response from transcript
    TRANSCRIPT_PATH=$(echo "$INPUT" | jq -r '.transcript_path // empty')
    [ -z "$TRANSCRIPT_PATH" ] && exit 0

    # Get the last assistant message from transcript
    RESPONSE=$(tac "$TRANSCRIPT_PATH" \
      | jq -r 'select(.message.role == "assistant") | .message.content[] | select(.type == "text") | .text' \
      | head -1)
    [ -z "$RESPONSE" ] && exit 0

    # Insert Response section into org SDD section
    call_emacs "(claude-org-sdd-bridge-insert-response \"$SDD_ORG_FILE\" \"$SDD_SESSION_ID\" $(echo "$RESPONSE" | jq -Rs .))"
    ;;
esac
#+end_src

Environment variables exported by the launcher (inherited by hooks):
- =SDD_ORG_FILE=: absolute path to the org notebook (required)
- =SDD_SESSION_ID=: identifies which org SDD section to target (required)
- =EMACS_MCP_URL=: MCP server endpoint (required)

    (claude-org-sdd-bridge--goto-session (current-buffer) session-id)
    ;; 1. Find the last AI block (most recent Instruction)

    ;; 4. Insert response text

All bridge functions take =org-file= as the first argument — no ambiguity about
which buffer to use. The file is opened via =find-file-noselect= if not already
visiting, so the user doesn't need to have the file open beforehand.

** 5. Turn Counter and State

Turn numbering is Emacs-side: count existing Instruction/Response headings in
the Workflow section. No external state files needed — Emacs already has the org
tree and counting headings is trivial.

** 6. Transcript Parsing for Response Extraction

The =Stop= hook reads the transcript file (newline-delimited JSON). To extract
the latest assistant response:

1. Read from end of file (=tac=) to find last assistant message
2. Extract text content blocks (skip tool_use/tool_result blocks)
3. Concatenate text blocks if multiple exist
4. Pass to Emacs for insertion

For tool-heavy responses, we may want to include a summary of tool calls.
Initial version: text-only extraction. Enhance later if needed.

** Entry Type Taxonomy

Seven distinct =type= values in JSONL transcripts:

| Type | Description | Key fields |
|------+----------------------------------------------------+-------------------------------------------------------|
| =user= | Human message or tool_result | =message=, =isMeta=, =isCompactSummary=, =toolUseResult= |
| =assistant= | Model response (text, tool_use, or thinking) | =message=, =requestId=, =slug= |
| =progress= | Hook execution progress | =data= (has =type=: =hook_progress=), =toolUseID= |
| =queue-operation= | Internal message queue state | =operation= (enqueue/dequeue/remove/popAll) |
| =system= | Session events | =subtype=: =compact_boundary=, =stop_hook_summary=, =turn_duration=, =local_command= |
| =file-history-snapshot= | File state for undo/redo | =snapshot=, =messageId= |
| =last-prompt= | Most recent user prompt | =lastPrompt= string |

** Content Block Types

Inside =message.content= lists:

| Block type | Parent | Key fields |
|---+---+---|
| =text= | =assistant= | =text= |
| =tool_use= | =assistant= | =id=, =name=, =input=, =caller= |
| =thinking= | =assistant= | =thinking=, =signature= |
| =tool_result= | =user= | =tool_use_id=, =is_error=, =content= |
| =tool_reference= | =tool_result= content | =tool_name= |

** Critical Finding: Multi-block Responses

A single API request (one =requestId=) generates **multiple JSONL lines**.
Each content block (text, tool_use) is a separate entry linked via =parentUuid=:

#+begin_example
user[uuid=A]                           ← human message
  assistant[uuid=B, parent=A, req=R1]  ← text block
  assistant[uuid=C, parent=B, req=R1]  ← tool_use block (same requestId)
  user[uuid=D, parent=C]               ← tool_result
  assistant[uuid=E, parent=D, req=R2]  ← next turn response
#+end_example

In session =b23db72c=: 1,355 unique requestIds, 871 have multiple entries.
This means naive "find last assistant entry" misses the full picture.

** Session Boundaries

- No terminal/closing entry type — sessions end with the last =assistant= entry
- First entry varies: =queue-operation= (8/10) or =file-history-snapshot= (2/10)
- Context compaction: =system/compact_boundary= followed by =user= with
  =isCompactSummary: "True"= containing a narrative summary

** Implications for SDD Bridge

1. *Response extraction must filter by content block type, not entry type*:
   An assistant entry with =tool_use= is an intermediate turn. Only entries
   with pure =text= blocks (no =tool_use=) contain the final answer.

2. *No =result= entry*: The design doc's transcript fixtures assumed a
   =type: "result"= terminal entry (line 365). Real transcripts don't have
   this. The Stop hook's =last_assistant_message= is computed by the CLI,
   not stored in the transcript.

3. *=system/stop_hook_summary=* entries record hook execution metadata:
   =hookInfos= (command, durationMs), =hookErrors=, =stopReason=.
   Useful for debugging slow hooks but not needed for response extraction.

4. *=progress/hook_progress=* entries fire during PostToolUse hooks.
   These can be used to verify that our hooks are actually running.

5. *TodoWrite tool_input* is available in the =tool_use= content block
   under =input.todos=. The PostToolUse hook receives this as =tool_input=.

* Proposed Improvements

** P1: Smarter transcript extraction (implemented)

Current: =_extract_full_response()= skips assistant entries containing
=tool_use= blocks, keeping only pure-text turns.

Limitation: if the final answer also includes a =tool_use= (rare but possible
with parallel tool calls), its text is lost.

Better approach (future): group entries by =requestId=, collect text blocks
from the LAST request group. This correctly handles multi-block responses
where text and tool_use coexist in one API call.

** P2: Use =system/stop_hook_summary= for diagnostics

The =stop_hook_summary= entry records hook timing. We could parse this
to detect when our hooks are slow (>1s) and log a warning. This would
help diagnose "save-buffer taking too long" issues proactively.

** P3: Leverage =parentUuid= chain for conversation threading

Instead of "find last user entry, collect everything after", we could
walk the =parentUuid= chain backward from the last entry. This gives
the exact conversation thread, handling sidechains (=isSidechain= flag)
correctly. Current approach works because SDD sessions are linear,
but parentUuid threading would be more robust.

** P4: Context compaction awareness

When context compaction fires, the =compact_boundary= + summary =user=
entry resets the conversation context. Our transcript extraction should
recognize this boundary and only extract responses after the last
compaction event, not from the original user prompt which may be stale.

** P5: Hook matcher optimization (implemented)

The PostToolUse hook uses ="matcher": "TodoWrite"= in hooks.json so it
only fires for TodoWrite calls. Without this, the hook fires for every
tool use (~6,900 per session), causing significant overhead. The matcher
reduces this to only the ~10-20 TodoWrite calls per session.

* Design Decisions

1. *Org file always required*: The launcher takes =<org-file> <session-id>= as
   positional arguments. Both are required — no auto-detection needed. The org
   file is resolved to an absolute path and exported to hook scripts via env vars.

2. *Concurrent sessions*: Acceptable for now. Each session targets a distinct
   =CLAUDE_SESSION_ID= section, so insertions go to different positions even in
   the same org file. Emacs buffer operations are serialized by the single-threaded
   event loop, so no corruption risk.

3. *Response filtering*: Text-only, matching the Emacs-native workflow. Tool calls
   (Bash, Read, etc.) are excluded from response sections. Tool call summaries
   can be added later (F7) if valuable for review.

4. *Error handling*: Hooks log a warning to stderr but exit 0 so they don't block
   the terminal session. The =curl= call uses =--connect-timeout 3= and =--max-time 8=
   to fail fast. If Emacs MCP is down, the terminal conversation continues normally
   and the org record is simply incomplete.

5. *System prompt from Emacs*: Fetched via MCP at launch time (DRY). This means
   Emacs must be running with MCP server active before =claude-sdd= is invoked.
   The launcher validates the MCP connection and exits with a clear error if
   Emacs is unreachable — failing fast at startup rather than silently during
   the session.

* E2E Testing

** Strategy

The E2E tests verify the full pipeline without a real Claude CLI process.
Instead, we simulate hook events by piping the same JSON that Claude would
send on stdin to the bridge script, and verify the org buffer via MCP.

Two modes:
1. *Live MCP* — use the already-running Emacs MCP server on port 9999
2. *Test MCP* — start a dedicated server on an auto-selected port via
   =(emacs-mcp-server-start 0)= for isolated testing

The test script is a bash script that orchestrates: create temp org file →
call Emacs to set it up → simulate hook events → verify org buffer state.

# tests/helpers/mcp-call.sh
# Usage: mcp_call <elisp-code>
# Returns: the text content from MCP response
mcp_call() {
  local elisp="$1"
  local port="${EMACS_MCP_PORT:-9999}"
  local url="http://localhost:${port}/mcp"
  curl -sf --connect-timeout 3 --max-time 10 "$url" \
    -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",
         \"params\":{\"name\":\"evalElisp\",
                     \"arguments\":{\"code\":$(echo "$elisp" | jq -Rs .)}}}" \
    | jq -r '.result.content[0].text'
}
#+end_src

*** Helper: Read Org Section Content

#+begin_src bash
# Read the full buffer content to verify structure
read_org_buffer() {
  local org_file="$1"
  mcp_call "(with-current-buffer (find-buffer-visiting \"$org_file\")
    (buffer-substring-no-properties (point-min) (point-max)))"
}

# Count headings matching a pattern
count_headings() {
  local org_file="$1"
  local pattern="$2"
  mcp_call "(with-current-buffer (find-buffer-visiting \"$org_file\")
    (goto-char (point-min))
    (let ((count 0))
      (while (re-search-forward \"$pattern\" nil t)
        (setq count (1+ count)))
      (number-to-string count)))"
}
#+end_src

#+begin_src bash
#!/usr/bin/env bash
# E2E tests for Terminal SDD Bridge
# Requires: running Emacs MCP server, jq, curl
#
# Usage: bash tests/test-sdd-bridge-e2e.sh [port]

set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_DIR="$(cd "$SCRIPT_DIR/.." && pwd)"
cd "$PROJECT_DIR"

EMACS_MCP_PORT="${1:-9999}"
export EMACS_MCP_URL="http://localhost:${EMACS_MCP_PORT}/mcp"

# Source helpers
source tests/helpers/mcp-call.sh

PASS=0
FAIL=0

run_test() {
  local name="$1"
  echo -n "  $name... "
  if "$name" 2>/tmp/test-sdd-stderr.log; then
    echo "PASS"
    ((PASS++))
  else
    echo "FAIL"
    cat /tmp/test-sdd-stderr.log >&2
    ((FAIL++))
  fi
}

# Assertions
assert_contains()  { echo "$1" | grep -qF "$2" || { echo "Expected to contain: $2" >&2; return 1; }; }
assert_not_contains() { ! echo "$1" | grep -qF "$2" || { echo "Expected NOT to contain: $2" >&2; return 1; }; }
assert_equals()    { [ "$1" = "$2" ] || { echo "Expected '$2', got '$1'" >&2; return 1; }; }
assert_not_equals() { [ "$1" != "$2" ] || { echo "Expected not '$2'" >&2; return 1; }; }
assert_not_empty() { [ -n "$1" ] || { echo "Expected non-empty" >&2; return 1; }; }
assert_order() {
  local content="$1"; shift
  local prev_pos=0
  for pattern in "$@"; do
    local pos=$(echo "$content" | grep -n "$pattern" | head -1 | cut -d: -f1)
    [ "$pos" -gt "$prev_pos" ] || { echo "$pattern not after previous" >&2; return 1; }
    prev_pos=$pos
  done
}

# Verify MCP is reachable
echo "Checking MCP server on port $EMACS_MCP_PORT..."
mcp_call "(+ 1 1)" >/dev/null || { echo "FATAL: MCP server unreachable"; exit 1; }

echo "Running E2E tests..."
run_test test_single_prompt
run_test test_single_response
run_test test_multi_turn
run_test test_tool_response_text_only
run_test test_mcp_unreachable
run_test test_empty_prompt_ignored
run_test test_system_prompt_fetch
run_test test_launcher_fails_fast

echo ""
echo "Results: $PASS passed, $FAIL failed"
[ "$FAIL" -eq 0 ]
#+end_src
