#+TITLE: Multi-Agent Support in cmux Backend
#+DATE: 2026-04-01
#+STATUS: shipped

* Reality check (2026-04-27)
Shipped — `code-agent-org-cmux.org` defines an `agent-profile` system with
profiles for Claude Code, OpenCode, Copilot, etc.  Profile selection drives
the launch command, ready/busy patterns, cancel keys, and feature gates.
Now subsumed structurally by the *Tri-Protocol* refactor: agent identity
lives in the agent-family classes (`claude-agent-acp-*`); the cmux backend
sees them through the agent-profile slot.  See
`docs/design-docs/2026-tri-protocol-backend-refactor.org`.

* Overview

The cmux backend currently launches Claude Code automatically when an org
workspace session is created. This design adds support for alternative code
agents — starting with GitHub Copilot CLI — without breaking the existing
Claude Code integration.

| Aspect | Value |
|--------+-------|
| Module | =claude-org-cmux.org=, =python/claude_agent/= |
| New customization | =claude-org-cmux-agent-type= |
| New abstraction | =claude-org-cmux--agent-profile= struct |
| Primary new agent | GitHub Copilot CLI (=copilot=) |
| Backward compatibility | Full — Claude Code users see zero change |
| Effort estimate | ~2 days (elisp profile system + Python launcher) |

* Problem Statement

The cmux backend has five tight coupling points with Claude Code specifically:

| Integration Point | Claude Code Feature Used |
|-------------------+--------------------------|
| Launch command | =claude-workspace= Python script → =claude= CLI |
| CLI flags | =--mcp-config=, =--system-prompt=, =--ide=, =--resume=, =--chrome= |
| Session resume | =CLAUDE_CLI_SESSION= org property → =--resume <id>= |
| Hook events | =SessionStart=, =UserPromptSubmit=, =PreToolUse=, =PostToolUse=, =Stop= |
| Ready detection | Screen text: ="type a message"= / ="-- INSERT --"= |

Supporting GitHub Copilot CLI (or any future agent) requires decoupling
these points into a per-agent *profile* without changing the surrounding
workspace, streaming, mode-line, or verbose infrastructure.

* Gap Analysis: Claude Code vs. GitHub Copilot CLI

** Feature Comparison

| Capability | Claude Code | GitHub Copilot CLI |
|---------------------+------------------------------------+------------------------------|
| Launch command | =claude= | =copilot= |
| Session resume | =--resume <session-id>= | ✗ Not supported |
| MCP config | =--mcp-config '{"mcpServers":…}'= | =.github/mcp.json= (file) |
| System prompt | =--system-prompt <text>= | =.github/AGENTS.md= (file) |
| IDE integration | =--ide= + WebSocket lock file | ✗ Not available |
| Structured output | =--output-format stream-json= | ✗ TUI only |
| Hook events | =SessionStart=, =Stop=, =Pre/PostToolUse= | =sessionStart=, =sessionEnd=, =pre/postToolUse= |
| Ready TUI prompt | ="type a message"= / insert mode | ="> "= / ="copilot>"= |
| Cancel key | Escape | C-c or =/stop= |
| Autonomous mode | Default | Requires =--allow-all-tools= |
| Multi-turn memory | Persistent with =--resume= | Ephemeral (per terminal session) |
| Context window | 200K+ tokens | 32K–128K (model-dependent) |

** What Does NOT Change

The cmux terminal infrastructure is fully agent-agnostic and requires no
modification:
- =cmux new-workspace= / =cmux send= / =cmux pipe-pane= / =cmux send-key=
- Workspace color/icon (=WORKSPACE_COLOR=, =WORKSPACE_ICON= properties)
- Verbose output buffer and streaming timer
- Mode-line query tracking (=claude-agent--active-queries=)
- =claude-org-terminal-base= status files (=.from-emacs=, =.status=)
- Session state hash tables and org property persistence
- Loop support and story-changed hook

Only five thin layers are agent-specific and need to be abstracted.

* Proposed Design

** Principle: Agent Profile Registry

Each supported agent is described by a *profile struct* that carries the
agent-specific behaviors. Switching agents is a matter of selecting a different
profile — the rest of the cmux infrastructure is unchanged.

** Layer 1: New Customization Variable

Add to the =Configuration= section of =claude-org-cmux.org=:

#+begin_src elisp
(defcustom claude-org-cmux-agent-type 'claude
  "Code agent to launch in cmux workspaces.
  `claude'   - Claude Code (default, full integration via workspace bridge)
  `copilot'  - GitHub Copilot CLI
  A string   - Custom shell command (delegated to claude-org-cmux-launch-command)

Override per-session with the AGENT_TYPE org property:
  :PROPERTIES:
  :AGENT_TYPE: copilot
  :END:"
  :type '(choice (const claude) (const copilot) string)
  :group 'claude-org)

(defcustom claude-org-cmux-copilot-workspace-script
  (let* ((pkg-dir (file-name-directory
                   (or load-file-name buffer-file-name "")))
         (uv-cmd (format "uv run --project %s copilot-workspace"
                         (expand-file-name "python" pkg-dir))))
    uv-cmd)
  "Command to launch the copilot-workspace launcher.
Used when `claude-org-cmux-agent-type' is `copilot'."
  :type 'string
  :group 'claude-org)
#+end_src

** Layer 2: Agent Profile Struct

Add to =claude-org-cmux.org= after Configuration:

#+begin_src elisp
(cl-defstruct claude-org-cmux--agent-profile
  "Describes how to launch and integrate with a code agent in cmux."
  (name nil)                    ; Symbol: 'claude or 'copilot
  (launch-fn nil)               ; (org-file session-id project-root) → shell-cmd string
  (ready-patterns nil)          ; List of regexp strings: TUI is ready for input
  (busy-patterns nil)           ; List of regexp strings: TUI is processing
  (cancel-keys nil)             ; List of cmux key names to send for cancel
  (supports-resume nil)         ; t if --resume SESSION_ID is supported
  (supports-ide nil)            ; t if IDE WebSocket integration available
  (supports-system-prompt nil)) ; t if system prompt injection is supported

(defvar claude-org-cmux--agent-profiles
  (list
   (make-claude-org-cmux--agent-profile
    :name 'claude
    :launch-fn #'claude-org-cmux--build-claude-launch-command
    :ready-patterns '("type a message" "-- INSERT --")
    :busy-patterns  '("Tool:" "Thinking" "esc to interrupt")
    :cancel-keys    '("escape")
    :supports-resume t
    :supports-ide    t
    :supports-system-prompt t)
   (make-claude-org-cmux--agent-profile
    :name 'copilot
    :launch-fn #'claude-org-cmux--build-copilot-launch-command
    :ready-patterns '("> " "copilot>")
    :busy-patterns  '("Thinking..." "Running " "●")
    :cancel-keys    '("C-c" "C-c")
    :supports-resume nil
    :supports-ide    nil
    :supports-system-prompt nil))
  "Registry of known agent profiles.
To add a new agent: push a new `claude-org-cmux--agent-profile' onto this list.")

(defun claude-org-cmux--get-agent-profile (&optional agent-type)
  "Return the agent profile for AGENT-TYPE symbol.
Falls back to `claude-org-cmux-agent-type', then to 'claude.
Returns nil if no profile matches."
  (let* ((type-sym (or agent-type
                       (let ((prop (condition-case nil
                                       (claude-org-terminal--find-session-property "AGENT_TYPE")
                                     (error nil))))
                         (when prop (intern (downcase prop))))
                       claude-org-cmux-agent-type
                       'claude))
         (profiles claude-org-cmux--agent-profiles))
    (cl-find type-sym profiles
             :key #'claude-org-cmux--agent-profile-name)))
#+end_src

** Layer 3: Dispatch in =build-launch-command=

Replace the existing =claude-org-cmux--build-launch-command= body with a
dispatcher. The current Claude logic moves to a dedicated function:

#+begin_src elisp
(defun claude-org-cmux--build-launch-command (org-file workspace-session-id project-root)
  "Build the shell command to launch the configured code agent in cmux.
Dispatches to the agent profile's launch-fn, or falls back to the
existing claude-org-cmux-launch-command string for custom commands."
  (ignore project-root)
  (let ((profile (claude-org-cmux--get-agent-profile)))
    (if profile
        (funcall (claude-org-cmux--agent-profile-launch-fn profile)
                 org-file workspace-session-id project-root)
      ;; Fallback: existing custom string command behavior
      (claude-org-cmux--build-custom-launch-command
       org-file workspace-session-id project-root))))

;; Existing build logic extracted verbatim into:
(defun claude-org-cmux--build-claude-launch-command
    (org-file workspace-session-id project-root)
  "Build Claude Code launch command (moved from build-launch-command)."
  ;; ... existing claude-workspace / bare claude / string logic unchanged ...
  )

;; New Copilot launcher:
(defun claude-org-cmux--build-copilot-launch-command
    (org-file workspace-session-id project-root)
  "Build GitHub Copilot CLI launch command."
  (ignore project-root)
  (let* ((workspace-script claude-org-cmux-copilot-workspace-script)
         (prop-args (claude-org-terminal--find-session-property "CLAUDE_EXTRA_ARGS"))
         (all-extra (append claude-org-cmux-extra-args
                            (when prop-args (split-string prop-args))))
         (extra (mapconcat #'shell-quote-argument all-extra " "))
         (parts (list workspace-script
                      (shell-quote-argument (or org-file ""))
                      (shell-quote-argument (or workspace-session-id "")))))
    ;; NOTE: No --resume: Copilot CLI does not support session resumption
    (when (and extra (not (string-empty-p extra)))
      (setq parts (append parts (list "--" extra))))
    (mapconcat #'identity parts " ")))
#+end_src

** Layer 4: Agent-Aware Ready Detection and Cancel

=wait-for-ready-poll= and =cancel= need to use profile patterns/keys:

#+begin_src elisp
(defun claude-org-cmux--wait-for-ready-poll (surface-id timeout)
  "Poll capture-pane for ready state using current agent's ready-patterns."
  (let* ((profile (claude-org-cmux--get-agent-profile))
         (patterns (if profile
                       (claude-org-cmux--agent-profile-ready-patterns profile)
                     '("type a message" "-- INSERT --"))))
    ;; existing polling loop, but using `patterns' instead of hardcoded strings
    ))

(defun claude-org-cmux-cancel ()
  "Cancel current agent operation using agent-specific cancel keys."
  (let* ((surface-id (claude-org-terminal--find-session-property "CMUX_SURFACE_ID"))
         (profile (claude-org-cmux--get-agent-profile))
         (cancel-keys (if profile
                          (claude-org-cmux--agent-profile-cancel-keys profile)
                        '("escape"))))
    (dolist (key cancel-keys)
      (claude-org-cmux--call "send-key" "--surface" surface-id key))))
#+end_src

** Layer 6: Python — New =copilot_workspace.py=

Analogous to =claude_workspace.py= but Copilot-specific:

#+begin_src python
# python/claude_agent/copilot_workspace.py
"""GitHub Copilot workspace launcher for cmux backend.

Launches GitHub Copilot CLI with workspace bridge hooks and MCP integration.
Usage: copilot-workspace <org-file> [session-id] [-- extra-args...]

Differences from claude_workspace.py:
  - No --resume (Copilot doesn't support session resumption)
  - No --ide (Copilot doesn't have WebSocket IDE integration)
  - MCP via .github/mcp.json (file-based, not --mcp-config flag)
  - System prompt via .github/AGENTS.md (file-based, not --system-prompt)
  - Requires --allow-all-tools for autonomous operation
  - Restores .github/mcp.json and AGENTS.md on exit
"""

def build_copilot_args(plugin_dir, mcp_url, system_prompt, extra_args, story_name=""):
    """Build args for GitHub Copilot CLI.

    Note: --resume is NOT passed because Copilot CLI does not support
    session resumption. Sessions are always fresh per workspace launch.
    """
    args = ["copilot"]

    # MCP: inject Emacs server into .github/mcp.json (file-based config)
    _inject_emacs_mcp_into_dotgithub(mcp_url)

    # System prompt: write to .github/AGENTS.md (Copilot's instruction mechanism)
    if system_prompt:
        _write_agents_md(system_prompt)

    # Required for agentic/autonomous operation
    args.append("--allow-all-tools")

    # Optional model override (from AGENT_MODEL org property via env var)
    model = os.environ.get("AGENT_MODEL")
    if model:
        args.extend(["--model", model])

    args.extend(extra_args)
    return args

def _inject_emacs_mcp_into_dotgithub(mcp_url: str) -> None:
    """Merge Emacs MCP server entry into .github/mcp.json.

    Saves the original content and registers restore via atexit so the
    user's repo is not permanently modified.
    """
    mcp_json_path = Path(".github/mcp.json")
    mcp_json_path.parent.mkdir(exist_ok=True)
    original = mcp_json_path.read_text() if mcp_json_path.exists() else None
    config = json.loads(original) if original else {}
    config.setdefault("mcpServers", {})["emacs"] = {"type": "http", "url": mcp_url}
    mcp_json_path.write_text(json.dumps(config, indent=2))
    atexit.register(_restore_file, mcp_json_path, original)

def _write_agents_md(system_prompt: str) -> None:
    """Prepend session system prompt to .github/AGENTS.md.

    Restores original on exit. If AGENTS.md already exists, the session
    instructions are prepended above the existing content.
    """
    agents_md_path = Path(".github/AGENTS.md")
    original = agents_md_path.read_text() if agents_md_path.exists() else None
    header = f"<!-- emacs-agent session instructions -->\n{system_prompt}\n\n"
    agents_md_path.write_text(header + (original or ""))
    atexit.register(_restore_file, agents_md_path, original)
#+end_src

* Gap Handling

** Gap 1: No Session Resume

Copilot CLI has no =--resume= equivalent; sessions are ephemeral.

- *Mitigation*: When =supports-resume nil=, skip reading =CLAUDE_CLI_SESSION=
  and skip writing it after =SessionStart=. The workspace persists (same cmux
  workspace) but conversation history is not retained across Emacs restarts.
- *UX*: No user-visible change for the common case (single session). Users who
  expect resume semantics should use Claude Code.

** Gap 2: MCP Config is File-Based

Claude Code accepts =--mcp-config <json-inline>=. Copilot reads
=.github/mcp.json= from the project directory.

- *Mitigation*: =copilot_workspace.py= reads any existing =.github/mcp.json=,
  merges the Emacs MCP server entry, and restores the original file on
  process exit via =atexit=. This prevents permanent repo modification.
- *Risk*: If Copilot forks a subprocess that outlives the launcher, restore
  may race with Copilot's file read. Acceptable given the alternative is worse.

** Gap 3: System Prompt is File-Based

Claude Code accepts =--system-prompt <text>=. Copilot reads =.github/AGENTS.md=.

- *Mitigation*: =copilot_workspace.py= prepends the workspace session's system
  prompt to =.github/AGENTS.md= (or creates it) and restores on exit.
- *Note*: Copilot's AGENTS.md instructions persist for the session, so changes
  made by Copilot to AGENTS.md could be overwritten by restore. This is fine
  — the file is session-scoped.

** Gap 4: Different Ready/Busy Screen Patterns

Copilot's TUI displays different text when idle vs. busy.

- *Mitigation*: =wait-for-ready-poll= and =get-status= use the profile's
  =ready-patterns= and =busy-patterns= lists instead of hardcoded strings.
  No structural change to the polling loop.

** Gap 5: No Structured Output (No =stream-json=)

Copilot has no =--output-format stream-json=, so token-level streaming and
tool call parsing are unavailable.

- *Mitigation*: The cmux backend delivers response text via the =Stop=/
  =sessionEnd= hook path → =workspace_bridge.py= → MCP →
  =claude-org-workspace-bridge-insert-response= → =claude-org--terminal-query-completed=.
  This path is agent-agnostic. Live terminal echo (for users who want to see
  progress while the agent thinks) is available via the async /Verbose Output
  Mirror/ (=claude-org-cmux--start-verbose=). (Note: the earlier
  =claude-org-cmux--stream-tick= =pipe-pane= polling was removed in commit
  01b4143 — it was dead code whose insertion marker never initialised.)
- *Loss*: No per-token response streaming in the org response section for
  Copilot. The response appears only after =sessionEnd= fires (batch, not live).
  This is a known limitation of Copilot's TUI-only design.

** Gap 6: No IDE WebSocket Integration

Claude Code supports =--ide= for WebSocket-based editor integration.
Copilot has no equivalent.

- *Mitigation*: Guard the =claude-org-cmux--ensure-ide-server= call behind
  =(when (claude-org-cmux--agent-profile-supports-ide profile) ...)=.
  Mode-line IDE indicators are hidden gracefully (show only for Claude).

** Adding a Third Agent (Extension Point)

To add a new agent (e.g., Cursor, Gemini CLI) in the future:

1. Create =python/claude_agent/myagent_workspace.py= (stateless launcher)
2. Create =hooks/myagent_hooks.json= (hook event config)
3. Add aliases to =workspace_bridge.py= =EVENT_HANDLERS=
4. Push a new =claude-org-cmux--agent-profile= onto
   =claude-org-cmux--agent-profiles= (no other elisp changes needed)
5. Add =myagent-workspace= entry point to =pyproject.toml=

* Design Principles Preserved

| Principle | How preserved |
|-----------+---------------|
| Emacs owns all state | Copilot has no resume, so nothing to persist — correct by omission |
| Python is stateless | =copilot_workspace.py= receives org-file and session-id as args |
| Zero regression for Claude Code | All existing logic moves to =build-claude-launch-command=; nothing changes for Claude users |
| Additive architecture | Profile registry is open for extension without modifying existing code |
| Process filter safety | No changes to process filter or sentinel; streaming remains agent-agnostic |

* Open Questions
