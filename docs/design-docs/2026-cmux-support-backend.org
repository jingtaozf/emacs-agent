#+TITLE: Terminal Backends: cmux & iTerm2
#+DATE: 2026-03-15
#+STATUS: implemented

* Overview

claude-agent supports two terminal backends for running Claude Code TUI
inside a macOS terminal controlled from Emacs org-mode. Both backends share
the same SDD bridge, query registration, and mode-line infrastructure.
They differ only in how they control the terminal application.

| Backend | Terminal App | IPC Mechanism | Module |
|---------+-------------+---------------+--------|
| cmux | cmux (Ghostty-based) | Unix socket CLI | =claude-org-cmux.org= |
| iTerm2 | iTerm2 | Python/AppleScript bridge | =claude-org-iterm2.org= |

Backend is selected per org section via =CLAUDE_BACKEND= property.

* Shared Architecture

Both backends follow the same execution flow and share common infrastructure.

** Execution Flow (both backends)

#+begin_example
1. User presses C-c C-c on #+begin_src ai block
2. claude-org-execute:
   a. Read CLAUDE_BACKEND property (inherit=t)
   b. Fire claude-org-execute-hook (history, jump)
   c. Auto-generate section title if needed
   d. Set loop state if applicable
   e. Dispatch to backend-specific --execute-ai-block
3. Backend --execute-ai-block:
   a. Extract prompt from ai block
   b. Ensure terminal session (create or reuse)
   c. Check status — error if busy
   d. Register query in claude-agent--active-queries
   e. Write from-emacs flag file
   f. Send prompt to terminal
4. Claude Code processes prompt, calls SDD bridge hooks
5. SDD bridge calls back via MCP:
   - Insert response into org buffer
   - Call claude-org--terminal-query-completed
6. Backend --query-completed:
   - Unregister from active queries
   - Handle loop continuation if applicable
#+end_example

** Shared Infrastructure

| Component | Location | Used By |
|-----------+----------+--------|
| SDD bridge (Python) | =python/claude_agent/sdd_bridge.py= | Both |
| Query registration | =claude-agent--register-query= / =--active-queries= | Both |
| Mode-line display | =claude-agent-activity-mode-line= | Both |
| Session properties | =CLAUDE_SESSION_ID=, =CLAUDE_CLI_SESSION= | Both |
| Status files | =/tmp/claude-agent-status/<session-id>.*= | Both |
| Backend dispatch | =claude-org-execute= early-return pattern | Both |
| Completion dispatch | =claude-org--terminal-query-completed= | Both |
| Tracing | =claude-agent-with-span= + =:trace-ctx= | Both |
| MCP server | =emacs-mcp-server.org= | Both |
| IDE server | =claude-org-iterm2--ensure-ide-server= | Both (cmux uses =fboundp= guard) |

** SDD Bridge (Backend-Agnostic)

The Python SDD bridge handles Claude Code hook events identically for both
backends. It runs inside the Claude Code process and calls back to Emacs
via MCP (=EMACS_MCP_URL= environment variable).

| Hook Event | Bridge Handler | MCP Callback |
|------------+----------------+--------------|
| =prompt= | Write "busy" status; detect from-emacs flag | =claude-org-sdd-bridge-insert-prompt= |
| =response= | Write "ready" status; extract response text | =claude-org-sdd-bridge-insert-response= + =query-completed= |
| =tool= | Handle TodoWrite | =claude-org-sdd-bridge-update-todos= |
| =permission= | Permission request | =claude-org-iterm2--permission-needed= (hardcoded) |
| =permission-clear= | Permission resolved | =claude-org-iterm2--permission-resolved= (hardcoded) |

Status files per session (all under =/tmp/claude-agent-status/=):

| File | Content |
|------+---------|
| =<session-id>= | ="ready"= or ="busy"= |
| =<session-id>.request-id= | Request ID for query tracking |
| =<session-id>.custom-id= | CUSTOM_ID of active instruction |
| =<session-id>.from-emacs= | Flag: prompt originated from Emacs |

** Backend Dispatch

=claude-org-execute= reads =CLAUDE_BACKEND= property and early-returns:

#+begin_src elisp
;; In claude-org-execute():
(cond
 ((string-equal backend "iterm2")
  (claude-org-iterm2--execute-ai-block)
  (cl-return-from claude-org-execute nil))
 ((string-equal backend "cmux")
  (claude-org-cmux--execute-ai-block)
  (cl-return-from claude-org-execute nil)))
;; else: fall through to json-stream/claude-cli backend
#+end_src

Completion dispatch in =claude-org--terminal-query-completed=:
- Checks cmux hash table first (=claude-org-cmux--sdd-to-session-key=)
- Falls through to iTerm2 as default

* cmux Backend

** What is cmux?

cmux is a native macOS terminal (Swift/AppKit) built on Ghostty's GPU
rendering engine. Purpose-built for AI coding workflows with:
- Vertical-tab sidebar with workspaces
- Unix domain socket API (=cmux= CLI binary)
- Sidebar metadata: status, progress bars, logs
- Notification rings (in-app, no OS notification fatigue)
- Built-in scriptable browser

*Repository*: [[https://github.com/manaflow-ai/cmux][manaflow-ai/cmux]]

** Communication Layer

#+begin_example
┌─────────────┐     call-process     ┌──────────┐    unix socket    ┌──────┐
│ claude-agent │ ──────────────────► │ cmux CLI │ ────────────────► │ cmux │
│   (Elisp)   │  cmux send "prompt" │ (Swift)  │   JSON-RPC v2    │ app  │
└─────────────┘                     └──────────┘                   └──────┘
#+end_example

Each =cmux= CLI call: connect socket → send JSON-RPC → receive response → exit.
Lightweight per-command subprocess (no long-running bridge process).

** cmux Object Hierarchy

#+begin_example
Window (macOS app window)
 └── Workspace (sidebar tab — one per SDD story)
      └── Pane (split region)
           └── Surface (terminal or browser instance)
#+end_example

Each SDD story gets its own workspace. The workspace title shows the story name.

** Configuration

| Variable | Default | Purpose |
|----------+---------+---------|
| =claude-org-cmux-socket-path= | =nil= (auto-detect) | Explicit socket path |
| =claude-org-cmux-launch-command= | ='claude-sdd= | Launch mode: =claude-sdd=, =claude=, or string |
| =claude-org-cmux-extra-args= | =nil= | Extra CLI args for launch command |
| =claude-org-cmux-sdd-script= | =uv run ...= | Path to SDD launcher script |
| =claude-org-cmux-ready-timeout= | =30= | Seconds to wait for TUI readiness |

** cmux-Specific Org Properties

| Property | Purpose | Example |
|----------+---------+---------|
| =CMUX_SURFACE_ID= | Terminal surface ref (cached) | =surface:28= |
| =CMUX_WORKSPACE_ID= | Workspace ref (cached) | =workspace:27= |

** Session Lifecycle

#+begin_example
claude-org-cmux--ensure-session:
1. Read CMUX_SURFACE_ID from org property
2. If saved: verify alive via `cmux capture-pane --surface <id>`
   → Return saved ref if live
3. If dead or missing:
   a. Read CLAUDE_SESSION_ID (required)
   b. Build launch command (with --resume if CLAUDE_CLI_SESSION exists)
   c. `cmux new-workspace --cwd <root> --command <cmd>`
      (on TabManager error: `cmux new-window`, retry)
   d. Parse "OK workspace:N" → get surface via list-pane-surfaces
   e. `cmux rename-workspace` → set story name as title
   f. Save CMUX_SURFACE_ID + CMUX_WORKSPACE_ID as org properties
   g. Wait for TUI ready (poll capture-pane for "-- INSERT --", up to 30s)
#+end_example

** Prompt Sending

1. Ensure INSERT mode (send ="i"= if not in INSERT mode)
2. If prompt < 100KB: =cmux send --surface <id> <text>=
3. If prompt >= 100KB: =cmux set-buffer= + =cmux paste-buffer= (workaround)
4. Always =cmux send-key --surface <id> enter= to submit

** Status Detection

Two-tier detection:
1. *Hook status file*: read =/tmp/claude-agent-status/<session-id>= → ="ready"= or ="busy"=
2. *Screen fallback*: =cmux capture-pane= → pattern match:
   - ="-- INSERT --"= or ="type a message"= → ready
   - ="Tool:"= or ="Thinking"= → busy
   - Empty → dead

** cmux-Exclusive Features

| Feature | API | Purpose |
|---------+-----+---------|
| Sidebar status | =cmux set-status agent "Running..."= | Show agent state |
| Progress bar | =cmux set-progress 0.5= | Visual progress |
| Notifications | =cmux notify --title T --body B= | In-app alerts |
| Log entries | =cmux log info "message"= | Sidebar log |
| Workspace rename | =cmux rename-workspace "story name"= | Meaningful sidebar titles |

* iTerm2 Backend

** Communication Layer

#+begin_example
┌─────────────┐   call-process   ┌──────────────┐   AppleScript    ┌────────┐
│ claude-agent │ ──────────────► │ iterm2_ctl.py │ ──────────────► │ iTerm2 │
│   (Elisp)   │  python3 ...    │   (pyobjc)   │   Python API     │  app   │
└─────────────┘                 └──────────────┘                   └────────┘
#+end_example

Uses a Python bridge script (=iterm2_ctl.py=) because iTerm2 exposes only
a Python API (pyobjc). The bridge is invoked per-command via =call-process=.

** Configuration

| Variable | Default | Purpose |
|----------+---------+---------|
| =claude-org-iterm2-script= | =python/.../iterm2_ctl.py= | Path to Python bridge |
| =claude-org-iterm2-launch-command= | ='claude-sdd= | Same 3-way as cmux |
| =claude-org-iterm2-sdd-script= | =uv run ...= | Same default as cmux |
| =claude-org-iterm2-extra-args= | =nil= | Same as cmux |

** iTerm2-Specific Org Properties

| Property | Purpose | Example |
|----------+---------+---------|
| =ITERM2_SESSION_ID= | iTerm2 session UUID | =w0t0p0:UUID= |

** Session Lifecycle

#+begin_example
claude-org-iterm2--ensure-session:
1. Read ITERM2_SESSION_ID from org property
2. If saved: call `iterm2_ctl.py status --session <id>` → parse JSON
   → Return saved ID if state != "dead"
3. If dead or missing:
   a. `iterm2_ctl.py launch --title <title> --cwd <root> --launch-cmd <cmd>`
   b. Returns iTerm2 UUID directly
   c. Save ITERM2_SESSION_ID as org property
   (No readiness waiting — returns immediately)
#+end_example

** iTerm2-Exclusive Features

| Feature | Function | Purpose |
|---------+----------+---------|
| Permission alerts | =--permission-needed= | Mode-line alert + dock bounce + app focus |
| Permission resolve | =--permission-resolved= | Clear alert |
| App activation | =--activate-app= | AppleScript focus switching |
| UUID reverse-lookup | =--lookup-iterm2-session= | Find session across buffers |

* Comparison: cmux vs iTerm2

| Aspect | cmux | iTerm2 |
|--------+------+--------|
| IPC | Unix socket CLI (native Swift) | Python bridge (pyobjc) |
| Terminal ID | Surface ref (=surface:N=) | UUID |
| Session creation | =cmux new-workspace= + rename | =iterm2_ctl.py launch= |
| Liveness check | =capture-pane= (non-empty?) | =status= JSON (state != dead?) |
| Wait for ready | Yes (polls 30s for INSERT mode) | No (returns immediately) |
| INSERT mode mgmt | Yes (sends ="i"= before prompt) | No |
| Large text handling | =set-buffer= + =paste-buffer= (>100KB) | Always via stdin temp file |
| Workspace naming | =rename-workspace= → story name | Tab title only |
| Sidebar metadata | Status, progress, logs | Not available |
| In-app notifications | Notification rings | OS-level only |
| Permission UI | None (uses iTerm2's) | Alert + dock bounce + focus |
| Property inheritance | =org-entry-get nil prop t= | Manual heading walk |
| from-emacs flag order | Register query FIRST, then flag | Write flag FIRST, then register |
| Text property stripping | =substring-no-properties= | Not done |
| Cancel | =send-key escape= | =iterm2_ctl.py cancel= |
| Dependencies | cmux.app + CLI binary | Python 3, pyobjc, iTerm2.app |

* Known Coupling

1. *cmux → iTerm2 dependency*: cmux calls
   =claude-org-iterm2--ensure-ide-server= (guarded by =fboundp=) for MCP
   IDE server startup. Works without iTerm2 loaded, but IDE features
   require it.

2. *SDD bridge → iTerm2 hardcoding*: =sdd_bridge.py= hardcodes
   =claude-org-iterm2--permission-needed= (in =handle_permission=) and
   =claude-org-iterm2--permission-resolved= (in =handle_permission_clear=)
   regardless of backend. cmux sessions receive no permission UI.

3. *Completion dispatch priority*: =claude-org--terminal-query-completed=
   checks cmux hash table first, then falls through to iTerm2 as default.

Switch by changing =CLAUDE_BACKEND= property (=cmux=, =iterm2=, or =native=).
