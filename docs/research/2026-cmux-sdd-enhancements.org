#+TITLE: cmux SDD Story Enhancements — Research & Ideas
#+DATE: 2026-03-20

* Overview

Research into leveraging cmux's terminal capabilities to improve the SDD
(Story-Driven Development) workflow. Focuses on features that exploit cmux's
unique position as a terminal app with Unix socket API, sidebar metadata, and
direct access to PTY output.

* Current Architecture

#+begin_example
  Emacs (org-mode)           cmux (terminal)           Claude Code (TUI)
  ┌─────────────┐           ┌──────────────┐          ┌──────────────┐
  │ AI block    │──prompt──→│ send-text    │─────────→│ CLI process  │
  │ Response    │←─hook────│ pipe-pane    │←─output──│              │
  │ section     │           │ set-status   │           │ hooks fire   │
  └─────────────┘           └──────────────┘          └──────────────┘
       ↑                         ↑                          │
       │                         │                          │
       └── MCP evalElisp ────────┘──── sdd-bridge.sh ──────┘
#+end_example

Pain points:
- Must switch to cmux to see Claude Code output
- Response only appears in org after full completion (Stop hook)
- No real-time feedback during long operations
- Context-switching between Emacs and cmux interrupts flow

* Feature A: Live Output Mirror in Emacs

** Concept

Stream cmux terminal output into a read-only Emacs buffer alongside the org
file. Like =*compilation*= but for Claude Code. Accessible via
=claude-org-menu → v → Verbose output= (same as JSON stream backend).

** Architecture

#+begin_example
  cmux terminal surface (Claude Code running)
      │
      ├── pipe-pane --follow (NEW cmux feature)
      │   continuous PTY output stream via Unix socket
      │
      └── Emacs: make-network-process :filter
          ├── strips ANSI escape sequences (ansi-color-apply)
          ├── inserts into *Claude Output [story-name]* buffer
          ├── auto-scrolls to bottom (like comint-mode)
          └── file paths are clickable (compilation-error-regexp-alist)
#+end_example

** cmux side: =pipe-pane --follow=

Extend =pipe-pane= to support continuous streaming. Current behavior is one-shot
(captures scrollback snapshot). New =--follow= flag keeps the connection open
and sends new output as it arrives.

Alternative: Add =surface.subscribe_output= V2 method that pushes new terminal
content to the socket client as it arrives. More architecturally clean than
extending the V1 =pipe-pane= command.

** Emacs side: Verbose buffer for terminal backend

Reuse the existing =claude-org-show-verbose= infrastructure. The JSON stream
backend already creates verbose buffers via =claude-agent-get-verbose-buffer=.
For the cmux backend, create an equivalent buffer that receives streamed output.

** See also

Design doc: =docs/design-docs/2026-cmux-live-output-mirror.org=

* Feature B: Bidirectional Jump Navigation

** Concept

Two-way navigation between Emacs and cmux:
- When you execute an AI block (C-c C-c), cmux workspace auto-focuses
- When Claude Code finishes, Emacs navigates to the response section and pulses it
- Clickable file paths in the output buffer jump to files in Emacs

** cmux → Emacs (already works)

The SDD bridge hooks call MCP =evalElisp= to insert prompts/responses.
Extend to also navigate Emacs to the modified file when Claude Code edits it.

#+begin_src bash
# In Stop hook, after response insertion:
emacsclient --no-wait --eval "(progn
  (switch-to-buffer \"$ORG_FILE_BUFFER\")
  (goto-char $RESPONSE_POSITION)
  (recenter)
  (pulse-momentary-highlight-region ...))"
#+end_src

** Emacs → cmux (already works)

=claude-org-execute= sends prompt, =select-workspace= focuses cmux.
Enhancement: auto-split Emacs frame — left = org file, right = verbose output buffer.

** New: Clickable file paths in output buffer

Apply =compilation-error-regexp-alist= to the verbose output buffer so file
paths mentioned by Claude Code are clickable. Pressing RET on a path opens the
file in Emacs at the right line.

* Feature C: cmux Sidebar as SDD Dashboard

** Concept

Use cmux's existing sidebar metadata commands to show rich per-story context
without switching to Emacs.

** Visual design

#+begin_example
  ┌─ cmux sidebar ─────────────────────┐
  │                                     │
  │ 🔵 claude-agent-dev                │
  │   ├ 🔨 native claude code backend │
  │   │   Running (2m 15s)             │  ← status pill
  │   │   Fix trace root spans         │  ← report_meta_block
  │   │   ████████░░ 80%              │  ← set-progress
  │   │                                │
  │ 🩵 skills-network-dev              │
  │   ├ 🌐 study pcr skill networking │
  │   │   Idle                         │
  │   │                                │
  │ 🟢 mega-code-dev                   │
  │   ├ 🔥 deployment                  │
  │   │   ⚠️ Permission needed         │  ← orange color
  │   │   Approve Edit on auth.py     │
  │                                     │
  └─────────────────────────────────────┘
#+end_example

** Commands used

| Feature | cmux command | Data source |
|---------+--------------+-------------|
| Tab color | =set_workspace_color= (raw socket) | SDD_COLOR org property |
| Project pill | =set-status project= | Org file name + SDD_ICON |
| Query text | =report_meta_block story= | Truncated prompt from execute |
| Progress bar | =set-progress= | TODO checkboxes from =update-todos= |
| Running/Idle | =set-status claude_code= | Claude Code hooks (automatic) |

** Implementation

All commands already exist in cmux. Only Emacs-side code needed (~20 lines):
- Call =report_meta_block= with truncated prompt on =claude-org-execute=
- Call =set-progress= from =claude-org-sdd-bridge-update-todos=

* Feature D: Streaming Response Insertion

** Concept

Instead of waiting for the Stop hook to insert the full response, stream
partial responses into the org response section in real-time. Uses Feature A's
live output as the data source.

** Architecture

#+begin_example
  Claude Code types response in terminal
      │
      ├── Feature A: live output → verbose buffer
      │
      └── Output parser
          ├── detects text blocks (strips TUI chrome, tool calls)
          └── inserts into org Response section progressively
              (same marker-based insertion as JSON stream backend)
#+end_example

** Challenges

- Parsing: Claude Code TUI output mixes user text with tool calls, thinking
  blocks, and TUI chrome. Need a parser that extracts just the response content.
- Duplication: The Stop hook will also insert the canonical response. Need to
  replace streamed content with the canonical version on completion.
- ANSI: Terminal output has escape sequences that must be stripped before
  org insertion.

** Build order

Requires Feature A (live output) as foundation. The parser is the hard part.
Can start simple (stream everything) and refine (filter to response text only).

* Build Priority

| Priority | Feature | Effort | Dependencies |
|----------+---------+--------+--------------|
| 1 | A: Live output mirror | Medium | cmux: pipe-pane --follow |
| 2 | C: Sidebar dashboard | Low | None (all APIs exist) |
| 3 | B: Jump navigation | Low | Feature A for clickable paths |
| 4 | D: Streaming response | High | Feature A + parser |
