#+TITLE: Ghostty Features for SDD Workflow — Research Findings
#+DATE: 2026-03-21

* Overview

Analysis of Ghostty (libghostty) features available through cmux that can
improve the SDD (Story-Driven Development) workflow with Emacs.

cmux is built on Ghostty. All Ghostty features surface through the
=ghostty_runtime_action_cb= callback in Swift, which cmux can relay
to Emacs via its Unix socket API.

* Key Findings

** OSC 133 Semantic Prompt Markers — Available but Not Exposed

Shell integration (=ghostty.bash=, =ghostty-integration= for zsh) injects:

| Marker | Meaning | When emitted |
|--------+---------+--------------|
| =ESC]133;A= | Prompt start | Before prompt displayed |
| =ESC]133;B= | Input start | After prompt, before user types |
| =ESC]133;C= | Output start | After Enter, before command runs |
| =ESC]133;D;exit= | Command end | After command finishes, with exit code |

*Status*: zsh integration IS active in cmux (=CMUX_LOAD_GHOSTTY_ZSH_INTEGRATION=1=,
=GHOSTTY_SHELL_FEATURES=cursor:steady,path,title=). OSC 133 markers ARE emitted.

*Limitation*: Ghostty's terminal parser consumes these markers and stores them as
per-row =semantic_prompt= flags in the page data. They are NOT preserved in
=surface.read_text= output (which returns rendered text only).

*To use*: cmux would need to expose the row-level semantic flags via a new API
(e.g. =surface.read_text_with_marks=), or relay the =command_finished= action
callback via its socket protocol.

** GHOSTTY_ACTION_COMMAND_FINISHED — Not Yet Handled by cmux

Ghostty fires =GHOSTTY_ACTION_COMMAND_FINISHED= with exit code and nanosecond
duration when OSC 133 D arrives. This action EXISTS in =ghostty.h= but cmux
does NOT handle it in its Swift action callback.

*Impact*: If cmux handled this, Emacs could receive push notifications when
Claude Code sub-commands complete — replacing hook-file polling.

** OSC 7 PWD Tracking — Working

Shell emits =ESC]7;kitty-shell-cwd://<host><path>= on directory change.
cmux processes =GHOSTTY_ACTION_PWD= and updates sidebar directory display.
Already visible in =sidebar-state= output.

** OSC 8 Hyperlinks — Supported by Ghostty

Ghostty fully implements OSC 8 hyperlinks. =GHOSTTY_ACTION_MOUSE_OVER_LINK=
fires when cursor hovers. If Claude Code output wrapped file paths in
=ESC]8;;file:///path\atext\ESC]8;;\a=, cmux could route clicks to Emacs.

** OSC 9;4 Progress Report — Available

ConEmu protocol for progress bars. Not currently used by Claude Code, but
could be emitted by the SDD bridge for long operations.

** OSC 3008 Context Signal — Rich Structured Events

Newer UAPI protocol for hierarchical context signals:
#+begin_example
ESC]3008;start=uuid;type=command;cmdline=git status\a
ESC]3008;end=uuid;exit=success;status=0\a
#+end_example

More structured than OSC 133 — carries =cmdline=, =type=, =exit=, =status=.
Could be emitted by Claude Code hooks for richer tool-use tracking.

** Kitty Graphics Protocol — Supported

Inline images via APC sequences. No Sixel support. Could render diagrams.

** Manual IO Mode — Available

=GHOSTTY_SURFACE_IO_MANUAL= allows the host to drive all terminal I/O.
Could create synthetic status terminals without real processes.

* E2E Test Results

Tested with a real Claude Code session in cmux:

1. Created workspace, started Claude Code
2. Sent multi-step task (read file, run git log, search code)
3. Captured output via =surface.read_text= (v2 API)
4. Checked for OSC 133 markers in output → NOT present (stripped by parser)
5. Verified =GHOSTTY_SHELL_FEATURES= active → =cursor:steady,path,title=
6. Verified =CMUX_LOAD_GHOSTTY_ZSH_INTEGRATION=1= → integration loaded
7. Confirmed: semantic marks exist in page data but no API to read them

*Conclusion*: OSC 133 works at the Ghostty level but cmux doesn't expose
the semantic data or the =command_finished= action. Two cmux changes needed:

1. Handle =GHOSTTY_ACTION_COMMAND_FINISHED= in Swift action callback
2. Either expose semantic row marks in =read_text= or relay the action via socket

* Prioritized Feature List

** Tier 1: cmux Changes Needed

| Feature | cmux change | Emacs impact |
|---------+------------+--------------|
| =command_finished= action | Handle in Swift callback, relay via socket | Replace hook-file polling for completion |
| Semantic-aware =read_text= | New API or flag on existing API | Clean response extraction (no TUI chrome) |

** Tier 2: Already Usable

| Feature | How to use |
|---------+------------|
| PWD tracking | Read from =sidebar-state= |
| Live output mirror | =capture-pane --follow= (implemented) |
| Workspace color | =set_workspace_color= (implemented) |

** Tier 3: Future

| Feature | Effort |
|---------+--------|
| OSC 8 hyperlinks | Claude Code or hooks emit them |
| OSC 9;4 progress | SDD bridge emits for long operations |
| OSC 3008 context | Rich tool-use tracking protocol |
| Kitty graphics | Inline diagrams in terminal |
