* Installation

** macOS (DMG — recommended)

Download from [[https://github.com/manaflow-ai/cmux/releases/latest/download/cmux-macos.dmg][GitHub Releases]].
Open the =.dmg= and drag to Applications. Auto-updates via Sparkle.

** Homebrew

#+begin_src bash
brew tap manaflow-ai/cmux
brew install --cask cmux
# Update:
brew upgrade --cask cmux
#+end_src

** Nightly (separate app, runs alongside stable)

https://github.com/manaflow-ai/cmux/releases/download/nightly/cmux-nightly-macos.dmg
#+end_src

** CLI Symlink

Install from command palette: =Cmd+P= → "Install cmux CLI".
This creates =/usr/local/bin/cmux= for shell/script access.

* Ghostty Configuration

cmux uses the Ghostty terminal engine. Your Ghostty config applies inside cmux.

** Config File Locations (checked in order)

1. =~/.config/ghostty/config=
2. =~/.config/ghostty/config.ghostty=
3. =~/Library/Application Support/com.mitchellh.ghostty/config=
4. cmux-specific: =~/Library/Application Support/com.cmuxterm.app/config=

** Recommended Config

#+begin_src ini
# Font
font-family = "Berkeley Mono"
font-size = 14

# Theme (supports light/dark dual mode)
theme = "Tokyo Night"
# or dual mode:
# theme = "light:Catppuccin Latte,dark:Catppuccin Mocha"

# Transparency
background-opacity = 0.92

# Scrollback
scrollback-limit = 50000

# Split pane appearance
unfocused-split-opacity = 0.7
split-divider-color = #3d4060

# cmux-specific sidebar tinting
sidebar-background = #1e2030
sidebar-tint-opacity = 0.85
#+end_src

** Theme Picker

#+begin_src bash
cmux themes   # interactive picker with live preview
#+end_src

Theme files searched in:
- =~/.config/ghostty/themes/<name>=
- =/Applications/Ghostty.app/Contents/Resources/ghostty/themes/<name>=

* Socket Access for External Tools

cmux's Unix socket allows external tools (Emacs, scripts) to control it.

** Access Modes

| Mode | Who Can Connect | Use Case |
|------+-----------------+----------|
| =cmuxOnly= (default) | Processes descended from cmux only | Shell scripts inside cmux |
| =automation= | Any process from same macOS user | *Emacs integration, cron jobs* |
| =password= | Any process with correct password | Shared machines |
| =allowAll= | All local processes | Development only |

** Setup for Emacs Integration

Set socket access to =automation= in =Settings > Socket Access=.

Socket path: =~/Library/Application Support/cmux/cmux.sock=
Override: =CMUX_SOCKET_PATH= env var.

* Shell Integration

Shell integration is *injected automatically* — no manual setup needed.
It hooks =preexec= / =precmd= to push real-time state to the sidebar.

** What the Sidebar Shows Automatically

| Data | Source | Refresh |
|------+--------+---------|
| Current directory | =precmd= | Every prompt |
| Git branch + dirty flag | Async =git rev-parse= | Every prompt (debounced 3s) |
| PR status | =gh pr view= | Every 45 seconds |
| Listening ports | =ps= + =lsof= | On each command + 6 scans over 10s |
| Shell activity | =preexec= / =precmd= | Instant |

** Environment Variables in Every Terminal

| Variable | Description |
|----------+-------------|
| =CMUX_SOCKET_PATH= | Socket path for CLI/scripts |
| =CMUX_WORKSPACE_ID= | Current workspace ref |
| =CMUX_SURFACE_ID= | Current surface ref |
| =CMUX_TAB_ID= | Workspace UUID (V1 compat) |
| =CMUX_PANEL_ID= | Panel UUID (V1 compat) |

#+end_src

#+end_src

* Sidebar as Agent Dashboard

Beyond automatic git/port info, the sidebar supports manual entries:

#+begin_src bash
# Set named status (multiple keys coexist)
cmux set-status "build" "Compiling..." --icon bolt.fill --color "#FF9500"

# Progress bar
cmux set-progress 0.75 --label "3/4 tests done"

# Log entries
cmux log "Starting build..."
cmux log --level success "All tests passing"
cmux log --level error "Build failed: missing dependency"

# Clear
cmux clear-status "build"
cmux clear-progress
cmux clear-log
#+end_src

* CLI Quick Reference

#+begin_src bash
# Self-identification
cmux identify                              # where am I?
cmux tree --all                            # full workspace hierarchy

# Read terminal content
cmux read-screen --surface surface:N       # visible screen
cmux read-screen --surface surface:N --scrollback --lines 100

# Send to terminal
cmux send --surface surface:N "command"
cmux send-key --surface surface:N enter

# Create workspace/panes
cmux new-workspace --cwd /path/to/project
cmux new-split right
cmux new-split down

# Notifications
cmux notify --title "Done" --body "Task complete"
cmux list-notifications
cmux clear-notifications

# Workspace management
cmux rename-workspace "my-story"
cmux select-workspace --workspace workspace:2
cmux close-workspace --workspace workspace:3

# Event synchronization
cmux wait-for my-signal --timeout 30       # block until signal
cmux wait-for -S my-signal                 # create signal

# Output processing
cmux pipe-pane --surface surface:N --command "grep error"
#+end_src

* Emacs Integration Tips

1. *Set socket mode to =automation=* — Emacs is not a cmux child process
2. *Use =cmux identify= to discover context* — don't hardcode surface IDs
3. *Session recovery*: Read =~/.cmuxterm/claude-hook-sessions.json= or call
   =cmux tree --all= to find existing workspaces after Emacs restart
4. *Avoid TAB conflicts*: cmux's shell integration and yasnippet both use TAB;
   yasnippet's conditional binding (=yas-maybe-expand=) handles this gracefully
5. *Large text*: For prompts >4KB, use =workspace.select= before =surface.send_text=

* Session Restore

On relaunch, cmux restores:
- Window/workspace/pane layout
- Working directories
- Terminal scrollback (best effort, up to 4000 lines / 400KB)
- Browser URLs

Does NOT restore: live processes (Claude Code, tmux). Use Claude Code's
=--resume= flag or =claude-hook= session store to reconnect.

* Known Limitations

- Terminal title updates suppressed when workspace unfocused
- CLI commands without =--workspace= target the focused workspace (not caller's)
- After opening browser tab, arrow keys may not work in terminal until clicked
- =pipe-pane= is one-shot capture, not continuous streaming

* cmux Notification Patterns (from cmux.dev)

** Custom Notification Command

Settings > App > Notification Command. Env vars available:
- =CMUX_NOTIFICATION_TITLE=
- =CMUX_NOTIFICATION_SUBTITLE=
- =CMUX_NOTIFICATION_BODY=

** Shell Function for Long Commands

#+begin_src bash
notify-after() {
  "$@"
  local exit_code=$?
  [ $exit_code -eq 0 ] && \
    cmux notify --title "✓ Complete" --body "$1" || \
    cmux notify --title "✗ Failed" --body "$1 (exit $exit_code)"
  return $exit_code
}

# Usage:
notify-after make test
notify-after npm run build
#+end_src

** Python / Node.js Notification

#+begin_src python
# Python — uses OSC 777 (works in any terminal, not just cmux)
import sys
def notify(title, body):
    sys.stdout.write(f'\x1b]777;notify;{title};{body}\x07')
    sys.stdout.flush()
#+end_src

#+begin_src javascript
// Node.js
function notify(title, body) {
  process.stdout.write(`\x1b]777;notify;${title};${body}\x07`);
}
#+end_src
