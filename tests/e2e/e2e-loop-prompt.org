* Phoenix Trace Verification

When Phoenix is running (localhost:6006), verify traces after each execution.
Query via GraphQL against project ID "UHJvamVjdDoy".

** Span Tree Assertions

For a standard AI block execution, verify this tree:

#+begin_example
execute-ai-block (root, parentId=null, kind=SERVER)
├── cmux-ensure-session (kind=INTERNAL)
├── cmux-execute (kind=INTERNAL)
│   └── cmux-send-text (kind=CLIENT)
├── cmux-wait-for-ready
├── cmux-query-completed
└── handle-complete (has duration-sec, tool-call-count attrs)
#+end_example

** Assertion Categories

1. Root span exists: execute-ai-block with parentId=null
2. Parent-child: cmux-execute is child of execute-ai-block
3. No errors: no span has statusCode="ERROR"
4. Span kind: root=SERVER, cmux-call=CLIENT, internal=INTERNAL
5. Attributes: custom.id matches block CUSTOM_ID, session.id matches
6. Latency: latencyMs within reasonable bounds
7. Use polling (not fixed sleep) when waiting for spans

** GraphQL Query Template

#+begin_src bash
curl -s -X POST http://localhost:6006/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"query{node(id:\"UHJvamVjdDoy\"){...on Project{
    spans(first:20,sort:{col:startTime,dir:desc}){edges{node{
      name spanId parentId spanKind statusCode startTime
      latencyMs attributes}}}}}}"}'
#+end_src

* Each Iteration

** 1. Brief Web Research

Search 1-2 targeted topics to improve current test gaps. Examples:
"E2E test organization patterns", "trace-based testing assertions",
"org-mode automation testing". Apply findings to design doc and tests.

** 2. Review and Enhance Coverage

- Read workspace-test.org, runbook, design doc, and gap analysis
- Identify highest-priority untested journey
- Add test stories with realistic content:
  - Every heading gets a unique CUSTOM_ID
  - Every workspace: CLAUDE_SESSION_ID, CLAUDE_BACKEND: cmux
  - System prompts describe realistic project contexts
  - AI queries are practical developer tasks (not "say hello")

** 3. Create cmux Workspaces

For new test workspaces lacking CMUX_WORKSPACE_ID:
#+begin_example
cmux new-workspace --name "e2e-<test-name>"
#+end_example
Update org properties with returned ID/ref.
Apply workspace color if WORKSPACE_COLOR is set.
Use production cmux (default socket, no override).

** 4. Execute and Verify

- Open workspace-test.org in Emacs via evalElisp
- Navigate by CUSTOM_ID (never heading text)
- Execute AI blocks via code-agent-org-execute
- Wait for completion, verify response in org buffer
- Verify cmux state: list-workspaces, sidebar-state, capture-pane
- Query Phoenix traces if service is running (skip-unless pattern)
- Assert: root spans, parent-child, no errors, correct attributes

** 5. Fix Issues

- Diagnose root cause in source code
- Fix, reload via literate-elisp-load, retest
- Run make test-smoke after any source edit
- Run make check if substantial changes
- Commit fixes separately from test improvements

** 6. Record Results

Update living-workspace-test.org with structured entries:
- Test ID, date, PASS/FAIL/SKIP
- Command, expected, actual
- Phoenix trace assertions if applicable
- Bugs found + fixes applied
Update design doc with lessons learned.

** 7. Quality Review

- Deduplicate: merge redundant test stories
- Verify: all CUSTOM_IDs unique, structure consistent
- Archive: move old PASS results if file > 500 lines
- Clean: remove stale properties from test workspaces

* Rules

- Production cmux socket (no CMUX_SOCKET_PATH override)
- evalElisp for Emacs operations (< 2s only)
- Bash for make check, cmux CLI, git, Phoenix queries
- Navigate org by CUSTOM_ID, never heading text
- Never delete existing test stories — only add or improve
- Never ask questions — decide autonomously
- Never enter plan mode — act directly
- After editing .org source, always reload via literate-elisp-load
- After code fixes, make test-smoke minimum
- Separate commits: test improvements vs code fixes
- Each test = real E2E (create workspace, assign story, execute AI
  block, check cmux + Emacs + optionally Phoenix) — no mock-only
