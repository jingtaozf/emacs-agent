* Operational Notes

** cmux restart cleans up E2E workspaces (expected)

When cmux is restarted (e.g., after surface degradation from many E2E
test iterations), all E2E workspaces are lost. This is expected behavior:
cmux does not persist workspace state across restarts. After restart:
1. Only pre-existing workspaces (e.g., dev workspace:5) remain
2. E2E workspace-test.org retains stale CMUX_WORKSPACE_ID/SURFACE_ID properties
3. To re-test, clear those properties from the org file (ensure-session will
   create fresh workspaces)
4. Or run =ensure-session= -- it will detect stale refs via =tree --workspace UUID=
   and auto-create new workspaces

** cmux new-workspace requires --command for working surfaces

=cmux new-workspace= without =--command= creates workspaces whose surfaces
report "Surface is not a terminal" for all I/O operations. Always use:
#+begin_example
cmux new-workspace --command "exec zsh"
#+end_example

** read-screen vs capture-pane

=capture-pane= (tmux compat API) may fail on workspace-bridge-created surfaces.
=read-screen= (native cmux API) works reliably. Prefer =read-screen= for
liveness checks and content inspection.

** E39: CMUX_GROUP org property files workspace under a named sidebar group
:PROPERTIES:
:STATUS: PASS
:ADDED: 2026-06-02
:STORY: e2e-cmux-group-a, e2e-cmux-group-b
:END:

*Background.*  cmux 0.64.11 added collapsible *workspace groups*
(=cmux workspace-group <subcommand>=).  Each group is owned by an
anchor workspace whose sidebar row IS the group header.  Emacs-agent
gained a =:CMUX_GROUP: <name>= org property so a launched workspace is
filed under that named group.  The property *inherits*
(=find-session-property= → =org-entry-get nil PROP t= + file-level
=#+PROPERTY:=), so a project-level heading groups every session beneath
it.  No property → ungrouped, exactly as before.

*Implementation.*  =code-agent-org-cmux--ensure-group-membership= runs
right after =--apply-color= in =--launch-workspace=:
- group missing → =workspace-group create --name <group> --from <ws>=
  (the *create* path; cmux titles the auto-created anchor header with
  the group name — *no "分组 N" placeholder*);
- group exists → =workspace-group add --group <ref> --workspace <ws>=
  (the *add* path; group resolved by name via
  =--find-group-by-name= parsing =workspace-group list --json=).
Best-effort: a missing subcommand (older cmux) or RPC hiccup is logged,
never signalled, so grouping can never abort a launch.
