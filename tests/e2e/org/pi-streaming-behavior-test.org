Reproduces the 2026-05-27 Pi error reported when running an ai block
while Pi was already mid-stream:

#+begin_example
[Error: Agent is already processing. Specify streamingBehavior
('steer' or 'followUp') to queue the message.]
#+end_example

Source: =reference/pi/packages/coding-agent/src/core/agent-session.ts=
line 1009 — Pi's =session.prompt()= throws this exact text when
called while a previous prompt is still streaming AND the caller
omitted the =streamingBehavior= option.

** Fix landed (2026-05-27)

Two layers cooperate:

1. *Emacs-side queue* (=lp/org/code-agent-org-queue.org=): when
   =session :busy= is set, =--queue-block= captures the new block
   onto the pending queue rather than firing a second
   =backend-query=.  This is the *primary* gate.
2. *Pi-side safety net* (=lp/backend/code-agent-pi-backend.org=):
   every =prompt= command now carries
   =streamingBehavior: followUp= (controlled by the new
   =code-agent-pi-streaming-behavior= defcustom, default
   =follow-up=).  If the Emacs queue ever misses a state
   transition (session restore, residual mid-stream from a
   crashed prior turn, etc.), Pi queues the new prompt itself
   instead of erroring out.

The unit tests in =tests/test-code-agent-pi-backend.el= assert the
payload includes the field; this fixture is the human-readable
end-to-end reproduction.

** Story 2 — second prompt while first still streaming :pi-streaming:
:PROPERTIES:
:CUSTOM_ID: pi-streaming-block-2
:EXPECTED: STREAM_SECOND_OK
:TIMEOUT: 60
:END:

Run =C-c C-c= on this block *while Story 1 is still streaming*.
With the fix, one of two paths handles it:

- Emacs-side queue catches =:busy= → block 2 enters pending queue,
  fires after block 1 completes.  Message line: "Scheduled
  [N]. Will run after current query completes."
- Pi-side =streamingBehavior: followUp= catches it if the Emacs
  queue missed → Pi queues internally + streams once block 1
  ends.

Either way, *no =[Error: Agent is already processing]= surfaces*,
and block 2 eventually replies STREAM_SECOND_OK.

#+begin_src ai
Reply with exactly the text STREAM_SECOND_OK and nothing else.
#+end_src
