* Pi Backend Test Workspace

This file is the canonical *fixture* for the Pi backend's end-to-end
test suite. Each story below is a self-contained prompt + expected
outcome; the runner at =tests/test-e2e-pi-backend.el= reads the
properties of every =:pi-e2e:= tagged heading, drives the prompt
through =code-agent-pi-backend=, and asserts against =EXPECTED=.

The stories progress from simple (text-only round trip) to the
bi-directional Pi-↔-Emacs integration enabled by the
=emacs-mcp.ts= extension.

Why a fixture file and not pure elisp? Two reasons:

1. *Reviewable* — a human reader can scan the prompts + expected
   outcomes without parsing elisp.
2. *Future C-c C-c usable* — once A3 wires the dispatch path
   (=CLAUDE_BACKEND="pi"= in =code-agent-org-execute=), the same
   stories run interactively as well as in the test harness.

Properties consumed by the runner:

| Property | Required | Meaning |
|----------|----------|---------|
| =CUSTOM_ID= | yes | Stable anchor, also used as test name |
| =EXPECTED= | yes | Substring that must appear in the streamed tokens |
| =TIMEOUT= | yes | Seconds to wait for =on-complete= or =on-error= |
| =NEEDS= | no | Comma list of extras to skip-unless: =mcp=, =extension= |
| =CANCEL_AFTER= | no | Seconds — if set, send =backend-cancel= mid-flight |
| =SHOW_THINKING= | no | If =yes=, route =thinking_delta= as tokens too |

** Story 2 — multi-line-streaming :pi-e2e:

A reply that forces multiple =text_delta= events so we exercise the

** Story 6 — confirm-gate (manual) :pi-e2e-manual:
:PROPERTIES:
:CUSTOM_ID: pi-e2e-confirm-gate
:END:

The =emacs_eval= tool is gated by an interactive =ctx.ui.confirm=
dialog in the Pi extension. In headless test runs the gate refuses
(no UI to confirm), and the LLM's reaction to a refused tool is
non-deterministic — sometimes it tries again, sometimes it
gracefully explains. This story is intentionally *not* in the
automated runner; it's here as the canonical manual-verification
scenario.

How to verify manually:

1. =M-x emacs-mcp-server-start=
2. =EMACS_MCP_VERBOSE=1 pi= (interactive TUI)
3. Send the prompt below
4. Confirm the =Allow emacs_eval?= dialog appears
5. Press =n= — LLM should fall back to text-only reasoning
6. Re-run with =EMACS_MCP_ALLOW_EVAL=1 pi= and confirm the gate is
   skipped

#+begin_src ai
Use the emacs_eval tool with code="(+ 1 2 3 4 5)" and report the result.
#+end_src
