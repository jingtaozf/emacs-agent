This fixture documents the 2026-04-22 bug observed in
=skills-network-dev.org :: * PCR dev1= where the response to the
=/loop= dynamic-mode sentinel (=<<autonomous-loop-dynamic>>=) was
silently dropped from the org buffer.

Root cause (=workspace_bridge.py=):
1. =_handle_prompt= filters any prompt whose first non-whitespace char
   is =<=.  This was right for =<task-notification>= and
   =<system-reminder>= — they're framework-internal, not human
   prompts.  But the =/loop= sentinel *also* matches, so its
   UserPromptSubmit skips queue-append.
2. When the corresponding Stop fires, the queue is empty → legacy
   path → =_mint_missing_custom_id= tries to insert a new
   instruction using =last_user_message= (often empty or the
   sentinel itself) → returns None → response silently dropped.

Fix:

* New elisp function =code-agent-org-workspace-bridge-latest-instruction
  -custom-id= walks the session's workflow, returns the newest
  =:claude_chat:= instruction's =CUSTOM_ID=.
* Python =_handle_response= legacy path now falls back to that
  function when =_mint_missing_custom_id= can't mint.  The existing
  =insert-response= MCP call then appends the response to the
  newest instruction's Response section (or creates one).
