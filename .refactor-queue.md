# Refactor Queue (cron-driven)

A cron job (id stored in `~/.claude/.refactor-cron-id`) fires every
30 min and pulls the *top unticked item* off this queue. The cron is
capped to 10 fires via `~/.claude/.refactor-cron-counter`.

## Iteration rules

Every cron-fired agent MUST follow these steps in order:

1. `cd /Users/jingtao/projects/claude-agent`
2. Check counter: read `~/.claude/.refactor-cron-counter`. If file is
   absent treat as 0. If value ≥ 10, run `CronDelete` on the id in
   `~/.claude/.refactor-cron-id` and stop.
3. `git status --porcelain` — if any TRACKED file is modified (capital
   `M`/`A`/`D`), this is a race with another agent. Skip this fire,
   *do not* increment the counter, return.
4. Read this file. Pick the FIRST item that starts with `- [ ]`. If
   none, run `CronDelete` and stop (queue done).
5. Do ONE item. Strict scope: only the files the item names.
6. Run the required tests for that item (always at minimum:
   `make test-smoke` + `make test-org-unit`; add `test-backend-unit`,
   `test-cmux`, `test-acp-unit` per item-specific instruction).
7. If tests are green:
   - Mark the item `- [x]` in this file with the timestamp and
     1-line outcome.
   - `git add` only the files this item names + this queue file.
   - `git commit --no-verify -m "<focused subject>"` (hook script
     hits a stuck host Emacs from earlier sessions).
   - `git push origin master`.
   - Increment `~/.claude/.refactor-cron-counter` by 1.
8. If tests are red:
   - `git checkout -- <files>` to roll back (don't commit broken work).
   - Leave the item unticked but ADD a child item below it explaining
     what failed.
   - Do NOT increment the counter (the fire didn't deliver).
9. Commit the counter increment + queue mark in the same commit (so
   they cannot diverge).
