# pi-topic embed points → pi-coding-agent public API

Source: `reference/pi-coding-agent` @ **v2.7.0** (`60c53bd`, detached).
Every `file:line` below was verified against that checkout.

| Need | Public API (symbol + file:line) | Private fallback if no public API | Upstream PR needed? |
|---|---|---|---|
| 1. Create a session non-interactively for a given directory + name | `pi-coding-agent` — `pi-coding-agent.el:238`, `;;;###autoload`, `(&optional session)`. Non-interactive call: `(let ((default-directory dir)) (pi-coding-agent "topic-name"))` | `pi-coding-agent--setup-session` — `pi-coding-agent.el:118`, `(dir &optional session)`, takes dir **explicitly** and **returns the chat buffer**. Needed because (a) the public entry derives its dir from `pi-coding-agent--session-directory` (`pi-coding-agent-ui.el:902`), which prefers `(project-root (project-current))` — so a topic dir inside a git repo silently becomes the repo root; (b) `pi-coding-agent` returns the value of `pi-coding-agent--show-session-buffers`, not the buffer; (c) it always displays windows | **Yes** — ask for a non-interactive constructor, e.g. `(pi-coding-agent-create-session DIR &optional SESSION NO-DISPLAY)` returning the chat buffer, honouring DIR verbatim |
| 2. Resume/attach from an absolute `~/.pi/agent/sessions/*.jsonl` path | `pi-coding-agent-open-session-file` — `pi-coding-agent.el:260`, `;;;###autoload`, `(session-file)`, returns the chat buffer. **Unusable for pi-topic**: it calls `pi-coding-agent--setup-session` with **no session name** (`pi-coding-agent.el:272`), so the transcript lands in the *unnamed* buffer for that dir. Measured on a live run — after reap+resume the buffer went from `*pi-coding-agent-chat:<dir><pi-…-od9f>*` to `*pi-coding-agent-chat:<dir>*`, and `--find-session` on the topic's own (cwd, id) returned nil forever | **Required, and it is what pi-topic ships.** Get a named session first (`--find-session`, else `--setup-session`), then switch it onto the transcript the way upstream's own resume does: `pi-coding-agent--get-process` (`pi-coding-agent-ui.el:1509`) → `pi-coding-agent--rpc-async` (`pi-coding-agent-core.el:466`) with `(:type "switch_session" :sessionPath PATH)` → on `:success` only, `pi-coding-agent--refresh-session-state` (`pi-coding-agent-menu.el:620`, arity `(2 . 5)`) and `pi-coding-agent--load-session-history` (`pi-coding-agent-menu.el:529`, arity `(2 . 4)`). Model: `pi-coding-agent--resume-selected-session`, `pi-coding-agent-menu.el:752`. Cost: the private surface grows from 2 symbols to 6 | **Yes — resume into a NAMED session.** Either a `SESSION` argument on `pi-coding-agent-open-session-file`, or a public `(pi-coding-agent-switch-session CHAT-BUF PATH)` that performs the switch+refresh+history sequence on an existing named session. Either one collapses four guarded private symbols back to zero |
| 3. Send a prompt programmatically to a specific session | `pi-coding-agent-send` — `pi-coding-agent-input.el:305`. Drive it as: `(with-current-buffer input-buf (erase-buffer) (insert text) (pi-coding-agent-send))`. It reads `(buffer-string)`, resolves the chat buffer itself, and auto-queues as a follow-up when Pi is busy. For slash commands only: `pi-coding-agent-run-command` — `pi-coding-agent-menu.el:1433`, `(name &optional args)`, call inside `(with-current-buffer chat-buf …)` | `pi-coding-agent--prepare-and-send` — `pi-coding-agent-render.el:703`, `(text &optional queued)`, called in the chat buffer. Only needed to bypass the input buffer entirely (no buffer mutation, no busy-queue policy) | **Optional** — `(pi-coding-agent-send-text CHAT-BUF TEXT)` would remove the erase/insert dance; the buffer-driven route works today |
| 4. Learn a turn finished **and** get the final assistant text | Finish signal: `pi-coding-agent-activity-phase-functions` — `pi-coding-agent-ui.el:137`, abnormal hook, `(CHAT-BUFFER INPUT-BUFFER OLD-PHASE NEW-PHASE REASON)`; turn end = NEW-PHASE `"idle"` with REASON `phase-change` (dispatched from `pi-coding-agent--set-activity-phase`, `pi-coding-agent-ui.el:1234`; run via `pi-coding-agent--run-activity-phase-functions`, `pi-coding-agent-ui.el:1217`). Text: `pi-coding-agent-copy-last-message` — `pi-coding-agent-menu.el:1211`, but it only `kill-new`s the text and takes no callback | Text retrieval: `pi-coding-agent--rpc-async` (`pi-coding-agent-core.el:466`, `(process command callback)`) with `'(:type "get_last_assistant_text")` on the process from `pi-coding-agent--get-process` (`pi-coding-agent-ui.el:1509`); read `(plist-get (plist-get response :data) :text)` — exactly what `copy-last-message` does internally | **Yes** — for the text half. Either a public `(pi-coding-agent-last-assistant-text CHAT-BUF CALLBACK)`, or a 6th `TEXT` argument on the phase hook. The phase hook itself is sufficient and needs no PR |
| 5. Find the chat buffer belonging to a topic/session name | `pi-coding-agent-project-buffers` — `pi-coding-agent-ui.el:989`, returns live chat buffers whose canonical session dir matches the **current** project dir, `buffer-list` order. No name filter, no dir argument | `pi-coding-agent--find-session` — `pi-coding-agent-ui.el:946`, `(dir &optional session)`, exact (dir, name) → chat buffer; matches the *canonical* identity so it still works after the buffer is renamed by a transcript visit. Name-only filter over the public list: `pi-coding-agent--chat-session-name` (`pi-coding-agent-ui.el:803`). Do **not** reconstruct the name with `get-buffer` — the format lives in the private `pi-coding-agent--buffer-name` (`pi-coding-agent-ui.el:933`) and live buffer names drift | **Yes** — publish a lookup taking (dir, session) and/or give `pi-coding-agent-project-buffers` optional DIR + SESSION arguments. This is the single most-needed PR: one topic = one named session, and there is no public way to address it |
| 6. Reap a session (kill process + buffers) | `pi-coding-agent-quit` — `pi-coding-agent-input.el:349`; call inside `(with-current-buffer chat-buf …)` (it resolves both buffers itself). Kills chat then input (`pi-coding-agent-input.el:374-377`), clears `process-query-on-exit-flag`, deletes input windows. Bind `pi-coding-agent-quit-without-confirmation` (`pi-coding-agent-ui.el:237`) to `t` to suppress the `yes-or-no-p` on a live process | None required. `pi-coding-agent--get-chat-buffer` (`pi-coding-agent-ui.el:1495`) only if you must resolve the buffer from an input buffer without entering it | **No** |

## Summary

Public-only coverage: needs 2 (single unnamed session per dir), 3, 6.
Needs 1, 4, 5 each require at least one private symbol today; need 5 is
the hard blocker for concurrent per-topic sessions.
