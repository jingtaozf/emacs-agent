* Invariants

These must always be true:

- Every public function has a docstring
- Every test file appears in a Makefile target
- Session state lives in hash tables, never global variables
- Process filters/sentinels wrapped in condition-case (F36 enforces)
- All code lives in =#+begin_src elisp= blocks (literate-elisp requirement)
- Timer callbacks check liveness before operating on process/buffer
- Test failures include =FIX:= remediation messages

* Absence Constraints

These do NOT exist in the codebase:

| Constraint                                      | Why                                    |
|-------------------------------------------------+----------------------------------------|
| claude-agent.org has no org-mode dependency      | Core SDK must work without org         |
| emacs-mcp-server.org has no claude-* dependency  | Reusable as standalone MCP server      |
| No circular dependencies between modules         | Load order would break                 |
| No hardcoded paths in test files                 | Portable CI                            |
| literate-elisp ignores lexical-binding: t        | Use lexical-let for closures           |
| Tests never live inside .org files               | Always in tests/*.el                   |
| No global mutable state                          | Session state keyed by buffer-local    |
| No iTerm2 references in source .org files        | Backend removed; use generic terms     |
| No standalone =claude-agent--active-states= var  | Registry is sole owner; prevents split-brain |
| No unguarded =(if parsed ...)= in JSON dispatch | Must check =(listp parsed)= first; bare JSON crashes |

* Literate Programming

Elisp source in .org files loaded by literate-elisp. Key constraints:
=lexical-let= for closures, =cond=+equal= for string dispatch. See
=.claude/rules/literate-programming-document-first.md= for the full
document-first protocol plus mechanical org conventions (heading levels,
block naming, property inheritance).

* Python LP

=claude-agent-python.org= (tangle to =python/claude_agent/*.py=). =make tangle-python=, =make check-python-structure=. Hook blocks direct .py edits.

* Tri-Protocol Architecture

Shipped 2026-04-24 (Phases 0–4). Full design in =claude-agent-backend.org=
→ "Tri-Protocol Architecture". Four protocols — lifecycle
(=claude-agent-backend-*=), agent-wire (=claude-agent-agent-*=),
mux-wire (=claude-agent-mux-*=), org-integration (=claude-org-backend-*=).
Families: agent (claude-code, opencode, gemini, codex) and multiplexer
(cmux, tmux), symmetric siblings. Frontend dispatches via Protocol 3
generics on the backend instance — no =CLAUDE_BACKEND= string-match.

* Removed Backends

Three pre-Tri-Protocol approaches deleted in commit =1038144= once
cmux + tmux covered the same ground better. Listed for the lesson:

| Removed | Tried | Why it lost |
|---------+-------+-------------|
| iTerm2 driver | =iterm2-ctl= + screen-scrape | macOS-only; brittle; cmux has native hooks |
| Native eat / vterm | Run Claude in-Emacs terminal | Emacs main thread blocks; can't survive process restart |
| In-Emacs harness (general) | Various wrappers | External multiplexer wins on every axis |

What survived: the =--active-queries= registry / mode-line spinner /
=*Claude Queries*= buffer (now drive cmux + tmux); the JSON-stream
path — see =claude-agent-backend.org= → "JSON Stream Backend" →
"Design Heritage".
