* Invariants

These must always be true:

- Every public function has a docstring
- Every test file appears in a Makefile target
- Session state lives in hash tables, never global variables
- Process filters never signal errors (kills the process)
- All code lives in =#+begin_src elisp= blocks (literate-elisp requirement)
- Timer callbacks check liveness before operating on process/buffer
- Test failures include =FIX:= remediation messages

* Absence Constraints

These do NOT exist in the codebase:

| Constraint                                      | Why                                    |
|-------------------------------------------------+----------------------------------------|
| claude-agent.org has no org-mode dependency      | Core SDK must work without org         |
| emacs-mcp-server.org has no claude-* dependency  | Reusable as standalone MCP server      |
| No circular dependencies between modules         | Load order would break                 |
| No hardcoded paths in test files                 | Portable CI                            |
| literate-elisp ignores lexical-binding: t        | Use lexical-let for closures           |
| Tests never live inside .org files               | Always in tests/*.el                   |
| No global mutable state                          | Session state keyed by buffer-local    |

* Extension Points

| To add...              | Go here                                                    |
|------------------------+------------------------------------------------------------|
| New backend            | Create claude-agent-BACKEND.org, add to claude-code.el     |
| New MCP tool           | Call =emacs-mcp-server-register-tool= from any module      |
| New structural test    | Add =ert-deftest= to test-structural.el with =FIX:= msg   |
| New org sub-module     | Create claude-org-NAME.org, add to claude-code.el/Makefile |
| New test file          | Create tests/test-NAME.el, add to Makefile target          |
| New behavior prompt    | Add .org file to prompts/tags/                             |

* Development Lifecycle

#+begin_example
  Edit .org  ──>  Reload  ──>  Smoke  ──>  Unit
     │               │           │           │
  any .org     M-x literate-   make        make
   file        elisp-load    test-smoke  test-unit
#+end_example

Key constraints for literate-elisp:
- Use =lexical-let= for closures (lexical-binding header is ignored)
- Use =cond= + =equal= instead of =pcase= string patterns
- Prose before code explains intent; section headings are the docs

* Literate Programming

All source lives in .org files loaded by literate-elisp. Section headings
serve as module documentation. See =docs/literate-programming-principles.org=
for full guidelines.
