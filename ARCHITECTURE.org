* Invariants

- Every public function has a docstring
- Every test file appears in a Makefile target
- Session state lives in hash tables, never global variables
- Process filters/sentinels wrapped in condition-case (F36 enforces)
- All code lives in =#+begin_src elisp= blocks (literate-elisp requirement)
- Timer callbacks check liveness before operating on process/buffer
- Test failures include =FIX:= remediation messages

* Absence Constraints

| Constraint                                      | Why                                    |
|-------------------------------------------------+----------------------------------------|
| code-agent.org has no org-mode dependency      | Core SDK must work without org         |
| emacs-mcp-server.org has no claude-* dependency  | Reusable as standalone MCP server      |
| No circular dependencies between modules         | Load order would break                 |
| No hardcoded paths in test files                 | Portable CI                            |
| literate-elisp ignores lexical-binding: t        | Use lexical-let for closures           |
| Tests never live inside .org files               | Always in tests/*.el                   |
| No global mutable state                          | Session state keyed by buffer-local    |
| No iTerm2 references in source .org files        | Backend removed; use generic terms     |
| No standalone =code-agent--active-states= var  | Registry is sole owner; prevents split-brain |
| No unguarded =(if parsed ...)= in JSON dispatch | Must check =(listp parsed)= first; bare JSON crashes |

* Literate Programming

=lexical-let= for closures, =cond=+equal= for string dispatch. The full
document-first protocol + mechanical org conventions (heading levels,
block naming, property inheritance) live in the imported literate-agent
=literate-programming-document-first.md= rule (see =CLAUDE.md= top).

* Tri-Protocol Architecture

Shipped 2026-04-24 (Phases 0–4). Full design in =code-agent-backend.org=
→ "Tri-Protocol Architecture". Three protocols — lifecycle
(=code-agent-backend-*=), mux-wire (=code-agent-mux-*=),
org-integration (=code-agent-org-backend-*=). The agent-wire layer retired
2026-05; agent backends inherit lifecycle base directly. The ACP agent
family (opencode, gemini, codex) and =code-agent-claude-code-backend=
(the JSON-stream agent backend) were both removed by 2026-07 — zero
production callers survived the org-as-control-plane pivot. Only the
multiplexer family (cmux, tmux) remains; Pi runs as a cmux agent
profile, not a distinct backend. Frontend dispatches via Protocol 3
generics.

*Single-page reference*: [[file:lp/sdk/PROTOCOL-MAP.org][lp/sdk/PROTOCOL-MAP.org]] — every
=cl-defgeneric= × every backend, with "specialised by" + test-
coverage columns.  Consult before adding a new backend or a new
generic.

* Removed Backends

Pre-Tri-Protocol approaches deleted in commit =1038144= once cmux + tmux
covered the same ground better:

| Removed | Tried | Why it lost |
|---------+-------+-------------|
| iTerm2 driver | =iterm2-ctl= + screen-scrape | macOS-only; brittle; cmux has native hooks |
| Native eat / vterm | Run Claude in-Emacs terminal | Emacs main thread blocks; can't survive process restart |
| In-Emacs harness (general) | Various wrappers | External multiplexer wins on every axis |

Survived: =--active-queries= registry / mode-line spinner /
=*Claude Queries*= buffer (now drive cmux + tmux). The JSON-stream
path itself (=code-agent-claude-code-backend= and the process-lifecycle
wiring around it) did not survive — deleted 2026-07, zero production
callers once cmux/tmux covered execution entirely.
