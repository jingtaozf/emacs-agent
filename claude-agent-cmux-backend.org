* Claude Agent — cmux Backend
:PROPERTIES:
:header-args:elisp: :tangle yes
:END:

Concrete multiplexer backend for cmux, the macOS-native terminal
multiplexer (Swift + Ghostty) with first-class Claude Code integration.
Subclass of =claude-agent-multiplexer-backend= implementing Protocol 2b
(multiplexer wire) and Protocol 3 overrides specific to cmux.

** Why cmux Earned a Dedicated Backend

cmux is not "just another terminal" — three of its properties shaped
this backend's design:

- =claude-hook= CLI subcommand: cmux natively runs hook handlers on
  SessionStart / UserPromptSubmit / PreToolUse / Notification / Stop /
  SessionEnd. We coexist with cmux's built-in hooks (sidebar status,
  notification cache) instead of replacing them. =claude-hook= is
  registered in cmux's global settings; our =workspace-bridge= is
  registered in this plugin's =hooks.json=; both fire and they do not
  conflict.
- Rich sidebar API: =cmux set-status=, =set-progress=, =report_meta_block=,
  =markdown open= give us a per-workspace status surface that no other
  multiplexer offers. The Sidebar Feedback section in
  =code-agent-org-cmux.org= uses this.
- 100+ CLI methods over a Unix-domain socket, dual-protocol (V1 text +
  V2 JSON-RPC, auto-detected). Reliable, scriptable, and the daemon
  exposes a =cmuxOnly= PID-ancestry security mode so any process not
  descended from cmux is refused. The CLI Gateway section in
  =code-agent-org-cmux.org= documents the dialect.

** Two-Module Split: Facade Here, Legacy Body Elsewhere

Thin facade — the bulk of cmux-driving Elisp (launch pipeline,
send-text path, capture/follower, verbose buffer, agent profiles,
workspace colour, IDE server, sidebar feedback, permission-needed
alerts, session recovery) still lives in =code-agent-org-cmux.org=
(2 000+ lines).  Protocol 2b / Protocol 3 methods below delegate to
=code-agent-org-cmux--*=.

The split is intentional and temporary: a later phase will fold the
legacy body up into this file once the multiplexer family stabilises
across cmux and tmux.  Until then, keeping the two layers separate
makes the wire surface cheaper to evolve.

** Class

cmux-specific state: the Unix-domain socket path (when overridden),
the workspace UUID returned by =cmux new-workspace=, and cosmetic
niceties (workspace colour, icon) that cmux exposes but tmux does not.

#+BEGIN_SRC elisp
(cl-defstruct (claude-agent-cmux-backend
               (:include claude-agent-multiplexer-backend (type :cmux))
               (:constructor claude-agent-cmux-backend--create)
               (:copier nil))
  "Concrete cmux-driven terminal backend.
Slots in addition to those inherited from
`claude-agent-multiplexer-backend':
- `socket-path': overrides the auto-detected cmux CLI socket.
- `workspace-uuid': cmux's workspace identifier (distinct from the
  user-visible workspace heading name).
- `workspace-color': hex color for the sidebar pill (cmux only).
- `workspace-icon': SF Symbol name for the sidebar pill (cmux only)."
  (socket-path     nil)
  (workspace-uuid  nil)
  (workspace-color nil)
  (workspace-icon  nil))
#+END_SRC

*** Start / Stop Follower

=code-agent-org-cmux--start-verbose= and =--stop-verbose= already
implement the =capture-pane --follow= stream with the 256 KB cap +
kill-buffer-hook from the 2026-04-24 memory-leak fix.  The Protocol
2b generics forward to them unchanged.

#+BEGIN_SRC elisp
(cl-defmethod claude-agent-mux-start-follower
  ((backend claude-agent-cmux-backend) _sink)
  "Start the verbose follower for BACKEND's session.
SINK is ignored — cmux uses an in-Emacs buffer, not a file sink."
  (let ((sk (claude-agent-multiplexer-backend-session-key backend))
        (sf (claude-agent-multiplexer-backend-pane-id backend)))
    (when (and sk sf)
      (code-agent-org-cmux--start-verbose sf sk))))

(cl-defmethod claude-agent-mux-stop-follower
  ((backend claude-agent-cmux-backend))
  "Stop the follower subprocess for BACKEND's session."
  (when-let* ((sk (claude-agent-multiplexer-backend-session-key backend)))
    (code-agent-org-cmux--stop-verbose sk)))
#+END_SRC

** Protocol 3 — cmux-specific overrides

*** Execute Block

Delegate to the legacy =code-agent-org-cmux--execute-ai-block= which
handles the full cmux launch/send/register/verbose-start pipeline.
Unlike agent-family backends where Protocol 3 =execute-block=
unpacks =block-info= explicitly, cmux's legacy function reads the
block from point — =block-info= is effectively redundant for now
(the caller has already navigated to the block).

#+BEGIN_SRC elisp
(cl-defmethod claude-org-backend-execute-block
  ((_backend claude-agent-cmux-backend) _block-info)
  "Execute the AI block at point via the cmux legacy pipeline.
Ignores BLOCK-INFO; reads the block from `point' because that's what
the legacy function does.  Returns no cancel handle — cancellation
goes through `cancel-from-org' which dispatches to
`code-agent-org-cmux-cancel'."
  (code-agent-org-cmux--execute-ai-block)
  ;; No meaningful cancel handle for multiplexer backends today —
  ;; cancellation flows through send-key :escape / :ctrl-c instead.
  nil)
#+END_SRC
