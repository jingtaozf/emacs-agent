Backend module containing the bulk of the Claude Agent SDK logic:
shared utilities, process management, JSON protocol, core and client APIs,
backend protocol abstractions, and concrete backend implementations.

* Overview
:PROPERTIES:
:CUSTOM_ID: backend-overview
:END:

This file is the backend layer's home — both the *protocol* (Protocol 1
lifecycle generics + Protocol 3 org-integration generics, dispatched on
the abstract =code-agent-backend= struct) and the *concrete shipped
agent backend* (=code-agent-claude-code-backend=, the JSON-stream-
over-stdio family). The two-family split — agent-family vs multiplexer-
family — comes from two inheritance roots: agent backends subclass
this file's =code-agent-backend= directly; multiplexer backends
subclass =code-agent-multiplexer-backend= in
[[file:../backend/code-agent-multiplexer.org][code-agent-multiplexer.org]], which in turn inherits the protocols
defined here.

Read order if you're new to this file:

1. * Tri-Protocol Architecture (high-level meta-design — why three
   protocols, two families, what the capability matrix is for).
2. * Backend Protocol (Protocol 1 + Protocol 3 generic declarations).
3. * JSON Stream Backend (the concrete claude-code-backend — wire,
   completion-model invariants, design heritage).
4. Everything else (process management, JSON parsing, control-request
   handling, verbose buffer, query cancellation) — implementation
   details the protocol layers consume.

The file is large (~4400 lines) because the concrete JSON-stream backend
is large; the protocol surface itself is thin (~150 lines).

*** Input Validation

Input validation layer to prevent security issues and denial-of-service attacks.

*** Answer Validation

Defensive guard on =AskUserQuestion= responses — the user's answer is forwarded verbatim to the LLM, so a length cap stops accidental megabyte responses (often a paste-buffer mishap) from flooding the prompt.

#+BEGIN_SRC elisp
(defun code-agent--validate-answer (answer)
  "Validate ANSWER string for AskUserQuestion responses.
Signals error if answer exceeds `code-agent-max-answer-length'.
Returns t if valid, nil for nil/empty input (valid no-answer)."
  (cond
   ((null answer) t)
   ((stringp answer)
    (if (> (length answer) code-agent-max-answer-length)
        (error "Answer exceeds maximum length of %d characters"
               code-agent-max-answer-length)
      t))
   (t (error "Answer must be a string or nil"))))
#+END_SRC

*** File Path Validation

Defensive guard on file paths — null-byte injection and other shell-escape patterns are rejected before reaching any tool that opens the file or shells out with it.

#+BEGIN_SRC elisp
(defun code-agent--validate-file-path (path)
  "Validate file PATH for suspicious patterns.
Signals error if path contains null bytes or other dangerous patterns.
Returns t if valid."
  (cond
   ((null path) (error "File path cannot be nil"))
   ((not (stringp path)) (error "File path must be a string"))
   ;; Null bytes can truncate path security checks
   ((string-match-p "\x00" path)
    (error "File path contains null byte"))
   (t t)))
#+END_SRC

*** Command Validation

Defensive guard on Bash-tool commands — length cap prevents runaway prompt injection from issuing megabyte-sized shell commands.

#+BEGIN_SRC elisp
(defun code-agent--validate-command (command)
  "Validate COMMAND string for Bash tool.
Signals error if command exceeds `code-agent-max-command-length'.
Returns t if valid."
  (cond
   ((null command) (error "Command cannot be nil"))
   ((not (stringp command)) (error "Command must be a string"))
   ((> (length command) code-agent-max-command-length)

*** Docker Command Detection

Recognises =docker run= / =docker-compose= / =docker exec= CLI shapes — drives the Docker-mode branch that routes subsequent invocations into the container.

#+BEGIN_SRC elisp
(defun code-agent--docker-command-p (cmd)
  "Return non-nil if CMD is a Docker command.
Detects 'docker run', 'docker-compose', and 'docker compose' patterns."
  (and cmd
       (stringp cmd)
       (string-match-p
        (rx bos (* space)
            (or "docker run"
                "docker-compose"
                "docker compose"))
        cmd)))

(defun code-agent--split-command (cmd)
  "Split CMD string into a list of arguments.
Handles quoted strings and basic shell syntax.
For non-Docker commands, returns a single-element list."
  (if (code-agent--docker-command-p cmd)
      (split-string-and-unquote cmd)
    (list cmd)))

(defun code-agent--extract-compose-file-from-command (cmd)
  "Extract compose file path from Docker command CMD.
Looks for -f or --file flag followed by the path.
Returns the compose file path or nil if not found."
  (when (and cmd (stringp cmd))
    (let ((args (split-string-and-unquote cmd)))
      (cl-loop for (arg next) on args
               when (and (member arg '("-f" "--file"))
                         next)
               return next))))
#+END_SRC

*** Docker Compose Directory Discovery

Finds the =docker-compose.yml= owning the configured CLI — needed so subsequent =docker compose= calls run with the correct working directory regardless of where Emacs was started.

#+BEGIN_SRC elisp
(defun code-agent--find-compose-dir (&optional cli-path project-root)
  "Find directory containing docker-compose.yml for Claude.

Optional CLI-PATH is the Docker command which may contain -f flag.
Optional PROJECT-ROOT is the project directory for resolving relative paths.

Search order:
1. Extract from CLI-PATH -f flag (absolute or relative to PROJECT-ROOT)
2. .devcontainer/ in PROJECT-ROOT
3. .devcontainer/ in directory hierarchy from PROJECT-ROOT
4. docker-compose.yml directly in PROJECT-ROOT
5. docker-compose.yml in directory hierarchy from PROJECT-ROOT

Returns the directory path or nil if not found."
  (let ((search-dir (or project-root default-directory)))
    (or
     ;; 1. Extract from CLI command -f flag
     (when-let* ((compose-file (code-agent--extract-compose-file-from-command cli-path)))
       (let* ((expanded (if (file-name-absolute-p compose-file)
                            compose-file
                          (expand-file-name compose-file (or project-root default-directory))))
              (dir (file-name-directory expanded)))
         (when (file-exists-p expanded)
           dir)))
     ;; 2. Look for .devcontainer/docker-compose.yml from project-root
     (when project-root
       (let ((devcontainer (expand-file-name ".devcontainer" project-root)))
         (when (file-exists-p (expand-file-name "docker-compose.yml" devcontainer))
           devcontainer)))
     ;; 3. Look for .devcontainer in directory hierarchy
     (when-let* ((project-dir (locate-dominating-file search-dir ".devcontainer")))
       (let ((devcontainer (expand-file-name ".devcontainer" project-dir)))
         (when (file-exists-p (expand-file-name "docker-compose.yml" devcontainer))
           devcontainer)))
     ;; 4. Look for docker-compose.yml directly in project-root
     (when (and project-root
                (file-exists-p (expand-file-name "docker-compose.yml" project-root)))
       project-root)
     ;; 5. Look for docker-compose.yml in directory hierarchy
     (locate-dominating-file search-dir "docker-compose.yml"))))
#+END_SRC

*** Container Status Check

(defun code-agent--docker-container-running-p (&optional cli-path project-root)
  "Check if the Claude Docker container is running.
Uses docker compose ps to check container status.

Optional CLI-PATH is the Docker command which may contain -f flag.
Optional PROJECT-ROOT is the project directory for resolving relative paths."
  (let ((compose-dir (code-agent--find-compose-dir cli-path project-root)))

             (cmd (format "docker compose ps --status running -q %s 2>/dev/null"

             (output (shell-command-to-string cmd)))

*** Container Startup

Brings the Claude container up if it isn't running.  Called lazily from the first Docker-mode query so cold-starts are transparent to the user.

#+BEGIN_SRC elisp
(defun code-agent--ensure-docker-container (&optional cli-path project-root)
  "Ensure the Claude Docker container is running.
Starts the container if not already running.

Optional CLI-PATH is the Docker command which may contain -f flag.
Optional PROJECT-ROOT is the project directory for resolving relative paths.

Returns t if container is ready, signals error on failure."
  (if (code-agent--docker-container-running-p cli-path project-root)
      t
    (let ((compose-dir (code-agent--find-compose-dir cli-path project-root)))
      (unless compose-dir
        (error "Cannot find docker-compose.yml for Claude container"))
      (message "Starting Claude Docker container...")
      (let* ((default-directory compose-dir)
             (output-buffer (get-buffer-create "*docker-compose-output*"))
             (exit-code (with-current-buffer output-buffer
                          (erase-buffer)
                          (call-process "docker" nil t nil "compose" "up" "-d"))))
        (unless (zerop exit-code)
          (error "Docker compose up failed (exit code %d). See *docker-compose-output* buffer"
                 exit-code)))
      ;; Wait for container to be ready (includes Claude Code installation)
      (let ((retries 30)  ; 30 seconds max
            (ready nil))
        (while (and (> retries 0) (not ready))
          (sleep-for 1)
          (setq ready (code-agent--docker-container-running-p cli-path project-root))
          (cl-decf retries))
        (if ready
            (progn
              (message "Claude Docker container ready")
              t)
          (error "Failed to start Claude Docker container (timeout)"))))))
#+END_SRC

*** Process Environment

=process-environment= assembly — collects =CLAUDE_*= env vars, the Bun memory cap, and per-session identifiers into the child process's environment before =start-process=.

#+BEGIN_SRC elisp
(defcustom code-agent-bun-memory-limit nil
  "Memory limit in bytes for Bun's JSC heap via BUN_JSC_forceRAMSize.
When non-nil, this value is injected into the subprocess environment,
telling Bun's JavaScriptCore engine to treat available RAM as this many
bytes.  This constrains JS heap growth and triggers GC earlier, helping
prevent OOM kills (signal 9) on macOS.

Recommended value: (* 3 1024 1024 1024) for 3 GB.
Set to nil to disable (default)."
  :type '(choice (integer :tag "Bytes")
                 (const :tag "Disabled" nil))
  :group 'code-agent)

(defvar code-agent--stripped-env-vars '("CLAUDECODE")
  "Environment variables to strip when spawning Claude CLI subprocesses.
Claude CLI refuses to launch when CLAUDECODE is set (nested session detection).
Our SDK must unset it so Emacs users can run queries from within a Claude Code session.")

(defun code-agent--build-process-environment (env-vars cli-dir)
  "Build process environment for a Claude CLI subprocess.
ENV-VARS is an alist of (NAME . VALUE) pairs to add.
CLI-DIR is the directory of the CLI binary (prepended to PATH), or nil.
Strips variables listed in `code-agent--stripped-env-vars'.
Injects BUN_JSC_forceRAMSize when `code-agent-bun-memory-limit' is set."
  (let ((base-env (cl-remove-if
                   (lambda (entry)
                     (cl-some (lambda (var)
                                (string-prefix-p (concat var "=") entry))
                              code-agent--stripped-env-vars))
                   process-environment)))
    (append
     (when cli-dir
       (list (concat "PATH=" cli-dir ":" (getenv "PATH"))))
     ;; Bun memory tuning: cap JSC heap to prevent OOM kills
     (when code-agent-bun-memory-limit
       (list (format "BUN_JSC_forceRAMSize=%d" code-agent-bun-memory-limit)))
     (mapcar (lambda (pair)
               (format "%s=%s" (car pair) (cdr pair)))
             env-vars)
     base-env)))

(defun code-agent--kill-child-processes (pid)
  "Kill all child processes of process with PID.
This prevents orphaned shells from surviving after the main process exits.
PID is guaranteed to be a number from `process-id', so shell injection is not possible."
  (when (and pid (> pid 0))
    (let ((child-pids (split-string
                      (string-trim
                       (shell-command-to-string
                        (format "pgrep -P %d 2>/dev/null" pid)))
                      "\n" t)))
      (dolist (child-pid child-pids)
        (let ((cpid (string-to-number child-pid)))
          (when (> cpid 0)
            (signal-process cpid 9)))))))

(defun code-agent--kill-process-tree (process &optional signal)
  "Kill PROCESS and all its descendant processes.
SIGNAL defaults to SIGKILL (9).  On Unix, child shells (zsh, bash) create
their own process groups via setsid/setpgid, so killing just the parent or
its process group leaves grandchildren orphaned.  This function uses pgrep
to find all descendants and kills them bottom-up."
  (when (process-live-p process)
    (let ((pid (process-id process))
          (sig (or signal 9)))
      (when pid
        ;; Kill descendants first (children, grandchildren, etc.)
        ;; pgrep -P finds direct children; we recurse via the shell
        (let ((desc-pids (split-string
                          (string-trim
                           (shell-command-to-string
                            (format "pgrep -P %d 2>/dev/null" pid)))
                          "\n" t)))
          (dolist (child-pid desc-pids)
            (let ((child-pid-num (string-to-number child-pid)))
              (when (> child-pid-num 0)
                ;; Recursively kill grandchildren first
                (let ((grandchild-pids
                       (split-string
                        (string-trim
                         (shell-command-to-string
                          (format "pgrep -P %s 2>/dev/null" child-pid)))
                        "\n" t)))
                  (dolist (gc-pid grandchild-pids)
                    (let ((gc-pid-num (string-to-number gc-pid)))
                      (when (> gc-pid-num 0)
                        (signal-process gc-pid-num sig)))))
                (signal-process child-pid-num sig)))))
        ;; Finally kill the main process
        (kill-process process)))))

  "Clear session mapping for SESSION-KEY.

  (when session-key
    (remhash session-key code-agent--session-mapping)
    ;; Optionally kill verbose buffer
    (when code-agent-verbose-buffer-auto-kill
      (when-let* ((buf (gethash session-key code-agent--session-verbose-buffers)))

          (kill-buffer buf)))
      (remhash session-key code-agent--session-verbose-buffers))
    (code-agent--debug-log "Session cleared: %s" session-key)))

(defun code-agent--session-expired-p (error-message)
  "Check if ERROR-MESSAGE indicates session expiration.

*** Argument Builder

The argument builder transforms the options plist into CLI arguments for the

*** Core Argument Builder

Build the complete argument list by combining base arguments with option-specific
flags. The function processes options in groups: execution limits, permissions,
tool controls, session management, and output format.

#+NAME: arg-builder-main
#+BEGIN_SRC elisp
(defun code-agent--build-args (options &optional streaming-p)
  "Build CLI arguments from OPTIONS plist.
If STREAMING-P is non-nil, use streaming input mode."
  (let ((args (list "--output-format" "stream-json" "--verbose")))
    ;; === Execution Limits ===
    (let ((system-prompt (plist-get options :system-prompt)))
      (when system-prompt
        (setq args (append args (list "--system-prompt" system-prompt)))))
    (let ((max-turns (plist-get options :max-turns)))
      (when max-turns
        (setq args (append args (list "--max-turns" (number-to-string max-turns))))))
    (let ((max-budget (plist-get options :max-budget-usd)))
      (when max-budget
        (setq args (append args (list "--max-budget-usd" (number-to-string max-budget))))))

    ;; === Permission Mode ===
    (let ((perm-mode (plist-get options :permission-mode)))
      (when perm-mode
        (let ((mode-str (code-agent--permission-mode-to-string perm-mode)))
          (when mode-str
            (setq args (append args (list "--permission-mode" mode-str)))))))

    ;; === Permission Callback (requires streaming mode for control protocol) ===
    (when (and streaming-p code-agent-permission-functions)
      (setq args (append args (list "--permission-prompt-tool" "stdio"))))

    ;; === Tool Controls ===
    (let ((allowed-tools (plist-get options :allowed-tools)))
      (when allowed-tools
        (setq args (append args (list "--allowedTools"
                                      (string-join allowed-tools ","))))))
    (let ((disallowed-tools (plist-get options :disallowed-tools)))
      (when disallowed-tools
        (setq args (append args (list "--disallowedTools"
                                      (string-join disallowed-tools ","))))))
    (let ((mcp-config (plist-get options :mcp-config)))
      (when mcp-config
        (setq args (append args (list "--mcp-config" mcp-config)))))

    ;; === Session Management ===
    (when (plist-get options :continue-conversation)
      (setq args (append args (list "--continue"))))
    (let ((resume (plist-get options :resume)))
      (when resume
        (setq args (append args (list "--resume" resume)))))
    (let ((setting-sources (plist-get options :setting-sources)))
      (when setting-sources
        (setq args (append args (list "--setting-sources"
                                      (string-join setting-sources ","))))))

    ;; === Output Format ===
    (if streaming-p
        (setq args (append args (list "--input-format" "stream-json")))
      (setq args (append args (list "--print"))))
    args))

(defun code-agent--remove-hash-entries-by-value (table value)
  "Remove all entries from TABLE whose value equals VALUE.
Collects keys first to avoid modify-during-iterate."
  (let (keys)
    (maphash (lambda (k v)
               (when (equal v value) (push k keys)))
             table)
    (dolist (k keys) (remhash k table))))

(defun code-agent-registry-cleanup-process (state)
  "Per-process cleanup for STATE. Removes only entries owned by this process.
Never calls clrhash — preserves parallel sessions.
Also unregisters from `code-agent--active-queries' to ensure the
*Claude Queries* buffer and mode-line reflect the terminal state."
  (let* ((req-id (code-agent--process-state-request-id state))
         (reg code-agent--registry))
    ;; Remove from active-states list (registry is sole owner)
    (setf (code-agent--registry-active-states reg)
          (delq state (code-agent--registry-active-states reg)))
    ;; Remove owned entries from all registry tables
    (when req-id
      (code-agent--remove-hash-entries-by-value
       (code-agent--registry-background-tasks reg) req-id)
      (code-agent--remove-hash-entries-by-value
       (code-agent--registry-control-requests reg) req-id)
      (remhash req-id (code-agent--registry-queries reg))
      ;; Also unregister from active-queries hash table.
      ;; This is critical for the abnormal exit (recovery) path where
      ;; sentinel-cleanup is NOT called, so without this the old dead
      ;; entry would persist in active-queries indefinitely.
      (code-agent--unregister-query req-id))))

  "Kill all active Claude agent processes and their children.
This is useful for cleanup after tests or when processes are stuck.
Returns the number of processes killed."
  (interactive)
  (let ((killed 0))
    ;; Kill via active-states tracking (read from registry)
    (dolist (state (code-agent-registry-active-states))
      (when-let* ((process (code-agent--process-state-process state)))
        (when (process-live-p process)
          (code-agent--kill-process-tree process)
          (cl-incf killed))))
    ;; Also kill via active-queries hash table
    (maphash (lambda (_req-id state)
               (when-let* ((process (code-agent--process-state-process state)))
                 (when (process-live-p process)
                   (code-agent--kill-process-tree process)
                   (cl-incf killed))))
             code-agent--active-queries)
    ;; Clear state tracking (registry is sole owner)
    (setf (code-agent--registry-active-states code-agent--registry) nil)
    (clrhash code-agent--active-queries)
    (when (called-interactively-p 'any)
      (message "Killed %d Claude process(es)" killed))
    killed))

**** Error Detection

Detect and extract error messages from various JSON response formats.
The Claude CLI can signal errors in multiple ways - result messages with
=is_error=true=, assistant messages with error fields, etc.

#+NAME: filter-extract-error
#+BEGIN_SRC elisp
(defconst code-agent--known-error-subtypes
  '(("error_during_execution" . "Execution error (Claude encountered an issue during tool use)")
    ("invalid_request" . "Invalid request error")
    ("rate_limit" . "Rate limit exceeded"))
  "Alist mapping known error subtype strings to human-readable messages.")

(defun code-agent--extract-result-error (parsed)
  "Extract error from a result message in PARSED JSON.
Checks :errors array, known subtypes, error_details, field values,
and deep-search as fallback.  Returns error string or nil."
  (let ((subtype (plist-get parsed :subtype))
        (errors (plist-get parsed :errors)))
    (cond
     ;; :errors array with specific error messages
     ((and errors (listp errors) (car errors) (stringp (car errors)))
      (car errors))
     ;; Known subtype with human-readable message
     ((cdr (assoc subtype code-agent--known-error-subtypes)))
     ;; error_details field
     ((plist-get parsed :error_details)
      (let ((details (plist-get parsed :error_details)))
        (if (stringp details) details (format "%S" details))))
     ;; Try :result, :error, :message — skip values that duplicate subtype names
     ((let ((subtype-values (mapcar #'car code-agent--known-error-subtypes)))
        (or (let ((v (plist-get parsed :result)))
              (and v (not (member v subtype-values)) v))
            (let ((v (plist-get parsed :error)))
              (and v (not (member v subtype-values)) v))
            (let ((v (plist-get parsed :message)))
              (and v (not (member v subtype-values)) v)))))
     ;; Other subtype values — format nicely
     ((and subtype (not (string= subtype "")))
      (format "Error: %s" subtype))
     ;; Deep search for meaningful error strings
     (t
      (or
       (cl-labels ((find-error-string (obj)
                     (cond
                      ((stringp obj)
                       (when (and (> (length obj) 20)
                                  (string-match-p "\\(?:error\\|Error\\|failed\\|not found\\)" obj))
                         obj))
                      ((listp obj)
                       (cl-some #'find-error-string obj))
                      (t nil))))
         (find-error-string parsed))
       (format "Error (fields: %s)"
               (mapcar #'car (seq-partition (cdr parsed) 2))))))))

(defun code-agent--extract-assistant-error (parsed)
  "Extract error from an assistant message in PARSED JSON.
Checks for :message with non-empty :error field, extracts text
content or falls back to error string.  Returns error string or nil."
  (let* ((msg (plist-get parsed :message))
         (err (plist-get msg :error)))
    (when (and err (stringp err) (not (string-empty-p err)))
      (let* ((content (plist-get msg :content))
             (text-block (car-safe (seq-filter
                                    (lambda (b) (string= (plist-get b :type) "text"))
                                    content))))
        (or (plist-get text-block :text)
            err
            "API error")))))

(defun code-agent--extract-json-error (parsed)
  "Extract error message from PARSED JSON if it indicates an error.
Returns the error message string if an error is detected, nil otherwise.
Delegates to sub-extractors for result and assistant message types."
  (let ((type (plist-get parsed :type)))
    (cond
     ((and (string= type "result")
           (code-agent--json-true-p (plist-get parsed :is_error)))
      (code-agent--extract-result-error parsed))
     ((string= type "assistant")
      (code-agent--extract-assistant-error parsed))
     (t nil))))

**** Normal Message Processing

Routes a non-control message (assistant / user / system / result) into the matching callback path — content blocks feed token streaming, structured events feed hooks.

#+BEGIN_SRC elisp
(defun code-agent--process-normal-message (parsed state)
  "Process a normal (non-control) message.
PARSED is the JSON plist, STATE is process state.
Callbacks and process are extracted from STATE."
  (let ((callback (code-agent--process-state-callback state))
        (token-callback (code-agent--process-state-token-callback state))
        (error-callback (code-agent--process-state-error-callback state))
        (process (code-agent--process-state-process state))
        (json-error (code-agent--extract-json-error parsed))
        (is-result (string= (plist-get parsed :type) "result")))
    ;; Set got-result flag for ANY result message (error or success)
    ;; This prevents infinite recovery loops when CLI returns error results
    (when is-result
      (setf (code-agent--process-state-got-result state) t))
    (if json-error
        ;; Error detected in JSON - call error callback
        (progn
          (code-agent--debug-log "JSON error detected: %s" json-error)
          (when error-callback
            (funcall error-callback
                     (list 'code-agent-api-error
                           :message json-error
                           :parsed parsed))))
      ;; Normal message processing (else-branch is implicit progn)
      ;; Extract text for token callback (streaming)
      (when token-callback
        (code-agent--extract-tokens parsed token-callback))
      ;; Call message callback with parsed message
      (let ((message (code-agent--parse-message parsed)))
        (when message
          ;; Capture session-id from system/init message (available at start)
          ;; This is critical for recovery - result message comes too late
          (when (and (code-agent-system-message-p message)
                     (equal (code-agent-system-message-subtype message) "init"))
            (when-let* ((sid (plist-get (code-agent-system-message-data message) :session_id)))
              (setf (code-agent--process-state-session-id state) sid)))
          ;; Set got-result flag when result message received
          (when (code-agent-result-message-p message)
            (setf (code-agent--process-state-got-result state) t))
          ;; Write to verbose buffer if session-key is set
          (code-agent--verbose-write-message
           (code-agent--process-state-session-key state) message)
          ;; Call user callback
          (when callback
            (funcall callback message))))
      ;; Close stdin when result is received (streaming mode)
      (code-agent--maybe-close-stdin process parsed))))
#+END_SRC

(defun code-agent--try-parse-json (string)

  (condition-case nil
      (let ((json-object-type 'plist)
            (json-array-type 'list)

#+NAME: filter-process-json-buffer
#+BEGIN_SRC elisp
(defun code-agent--process-json-buffer (process)
  "Process accumulated JSON for PROCESS.
PROCESS has state stored via `process-get'.
Parses complete newline-delimited JSON and invokes callbacks."
  (let* ((state (process-get process 'code-agent-state))
         (buf (code-agent--process-state-json-buffer state))
         (error-callback (code-agent--process-state-error-callback state)))
    (while (string-match "^\\([^\n]+\\)\n" buf)
      (let* ((line (match-string 1 buf))
             (rest (substring buf (match-end 0))))
        (setf (code-agent--process-state-json-buffer state) rest)
        (setq buf rest)
        (when (and line (not (string-empty-p (string-trim line))))
          (let ((parsed (code-agent--try-parse-json line)))
            (if (and parsed (listp parsed))
                (let ((msg-type (plist-get parsed :type)))
                  (if (not (stringp msg-type))
                      ;; Parsed as JSON object but missing :type — treat as error
                      (progn
                        (code-agent--debug-log "JSON object without :type field: %s" line)
                        (when error-callback
                          (funcall error-callback
                                   (list 'code-agent-cli-error
                                         :message line
                                         :original-error nil))))
                    (code-agent--debug-log "Parsed JSON: %S" msg-type)
                    ;; Control requests use direct dispatch (bidirectional protocol)
                    (if (equal msg-type "control_request")
                        (code-agent--handle-control-request process parsed)
                      ;; All other types: generic dispatch via cl-defmethod
                      (code-agent-handle-message
                       (intern msg-type) parsed state))))
              ;; Line is not valid JSON or is a bare value (number, string, boolean)
              (code-agent--debug-log "Non-JSON output: %s" line)
              (when error-callback
                (funcall error-callback
                         (list 'code-agent-cli-error
                               :message line
                               :original-error nil))))))))))

**** Process Filter Entry Point

#+NAME: filter-main
#+BEGIN_SRC elisp
(defun code-agent--process-filter (process output)
  "Process filter function for PROCESS.
OUTPUT is the data received from the process.
Uses `process-get' to retrieve state instead of closures (for dynamic binding compat)."
  (condition-case err
      (let ((state (process-get process 'code-agent-state)))
        (when (and state (code-agent--process-state-ready state))
          ;; Log stdout to verbose buffer for debugging
          (when-let* ((session-key (code-agent--process-state-session-key state)))
            (code-agent--verbose-insert session-key
                                          (format "<<< STDOUT: %s" output)))
          (let* ((json-buf (or (code-agent--process-state-json-buffer state) ""))
                 (new-buf (concat json-buf output)))
            (if (> (length new-buf) code-agent-max-json-buffer-size)
                ;; Buffer overflow — clear buffer, signal error, kill process
                (progn
                  ;; Clear buffer FIRST to prevent sentinel from re-parsing garbage
                  (setf (code-agent--process-state-json-buffer state) "")
                  (let ((err-cb (code-agent--process-state-error-callback state)))
                    (when err-cb
                      (funcall err-cb
                               (list :error
                                     (format "JSON buffer overflow: %d bytes exceeds %d byte limit"
                                             (length new-buf)
                                             code-agent-max-json-buffer-size)))))
                  (when (process-live-p process)
                    (delete-process process)))
              (setf (code-agent--process-state-json-buffer state) new-buf)
              (code-agent--process-json-buffer process)))))
    (error (message "code-agent: error in process filter: %S" err))))

*** Process Sentinel

Normal-exit branch of the sentinel.  Fires complete callback, unregisters the active query, frees the buffer — the path every non-error query takes.

#+BEGIN_SRC elisp
(defun code-agent--sentinel-handle-normal-exit (state event)
  "Handle normal (non-recovery) exit for STATE with EVENT.
Calls the complete callback with nil for successful exit, or with
an error plist for abnormal exit codes.
Skips the complete callback entirely if the query was cancelled,
since the cancel path already handled cleanup."
  (code-agent-with-span "sentinel-normal-exit"
      (list :event event) nil
  ;; When a query is cancelled, code-agent-org-cancel (or cancel-query) already
  ;; cleans up the session state (frees marker, sets status, stops spinner).
  ;; Calling complete-callback here would cause duplicate cleanup and fire
  ;; completion hooks with the wrong status.
  (unless (code-agent--process-state-cancelled state)
    (let ((complete-cb (code-agent--process-state-complete-callback state)))
      (cond
       ((string-match-p "finished" event)
        (when complete-cb
          (funcall complete-cb nil)))
       ((string-match-p "exited abnormally" event)
        (let ((exit-code (when (string-match "code \\([0-9]+\\)" event)
                           (string-to-number (match-string 1 event)))))
          (when complete-cb
            (funcall complete-cb
                     (list 'code-agent-process-error
                           :message "Process exited abnormally"
                           :exit-code exit-code)))))
       (t
        (when complete-cb
          (funcall complete-cb
                   (list 'code-agent-process-error
                         :message (format "Process event: %s" event))))))))))

(defun code-agent--sentinel-handle-abnormal-exit (process state event)
  "Handle abnormal exit (recovery path) for PROCESS with STATE and EVENT.
Inserts recovery message, kills orphaned children, does minimal cleanup,
then resumes the session."
  (let ((trace-ctx (process-get process 'code-agent-trace-ctx)))
  (code-agent-with-span "sentinel-abnormal-exit"
      (list :event (string-trim event)) trace-ctx
  (when-let* ((session-key (code-agent--process-state-session-key state)))
    (code-agent--verbose-insert session-key
                                  (format ">>> ABNORMAL EXIT DETECTED - initiating recovery")))
  (code-agent--insert-recovery-message state event)
  (code-agent--kill-child-processes (process-id process))
  ;; Clear Docker path mappings if this process owned them
  (when (code-agent--process-state-docker-mode state)
    (setq emacs-mcp-server-path-mappings nil))
  ;; Registry-aware cleanup (removes from active-states, queries, etc.)
  (code-agent-registry-cleanup-process state)
  ;; Kill output buffer after registry cleanup
  (when-let* ((buf (code-agent--process-state-buffer state)))
    (when (buffer-live-p buf)
      (kill-buffer buf)))
  (code-agent--resume-session state))))

(defun code-agent--sentinel-cleanup (process state)
  "Clean up after PROCESS exits with STATE.
Kills orphaned children, removes from active-states, unregisters
query, clears Docker mappings, and kills output buffer."
  ;; Kill any orphaned child processes (delegate to existing helper)
  (code-agent--kill-child-processes (process-id process))
  ;; Remove from active states (registry is sole owner)
  (setf (code-agent--registry-active-states code-agent--registry)
        (delq state (code-agent--registry-active-states code-agent--registry)))
  ;; Per-process cleanup via registry
  (when-let* ((req-id (code-agent--process-state-request-id state)))
    (code-agent--cleanup-process-entries req-id)
    (code-agent--unregister-query req-id))
  ;; Clear Docker path mappings if this process owned them
  (when (code-agent--process-state-docker-mode state)
    (setq emacs-mcp-server-path-mappings nil))
  (when-let* ((buf (code-agent--process-state-buffer state)))
    (when (buffer-live-p buf)
      (kill-buffer buf))))

(defun code-agent--sentinel-log-exit (state event)
  "Log PROCESS EVENT to STATE's verbose buffer with pending-counter summary."
  (when-let* ((session-key (code-agent--process-state-session-key state)))
    (code-agent--verbose-insert
     session-key
     (format ">>> PROCESS EXIT: %s (pending-bg=%d pending-ctrl=%d)"
             (string-trim event)
             (hash-table-count code-agent--pending-background-tasks)
             (hash-table-count code-agent--pending-control-requests)))))

(defun code-agent--sentinel-flush-final-line (state trimmed)
  "Best-effort handling of the last line that arrived without trailing newline.

Three shapes matter:
- A `control_request` we cannot answer — log a clear WARNING since
  the CLI has died before we could write the response.
- Any other valid JSON message — log it as INFO; nothing else to do
  because the regular dispatcher only fires on newline-terminated
  lines.
- Anything that does not parse — forward to ERROR-CALLBACK as a
  raw CLI error so the caller's failure path runs."
  (let ((session-key (code-agent--process-state-session-key state))
        (error-callback (code-agent--process-state-error-callback state))
        (parsed (code-agent--try-parse-json trimmed)))
    (code-agent--debug-log "Remaining output without newline: %s" trimmed)
    (if (and parsed (listp parsed))
        (let ((msg-type (plist-get parsed :type)))
          (cond
           ((not (stringp msg-type))
            (when session-key
              (code-agent--verbose-insert
               session-key
               (format ">>> INFO: Final JSON without :type: %s" trimmed))))
           ((equal msg-type "control_request")
            (when session-key
              (code-agent--verbose-insert
               session-key
               ">>> WARNING: control_request received without newline (CLI died?) - cannot respond"))
            (message "Claude: control_request received but CLI died before we could respond"))
           (t
            (code-agent--debug-log "Parsed remaining JSON: %S" msg-type)
            (when session-key
              (code-agent--verbose-insert
               session-key
               (format ">>> INFO: Final message without newline: %s" msg-type))))))
      (when error-callback
        (funcall error-callback
                 (list 'code-agent-cli-error
                       :message trimmed
                       :original-error nil))))))

(defun code-agent--sentinel-emergency-cleanup (process)
  "Minimal cleanup to prevent state leaks if the sentinel itself errored.
Wraps `code-agent-registry-cleanup-process' in its own condition-case
because the original sentinel-level handler has already fired."
  (condition-case nil
      (let ((state (process-get process 'code-agent-state)))
        (when state
          (code-agent-registry-cleanup-process state)))
    (error nil)))

(defun code-agent--process-sentinel (process event)
  "Process sentinel function for PROCESS.
EVENT is the process event string.

Five phases under one `process-sentinel' span:
1. Log the exit to the per-session verbose buffer.
2. Mark STATE closed/not-ready so in-flight callbacks no-op.
3. Drain any newline-terminated JSON still in the buffer.
4. Handle the trailing partial line (no newline) via
   `--sentinel-flush-final-line'.
5. Dispatch to the normal vs abnormal exit handler.

Outer `condition-case' falls back to
`--sentinel-emergency-cleanup' so a bug here can't leak STATE
out of the registry."
  (condition-case err
      (let* ((state (process-get process 'code-agent-state))
             (trace-ctx (process-get process 'code-agent-trace-ctx)))
        (code-agent-with-span "process-sentinel"
            (list :event (string-trim event)) trace-ctx
          (code-agent--debug-log "Process event: %s" (string-trim event))
          (when state
            (code-agent--sentinel-log-exit state event)
            (setf (code-agent--process-state-closed state) t)
            (setf (code-agent--process-state-ready state) nil)
            (code-agent--process-json-buffer process)
            (let ((remaining (code-agent--process-state-json-buffer state)))
              (when (and remaining
                         (not (string-empty-p (string-trim remaining))))
                (code-agent--sentinel-flush-final-line
                 state (string-trim remaining))))
            (if (code-agent--is-abnormal-exit-p event state)
                (code-agent--sentinel-handle-abnormal-exit process state event)
              (code-agent--sentinel-handle-normal-exit state event)
              (code-agent--sentinel-cleanup process state)))))
    (error
     (message "code-agent: error in process sentinel: %S" err)
     (code-agent--sentinel-emergency-cleanup process))))

**** Abnormal Exit Detection

Classifies the sentinel's =event= argument into normal vs recovery-warranting.  Signals like SIGKILL + non-zero exit during streaming trigger the recovery branch below.

#+BEGIN_SRC elisp
(defun code-agent--is-abnormal-exit-p (event state)

*** Pipe Deadlock Prevention

When using pipes for bidirectional communication, deadlock can occur if:
1. The CLI writes to stdout faster than Emacs reads
2. The pipe buffer fills up (64KB Linux, 16KB macOS)
3. The CLI blocks waiting for buffer space
4. Emacs blocks waiting for CLI to accept stdin

Solution: Always drain pending output before writing to stdin, and chunk
large messages with interleaved draining.

#+BEGIN_SRC elisp
(defun code-agent--drain-output (process &optional timeout-ms)
  "Drain pending output from PROCESS before sending input.
TIMEOUT-MS is milliseconds to wait per drain cycle, defaults to 50ms.
Returns t if any output was drained, nil otherwise."
  (let ((timeout-secs (/ (or timeout-ms 50) 1000.0))
        (drained nil))
    (while (and (process-live-p process)
                (accept-process-output process timeout-secs nil t))
      (setq drained t))
    drained))

(defun code-agent--send-json-safe (process json-str session-key)
  "Send JSON-STR to PROCESS with deadlock prevention.
Drains output before sending, chunks large messages.
SESSION-KEY is used for verbose logging."
  ;; Log to verbose buffer
  (when session-key
    (code-agent--verbose-insert session-key
                                  (format ">>> STDIN: %s" json-str)))
  (code-agent--debug-log "Sending to stdin: %s"
                           (substring json-str 0 (min 200 (length json-str))))
  ;; Only send if process is alive
  (when (process-live-p process)
    ;; CRITICAL: Drain stdout first to prevent deadlock
    (code-agent--drain-output process)
    ;; Send in chunks with interleaved draining for large messages
    (let ((len (length json-str))
          (pos 0)
          (chunk-size code-agent-stdin-chunk-size))
      (while (< pos len)
        ;; Drain between chunks (except first)
        (when (> pos 0)
          (code-agent--drain-output process 10))
        (let ((chunk (substring json-str pos (min (+ pos chunk-size) len))))
          (process-send-string process chunk))
        (setq pos (+ pos chunk-size))))))

(defun code-agent--configure-process-io (process)
  "Configure PROCESS for optimal I/O throughput.
Sets buffer sizes and coding for reliable bidirectional communication."
  (with-current-buffer (process-buffer process)
    ;; Increase read chunk size (Emacs 27+)
    (when (boundp 'read-process-output-max)
      (setq-local read-process-output-max (* 1024 1024)))
    ;; Disable adaptive buffering for lower latency
    (setq-local process-adaptive-read-buffering nil))
  ;; UTF-8 encoding (already set in make-process, but be explicit)
  (set-process-coding-system process 'utf-8-unix 'utf-8-unix))
#+END_SRC

In streaming mode, we need to:

2. Send the user prompt as a JSON message
3. Keep stdin open for bidirectional communication

#+BEGIN_SRC elisp
(defun code-agent--send-stdin (process json-data session-key)
  "Send JSON-DATA to PROCESS stdin with deadlock prevention.

and chunk large messages to prevent pipe buffer blocking."
  (let* ((json-object-type 'plist)
         (json-array-type 'list)
         (json-key-type 'keyword)

    (code-agent--send-json-safe process json-str session-key)))

(defun code-agent--streaming-init (process state prompt)
  "Initialize streaming mode for PROCESS with STATE and send PROMPT.

  (let ((session-key (code-agent--process-state-session-key state)))

    (let ((init-request (list :type "control_request"
                              :request_id "init_1"

                                            :hooks nil))))

*** Background Task Tracking

Track background tasks (launched with =run_in_background: true=) to keep the
process alive until all tasks complete. The tracker is registered on the
=code-agent-post-tool-use-functions= hook.

Two types of background tasks exist:
1. *Task tool* (subagents): Returns =isAsync: true= with =agentId=
2. *Bash tool*: Returns =backgroundTaskId= field (no =isAsync= flag)

Both must be tracked to prevent premature stdin close.

#+BEGIN_SRC elisp
;; `code-agent--pending-background-tasks' is defined as an alias into the
;; unified registry in the "Standalone Variable Aliases" section above.
;; All mutations via puthash/remhash/clrhash on the standalone var go to
;; the same hash-table object that lives in the registry struct.

(defun code-agent--background-task-tracker (_tool-use-id _result _is-error
                                              tool-use-result state)
  "Track background tasks from PostToolUse hook.
STATE is the process-state struct (used to identify the owning process).
TOOL-USE-RESULT contains:
- For Task tool: isAsync=t, agentId (e.g., \"a4b3ecf\")
- For Bash tool: backgroundTaskId (e.g., \"b8406fe\")
- For TaskOutput: task.task_id, task.status"
  (when tool-use-result
    (let ((owner (and state (code-agent--process-state-request-id state))))
      ;; Case 1: Task tool async launch - isAsync=t with agentId
      (when (and (eq (plist-get tool-use-result :isAsync) t)
                 (plist-get tool-use-result :agentId))
        (let ((agent-id (plist-get tool-use-result :agentId)))
          (puthash agent-id (or owner t) code-agent--pending-background-tasks)
          (code-agent--debug-log "Background Task started: %s (owner: %s)"
                                   agent-id owner)))
      ;; Case 2: Bash tool background - backgroundTaskId field
      (when-let* ((bg-task-id (plist-get tool-use-result :backgroundTaskId)))
        (puthash bg-task-id (or owner t) code-agent--pending-background-tasks)
        (code-agent--debug-log "Background Bash started: %s (owner: %s)"
                                 bg-task-id owner))
      ;; Task completion: task.status="completed"
      (when-let* ((task (plist-get tool-use-result :task))
                  (task-id (plist-get task :task_id))
                  (status (plist-get task :status)))
        (when (equal status "completed")
          (remhash task-id code-agent--pending-background-tasks)
          (code-agent--debug-log "Background task completed: %s" task-id))))))

(defun code-agent--has-pending-background-tasks-p (&optional owner-request-id)
  "Return non-nil if there are pending background tasks.
When OWNER-REQUEST-ID is non-nil, only count tasks owned by that process.
When nil, checks the global count (any owner).  Callers should guard
with (and owner-req-id (has-pending-...)) to avoid stale-task blocking."
  (if owner-request-id
      (catch 'found
        (maphash (lambda (_k v)
                   (when (equal v owner-request-id)
                     (throw 'found t)))
                 code-agent--pending-background-tasks)
        nil)
    (> (hash-table-count code-agent--pending-background-tasks) 0)))

;; Register tracker on PostToolUse hook
(add-hook 'code-agent-post-tool-use-functions
          #'code-agent--background-task-tracker)
#+END_SRC

*** Closing Stdin After Result

We need to close stdin when we receive the result message to signal completion.
This is handled in the process filter when a result message is received.
If there are pending background tasks, we keep stdin open.

**** Why Delayed Stdin Close is Necessary

The Claude Code CLI uses a bidirectional protocol over stdin/stdout:
- We send: user prompts, control responses (permissions, hooks)
- CLI sends: messages, control requests (can_use_tool, mcp_message, hook_callback)

When we receive a =result= message, it signals the end of the conversation turn.
However, closing stdin immediately can cause issues:

1. *Process Filter Timing*: The =result= message is processed inside
   =code-agent--process-filter=. If we call =process-send-eof= synchronously,
   it may trigger process termination before the current filter completes.

2. *MCP Server Communication*: With =emacs-mcp-server= active, there may be
   pending =mcp_message= control requests or responses in flight.

3. *Hook Callbacks*: Any pending hook callbacks need to complete before
   the connection closes.

The Python SDK handles this by waiting for the result event before closing
stdin when MCP servers or hooks are present (see =stream_input= in query.py).

Our solution: Use =run-at-time= with a small delay (0.1s) to:
- Let the current process filter invocation complete
- Allow any pending filter calls to run
- Give MCP communication time to settle
- Then close stdin cleanly

#+BEGIN_SRC elisp
(defcustom code-agent-stdin-close-delay 0.1
  "Delay in seconds before closing stdin after receiving result message.
This delay allows pending process filter invocations and MCP communication
to complete before signaling end-of-input to the Claude CLI.

The Python SDK uses a similar approach, waiting for the result event
before closing stdin when MCP servers are active.

Set to 0 to close immediately (original behavior, may cause early exit issues).
Set to nil to disable automatic stdin close (for debugging)."
  :type '(choice (number :tag "Delay in seconds")
                 (const :tag "Disable auto-close" nil))
  :group 'code-agent)

(defun code-agent--maybe-close-stdin (process parsed)
  "Close stdin when PARSED is a result message.
PROCESS is the CLI process.
Delegates to `code-agent--schedule-stdin-close' which retries
if control requests are still pending.

Background tasks are NOT checked — the CLI waits for all background
agents internally before emitting the result message.  By the time
we receive result, all agent output has already been streamed.

The delay between retries uses `code-agent-stdin-close-delay'."
  (when (equal (plist-get parsed :type) "result")
    (if (not code-agent-stdin-close-delay)
        (code-agent--debug-log "Result received, stdin auto-close disabled")
      (code-agent--debug-log "Result received, scheduling stdin close")
      (code-agent--schedule-stdin-close process 0))))

(defun code-agent--schedule-stdin-close (process attempt)
  "Try to close PROCESS stdin.  Retry if control requests are pending.
ATTEMPT is the current retry count (0-based).
Retries up to 50 times (5 seconds) then force-closes to prevent hang."
  (let ((max-attempts 50)
        (delay (or code-agent-stdin-close-delay 0.1)))
    (cond
     ;; Process already dead — nothing to do
     ((not (process-live-p process)) nil)
     ;; No pending control requests — close now
     ((not (code-agent--has-pending-control-requests-p))
      (code-agent--debug-log "Closing stdin (attempt %d)" attempt)
      (process-send-eof process))
     ;; Max attempts reached — force close to prevent infinite hang
     ((>= attempt max-attempts)
      (code-agent--debug-log "Force-closing stdin after %d retries, %d control requests still pending"
                               attempt (hash-table-count code-agent--pending-control-requests))
      (process-send-eof process))
     ;; Retry after delay
     (t
      (code-agent--debug-log "Control requests pending (%d), retry %d/%d"
                               (hash-table-count code-agent--pending-control-requests)
                               attempt max-attempts)
      (lexical-let ((proc process)
                    (next-attempt (1+ attempt)))
        (run-at-time delay nil
                     (lambda ()
                       (code-agent--schedule-stdin-close proc next-attempt))))))))
#+END_SRC

(defun code-agent--launch-and-wire-process (command state session-key prompt
                                                       cli-parts args
                                                       default-directory env-vars)
  "Spawn the CLI subprocess from COMMAND and wire STATE onto it.

Bidirectional wiring: STATE keeps a reference to the process and
its buffer; the process carries STATE + trace context via
`process-put' so the filter and sentinel (which receive only the
process) can recover the state without closure capture.  Side
effects: configures I/O, registers the query for cancellation,
seeds the per-session verbose buffer when session-key is set,
sends the streaming-mode init payload, and registers STATE in the
registry's active-states list.  Returns nothing (caller already
holds STATE)."
  (let ((process (make-process
                  :name "code-agent"
                  :command command
                  :buffer (generate-new-buffer " *code-agent*")
                  :connection-type 'pipe ; use pipe, not PTY
                  :filter #'code-agent--process-filter
                  :sentinel #'code-agent--process-sentinel
                  :coding 'utf-8-unix
                  :noquery t)))
    (process-put process 'code-agent-state state)
    (process-put process 'code-agent-trace-ctx (code-agent-trace-context))
    (setf (code-agent--process-state-process state) process)
    (setf (code-agent--process-state-buffer state) (process-buffer process))
    (code-agent--configure-process-io process)
    (code-agent--register-query
     (code-agent--process-state-request-id state) state)
    (when session-key
      (code-agent--get-session-verbose-buffer session-key)
      (code-agent--verbose-insert-query-header
       session-key prompt (string-join cli-parts " ")
       args default-directory env-vars))
    (code-agent--streaming-init process state prompt)
    (setf (code-agent--registry-active-states code-agent--registry)
          (cons state (code-agent--registry-active-states code-agent--registry)))))

All other arguments are keyword arguments:
  :CALLBACK is called with each parsed message.
  :ERROR-CALLBACK is called on errors.
  :COMPLETE-CALLBACK is called when process completes.

  :REQUEST-ID is a unique identifier for this request (auto-generated if nil).

                   options req-id docker-p

                   source-location-fn source-location-args))

Per-type dispatch via =cl-defgeneric=.  Each block kind gets its own
=cl-defmethod=, keyed on the type symbol (=text=, =tool_use=, etc.).

  The function is called with SOURCE-LOCATION-ARGS in SOURCE-BUFFER.

SOURCE-LOCATION-ARGS is a list of args for SOURCE-LOCATION-FN (optional).
  Passed to the location function when navigating to source.

CLI-PATH overrides `code-agent-cli-path' for this query (optional).
  Use for Docker execution, e.g., \"docker compose exec claude claude\".
  When a Docker command is detected and `code-agent-docker-auto-start' is t,
  the container will be started automatically.

PATH-MAPPINGS is an alist of (HOST-PATH . CONTAINER-PATH) for Docker mode (optional).
  These mappings are let-bound to `emacs-mcp-server-path-mappings' during query
  execution, enabling path translation between container and host.

PROJECT-ROOT is the project directory path (optional).
  Used to resolve relative paths in Docker compose commands and for finding
  docker-compose.yml. Typically set from org property PROJECT_ROOT.

Returns the process state object for potential interruption.
The process state includes a request-id that can be used with
`code-agent-cancel-query' for cancellation.

Example:
  (code-agent-query
   \"What is 2+2?\"
   :on-message (lambda (msg)
                 (when (code-agent-assistant-message-p msg)
                   (message \"Response: %s\"
                            (code-agent-extract-text msg))))
   :on-token (lambda (text)
               (insert text))  ; For streaming display
   :on-complete (lambda (result)
                  (message \"Done!\"))
   :session-key \"my-session\"
   :source-buffer (current-buffer)
   :query-context (code-agent-make-query-context :instruction-num 5))

Docker example:
  (code-agent-query
   \"List files\"
   :cli-path \"docker compose exec claude claude\"
   :path-mappings \\='((\"/home/user/project\" . \"/workspace\")))"
  (unless prompt
    (error "Prompt is required"))
  (code-agent-with-span "code-agent-query"
      (list :span-kind "CLIENT" :session-key session-key
            :input prompt) nil
  (let* ((prepared (code-agent--prepare-query-options options cli-path project-root))
         (effective-cli-path (plist-get prepared :cli-path))
         (opts (plist-get prepared :options)))
    ;; Set path mappings for MCP server (for Docker mode path translation).
    ;; This must be setq (not let-bound) because MCP requests arrive
    ;; asynchronously via HTTP, outside any let-binding scope.
    ;; The variable is cleared on query completion.
    (setq emacs-mcp-server-path-mappings path-mappings)
    ;; Execute query
    (let ((code-agent-cli-path effective-cli-path))
      (let ((state (code-agent--start-process
                    prompt opts
                    :callback on-message
                    :error-callback on-error
                    :complete-callback on-complete
                    :token-callback on-token
                    :session-key session-key
                    :source-buffer source-buffer
                    :query-context query-context
                    :source-location-fn source-location-fn
                    :source-location-args source-location-args)))
        ;; Store context-label on the process for permission callbacks
        (when (and state context-label)
          (let ((process (code-agent--process-state-process state)))
            (when process
              (process-put process :context-label context-label))))
        state)))))

#+BEGIN_SRC elisp
(cl-defun code-agent-query-accumulate (prompt &key options on-result on-error
                                              session-key)

#+BEGIN_SRC elisp
(defun code-agent-extract-text (message)
  "Extract text content from an assistant MESSAGE.
Returns concatenated text from all text blocks, or nil if no text."
  (when (code-agent-assistant-message-p message)
    (let ((texts nil))
      (dolist (block (code-agent-assistant-message-content message))
        (when (code-agent-text-block-p block)
          (push (code-agent-text-block-text block) texts)))
      (when texts
        (string-join (nreverse texts) "")))))

(defun code-agent-message-type (message)
  "Get the type symbol for MESSAGE.
Returns one of: user, assistant, system, result, or unknown."
  (cond
   ((code-agent-user-message-p message) 'user)
   ((code-agent-assistant-message-p message) 'assistant)
   ((code-agent-system-message-p message) 'system)
   ((code-agent-result-message-p message) 'result)
   (t 'unknown)))

(defun code-agent-extract-tool-uses (message)
  "Extract tool use blocks from an assistant MESSAGE.
Returns a list of `code-agent-tool-use-block' structs."
  (when (code-agent-assistant-message-p message)
    (cl-remove-if-not #'code-agent-tool-use-block-p
                      (code-agent-assistant-message-content message))))

(defun code-agent-extract-thinking (message)
  "Extract thinking content from an assistant MESSAGE.
Returns concatenated thinking text, or nil if none."
  (when (code-agent-assistant-message-p message)
    (let ((thoughts nil))
      (dolist (block (code-agent-assistant-message-content message))
        (when (code-agent-thinking-block-p block)
          (push (code-agent-thinking-block-thinking block) thoughts)))
      (when thoughts
        (string-join (nreverse thoughts) "\n")))))

(defun code-agent--extract-error-message (error)
  "Extract human-readable message from ERROR.
ERROR can be (symbol :message ...) plist, a string, or other."
  (cond
   ;; CLI error: (code-agent-cli-error :message "..." ...) - plist starts at cdr
   ((and (listp error) (symbolp (car error)) (plist-get (cdr error) :message))
    (plist-get (cdr error) :message))
   ;; Plain plist with :message
   ((and (listp error) (plist-get error :message))
    (plist-get error :message))
   ;; String error
   ((stringp error) error)
   ;; Symbol error (e.g., 'error)
   ((symbolp error) (symbol-name error))
   ;; List with error symbol and details: (error "message" ...)
   ((and (listp error) (eq (car error) 'error) (stringp (cadr error)))
    (cadr error))
   ;; Fallback: convert to string, truncate if too long
   (t (let ((str (format "%S" error)))
        (if (> (length str) 200)
            (concat (substring str 0 197) "...")
          str)))))

(defun code-agent-format-elapsed-time (start-time &optional format-style)
  "Format elapsed time since START-TIME as human-readable string.
FORMAT-STYLE can be:
  'compact   - \"5s\", \"10m\", \"2h\" (default for mode-line)
  'verbose   - \"started 5 seconds ago\"
  nil        - defaults to 'compact

Returns \"unknown\" if START-TIME is nil."
  (if (null start-time)
      "unknown"
    (let* ((elapsed (- (float-time) start-time))
           (style (or format-style 'compact)))
      (cond
       ;; Less than 60 seconds
       ((< elapsed 60)
        (if (eq style 'verbose)
            (format "started %d seconds ago" (round elapsed))
          (format "%ds" (round elapsed))))
       ;; Less than 1 hour
       ((< elapsed 3600)
        (if (eq style 'verbose)
            (format "started %d minutes ago" (round (/ elapsed 60)))
          (format "%dm" (round (/ elapsed 60)))))
       ;; 1 hour or more
       (t
        (if (eq style 'verbose)
            (format "started %d hours ago" (round (/ elapsed 3600)))
          (format "%dh" (round (/ elapsed 3600)))))))))

*** Client Methods

Connection + send + disconnect verbs on the client.  Each is a thin wrapper over the per-query =code-agent-query= path, specialised to persist state across multiple turns.

#+BEGIN_SRC elisp
(defun code-agent-client-connect (client &optional initial-prompt)
  "Connect CLIENT to Claude with optional INITIAL-PROMPT.

Starts the CLI process in streaming mode."
  (code-agent-with-span "client-connect" (list :span-kind "CLIENT") nil
  (when (code-agent-client-connected-p client)
    (error "Client is already connected"))
  (let* ((options (code-agent-client-options client))
         (prompt (or initial-prompt ""))
         (on-msg (code-agent-client-on-message client))
         (on-err (code-agent-client-on-error client)))
    (setf (code-agent-client-state client)
          (code-agent--start-process
           prompt options
           :callback (lambda (msg)
                       ;; Track session ID from result messages
                       (when (code-agent-result-message-p msg)
                         (setf (code-agent-client-session-id client)
                               (code-agent-result-message-session-id msg)))
                       ;; Call user callback
                       (when on-msg
                         (funcall on-msg msg)))
           :error-callback on-err
           :complete-callback (lambda (result)
                                (setf (code-agent-client-connected-p client) nil)
                                (when (and result on-err)
                                  (funcall on-err result)))))
    (setf (code-agent-client-connected-p client) t)
    client)))

(cl-defun code-agent-client-send (client message &key on-response on-error)
  "Send MESSAGE through CLIENT (legacy - starts new process).

MESSAGE is a string to send to Claude.
ON-RESPONSE is called with each response message.
ON-ERROR is called if an error occurs.

Note: This creates a new query process for each message.
For persistent bidirectional streaming, use `code-agent-client-send-message'."
  (unless (code-agent-client-connected-p client)
    (error "Client is not connected"))
  ;; Legacy: start a new process for each message
  (let* ((options (code-agent-client-options client))
         ;; Continue from previous session if we have one
         (session-id (code-agent-client-session-id client))
         (new-options (if session-id
                          (plist-put (copy-sequence options) :resume session-id)
                        options)))
    (setf (code-agent-client-state client)
          (code-agent--start-process
           message new-options
           :callback (or on-response (code-agent-client-on-message client))
           :error-callback (or on-error (code-agent-client-on-error client))
           :complete-callback
           (lambda (result)
             (when (and result (code-agent-client-on-error client))
               (funcall (code-agent-client-on-error client) result)))))))

(cl-defun code-agent-client-send-message (client message &key on-message on-error
                                                   on-complete token-callback)
  "Send MESSAGE through CLIENT's persistent connection.

This sends the message through the existing process without spawning a new one.
Requires the client to be connected with `code-agent-client-connect'.

MESSAGE is the prompt string to send.
ON-MESSAGE is called for each response message (overrides client default).
ON-ERROR is called if an error occurs (overrides client default).
ON-COMPLETE is called when the response completes (overrides client default).
TOKEN-CALLBACK is called with each text token for streaming display.

Returns non-nil if the message was sent successfully."
  (code-agent-with-span "client-send-message" (list :span-kind "CLIENT") nil
  (unless (code-agent-client-connected-p client)
    (error "Client is not connected"))
  (let* ((state (code-agent-client-state client))
         (process (code-agent--process-state-process state))
         (session-key (code-agent-client-session-key client)))
    (unless (and process (process-live-p process))
      (error "Client process is not alive"))
    ;; Update client callbacks via public API
    (code-agent-update-state-callbacks state
     :callback (when on-message
                 (lambda (msg)
                   ;; Track session ID from result messages
                   (when (code-agent-result-message-p msg)
                     (setf (code-agent-client-session-id client)
                           (code-agent-result-message-session-id msg))
                     ;; Call on-complete when we get result
                     (when (or on-complete (code-agent-client-on-complete client))
                       (funcall (or on-complete (code-agent-client-on-complete client)) msg)))
                   (funcall on-message msg)))
     :error-callback on-error
     :token-callback token-callback)
    ;; Update client metadata
    (cl-incf (code-agent-client-query-count client))
    (setf (code-agent-client-last-activity client) (float-time))
    ;; Send user message through existing process
    (let ((user-message (list :type "user"
                              :message (list :role "user"
                                            :content message))))
      (code-agent--send-stdin process user-message session-key))
    t)))

(defun code-agent-client-disconnect (client)
  "Disconnect CLIENT from Claude.

Cleans up process and resources, calls on-disconnect callback if set."
  (when (code-agent-client-connected-p client)
    (let ((on-disconnect (code-agent-client-on-disconnect client))
          (session-key (code-agent-client-session-key client)))
      (when-let* ((state (code-agent-client-state client)))
        (when-let* ((process (code-agent--process-state-process state)))
          (when (process-live-p process)
            (code-agent--kill-process-tree process)))
        (when-let* ((buf (code-agent--process-state-buffer state)))
          (when (buffer-live-p buf)
            (kill-buffer buf))))
      (setf (code-agent-client-connected-p client) nil)
      (setf (code-agent-client-state client) nil)
      ;; Call on-disconnect callback
      (when on-disconnect
        (funcall on-disconnect client)))))

(defun code-agent-client-interrupt (client)
  "Send interrupt signal through CLIENT."
  (when-let* ((state (code-agent-client-state client)))
    (when-let* ((process (code-agent--process-state-process state)))
      (when (process-live-p process)
        (interrupt-process process)))))

(defun code-agent-get-session-id (client)
  "Get the current session ID from CLIENT.
Returns nil if not yet available."
  (code-agent-client-session-id client))

(defun code-agent-client-alive-p (client)
  "Return non-nil if CLIENT's process is alive and responsive."
  (and (code-agent-client-connected-p client)
       (when-let* ((state (code-agent-client-state client)))
         (when-let* ((process (code-agent--process-state-process state)))
           (process-live-p process)))))

*** Control Request Handling

The =control_request= side-channel — interrupt, set-permission-mode, set-model.  Each request-id gets a matching response sent back to the CLI's stdin.

#+BEGIN_SRC elisp
(defun code-agent--send-control-response (process request-id subtype response-data)
  "Send control protocol response to PROCESS.

REQUEST-ID: string matching the request
SUBTYPE: \"success\" or \"error\"
RESPONSE-DATA: plist with response fields or :error string

Also untracks the request from pending control requests."
  (let* ((response (list :type "control_response"
                        :response (list :subtype subtype
                                       :request_id request-id
                                       :response response-data)))
         (json-object-type 'plist)
         (json-array-type 'list)
         (json-key-type 'keyword)
         (json (concat (json-encode response) "\n"))
         (state (process-get process 'code-agent-state))
         (session-key (and state (code-agent--process-state-session-key state))))
    (code-agent--debug-log "Sending control response: %s"
                            (substring json 0 (min 200 (length json))))
    ;; Log to verbose buffer for debugging
    (when session-key
      (code-agent--verbose-insert session-key
                                    (format ">>> STDIN (control_response): %s"
                                            (substring json 0 (min 300 (length json))))))
    ;; Untrack the request now that we're sending the response
    (code-agent--untrack-control-request request-id)
    ;; Only send if process is still alive
    (if (process-live-p process)
        (progn
          ;; CRITICAL: Drain pending output before sending to prevent deadlock
          (code-agent--drain-output process)
          (process-send-string process json))
      ;; Log when we can't send the response - this indicates the CLI died unexpectedly
      (code-agent--debug-log "WARNING: Cannot send control_response - process is dead (id=%s)"
                               request-id)
      (when session-key
        (code-agent--verbose-insert session-key
                                      (format ">>> ERROR: control_response DROPPED (process dead) id=%s"
                                              request-id)))
      (message "Claude: control_response dropped - CLI process died (request-id: %s)" request-id))))

(defun code-agent--handle-control-can-use-tool (process request-id request-data)
  "Handle the ``can_use_tool'' subtype by running the permission hook.
Builds the context plist from process-attached metadata
(session-id, context-label, suggestions), dispatches through
`--run-permission-functions', and emits a success
`control_response' with the resolved behavior + updated input."
  (let* ((tool-name (plist-get request-data :tool_name))
         (tool-input (plist-get request-data :input))
         (session-id (process-get process :session-id))
         (context-label (process-get process :context-label))
         (context (list :session-id session-id
                        :context-label context-label
                        :suggestions
                        (plist-get request-data :permission_suggestions))))
    (code-agent--debug-log "Running permission functions for %s (id=%s)"
                             tool-name request-id)
    (let ((result (code-agent--run-permission-functions
                   tool-name tool-input context)))
      (code-agent--debug-log "Permission result for %s: %S (id=%s)"
                               tool-name result request-id)
      (code-agent--send-control-response
       process request-id "success"
       (list :behavior (or (plist-get result :behavior) "allow")
             :updatedInput (or (plist-get result :updated-input) tool-input)
             :message (plist-get result :message))))))

(defun code-agent--handle-control-request (process request)
  "Handle control_request from Claude CLI.

PROCESS: The Claude CLI process
REQUEST: Parsed control_request plist

Invokes appropriate Emacs hooks and sends control_response.
Tracks pending requests to prevent premature stdin close.

Subtypes:
- ``can_use_tool''    → `--handle-control-can-use-tool'
- ``hook_callback''   → reserved, empty success response
- (anything else)     → signals `error', caught by outer
                       `condition-case' which emits an error
                       control_response so the CLI side gets a
                       deterministic answer."
  (let* ((trace-ctx (process-get process 'code-agent-trace-ctx))
         (request-id (plist-get request :request_id))
         (request-data (plist-get request :request))
         (subtype (plist-get request-data :subtype)))
    (code-agent-with-span "handle-control-request"
        (list :subtype subtype) trace-ctx
      (code-agent--debug-log "Control request: %s (id=%s)" subtype request-id)
      ;; Track this request as pending until the response is sent — prevents
      ;; premature stdin close while we're still computing the answer.
      (let ((owner (when-let* ((state (process-get process 'code-agent-state)))
                     (code-agent--process-state-request-id state))))
        (code-agent--track-control-request request-id owner))
      (condition-case err
          (cond
           ((equal subtype "hook_callback")
            (code-agent--send-control-response
             process request-id "success" (list)))
           ((equal subtype "can_use_tool")
            (code-agent--handle-control-can-use-tool
             process request-id request-data))
           (t
            (error "Unsupported control request subtype: %s" subtype)))
        (error
         (code-agent--send-control-response
          process request-id "error"
          (list :error (error-message-string err))))))))

(defcustom code-agent-query-timeout 300
  "Seconds after which a query is considered stale and should be cleaned up.
Queries running longer than this are assumed to be zombie processes from
network issues or other failures. Set to nil to disable timeout cleanup."
  :type '(choice (integer :tag "Seconds")
                 (const :tag "Disable" nil))

(defun code-agent--query-timed-out-p (state)
  "Return t if STATE represents a query that has timed out.
Uses `code-agent-query-timeout' to determine staleness."
  (and code-agent-query-timeout
       (code-agent--process-state-p state)
       (code-agent--process-state-start-time state)
       (> (- (float-time) (code-agent--process-state-start-time state))
          code-agent-query-timeout)))

(defun code-agent--state-is-dead-p (state)
  "Return non-nil iff STATE is invalid, closed, or backs a dead process."
  (or (not (code-agent--process-state-p state))
      (code-agent--process-state-closed state)
      (let ((proc (code-agent--process-state-process state)))
        (and proc (not (process-live-p proc))))))

(defun code-agent--scan-stale-queries ()
  "One-pass scan of `--active-queries' for cleanup.
Returns ``(STALE-KEYS TIMED-OUT-KEYS PROCS-TO-KILL)''.  The list of
timed-out processes is collected here but killed by the caller —
mutating the hash table inside `maphash' is undefined behaviour."
  (let (stale timed-out procs)
    (maphash
     (lambda (key state)
       (cond
        ((code-agent--state-is-dead-p state)
         (push key stale))
        ((code-agent--query-timed-out-p state)
         (when-let* ((proc (code-agent--process-state-process state)))
           (when (process-live-p proc)
             (code-agent--debug-log
              "Killing timed-out query: %s (age: %.0fs)"
              key
              (- (float-time)
                 (code-agent--process-state-start-time state)))
             (push proc procs)))
         (push key timed-out))))
     code-agent--active-queries)
    (list stale timed-out procs)))

(defun code-agent--purge-active-states ()
  "Drop dead entries from `--registry-active-states' and log the count."
  (let* ((current (code-agent-registry-active-states))
         (initial (length current))
         (cleaned (cl-remove-if #'code-agent--state-is-dead-p current))
         (removed (- initial (length cleaned))))
    (setf (code-agent--registry-active-states code-agent--registry) cleaned)
    (when (> removed 0)
      (code-agent--debug-log "Cleaned up %d stale states" removed))))

(defun code-agent--cleanup-stale-queries ()
  "Remove stale entries from active-queries hash table and active-states list.
Called after code reload to clean up entries with dead processes,
outdated structure, or queries that have exceeded timeout.

Three phases — scan, kill, purge — avoid mutating the hash inside
`maphash':
1. `--scan-stale-queries' collects keys + procs-to-kill.
2. Kill collected processes outside the hash walk.
3. Remove keys from the hash and `--purge-active-states' from the
   registry's list (which can accumulate independently when the
   hash is correct but the list missed a removal)."
  (condition-case err
      (cl-destructuring-bind (stale-keys timed-out-keys procs-to-kill)
          (code-agent--scan-stale-queries)
        (dolist (proc procs-to-kill)
          (ignore-errors (delete-process proc)))
        (dolist (key (append stale-keys timed-out-keys))
          (remhash key code-agent--active-queries))
        (when stale-keys
          (code-agent--debug-log
           "Cleaned up %d stale queries" (length stale-keys)))
        (when timed-out-keys
          (code-agent--debug-log
           "Cleaned up %d timed-out queries" (length timed-out-keys)))
        (code-agent--purge-active-states))
    (error (message "code-agent: error in stale query cleanup: %S" err))))

;; Run cleanup on load
(code-agent--cleanup-stale-queries)

*** Cancellation Functions

Public =cancel-query= + helpers — marks the state cancelled, delivers a final SIGTERM, unregisters from the active-query table regardless of whether the process actually died.

#+BEGIN_SRC elisp
(defun code-agent-cancel-query (request-id)
  "Cancel query by REQUEST-ID.
Always marks as closed and cancelled, then unregisters, even if process is dead.
Sets the cancelled flag to prevent automatic recovery.
Returns t if found and cancelled, nil if not found."
  (code-agent-with-span "cancel-query"
      (list :request-id request-id) nil
  (let ((state (code-agent--get-active-query request-id)))
    (when state
      ;; Mark as closed and cancelled to prevent auto-recovery
      (setf (code-agent--process-state-closed state) t)
      (setf (code-agent--process-state-cancelled state) t)
      ;; Interrupt process if still alive
      (when-let* ((process (code-agent--process-state-process state)))
        (when (process-live-p process)
          (interrupt-process process)))
      ;; Always unregister from hash table
      (code-agent--unregister-query request-id)
      (code-agent--debug-log "Query cancelled: %s" request-id)
      t))))

(defun code-agent-cancel-all-queries ()
  "Cancel all active queries."
  (maphash (lambda (id _state)
             (code-agent-cancel-query id))
           code-agent--active-queries))

  "Clean up all Claude agent state.
Cancels active queries and removes stale entries."
  (interactive)
  (code-agent-cancel-all-queries)
  (code-agent--cleanup-stale-queries))

*** Verbose Buffer Management

Insertion + trim primitives for the verbose buffer — wraps =insert= so the cap is enforced on every write rather than as a periodic sweep.

#+BEGIN_SRC elisp
(defun code-agent--verbose-insert (session-key text)
  "Insert TEXT into verbose buffer for SESSION-KEY.
When `code-agent-verbose-buffer-max-size' is set, trims oldest content
if buffer exceeds the limit after insertion."
  (when-let* ((buf (gethash session-key code-agent--session-verbose-buffers)))
    (when (buffer-live-p buf)
      (with-current-buffer buf
        (let ((inhibit-read-only t))
          ;; Trim if over max size before inserting
          (when (and code-agent-verbose-buffer-max-size
                     (> (buffer-size) code-agent-verbose-buffer-max-size))
            (let ((trim-to (/ code-agent-verbose-buffer-max-size 2)))
              (goto-char (+ (point-min) (- (buffer-size) trim-to)))
              ;; Advance to next line boundary for clean trim
              (forward-line 1)
              (delete-region (point-min) (point))
              (goto-char (point-min))
              (insert "[...verbose output trimmed...]\n")))
          (goto-char (point-max))
          (insert text)
          (unless (string-suffix-p "\n" text)
            (insert "\n")))))))

(defun code-agent--get-session-verbose-buffer (session-key)
  "Get or create verbose buffer for SESSION-KEY."
  (or (let ((buf (gethash session-key code-agent--session-verbose-buffers)))
        (and buf (buffer-live-p buf) buf))
      (let ((buf (generate-new-buffer
                  (format "*Claude Session[%s]*"
                          (if (string-match "::\\(.+\\)$" session-key)
                              (match-string 1 session-key)
                            (file-name-nondirectory session-key))))))
        (with-current-buffer buf
          (code-agent-verbose-mode)
          (let ((inhibit-read-only t))
            (insert (format "═══ Claude Session ═══\n"))
            (insert (format "Session: %s\n" session-key))
            (insert (format "Started: %s\n\n" (format-time-string "%Y-%m-%d %H:%M:%S")))))
        (puthash session-key buf code-agent--session-verbose-buffers)
        buf)))

(defun code-agent--group-args-as-pairs (args)
  "Group ARGS into (OPT . VAL) pairs for readable verbose-buffer rendering.
Bare flags (e.g. \"-v\") get a nil VAL; positional args also get
nil VAL.  Returns a list of cons cells in original order."
  (let (pairs (i 0))
    (while (< i (length args))
      (let ((arg (nth i args)))
        (cond
         ((and (string-prefix-p "-" arg)
               (< (1+ i) (length args))
               (not (string-prefix-p "-" (nth (1+ i) args))))
          (push (cons arg (nth (1+ i) args)) pairs)
          (setq i (+ i 2)))
         (t
          (push (cons arg nil) pairs)
          (setq i (1+ i))))))
    (nreverse pairs)))

(defun code-agent--insert-command-section (cli-path args)
  "Render a ``Command:'' block (cli-path + grouped option/value pairs)."
  (insert "\n"
          (propertize "Command:\n" 'face 'font-lock-keyword-face)
          (format "  %s \\\n" cli-path))
  (dolist (pair (code-agent--group-args-as-pairs args))
    (let ((opt (propertize (car pair) 'face 'font-lock-constant-face))
          (val (cdr pair)))
      (insert (if val
                  (format "    %s %s \\\n" opt val)
                (format "    %s \\\n" opt))))))

(defun code-agent--insert-env-section (env-vars)
  "Render an ``Environment:'' block, masking TOKEN/KEY/SECRET/PASSWORD values."
  (insert (format "\n%s\n"
                  (propertize "Environment:" 'face 'font-lock-keyword-face)))
  (dolist (pair env-vars)
    (let* ((name (car pair))
           (value (cdr pair))
           (display-value
            (if (string-match-p "TOKEN\\|KEY\\|SECRET\\|PASSWORD" name)
                (concat (substring value 0 (min 8 (length value))) "...")
              value)))
      (insert (format "  %s=%s\n"
                      (propertize name 'face 'font-lock-variable-name-face)
                      display-value)))))

(defun code-agent--verbose-insert-query-header
    (session-key prompt &optional cli-path args cwd env-vars)
  "Insert query header in verbose buffer for SESSION-KEY with PROMPT.
CLI-PATH is the path to claude CLI, ARGS are command line arguments,
CWD is working directory, ENV-VARS is alist of environment variables.

Renders four optional sections inside the buffer, in order:
banner → Command (`--insert-command-section') → Working directory
→ Environment (`--insert-env-section') → Prompt."
  (when-let* ((buf (gethash session-key code-agent--session-verbose-buffers)))
    (when (buffer-live-p buf)
      (with-current-buffer buf
        (let ((inhibit-read-only t))
          (goto-char (point-max))
          (insert "\n"
                  "════════════════════════════════════════════════════════════════\n"
                  (format "▸ Query [%s]\n" (format-time-string "%H:%M:%S")))
          (when (and cli-path args)
            (code-agent--insert-command-section cli-path args))
          (when cwd
            (insert (format "\n%s %s\n"
                            (propertize "Working directory:"
                                        'face 'font-lock-keyword-face)
                            cwd)))
          (when env-vars
            (code-agent--insert-env-section env-vars))
          (insert "\n"
                  (propertize "Prompt:\n" 'face 'font-lock-keyword-face)
                  prompt
                  "\n\n"))))))

*** Message Formatter

Pretty-prints tool inputs into the verbose buffer.  Different tool kinds (Read, Bash, Edit, etc.) carry different shapes; this dispatcher renders each with a tool-aware layout.

#+BEGIN_SRC elisp
(defun code-agent--verbose-format-tool-input (input)
  "Format tool INPUT for display, handling different types."
  (cond
   ((null input) "")
   ((stringp input) input)
   ((listp input)
    ;; Convert plist or alist to readable format
    (let ((json-str (condition-case nil
                        (json-encode input)
                      (error (format "%S" input)))))
      json-str))
   (t (format "%S" input))))

(defun code-agent--verbose-format-content-block (block)
  "Format a single content BLOCK for verbose display."
  (cond
   ;; Tool use block - show full tool call with input
   ((code-agent-tool-use-block-p block)
    (let* ((name (code-agent-tool-use-block-name block))
           (input (code-agent-tool-use-block-input block))
           (input-str (code-agent--verbose-format-tool-input input)))
      (concat
       (format "\n%s %s\n"
               (propertize "▶ Tool:" 'face 'font-lock-keyword-face)
               (propertize name 'face 'font-lock-function-name-face))
       (when (and input-str (not (string-empty-p input-str)))
         (format "%s\n%s\n"
                 (propertize "  Input:" 'face 'font-lock-comment-face)
                 input-str)))))

   ;; Tool result block - show content
   ((code-agent-tool-result-block-p block)
    (let* ((is-error (code-agent-tool-result-block-is-error block))
           (content (code-agent-tool-result-block-content block))
           (content-str (if (stringp content)
                            content
                          (code-agent--verbose-format-tool-input content))))
      (concat
       (format "%s %s\n"
               (propertize "◀ Result:" 'face 'font-lock-keyword-face)
               (if is-error
                   (propertize "ERROR" 'face 'error)
                 (propertize "OK" 'face 'success)))
       (when (and content-str (not (string-empty-p content-str)))
         (format "%s\n" content-str)))))

   ;; Thinking block - show actual thinking content
   ((code-agent-thinking-block-p block)
    (let ((thinking (code-agent-thinking-block-thinking block)))
      (concat
       (format "\n%s\n" (propertize "💭 Thinking:" 'face 'font-lock-comment-face))
       (when (and thinking (not (string-empty-p thinking)))
         (format "%s\n" (propertize thinking 'face 'font-lock-doc-face))))))

   ;; Text block
   ((code-agent-text-block-p block)
    (code-agent-text-block-text block))

   (t nil)))

(defun code-agent--verbose-format-content-blocks (blocks &optional parse-raw)
  "Format BLOCKS list into a single string via verbose-format-content-block.
Each block is formatted individually, then joined.  When PARSE-RAW is non-nil,
each element is first passed through `code-agent--parse-content-block'
\(used for raw user-message plists)."
  (let ((parts nil))
    (dolist (block blocks)
      (let ((parsed (if parse-raw
                        (code-agent--parse-content-block block)
                      block)))
        (when-let* ((formatted (code-agent--verbose-format-content-block parsed)))
          (push formatted parts))))
    (when parts
      (mapconcat #'identity (nreverse parts) ""))))

(defun code-agent--verbose-format-assistant-msg (msg)
  "Format assistant MSG for verbose buffer display."
  (let ((content (code-agent-assistant-message-content msg)))
    (code-agent--debug-log "Assistant content blocks: %d items" (length content))
    (dolist (block content)
      (code-agent--debug-log "  Block type: %s"
                               (cond
                                ((code-agent-tool-use-block-p block) "tool_use")
                                ((code-agent-thinking-block-p block) "thinking")
                                ((code-agent-text-block-p block) "text")
                                ((code-agent-tool-result-block-p block) "tool_result")
                                (t (format "unknown: %S" (type-of block))))))
    (code-agent--verbose-format-content-blocks content)))

(defun code-agent--verbose-format-user-msg (msg)
  "Format user MSG for verbose buffer display.
Shows tool results but skips plain string content (already in header)."
  (let ((content (code-agent-user-message-content msg)))
    (cond
     ;; Content is a list of blocks (tool results)
     ((and (listp content) (listp (car content)))
      (code-agent--verbose-format-content-blocks content t))
     ;; String content or anything else — nothing to show
     (t nil))))

(defun code-agent--verbose-format-system-msg (msg)
  "Format system MSG for verbose buffer display."
  (let* ((subtype (code-agent-system-message-subtype msg))
         (data (code-agent-system-message-data msg))
         (message-text (plist-get data :message)))
    (cond
     ((string= subtype "error")
      (format "❌ Error: %s\n" (or message-text subtype)))
     ((string= subtype "init")
      (format "ℹ️ %s\n" (or message-text "Initializing...")))
     (message-text
      (format "ℹ️ %s\n" message-text))
     (subtype
      (format "ℹ️ %s\n" subtype))
     (t nil))))

(defun code-agent--verbose-format-result-msg (msg)
  "Format result MSG for verbose buffer display."
  (format "\n%s\n"
          (propertize
           (format "════ Complete: %.1fs | $%.4f ════"
                   (/ (or (code-agent-result-message-duration-ms msg) 0) 1000.0)
                   (or (code-agent-result-message-total-cost-usd msg) 0))
           'face 'font-lock-comment-face)))

(defun code-agent--verbose-format-message (msg)
  "Format MSG for verbose buffer display.
Dispatches to type-specific formatters for assistant, user, system,
and result messages."
  (cond
   ((code-agent-assistant-message-p msg) (code-agent--verbose-format-assistant-msg msg))
   ((code-agent-user-message-p msg)      (code-agent--verbose-format-user-msg msg))
   ((code-agent-system-message-p msg)    (code-agent--verbose-format-system-msg msg))
   ((code-agent-result-message-p msg)    (code-agent--verbose-format-result-msg msg))
   (t nil)))

(defun code-agent--verbose-write-message (session-key msg)
  "Write MSG to verbose buffer for SESSION-KEY."
  (code-agent--debug-log "Verbose write: session=%s msg-type=%s"
                           session-key
                           (cond
                            ((code-agent-assistant-message-p msg) "assistant")
                            ((code-agent-user-message-p msg) "user")
                            ((code-agent-system-message-p msg) "system")
                            ((code-agent-result-message-p msg) "result")

                (formatted (code-agent--verbose-format-message msg)))
      (when (and buf (buffer-live-p buf) (not (string-empty-p formatted)))
        (with-current-buffer buf
          (let ((inhibit-read-only t))
            (goto-char (point-max))
            (insert formatted)))))))

* Tri-Protocol Architecture
:PROPERTIES:
:CUSTOM_ID: tri-protocol-architecture
:END:

The backend layer is structured as *three protocols stacked by concern*,
each dispatched on the same backend receiver (Smalltalk "one object
implements multiple protocols"). Shipped 2026-04-24 (Phases 0–4).

** Why Two Wire-Model Families

The project drives AI coding agents from Emacs through two fundamentally
different wire models, and the architecture reflects that split:

1. *JSON-stream over stdio* — the CLI subprocess emits newline-delimited
   JSON; Emacs reads token-by-token into the response section. Used by
   Claude Code (=--output-format stream-json=) and by three ACP agents
   (OpenCode, Gemini, Codex) speaking JSON-RPC 2.0.
2. *Terminal multiplexer* — the CLI runs inside a shell pane managed
   by a multiplexer (cmux on macOS, tmux cross-platform); Emacs types
   prompts into the pane and a Python =workspace-bridge= writes
   response text back into the org buffer through MCP callbacks.

Before this refactor the first family had a proper protocol but the
second was a single ~1880-line ad-hoc module that the frontend
branched into via =(string-equal CLAUDE_BACKEND "cmux")= checks at
six call sites. The two families are *siblings* in reality, not
master–slave; the frontend should dispatch identically through both.

** Protocol Stack

The three protocols form a clean separation:

| Protocol | Receiver | Purpose |
|----------+----------+---------|
| 1 — lifecycle | =code-agent-backend= | query / cancel / cleanup / introspect — what every backend does |
| 2b — multiplexer wire | =code-agent-multiplexer-backend= | launch-session / send-text / capture-screen — how to talk to a terminal multiplexer |
| 3 — org-integration | =code-agent-backend= | execute-block / append-response / cancel-from-org — how to plug a backend into a code-agent-org buffer |

(Protocol 2a — agent wire — was retired in 2026-05.  The aspirational
=code-agent-agent-backend= base class had zero subclasses; concrete
agent backends inherit from =code-agent-backend= directly.)

** Why Three Layers on the Agent Side

Three of the four agents (OpenCode, Gemini, Codex) share an ACP
JSON-RPC v1 wire format; their concrete subclasses differ only in
spawn-cmd + capability flags. Putting =code-agent-acp-agent-backend=
in the middle keeps the ACP machinery written once, inherited three
times. Claude Code's =--output-format stream-json= is *not* literally
ACP, so it sits as a sibling to the ACP abstract, not a child of it.
Adding a fifth agent that speaks ACP = flat subclass (cheap); adding
one that speaks something else = new sibling (also cheap).

** Why Two Layers on the Multiplexer Side

cmux and tmux have almost identical APIs at the conceptual level:
launch, send-keys, capture-pane, stream-output, query-status. The
=multiplexer-backend= base holds the Python-bridge adapter contract
(status files, workspace hash table, request-id persistence), the
verbose buffer machinery (ANSI strip, 256 KB cap, kill-buffer-hook
that stops the follower), agent-profile resolution, and the
Claude-only-args filter. Concrete subclasses supply roughly six
=cl-defmethod= implementations each — about 300 lines per multiplexer.

** Two Canonical Execution Flows

Same =C-c C-c= entry point, two shapes downstream depending on which
family the backend belongs to.

*** W1: Agent family (Claude Code / ACP)

#+begin_example

  └─▶ code-agent-org-execute                                    [frontend, backend-agnostic]
        ├─▶ prep: loop state, auto-title, execute-hook, queue-if-busy
        └─▶ code-agent-org-backend-execute-block (backend, info)  ← Protocol 3
              └─▶ method on agent-backend:
                    ├─▶ insert-prompt (no-op; ai block IS the prompt)
                    ├─▶ open-response-section → marker
                    ├─▶ register-query
                    ├─▶ send-prompt ──────▶ Protocol 2a: CLI streams events
                    │     └─▶ on token: append-response (marker, text)
                    │     └─▶ on permission req: handle-permission
                    └─▶ on stream-end: finalize-response (marker, meta)

#+end_example

The frontend never sees the difference. Backend dispatch is on the

** Design Rules (still in force)

These are not historical — they constrain every change to this layer:

- *No string discriminators in the frontend.* Dispatch on the receiver
  via =cl-defmethod=. Per the imported `oop-smalltalk-protocols` rule.
- *No backward-compatibility shims.* When a method or struct is
  renamed, every caller is updated in the same commit; no
  =defalias= layer. Per =.claude/rules/no-backward-compatibility.md=.
- *Pluggability.* Adding a new agent or multiplexer is a new file
  with a struct + =cl-defmethod= implementations + one registry
  entry. Zero frontend changes.
- *256 KB verbose-buffer cap and kill-buffer-hook live on the
  =multiplexer-backend= base*, not in any concrete subclass — a
  resource-leak fix that should not be re-derived per multiplexer.
  Per =.claude/rules/bounded-resource-usage.md=.

The remaining family-specific protocol — Protocol 2b for multiplexers
— lives in [[file:../backend/code-agent-multiplexer.org][code-agent-multiplexer.org]]. The Backend Protocol
section below defines Protocol 1 and the Org-Integration generics
(Protocol 3) that every backend consumes.

  "Filter CALLBACKS based on BACKEND capabilities.
Removes callback keys whose required capability is not supported.
See `code-agent-backend--callback-capabilities' for the mapping."
  (let (result)
    (dolist (mapping code-agent-backend--callback-capabilities)
      (let ((cb-key (car mapping))
            (cap-key (cdr mapping)))

          (when (or (eq cap-key :always)
                    (code-agent-backend-supports-p backend cap-key))
            (setq result (plist-put result cb-key cb))))))
    result))

** Org-Integration Protocol (Protocol 3)

The third protocol alongside lifecycle (Protocol 1) and the
family-specific wire protocols (Protocols 2a/2b).  Protocol 3 covers
*how a backend interacts with the org buffer* — executing an AI
block, inserting prompts, streaming responses, notifying on
permission, recovering sessions.  Every backend implements all three
protocols; sensible defaults cascade from the abstract bases.

The prefix =code-agent-org-backend-= (rather than the
=code-agent-backend-= of Protocols 1/2) is deliberate and final:
it marks the protocol as the org-level interaction surface, visible
to the frontend ([[file:../org/code-agent-org.org][code-agent-org.org]]), while Protocols 1/2 are
wire-level contracts internal to the SDK layer.

The =block-info= plist carries =:prompt=, =:callbacks=, =:props=,
=:session-key=, plus the optional surface keys (=:target-heading=,
=:custom-id=, =:source-buffer=, =:source-marker=, =:loop-max=,
=:loop-interval=) that concrete backends consume when present.

:PROPERTIES:
:CUSTOM_ID: backend-append-response
:END:

* JSON Stream Backend
:PROPERTIES:
:DEPENDS_ON: Backend Protocol
:DEPENDED_BY: Core API, Client API
:END:

The Claude Code backend wraps the existing process layer. It handles
both per-query (one-shot) and persistent-client (bidirectional) modes.

** Design Heritage

This backend's current shape is the result of two extraction passes
that preceded the Tri-Protocol Refactor. Both moves are shipped; the
notes below preserve the *why* now that the as-was layout is gone.

- *2026-03-09 — JSON-stream extraction.* The pre-refactor
  [[file:../chat/code-agent.org][code-agent.org]] was ~5000 lines and conflated two concerns:
  generic SDK coordination (sessions, query registry, mode-line, hooks)
  versus JSON-stream wire mechanics (process spawn, filter, JSON
  parse, control protocol, stdin management, message structs). The
  =backend-query= generic existed but the JSON-stream method just
  delegated back into the same file — the abstraction was a pretty
  facade over a monolith. Extraction created a dedicated backend
  module so callers depend only on generics; backend code stops
  mutating shared state directly.
- *2026-03-10 — per-backend split on the org-integration side.* The
  same shape repeated one layer up: =claude-org.org= was carrying ~1000
  lines of two now-removed terminal backends (deleted in commit
  =1038144= once the multiplexer family covered the same ground). Each
  backend got its own file so per-backend changes stop touching
  unrelated code. The backends themselves are gone; the structural
  pattern survived as the cmux / tmux split today.
- *2026-04-24 — Tri-Protocol formalisation.* The two earlier splits
  produced the right *files* but the *interfaces* between them were
  still ad-hoc — the frontend branched on =CLAUDE_BACKEND= strings,
  agent identity wasn't modelled. The refactor formalised everything
  into the four protocols documented in =* Tri-Protocol
  Architecture= above. The JSON-stream backend now lives as
  =code-agent-claude-code-backend= (Protocol 1 + Protocol 2a
  agent-wire), sibling to the ACP family which speaks JSON-RPC over
  the same agent-wire generics.

** Stream Lifecycle

Six components carry a single CLI invocation from spawn to completion;
each stage is one =defun= in this file. Reading them top-to-bottom is
the cleanest way to understand the wire.

| Stage | Function | What it does |
|-------+----------+--------------|
| 1 | =--start-process= | Spawns =claude --print --output-format stream-json=, attaches filter + sentinel, stores =--process-state= |
| 2 | =--process-filter= | Accumulates raw bytes into =json-buffer=, guards overflow, peels complete JSONL lines |
| 3 | =--process-json-buffer= | Parses each line; =control_request= → control handler, otherwise =handle-message= generic |
| 4 | =--process-normal-message= | Sets =got-result= on result type, fires token / message callbacks, captures =session-id=, calls =--maybe-close-stdin= |
| 5 | =--maybe-close-stdin= | After a =result= message, schedules EOF on stdin so the CLI exits |
| 6 | =--process-sentinel= | Process exit; flushes buffer; calls =on-complete= or triggers auto-recovery |

The =--process-state= struct holds every per-query field the chain
needs:

| Field | Role |
|-------+------|
| =process= / =json-buffer= | Process handle + JSONL accumulator |
| =callback= / =token-callback= / =error-callback= / =complete-callback= | Four lifecycle callbacks the org layer subscribes to |
| =got-result= | Set when the protocol-level =result= message arrives — sole differentiator between normal exit and crash |
| =closed= / =ready= / =cancelled= | Sentinel flags; filter ignores output when =ready= is nil |
| =session-id= | Captured from =system/init=; required for =--resume= |
| =session-key= / =request-id= | Owner identity for verbose logging and registry lookups |

** Real-World Protocol Facts

Audited from 698 real Claude Code sessions plus 24 fixtures
(2026-03 analysis). These are invariants the lifecycle code can rely
on; deviations would be CLI-side regressions, not Emacs bugs.

- *Exactly one =result= per CLI invocation.* Zero exceptions in the
  audit. Crashed/killed processes emit zero. Code that "defends" by
  expecting more is dead.
- *Background agents complete BEFORE =result=.* When the assistant
  launches a Task tool, the CLI waits for the agent internally and
  streams its output back as ordinary =assistant= messages. By the
  time =result= arrives, every byte of agent output is already in
  the org buffer. The SDK does not need to keep stdin open for
  background agents — see the dead-but-harmless tracker note below.
- *Parallel tool use is normal.* Up to 31 parallel tool calls
  observed in a single =assistant= message; 333 instances of
  2-parallel. All =tool_result= blocks for a parallel batch arrive
  in one =user= message. Each =tool_result= triggers PostToolUse
  hooks individually.
- *Message-type taxonomy.* =system= (init, always first) /
  =assistant= (streaming tokens or tool_use blocks) / =user= (tool
  results) / =result= (final, exactly one) / =rate_limit_event=
  (warning, non-fatal) / =control_request= (bidirectional mode,
  permission gating).
- *=stop_reason= values.* =null= (more tokens coming) / =end_turn=
  (assistant finished naturally) / =tool_use= (pausing for tool) /
  =stop_sequence= (CLI-initiated interrupt — dequeue path).

** Completion Model — Three Phases

The current completion path is a three-phase model. Earlier code was
two-phase (protocol-level signal + sentinel) and had a documented
hang: when control requests were pending at the moment =result=
arrived, =--maybe-close-stdin= would log-and-give-up with no retry,
the process never received EOF, and =on-complete= never fired. The
session stayed =:busy t= forever.

| Phase | Trigger | Action | Failure guard |
|-------+---------+--------+---------------|
| 1 — Protocol | =result= message received | Set =got-result=, fire result-received hook, schedule stdin close | — |
| 2 — Stdin Close | Polling retry up to 5 s | Close stdin when control requests clear | Force-close after =max-attempts × delay= |
| 3 — Process Exit | Sentinel fires | Call =on-complete=, cancel watchdog | Watchdog kills runaway process at =code-agent-query-timeout= (default 5 min) |

Three lessons from this design fold back into invariants the code
must keep:

- *No "give up" branches in stdin-close.* Either retry until clear,
  force-close after a max budget, or watchdog-kill — never log and
  return. The hang lived in exactly that gap.
- *Background-task tracker is dead but harmless.* It checks
  =(plist-get tool-use-result :isAsync)= but real Task results return
  *plain text*, not JSON, so =:isAsync= is never present and the
  tracker never registers any task. Removing it would simplify code,
  but since the CLI internally waits for background agents, the
  always-empty tracker does not block anything either. The tracker
  remains for informational display (mode-line, session manager) and
  must NOT block stdin close.
- *=got-result= is the abnormal-exit oracle.* The sentinel decides
  recovery via =--is-abnormal-exit-p=, which returns =t= when ALL
  of: auto-recovery enabled, =session-id= captured, =got-result= NOT
  set, =cancelled= NOT set, exit event matches "killed" / "exited
  abnormally" / "finished". A "finished" exit *without* =got-result=
  is treated as a crash and triggers =--resume-session=. Anything
  that mutates =got-result= prematurely (or skips setting it on the
  result message) breaks recovery.

  "Cancel query via HANDLE (a process-state)."
  (when handle
    (code-agent-query-interrupt handle)))

(cl-defmethod code-agent-backend-cleanup
    ((backend code-agent-claude-code-backend))
  "Clean up JSON backend resources."
  (when-let* ((state (code-agent-claude-code-backend-process-state backend)))
    (code-agent-close-process-state state)
    (setf (code-agent-claude-code-backend-process-state backend) nil))
  (when-let* ((client (code-agent-claude-code-backend-client backend)))
    (when (code-agent-client-alive-p client)
      (code-agent-client-disconnect client))
    (setf (code-agent-claude-code-backend-client backend) nil)))

(cl-defmethod code-agent-backend-send-input
    ((backend code-agent-claude-code-backend) input)
  "Send INPUT to the active Claude Code process via stdin."
  (when-let* ((state (code-agent-claude-code-backend-process-state backend)))
    (when-let* ((proc (code-agent--process-state-process state)))
      (when (process-live-p proc)
        (process-send-string proc (concat input "\n"))))))

(cl-defmethod code-agent-backend-query
    ((backend code-agent-claude-code-backend) prompt callbacks &rest args)
  "Send PROMPT via Claude Code backend, invoking CALLBACKS.
Delegates to `code-agent-query' (one-shot) or
`code-agent-client-send-message' (persistent)."
  (let* ((on-token (plist-get callbacks :on-token))
         (on-message (plist-get callbacks :on-message))
         (on-error (plist-get callbacks :on-error))
         (on-complete (plist-get callbacks :on-complete))
         (state
          (if (code-agent-claude-code-backend-persistent-p backend)
              ;; Persistent mode: reuse client
              (let* ((session-key (code-agent-claude-code-backend-session-key backend))
                     (options (plist-get args :options))
                     (client (or (code-agent-claude-code-backend-client backend)
                                 (let ((c (code-agent-client-create
                                           :options options
                                           :session-key session-key)))
                                   (code-agent-client-connect c "")
                                   (setf (code-agent-claude-code-backend-client backend) c)
                                   c))))
                (code-agent-client-send-message
                 client prompt
                 :token-callback on-token
                 :on-message on-message
                 :on-error on-error
                 :on-complete on-complete)
                (code-agent-client-state client))
            ;; One-shot mode: delegate to code-agent-query
            (apply #'code-agent-query prompt
                   :on-token on-token
                   :on-message on-message
                   :on-error on-error
                   :on-complete on-complete
                   (cl-loop for (k v) on args by #'cddr
                            append (list k v))))))
    ;; Store process-state for active-p / cancel
    (setf (code-agent-claude-code-backend-process-state backend) state)
    state))

** Backend Protocol Contract

*** Protocol Overview

A backend is a =cl-defstruct= inheriting from =code-agent-backend=.  It must
implement the 8 generic functions below.  The presentation layer (code-agent-org.org)
calls only these generics plus =code-agent-backend-filter-callbacks=.

| Generic | Required | Returns | Purpose |
|---------+----------+---------+---------|
| =backend-query= | yes | handle (opaque) | Start a query, invoke callbacks |
| =backend-cancel= | yes | nil | Cancel an in-flight query by handle |
| =backend-cleanup= | yes | nil | Release resources (process, connection) |
| =backend-active-p= | yes | boolean | Is a query currently running? |
| =backend-session-id= | no | string or nil | Resume ID for conversation continuity |
| =backend-send-input= | no | nil | Send user input (permission prompts) |
| =backend-supports-p= | yes | boolean | Capability feature flag check |
| =backend-classify-error= | yes | symbol | Classify error for recovery decisions |

*** Callback Contract

Backends receive a =callbacks= plist with these keys:

| Key | Capability Gate | Purpose |
|-----+-----------------+---------|
| =:on-token= | =:streaming-tokens= | Incremental text chunks |
| =:on-message= | =:structured-messages= | Full structured messages |
| =:on-error= | (always) | Error notification |
| =:on-complete= | (always) | Completion notification |

Use =code-agent-backend-filter-callbacks= before passing callbacks to strip
unsupported features.  =:on-error= and =:on-complete= are never filtered.

*** Standard Capabilities

| Capability | Meaning |
|------------+---------|
| =:streaming-tokens= | Backend emits incremental text tokens |
| =:structured-messages= | Backend emits typed message structs |
| =:tool-use= | Backend supports tool-use blocks |
| =:session-resume= | Backend can resume prior conversations |
| =:interactive-input= | Backend accepts mid-query user input |
| =:persistent-client= | Backend maintains a long-lived connection |

*** Error Classification

=backend-classify-error= must return one of:

| Symbol | Meaning | Recovery |
|--------+---------+----------|
| =context-limit= | Prompt/context too large | Truncate and retry |
| =session-expired= | Session ID no longer valid | Start fresh session |
| =network= | Connection or I/O failure | Retry with backoff |
| =auth= | Authentication/authorization failure | Re-authenticate |
| =unknown= | Unrecognized error | Show to user |

*** Implementing a New Backend

To add a new backend (e.g., HTTP API, terminal multiplexer):
