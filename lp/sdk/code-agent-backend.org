* Overview
:PROPERTIES:
:CUSTOM_ID: backend-overview
:END:

This file is the backend layer's home for the *protocol* (Protocol 1
lifecycle generics + Protocol 3 org-integration generics, dispatched on
the abstract =code-agent-backend= struct) plus the shared setup/session
utilities every backend implementation builds on. The two-family split —
agent-family vs multiplexer-family — comes from two inheritance roots:
agent backends subclass this file's =code-agent-backend= directly;
multiplexer backends subclass =code-agent-multiplexer-backend= in
[[file:../backend/code-agent-multiplexer.org][code-agent-multiplexer.org]], which in turn inherits the protocols
defined here.

The concrete JSON-stream-over-stdio agent backend
(=code-agent-claude-code-backend=, plus the one-shot =code-agent-query=
API, the interactive client wrappers, and the process-lifecycle wiring
that drove them) was deleted 2026-07 — three independent audits found
zero production callers left after the org-as-control-plane pivot moved
execution onto cmux/tmux terminal backends. What remains here is the
protocol surface (dispatched generics + base struct) and the handful of
session/process-state utilities that survive as live dependencies of the
cancellation and query-context machinery.

Read order if you're new to this file:

1. * Tri-Protocol Architecture (high-level meta-design — why three
   protocols, two families, what the capability matrix is for).
2. * Backend Protocol (Protocol 1 + Protocol 3 generic declarations,
   plus the backend-authoring contract every implementer follows).
3. Everything else (shared setup, session/process state, active-query
   tracking + cancellation) — utilities the protocol layer and the
   cmux/tmux backends consume.

*** Elapsed Time Formatting

Shared by the Session Manager dashboard ([[file:../chat/code-agent.org][code-agent.org]]) and org-session
status display — relocated here (2026-07) alongside Debug Logging for the
same reason: its only callers are outside the JSON-stream engine.

#+BEGIN_SRC elisp
(defun code-agent-format-elapsed-time (start-time &optional format-style)
  "Format elapsed time since START-TIME as human-readable string.
FORMAT-STYLE can be:
  'compact   - \"5s\", \"10m\", \"2h\" (default for mode-line)
  'verbose   - \"started 5 seconds ago\"
  nil        - defaults to 'compact

Returns \"unknown\" if START-TIME is nil."
  (if (null start-time)
      "unknown"
    (let* ((elapsed (- (float-time) start-time))
           (style (or format-style 'compact)))
      (cond
       ;; Less than 60 seconds
       ((< elapsed 60)
        (if (eq style 'verbose)
            (format "started %d seconds ago" (round elapsed))
          (format "%ds" (round elapsed))))
       ;; Less than 1 hour
       ((< elapsed 3600)
        (if (eq style 'verbose)
            (format "started %d minutes ago" (round (/ elapsed 60)))
          (format "%dm" (round (/ elapsed 60)))))
       ;; 1 hour or more
       (t
        (if (eq style 'verbose)
            (format "started %d hours ago" (round (/ elapsed 3600)))
          (format "%dh" (round (/ elapsed 3600)))))))))
#+END_SRC

*** Process State Operations

Functions that operate on process state for query lifecycle management.
=code-agent--kill-process-tree= is relocated here (2026-07) from the
(now-deleted) Discovery + Environment > Process Environment section — it is
=code-agent-kill-all-processes='s only remaining dependency from that tree.

#+BEGIN_SRC elisp
(defun code-agent--kill-process-tree (process &optional signal)
  "Kill PROCESS and all its descendant processes.
SIGNAL defaults to SIGKILL (9).  On Unix, child shells (zsh, bash) create
their own process groups via setsid/setpgid, so killing just the parent or
its process group leaves grandchildren orphaned.  This function uses pgrep
to find all descendants and kills them bottom-up."
  (when (process-live-p process)
    (let ((pid (process-id process))
          (sig (or signal 9)))
      (when pid
        ;; Kill descendants first (children, grandchildren, etc.)
        ;; pgrep -P finds direct children; we recurse via the shell
        (let ((desc-pids (split-string
                          (string-trim
                           (shell-command-to-string
                            (format "pgrep -P %d 2>/dev/null" pid)))
                          "\n" t)))
          (dolist (child-pid desc-pids)
            (let ((child-pid-num (string-to-number child-pid)))
              (when (> child-pid-num 0)
                ;; Recursively kill grandchildren first
                (let ((grandchild-pids
                       (split-string
                        (string-trim
                         (shell-command-to-string
                          (format "pgrep -P %s 2>/dev/null" child-pid)))
                        "\n" t)))
                  (dolist (gc-pid grandchild-pids)
                    (let ((gc-pid-num (string-to-number gc-pid)))
                      (when (> gc-pid-num 0)
                        (signal-process gc-pid-num sig)))))
                (signal-process child-pid-num sig)))))
        ;; Finally kill the main process
        (kill-process process)))))

(defun code-agent--query-active-p (state)
  "Return t if STATE represents a truly active query.
Checks both closed state and process liveness."
  (and state
       (code-agent--process-state-p state)
       (not (code-agent--process-state-closed state))
       ;; Process must be nil (not yet started) or alive
       (let ((proc (code-agent--process-state-process state)))
         (or (null proc) (process-live-p proc)))))

(defun code-agent-kill-all-processes ()
  "Kill all active Claude agent processes and their children.
This is useful for cleanup after tests or when processes are stuck.
Returns the number of processes killed."
  (interactive)
  (let ((killed 0))
    ;; Kill via active-states tracking (read from registry)
    (dolist (state (code-agent-registry-active-states))
      (when-let* ((process (code-agent--process-state-process state)))
        (when (process-live-p process)
          (code-agent--kill-process-tree process)
          (cl-incf killed))))
    ;; Also kill via active-queries hash table
    (maphash (lambda (_req-id state)
               (when-let* ((process (code-agent--process-state-process state)))
                 (when (process-live-p process)
                   (code-agent--kill-process-tree process)
                   (cl-incf killed))))
             code-agent--active-queries)
    ;; Clear state tracking (registry is sole owner)
    (setf (code-agent--registry-active-states code-agent--registry) nil)
    (clrhash code-agent--active-queries)
    (when (called-interactively-p 'any)
      (message "Killed %d Claude process(es)" killed))
    killed))

#+END_SRC

*** Active Query Tracking

Global hash table mapping =request-id= to live =process-state=.  Cancellation, sentinel sweep, status UI all consult this single source.

#+BEGIN_SRC elisp
(defvar code-agent--active-queries (make-hash-table :test 'equal)
  "Map request-id to process state for cancellation support.")

(defvar code-agent--request-counter 0
  "Counter for generating unique request IDs.")

(defun code-agent--generate-request-id ()
  "Generate a unique request ID for query tracking."
  (format "req-%d-%.0f" (cl-incf code-agent--request-counter) (* 1000 (float-time))))

(defun code-agent--register-query (request-id state)
  "Register STATE for REQUEST-ID in active queries table."
  (when request-id
    (puthash request-id state code-agent--active-queries)))

(defun code-agent--unregister-query (request-id)
  "Remove REQUEST-ID from active queries table."
  (when request-id
    (remhash request-id code-agent--active-queries)))

(defun code-agent--get-active-query (request-id)
  "Get process state for REQUEST-ID."
  (gethash request-id code-agent--active-queries))

(defcustom code-agent-query-timeout 300
  "Seconds after which a query is considered stale and should be cleaned up.
Queries running longer than this are assumed to be zombie processes from
network issues or other failures. Set to nil to disable timeout cleanup."
  :type '(choice (integer :tag "Seconds")
                 (const :tag "Disable" nil))
  :group 'code-agent)

(defun code-agent--query-timed-out-p (state)
  "Return t if STATE represents a query that has timed out.
Uses `code-agent-query-timeout' to determine staleness."
  (and code-agent-query-timeout
       (code-agent--process-state-p state)
       (code-agent--process-state-start-time state)
       (> (- (float-time) (code-agent--process-state-start-time state))
          code-agent-query-timeout)))

(defun code-agent--state-is-dead-p (state)
  "Return non-nil iff STATE is invalid, closed, or backs a dead process."
  (or (not (code-agent--process-state-p state))
      (code-agent--process-state-closed state)
      (let ((proc (code-agent--process-state-process state)))
        (and proc (not (process-live-p proc))))))

(defun code-agent--scan-stale-queries ()
  "One-pass scan of `--active-queries' for cleanup.
Returns ``(STALE-KEYS TIMED-OUT-KEYS PROCS-TO-KILL)''.  The list of
timed-out processes is collected here but killed by the caller —
mutating the hash table inside `maphash' is undefined behaviour."
  (let (stale timed-out procs)
    (maphash
     (lambda (key state)
       (cond
        ((code-agent--state-is-dead-p state)
         (push key stale))
        ((code-agent--query-timed-out-p state)
         (when-let* ((proc (code-agent--process-state-process state)))
           (when (process-live-p proc)
             (code-agent--debug-log
              "Killing timed-out query: %s (age: %.0fs)"
              key
              (- (float-time)
                 (code-agent--process-state-start-time state)))
             (push proc procs)))
         (push key timed-out))))
     code-agent--active-queries)
    (list stale timed-out procs)))

(defun code-agent--purge-active-states ()
  "Drop dead entries from `--registry-active-states' and log the count."
  (let* ((current (code-agent-registry-active-states))
         (initial (length current))
         (cleaned (cl-remove-if #'code-agent--state-is-dead-p current))
         (removed (- initial (length cleaned))))
    (setf (code-agent--registry-active-states code-agent--registry) cleaned)
    (when (> removed 0)
      (code-agent--debug-log "Cleaned up %d stale states" removed))))

(defun code-agent--cleanup-stale-queries ()
  "Remove stale entries from active-queries hash table and active-states list.
Called after code reload to clean up entries with dead processes,
outdated structure, or queries that have exceeded timeout.

Three phases — scan, kill, purge — avoid mutating the hash inside
`maphash':
1. `--scan-stale-queries' collects keys + procs-to-kill.
2. Kill collected processes outside the hash walk.
3. Remove keys from the hash and `--purge-active-states' from the
   registry's list (which can accumulate independently when the
   hash is correct but the list missed a removal)."
  (condition-case err
      (cl-destructuring-bind (stale-keys timed-out-keys procs-to-kill)
          (code-agent--scan-stale-queries)
        (dolist (proc procs-to-kill)
          (ignore-errors (delete-process proc)))
        (dolist (key (append stale-keys timed-out-keys))
          (remhash key code-agent--active-queries))
        (when stale-keys
          (code-agent--debug-log
           "Cleaned up %d stale queries" (length stale-keys)))
        (when timed-out-keys
          (code-agent--debug-log
           "Cleaned up %d timed-out queries" (length timed-out-keys)))
        (code-agent--purge-active-states))
    (error (message "code-agent: error in stale query cleanup: %S" err))))

;; Run cleanup on load
(code-agent--cleanup-stale-queries)

*** Cancellation Functions

Public =cancel-query= + helpers — marks the state cancelled, delivers a final SIGTERM, unregisters from the active-query table regardless of whether the process actually died.

#+BEGIN_SRC elisp
(defun code-agent-cancel-query (request-id)
  "Cancel query by REQUEST-ID.
Always marks as closed and cancelled, then unregisters, even if process is dead.
Sets the cancelled flag to prevent automatic recovery.
Returns t if found and cancelled, nil if not found."
  (code-agent-with-span "cancel-query"
      (list :request-id request-id) nil
  (let ((state (code-agent--get-active-query request-id)))
    (when state
      ;; Mark as closed and cancelled to prevent auto-recovery
      (setf (code-agent--process-state-closed state) t)
      (setf (code-agent--process-state-cancelled state) t)
      ;; Interrupt process if still alive
      (when-let* ((process (code-agent--process-state-process state)))
        (when (process-live-p process)
          (interrupt-process process)))
      ;; Always unregister from hash table
      (code-agent--unregister-query request-id)
      (code-agent--debug-log "Query cancelled: %s" request-id)
      t))))

(defun code-agent-cancel-all-queries ()
  "Cancel all active queries."
  (maphash (lambda (id _state)
             (code-agent-cancel-query id))
           code-agent--active-queries))

(defun code-agent-cleanup ()
  "Clean up all Claude agent state.
Cancels active queries and removes stale entries."
  (interactive)
  (code-agent-cancel-all-queries)
  (code-agent--cleanup-stale-queries))

#+END_SRC

(defcustom code-agent-cleanup-interval 5

* Tri-Protocol Architecture
:PROPERTIES:
:CUSTOM_ID: tri-protocol-architecture
:END:

The backend layer is structured as *three protocols stacked by concern*,
each dispatched on the same backend receiver (Smalltalk "one object
implements multiple protocols"). Shipped 2026-04-24 (Phases 0–4).

** Why Two Wire-Model Families

The project drives AI coding agents from Emacs through two fundamentally
different wire models, and the architecture reflects that split:

1. *JSON-stream over stdio* — the CLI subprocess emits newline-delimited
   JSON; Emacs reads token-by-token into the response section. Used by
   Claude Code (=--output-format stream-json=) and by three ACP agents
   (OpenCode, Gemini, Codex) speaking JSON-RPC 2.0.
2. *Terminal multiplexer* — the CLI runs inside a shell pane managed
   by a multiplexer (cmux on macOS, tmux cross-platform); Emacs types
   prompts into the pane and a Python =workspace-bridge= writes
   response text back into the org buffer through MCP callbacks.

Before this refactor the first family had a proper protocol but the
second was a single ~1880-line ad-hoc module that the frontend
branched into via =(string-equal CLAUDE_BACKEND "cmux")= checks at
six call sites. The two families are *siblings* in reality, not
master–slave; the frontend should dispatch identically through both.

** Protocol Stack

The three protocols form a clean separation:

| Protocol | Receiver | Purpose |
|----------+----------+---------|
| 1 — lifecycle | =code-agent-backend= | query / cancel / cleanup / introspect — what every backend does |
| 2b — multiplexer wire | =code-agent-multiplexer-backend= | launch-session / send-text / capture-screen — how to talk to a terminal multiplexer |
| 3 — org-integration | =code-agent-backend= | =open-terminal-tab= — the only surviving generic; how a multiplexer backend opens a terminal tab for the org buffer to drive |

(Protocol 2a — agent wire — was retired in 2026-05.  The aspirational
=code-agent-agent-backend= base class had zero subclasses; concrete
agent backends inherit from =code-agent-backend= directly.)

** Why Three Layers on the Agent Side (historical — ACP family removed)

Three of the four agents (OpenCode, Gemini, Codex) shared an ACP
JSON-RPC v1 wire format; their concrete subclasses differed only in
spawn-cmd + capability flags. Putting an ACP-agent abstract in the
middle kept the ACP machinery written once, inherited three times.
Claude Code's =--output-format stream-json= is *not* literally ACP,
so it sat as a sibling to the ACP abstract, not a child of it.

The ACP family (=code-agent-acp*.org=, =code-agent-jsonrpc.org=) was
removed — the pivot direction (org as control plane for agents living
in cmux/tmux terminals) drops embedded ACP chat backends entirely.
=code-agent-claude-code-backend= — the last agent-family backend — was
itself deleted 2026-07 (zero production callers after the pivot); the
agent-family side of this protocol is now unoccupied. The multiplexer
side (cmux/tmux, below) is unaffected.

** Why Two Layers on the Multiplexer Side

cmux and tmux have almost identical APIs at the conceptual level:
launch, send-keys, capture-pane, stream-output, query-status. The
=multiplexer-backend= base holds the Python-bridge adapter contract
(status files, workspace hash table, request-id persistence), the
verbose buffer machinery (ANSI strip, 256 KB cap, kill-buffer-hook
that stops the follower), agent-profile resolution, and the
Claude-only-args filter. Concrete subclasses supply roughly six
=cl-defmethod= implementations each — about 300 lines per multiplexer.

** Two Canonical Execution Flows (historical — both superseded 2026-07)

Same =C-c C-c= entry point, two shapes downstream depending on which
family the backend belongs to. This described the shipped 2026-04-24
architecture. Neither flow is current: =code-agent-org-execute= and
every Protocol 3 generic except =open-terminal-tab= were deleted
2026-07 when the org-as-control-plane pivot removed the Emacs-side
dispatch layer entirely. Kept as the historical record of how the two
families diverged downstream of the same entry point; see "Current
Execution Model" below for what actually runs today.

*** W1: Agent family (Claude Code / ACP) — removed 2026-07

#+begin_example
User C-c C-c in ai block
  └─▶ code-agent-org-execute                                    [frontend, backend-agnostic]
        ├─▶ prep: loop state, auto-title, execute-hook, queue-if-busy
        └─▶ code-agent-org-backend-execute-block (backend, info)  ← Protocol 3
              └─▶ method on agent-backend:
                    ├─▶ insert-prompt (no-op; ai block IS the prompt)
                    ├─▶ open-response-section → marker
                    ├─▶ register-query
                    ├─▶ send-prompt ──────▶ Protocol 2a: CLI streams events
                    │     └─▶ on token: append-response (marker, text)
                    │     └─▶ on permission req: handle-permission
                    └─▶ on stream-end: finalize-response (marker, meta)
                          └─▶ query-completed → advance loop / dequeue
#+end_example

This whole flow — =code-agent-org-backend-execute-block= and every
Protocol 3 generic it calls (=insert-prompt=, =open-response-section=,
=append-response=, =finalize-response=, =query-completed=, etc.) — was
deleted 2026-07 along with =code-agent-claude-code-backend=. Execution
now happens entirely inside the terminal the org buffer drives (W2
below); there is no Emacs-side org-integration dispatch for agent-family
backends anymore.

*** W2: Multiplexer family (cmux / tmux) — removed 2026-07

#+begin_example
User C-c C-c in ai block
  └─▶ code-agent-org-execute                                    [same frontend]
        └─▶ code-agent-org-backend-execute-block (backend, info)  ← Protocol 3
              └─▶ method on multiplexer-backend:
                    ├─▶ ensure-session ────▶ Protocol 2b: launch or reuse pane
                    ├─▶ wait-for-ready
                    ├─▶ insert-prompt   (writes :claude_chat: instruction)
                    ├─▶ open-response-section → marker
                    ├─▶ register-query (writes .request-id)
                    ├─▶ send-text (prompt)  ▶ Protocol 2b
                    ├─▶ send-key :enter     ▶ Protocol 2b
                    ├─▶ start-follower (if verbose mode)
                    └─▶ return — done (response arrives async)

Later, Python hook: UserPromptSubmit / PostToolUse / Stop
  └─▶ workspace_bridge.py → MCP evalElisp
        └─▶ code-agent-org-backend-{append-response,
                                    finalize-response,
                                    query-completed}            ← Protocol 3

Both flows dispatched on the *instance* via Protocol 3 generics, never
on a string discriminator — that part of the design survived. The
dispatch chain itself (=code-agent-org-execute=, =execute-block=,
=insert-prompt=, =open-response-section=, =register-query=,
=append-response=, =finalize-response=, =query-completed=) did not:
deleted 2026-07 along with the rest of the Emacs-side org-integration
layer.

** Current Execution Model — org as control plane

Org no longer dispatches AI-block execution through Protocol 3 at all.
=open-terminal-tab= raises (or focuses) a cmux/tmux terminal pane
running the agent CLI directly; the user interacts with the agent
inside that terminal, not through response text streamed into the org
buffer. What survives on the Emacs side: request-id registration in
=code-agent--active-queries= (mode-line spinner, =*Claude Queries*=
buffer, cancellation — see "Active Query Tracking" above) and the
Python =workspace_bridge.py= writing status to =/tmp/code-agent-status=
for cmux's sidebar. See [[file:../org/code-agent-org-terminal-base.org][code-agent-org-terminal-base.org]] for the
shared cmux/tmux primitives (status file I/O, session-key hash table,
tab-title generation).

** Design Rules (still in force)

These are not historical — they constrain every change to this layer:

- *No string discriminators in the frontend.* Dispatch on the receiver
  via =cl-defmethod=. Per the imported `oop-smalltalk-protocols` rule.
- *No backward-compatibility shims.* When a method or struct is
  renamed, every caller is updated in the same commit; no
  =defalias= layer. Per =.claude/rules/no-backward-compatibility.md=.
- *Pluggability.* Adding a new agent or multiplexer is a new file
  with a struct + =cl-defmethod= implementations + one registry
  entry. Zero frontend changes.
- *256 KB verbose-buffer cap and kill-buffer-hook live on the
  =multiplexer-backend= base*, not in any concrete subclass — a
  resource-leak fix that should not be re-derived per multiplexer.
  Per =.claude/rules/bounded-resource-usage.md=.

The remaining family-specific protocol — Protocol 2b for multiplexers
— lives in [[file:../backend/code-agent-multiplexer.org][code-agent-multiplexer.org]]. The Backend Protocol
section below defines Protocol 1 and the Org-Integration generics
(Protocol 3) that every backend consumes.

* Backend Protocol

Extensible backend abstraction via =cl-defgeneric= / =cl-defmethod=.
Each backend type (cmux/tmux terminal, future HTTP) implements this protocol.
The presentation layer (code-agent-org.org) depends only on these generics.

** Backend Base Struct

Abstract =code-agent-backend= — every concrete subclass (multiplexer-derived,
future HTTP/agent backends) inherits this single base; protocol generics
dispatch on it.

(cl-defstruct (code-agent-backend
               (:constructor nil)
               (:copier nil))
  "Base struct for all agent backends.
Dispatch on this type via cl-defmethod for protocol implementations.
Do not instantiate directly — use a concrete backend constructor."
  (type nil :read-only t
   :documentation "Keyword identifying backend type, e.g. :multiplexer, :terminal."))

** Backend Protocol Generics
:PROPERTIES:
:CUSTOM_ID: backend-backend-protocol-generics
:END:

Protocol 1 lifecycle + Protocol 3 org-integration =cl-defgeneric= declarations.  Concrete backends provide =cl-defmethod= specialisations; the frontend NEVER branches on backend type.

#+BEGIN_SRC elisp
(cl-defgeneric code-agent-backend-query (backend prompt callbacks &rest args)
  "Send PROMPT to BACKEND, invoking CALLBACKS during execution.
CALLBACKS is a plist with :on-token, :on-message, :on-error, :on-complete.
ARGS are keyword options: :options, :session-key, :source-buffer, etc.
Returns an opaque handle for cancellation.")

(cl-defgeneric code-agent-backend-cancel (backend handle)
  "Cancel the active query identified by HANDLE.
HANDLE is the opaque value returned by `code-agent-backend-query'.
No-op if HANDLE is nil or query already completed."
  ;; Default: no-op
  nil)

(cl-defgeneric code-agent-backend-cleanup (backend)
  "Release all resources held by BACKEND."
  ;; Default: no-op
  nil)

(cl-defgeneric code-agent-backend-active-p (backend)
  "Return non-nil if BACKEND has an active query."
  ;; Default: not active
  nil)

(cl-defgeneric code-agent-backend-session-id (backend)
  "Return the current session identifier, or nil if no session."
  ;; Default: no session
  nil)

(cl-defgeneric code-agent-backend-send-input (backend input)
  "Send user INPUT during active query (e.g., tool-use permission responses).
No-op if backend does not support interactive input."
  ;; Default: no-op
  nil)

(cl-defgeneric code-agent-backend-supports-p (backend capability)
  "Return non-nil if BACKEND supports CAPABILITY.
Standard capabilities:
  :streaming-tokens    — delivers :on-token callbacks
  :structured-messages — delivers typed :on-message callbacks
  :tool-use            — supports tool permission flow
  :session-resume      — can resume from session-id
  :interactive-input   — accepts send-input during query
  :persistent-client   — supports long-running connection"
  ;; Default: no capabilities
  nil)

(cl-defgeneric code-agent-backend-classify-error (backend error)
  "Classify ERROR into a standard category.
Returns one of: context-limit, session-expired, network, auth, unknown.
Frontend uses this for recovery decisions."
  ;; Default: unknown
  'unknown)

(cl-defgeneric code-agent-backend-ready-p (backend)
  "Return non-nil if BACKEND is ready to accept a new query.
Persistent backends may return nil when a query is still in-flight."
  ;; Default: always ready
  t)

(defconst code-agent-backend--callback-capabilities
  '((:on-token    . :streaming-tokens)
    (:on-message  . :structured-messages)
    (:on-error    . :always)
    (:on-complete . :always))
  "Alist mapping callback keys to required capabilities.
:always means the callback is never filtered out.")

(defun code-agent-backend-filter-callbacks (backend callbacks)
  "Filter CALLBACKS based on BACKEND capabilities.
Removes callback keys whose required capability is not supported.
See `code-agent-backend--callback-capabilities' for the mapping."
  (let (result)
    (dolist (mapping code-agent-backend--callback-capabilities)
      (let ((cb-key (car mapping))
            (cap-key (cdr mapping)))
        (when-let* ((cb (plist-get callbacks cb-key)))
          (when (or (eq cap-key :always)
                    (code-agent-backend-supports-p backend cap-key))
            (setq result (plist-put result cb-key cb))))))
    result))
#+END_SRC

** Org-Integration Protocol (Protocol 3)

The third protocol alongside lifecycle (Protocol 1) and the
multiplexer wire protocol (Protocol 2b).  Protocol 3 covers *how a
backend interacts with the org buffer*.  After the org-as-control-plane
pivot only one generic remains: =open-terminal-tab=, dispatched by the
frontend's =code-agent-org-open-terminal-tab= command.  The rest of the
old surface (execute-block, prompt/response streaming, permission
notify, session recovery, status badges, todos) was deleted 2026-07
with the embedded-chat path — see git history for the contracts if a
future backend needs them.

The prefix =code-agent-org-backend-= (rather than the
=code-agent-backend-= of Protocols 1/2) is deliberate and final:
it marks the protocol as the org-level interaction surface, visible
to the frontend ([[file:../org/code-agent-org.org][code-agent-org.org]]), while Protocols 1/2 are
wire-level contracts internal to the SDK layer.

*** Open Terminal Tab
:PROPERTIES:
:CUSTOM_ID: backend-open-terminal-tab
:END:

Raises the backend's live terminal so the user can look at it.  Only
meaningful for multiplexer backends — agent backends signal
=user-error= because a stream-json subprocess has no user-visible
terminal.

#+BEGIN_SRC elisp
(cl-defgeneric code-agent-org-backend-open-terminal-tab (backend)
  "Raise BACKEND's terminal tab.  Agent-family default: user-error
(no terminal).  Multiplexer-family overrides to call the multiplexer
CLI's focus/activate command."
  (ignore backend)
  (user-error "No terminal to open for %s backend"
              (or (code-agent-backend-type backend) "unknown")))
#+END_SRC


** Backend Protocol Contract

*** Protocol Overview

A backend is a =cl-defstruct= inheriting from =code-agent-backend=.  It must
implement the 8 generic functions below.  The presentation layer (code-agent-org.org)
calls only these generics plus =code-agent-backend-filter-callbacks=.

| Generic | Required | Returns | Purpose |
|---------+----------+---------+---------|
| =backend-query= | yes | handle (opaque) | Start a query, invoke callbacks |
| =backend-cancel= | yes | nil | Cancel an in-flight query by handle |
| =backend-cleanup= | yes | nil | Release resources (process, connection) |
| =backend-active-p= | yes | boolean | Is a query currently running? |
| =backend-session-id= | no | string or nil | Resume ID for conversation continuity |
| =backend-send-input= | no | nil | Send user input (permission prompts) |
| =backend-supports-p= | yes | boolean | Capability feature flag check |
| =backend-classify-error= | yes | symbol | Classify error for recovery decisions |

*** Callback Contract

Backends receive a =callbacks= plist with these keys:

| Key | Capability Gate | Purpose |
|-----+-----------------+---------|
| =:on-token= | =:streaming-tokens= | Incremental text chunks |
| =:on-message= | =:structured-messages= | Full structured messages |
| =:on-error= | (always) | Error notification |
| =:on-complete= | (always) | Completion notification |

Use =code-agent-backend-filter-callbacks= before passing callbacks to strip
unsupported features.  =:on-error= and =:on-complete= are never filtered.

*** Standard Capabilities

| Capability | Meaning |
|------------+---------|
| =:streaming-tokens= | Backend emits incremental text tokens |
| =:structured-messages= | Backend emits typed message structs |
| =:tool-use= | Backend supports tool-use blocks |
| =:session-resume= | Backend can resume prior conversations |
| =:interactive-input= | Backend accepts mid-query user input |
| =:persistent-client= | Backend maintains a long-lived connection |

*** Error Classification

=backend-classify-error= must return one of:

| Symbol | Meaning | Recovery |
|--------+---------+----------|
| =context-limit= | Prompt/context too large | Truncate and retry |
| =session-expired= | Session ID no longer valid | Start fresh session |
| =network= | Connection or I/O failure | Retry with backoff |
| =auth= | Authentication/authorization failure | Re-authenticate |
| =unknown= | Unrecognized error | Show to user |

*** Implementing a New Backend

To add a new backend (e.g., HTTP API, terminal multiplexer):

#+begin_example
;; 1. Define struct inheriting from base
(cl-defstruct (code-agent-my-backend
               (:include code-agent-backend (type :my-type))
               (:constructor code-agent-my-backend--create)
               (:copier nil))
  "My custom backend."
  (connection nil)
  (session-key nil))

;; 2. Implement required generics

(cl-defmethod code-agent-backend-query
    ((backend code-agent-my-backend) prompt callbacks &rest args)
  ;; Start query, invoke (plist-get callbacks :on-token) etc.
  ;; Return an opaque handle for cancel/tracking.
  ...)

(cl-defmethod code-agent-backend-cancel
    ((backend code-agent-my-backend) handle)
  ;; Cancel query identified by handle
  ...)

(cl-defmethod code-agent-backend-cleanup
    ((backend code-agent-my-backend))
  ;; Release all resources
  ...)

(cl-defmethod code-agent-backend-active-p
    ((backend code-agent-my-backend))
  ;; Return t if a query is in flight
  ...)

(cl-defmethod code-agent-backend-supports-p
    ((backend code-agent-my-backend) capability)
  ;; Return t for supported capabilities
  (memq capability '(:streaming-tokens :structured-messages)))

(cl-defmethod code-agent-backend-classify-error
    ((backend code-agent-my-backend) error)
  ;; Classify error string into standard symbol
  (cond
   ((string-match-p "timeout" error) 'network)
   (t 'unknown)))

;; 3. Create a factory function for code-agent-org integration
(defun code-agent-org--make-my-backend (session-key options)
  (code-agent-my-backend--create :session-key session-key))
#+end_example
