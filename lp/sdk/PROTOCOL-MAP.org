* Overview
:PROPERTIES:
:CUSTOM_ID: protocol-map-overview
:END:

One-page reference of every =cl-defgeneric= in the code-agent SDK,
broken down by protocol family + showing which backends implement
each (= a real =cl-defmethod= specialisation, not the abstract
default).  Read this BEFORE adding a new backend or a new generic —
the patterns visible here are the conventions a new entry should
match.

Invariant: every row's "Specialised by" column lists *only*
=cl-defmethod= sites; "(default)" means the generic's abstract
implementation handles all callers.  Generated 2026-05-27 from
=audit-quarterly=; refresh via =make audit-quarterly= (see
[[file:../../tasks/lessons.md][tasks/lessons.md]] for cadence).

* Protocol 1 — Lifecycle (=code-agent-backend-*=)
:PROPERTIES:
:CUSTOM_ID: protocol-1-lifecycle
:END:

The abstract base every concrete agent backend extends.  Multiplexer
backends inherit through =code-agent-multiplexer-backend=, which
itself extends =code-agent-backend=.

| Generic | Default | Specialised by |
|---------+---------+----------------|
| =code-agent-backend-query= | abstract (raises) | every concrete backend |
| =code-agent-backend-cancel= | abstract | every concrete backend |
| =code-agent-backend-send-input= | abstract | claude-code only (stream-json control msg) |
| =code-agent-backend-cleanup= | abstract | acp, claude-code, pi |
| =code-agent-backend-classify-error= | =unknown= | acp, claude-code, pi |
| =code-agent-backend-active-p= | nil | acp, claude-code, pi |
| =code-agent-backend-session-id= | nil | acp, claude-code, pi |
| =code-agent-backend-ready-p= | t | acp, claude-code, pi |
| =code-agent-backend-supports-p= | nil | acp, claude-code, pi |

Pattern: 9 generics × 3 fully-implementing agent backends + 1
multiplexer family base.  Adding a new agent backend means writing
~9 cl-defmethods.

* Protocol 2b — Multiplexer Wire (=code-agent-mux-*=)
:PROPERTIES:
:CUSTOM_ID: protocol-2b-mux
:END:

The wire protocol multiplexer backends speak to type into a shell
pane.  Only the multiplexer-family subclasses implement.

| Generic | tmux | cmux | orca | Frontend callers |
|---------+------+------+------+------------------|
| =code-agent-mux-cli-path= | yes | yes | yes | yes (via dispatch) |
| =code-agent-mux-launch-session= | yes | (legacy direct) | yes | 2 |
| =code-agent-mux-ensure-session= | yes | yes | yes | yes |
| =code-agent-mux-send-text= | yes | (legacy direct) | yes | 3 |
| =code-agent-mux-send-key= | yes | (legacy direct) | yes | 5 |
| =code-agent-mux-capture-screen= | yes | (legacy direct) | yes | 1 |
| =code-agent-mux-session-status= | yes | (legacy direct) | yes | 3 |
| =code-agent-mux-rename= | yes | no | yes | *0* — not wired |
| =code-agent-mux-focus= | yes | no | yes | 1 — permission alerts |

Pattern: tmux was the reference multi-backend implementation and orca
is the second complete one; cmux's hot path still uses legacy
=code-agent-org-cmux--call= direct dispatch (see
[[file:../backend/code-agent-cmux-backend.org][code-agent-cmux-backend.org]] §"Two-Module Split" for the Phase-3b
migration plan).

Two rows were deleted from this table on 2026-07-25:
=code-agent-mux-start-follower= and =-stop-follower=.  Neither had a
=cl-defgeneric= or a =cl-defmethod= anywhere in the tree — the
streaming follower was removed with the 1 Hz =pipe-pane= poll (see
[[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]] § Query Completion for why) and the map was
never updated.  A stale row in a protocol map is worse than a missing
one: it invites a new backend to implement a contract that does not
exist.

=code-agent-mux-focus= gained its first caller the same day.  It had
shipped as a forward declaration with a no-op default and zero
callers; the permission-alert path in
[[file:../org/code-agent-org-terminal-base.org][code-agent-org-terminal-base.org]] now dispatches through it instead of
calling a cmux CLI directly.

* Protocol 3 — Org Integration (=code-agent-org-backend-*=)
:PROPERTIES:
:CUSTOM_ID: protocol-3-org
:END:

How a backend opens a terminal tab for the org buffer to drive.
Visible to the frontend at =lp/org/code-agent-org.org=.

| Generic | Default | Specialised by | Test coverage |
|---------+---------+----------------+---------------|
| =open-terminal-tab= | signals =user-error= (no terminal for agent-family backends) | cmux, orca | yes |
| =query-completed= | no-op | cmux, orca | yes |
| =permission-needed= | no-op | cmux, orca | yes |
| =permission-resolved= | no-op | cmux, orca | yes |
| =adopt-identity= | no-op | cmux, orca | yes |
| =launch= | signals =user-error= | cmux, orca | yes |
| =cancel-from-org= | signals =user-error= | cmux, orca | yes |

The bulk of the old Protocol 3 surface (=execute-block=,
=insert-prompt=, =open-response-section=, =append-response=,
=finalize-response=, =status-badge=, =todos-update=, =register-query=)
was deleted 2026-07 along with the JSON-stream engine — execution
happens inside the terminal the org buffer drives, not through an
Emacs-side dispatch layer.  That deletion stands.

Six generics came back on 2026-07-25 when the orca backend landed, and
the distinction matters: the deleted ones carried *execution*; these
carry *routing*.  Three route hook callbacks that arrive from Python
over MCP with nothing but a workspace-session-id; =adopt-identity=
rebuilds a backend's pane identity after an Emacs restart; =launch= and
=cancel-from-org= are what the transient menu binds.  Before them the
frontend picked a handler with a =cond= over
=(fboundp 'code-agent-org-cmux--…)=, which made cmux the only
reachable multiplexer regardless of what any other backend
implemented.

* Internal dispatch protocols (within-module)
:PROPERTIES:
:CUSTOM_ID: internal-dispatch
:END:

Three more cl-defgeneric protocols introduced in Phase 6/8 of the
LP-alignment pass to replace large =cond= dispatchers.  These live
inside a single module (not the cross-module SDK protocols above);
listed here for completeness.

| Generic | Module | Replaces | Specialisations |
|---------+--------+----------+-----------------|
| =code-agent-block-parse= | [[file:code-agent-backend.org::*Content Block Parsing][code-agent-backend.org]] | 5-arm pcase on JSON =:type= | text, thinking, tool_use, tool_result |

Pattern: when adding a new wire-protocol message kind to any of the
three, write ONE =cl-defmethod=; no central dispatcher edit.
