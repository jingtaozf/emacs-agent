All user-tunable knobs for =code-agent-org=: the =defgroup=, every
=defcustom= and =defconst=.

Extracted out of [[file:code-agent-org.org][code-agent-org.org]] so the configuration surface is
readable end-to-end without scrolling through the 5K-line main
module. Loaded *first* in [[file:code-agent-org.org][code-agent-org.org]]'s module bootstrap so
every subsequent module sees the customs/hooks/property constants
already bound.

This module is invariant-light by design: nothing here decides
control flow at load time. The few =defun=​s in this file are *hook
attachments* — they exist to live alongside the hook =defvar= they
extend, since the hook contract (signature + status symbols) is the
public surface defined here.

(defcustom code-agent-org-auto-start-mcp-server t
  "Whether to auto-start MCP server when code-agent-org-mode is enabled.
When non-nil, the MCP server will be started automatically if not running."
  :type 'boolean
  :group 'code-agent-org)

(defcustom code-agent-org-setting-sources '("user")
  "List of setting sources for Claude CLI.
Controls where Claude loads skills and settings from.
Valid values: \"user\", \"project\", \"local\".

Can be overridden per-section via CLAUDE_SETTING_SOURCES property."
  :type '(repeat string)
  :group 'code-agent-org)
#+END_SRC

*** Default Multiplexer

Which terminal multiplexer a *newly created* workspace heading is
stamped with.  Backend choice stays declared in the file — the
=:CLAUDE_BACKEND:= property is what dispatch reads — so this only
decides what `code-agent-org-new-workspace' writes.  Runtime host
detection was considered and rejected: cmux and Orca can run at the
same time, and an org file whose behaviour depends on which terminal
happened to start Emacs is not reproducible.

#+NAME: custom-default-backend
#+BEGIN_SRC elisp
(defcustom code-agent-org-default-backend "cmux"
  "Value stamped into `:CLAUDE_BACKEND:' by `code-agent-org-new-workspace'.
Must be a key of `code-agent-org-backend-registry' — \"cmux\",
\"tmux\", or \"orca\".  Existing workspaces are unaffected; they
carry their own property."
  :type '(choice (const "cmux") (const "tmux") (const "orca") string)
  :group 'code-agent-org)
#+END_SRC


** Properties

The property-name constant table.

*** Property Name Constants

Org property names used for session and permission configuration.

| Property | Purpose |
|----------+---------|
| =CLAUDE_PERMISSION_MODE= | Tool permission level (readonly/accept-edits/plan/bypass) |
| =CLAUDE_CLI_SESSION= | Session identifier for =--resume= (all backends) |
| =CLAUDE_SETTING_SOURCES= | Comma-separated list of setting sources |
| =CLAUDE_CODE_PATH= | Claude CLI command/path (e.g. =docker compose exec claude claude=) |
| =CLAUDE_CONTAINER_PATH= | Container path for Docker mapping (e.g. =/workspace=). Uses PROJECT_ROOT as host path. |

;; ENV vars are no longer enumerated as a hard-coded org-property
;; allowlist.  The single source of truth is the `ENV_FILE' org property,
;; which points at a dotenv-style file whose VAR=VALUE lines are sourced
;; into the spawned Claude process.  See `code-agent-org--get-env-vars'.

(defconst code-agent-org--env-cli-flag-map
  '(("ANTHROPIC_MODEL"          . "--model")
    ("CLAUDE_CODE_EFFORT_LEVEL" . "--effort"))
  "Map ENV_FILE keys to Claude CLI flags that must be surfaced explicitly.

Both `ANTHROPIC_MODEL' and `CLAUDE_CODE_EFFORT_LEVEL' do reach the
spawned Claude process through ENV_FILE sourcing, but Claude Code's
~/.claude/settings.json values for `model' and `effort' override the
env-derived values during startup.  CLI flags beat settings.json
unconditionally, so we re-surface these two keys as `--model VALUE' /
`--effort VALUE' on the launcher extras.

Author intent wins: when USER-EXTRA-ARGS already specifies the flag
(either `--flag VALUE' or `--flag=VALUE'), we skip auto-injection to
avoid `--flag A --flag B' duplicates whose CLI-parser handling is
inconsistent across releases.

Add a new entry only when a second case appears whose env value is
silently overridden by settings.json; do not generalise speculatively.")

(defconst code-agent-org--permission-mode-map
  '(("readonly"      . (:cli "default"            :short "RO"))
    ("accept-edits"  . (:cli "acceptEdits"        :short "ED"))
    ("plan"          . (:cli "plan"               :short "PL"))
    ("bypass"        . (:cli "bypassPermissions"  :short "BP")))
  "Map permission preset names to CLI values and short display names.
Each entry is (PRESET . (:cli CLI-VALUE :short SHORT-NAME)).")
