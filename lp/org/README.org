#+TITLE: lp/org — Org-mode Integration

Everything that turns an org file into an AI workbench: =#+begin_src ai=
blocks, the =C-c C-c= execution path, session state, response
streaming, queue management, scheduled execution, the cmux-specific
hot path, and the workspace-bridge that closes the loop back from a
terminal into the org buffer.

* Read order

1. [[file:code-agent-org.org][code-agent-org.org]] first — it defines =code-agent-org-mode= and
   the public dispatch surface; everything else loads as
   sub-systems.
2. [[file:code-agent-org-customize.org][code-agent-org-customize.org]] early — defcustom symbols are
   referenced widely.
3. [[file:code-agent-org-session.org][code-agent-org-session.org]] — the session shape that every
   handler reads.
4. Then the area you're touching: cmux hot path, queue semantics,
   response delivery, etc.

* Boundaries

- /org/ → /sdk/: consumes the backend protocol via generics;
  never reaches into =lp/backend/= directly.
- /org/ → /trace/: consumes trace macros (=code-agent-trace-with-span=).
- /org/ → /chat/: chat surface lives in /chat/; this module owns
  the org-buffer surface specifically.
