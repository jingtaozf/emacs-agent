#+TITLE: Code Agent Org — Process / Query / Status
#+PROPERTY: literate-load yes

* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

Multi-session process management: persistent Claude clients keyed
by session-key, query-id tracking, response section creation, the
backend constructor registry, marker lifecycle helpers, and the
=AI_EXEC_STATUS= property writer/reader.

** Concerns owned

| Concern | Public surface |
|---------+----------------|
| Persistent client class | =code-agent-org-persistent-entry= / =-registry= structs + the 9 registry verbs (get-entry, get, alive-p, register, update-activity, disconnect, disconnect-buffer, list, count) |
| Backend registry | =code-agent-org-backend-registry= alist + =code-agent-org--make-default-backend= + the ACP session-id persistence wiring |
| Lifecycle hooks | =--on-buffer-kill= / =--on-todo-state-change= (attached to kill-buffer-hook and org-after-todo-state-change-hook in the main module) |
| Query-ID system | =--create-response-section= / =--find-response-by-query-id= / =--find-response-end-by-query-id= / =--insert-at-response= / =--handle-token-v2= |
| Marker lifecycle | =--marker-valid-p= / =--with-session-marker= macro |
| Execution status | =AI_EXEC_STATUS= property writer / reader / per-session variants |

** Why one module

Everything here participates in *the running of a query*:
construct (or look up) a persistent client → register it → mint a
query-id → write the response section → stream tokens into it via
marker-free lookup → mark exec status → on kill or state change,
disconnect. Splitting these across three files would scatter a
single causal chain.

The "registry" + "backend registry" pair is also an OOP cohesive
unit: backends are *what gets stored*; registry is *where they
live*. Same module.

** Load-order constraint

Sits late in the bootstrap dolist — after every module it reads
from:

| Reads from | Module |
|------------+--------|
| =--session-get/put= | =session= |
| =--current-session-key= | =session-context= |
| =--get-org-property= | =env-permission= |
| =--find-instruction-number= | =block= |
| =--normalize-headers-in-text=, =--auto-break-lines=, =--schedule-fontlock= | =response= |
| Backend constructors (=code-agent-claude-code-backend-create=, =code-agent-cmux-backend-create=, ACP creates) | their own modules (already required at file top of main) |

The main module reaches *back* into this one for
=code-agent-org-cancel-all= / =code-agent-org--goto-block-by-custom-id=
/ =code-agent-org--effective-section-level= / =code-agent-org--session-display-name=.
Those are late-bound through Elisp's runtime symbol lookup — fine
because nothing here invokes them at load time.

** Dependencies

Loaded eagerly at file evaluation time — symbols below assume every required feature is already provided.

* Persistent Client Registry

Long-running Claude clients keyed by session-key.  Unlike
=code-agent-org--sessions= (buffer-local, per-query state), this registry
owns live processes that survive across multiple queries.  Earlier
versions kept state in a bare hash table plus seven free functions —
the classic "wrap the hash in a class" smell that
the imported `oop-smalltalk-protocols` rule calls out.  The registry
is now an explicit coordinator: one =code-agent-org-persistent-registry=
struct, one singleton, generics for every verb callers need.

*** The Entry Class

One session's persistent-client state.  =cl-defstruct= with typed
slots replaces the previous untyped =:client= / =:buffer= / =:heading-pos=
plists so accessors are discoverable and refactors are compiler-checked.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-org-persistent-entry
               (:constructor code-agent-org-persistent-entry--create)
               (:copier nil))
  "One persistent-client entry held by `code-agent-org-persistent-registry'."
  (client nil
          :documentation "`code-agent-client' struct — the live process handle.")
  (buffer nil
          :documentation "Source org buffer that owns this client (cleaned up on buffer-kill).")
  (heading-pos nil
               :documentation "Position of the session-defining heading (for TODO state changes).")
  (last-activity nil
                 :documentation "float-time of the most recent query or response.")
  (query-count 0
               :documentation "Monotonically-incrementing count of queries dispatched through this client."))
#+END_SRC

*** The Registry Class + Singleton

The registry owns the hash.  Only one exists per Emacs
(=code-agent-org--persistent-registry=); every call site dispatches into
it via the generics below.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-org-persistent-registry
               (:constructor code-agent-org-persistent-registry--create)
               (:copier nil))
  "Registry of persistent Claude clients keyed by session-key.
See the Entry Class above for the per-session shape."
  (entries (make-hash-table :test 'equal)
           :documentation "Hash table: session-key (string) → `code-agent-org-persistent-entry'."))

(defvar code-agent-org--persistent-registry
  (code-agent-org-persistent-registry--create)
  "The module-wide singleton registry.
Tests may rebind this, but all normal code paths share the one
instance because a persistent client is a per-Emacs resource.")
#+END_SRC

*** Lookup

=get-entry= returns the internal struct; =get= returns just the
client (the common read path); =alive-p= is a bool shortcut.

#+BEGIN_SRC elisp
(defun code-agent-org-persistent-registry-get-entry (registry session-key)
  "Return the `code-agent-org-persistent-entry' for SESSION-KEY, or nil."
  (gethash session-key (code-agent-org-persistent-registry-entries registry)))

(defun code-agent-org-persistent-registry-get (registry session-key)
  "Return the live client handle for SESSION-KEY, or nil if absent."
  (when-let* ((entry (code-agent-org-persistent-registry-get-entry
                      registry session-key)))
    (code-agent-org-persistent-entry-client entry)))

(defun code-agent-org-persistent-registry-alive-p (registry session-key)
  "Return non-nil iff SESSION-KEY has a live client in REGISTRY."
  (when-let* ((client (code-agent-org-persistent-registry-get registry
                                                              session-key)))
    (code-agent-client-alive-p client)))
#+END_SRC

*** Registration + Activity

=register= records a new entry; =update-activity= bumps the
timestamp and increments the query counter after each successful
dispatch.

#+BEGIN_SRC elisp
(defun code-agent-org-persistent-registry-register
    (registry session-key client buffer heading-pos)
  "Record CLIENT + BUFFER + HEADING-POS under SESSION-KEY in REGISTRY."
  (puthash session-key
           (code-agent-org-persistent-entry--create
            :client client
            :buffer buffer
            :heading-pos heading-pos
            :last-activity (float-time)
            :query-count 0)
           (code-agent-org-persistent-registry-entries registry)))

(defun code-agent-org-persistent-registry-update-activity
    (registry session-key)
  "Bump `last-activity' and increment `query-count' for SESSION-KEY."
  (when-let* ((entry (code-agent-org-persistent-registry-get-entry
                      registry session-key)))
    (setf (code-agent-org-persistent-entry-last-activity entry) (float-time))
    (setf (code-agent-org-persistent-entry-query-count entry)
          (1+ (or (code-agent-org-persistent-entry-query-count entry) 0)))))
#+END_SRC

*** Disconnection

Two verbs: one-session and all-for-buffer.  The single-session path
emits a user-facing message; the buffer-sweep path delegates to the
single-session path so the message format stays consistent.

#+BEGIN_SRC elisp
(defun code-agent-org-persistent-registry-disconnect
    (registry session-key &optional reason)
  "Disconnect and remove the entry for SESSION-KEY from REGISTRY.
REASON (optional string) is shown in the user-facing message."
  (when-let* ((entry (code-agent-org-persistent-registry-get-entry
                      registry session-key)))
    (when-let* ((client (code-agent-org-persistent-entry-client entry)))
      (when (code-agent-client-alive-p client)
        (code-agent-client-disconnect client)))
    (remhash session-key
             (code-agent-org-persistent-registry-entries registry))
    (message "Claude: Disconnected session %s%s"
             (code-agent-org--session-display-name session-key)
             (if reason (format " (%s)" reason) ""))))

(defun code-agent-org-persistent-registry-disconnect-buffer (registry buffer)
  "Disconnect every entry whose `buffer' slot matches BUFFER."
  (let ((to-remove nil))
    (maphash (lambda (key entry)
               (when (eq (code-agent-org-persistent-entry-buffer entry) buffer)
                 (push key to-remove)))
             (code-agent-org-persistent-registry-entries registry))
    (dolist (key to-remove)
      (code-agent-org-persistent-registry-disconnect registry key "buffer killed"))))
#+END_SRC

*** Enumeration

Enumerates response sections in a buffer — used when the Stop hook needs to find the matching response section by sequence rather than by query-id.

#+BEGIN_SRC elisp
(defun code-agent-org-persistent-registry-list (registry)
  "Return a list of (SESSION-KEY . ENTRY) pairs for every entry in REGISTRY."
  (let ((pairs nil))
    (maphash (lambda (key entry) (push (cons key entry) pairs))
             (code-agent-org-persistent-registry-entries registry))
    (nreverse pairs)))

(defun code-agent-org-persistent-registry-count (registry)
  "Return the number of entries currently held by REGISTRY."
  (hash-table-count (code-agent-org-persistent-registry-entries registry)))
#+END_SRC

*** Backend Registry Dispatch

The backend registry maps CLAUDE_BACKEND property strings to
constructor lambdas.  It's wired to the persistent registry only
indirectly — ACP constructors use =code-agent-org--acp-session-persistence=
to set up session-id auto-save on the returned backend.

#+BEGIN_SRC elisp
(defun code-agent-org--acp-session-persistence ()
  "Read the stored ACP_SESSION_ID and return a (INITIAL-ID . SAVE-FN) pair.
SAVE-FN writes the new session id back to the org entry at point.
Captures the current marker so the save is bound to the block's heading
even if point moves later.  `lexical-let' is required because literate-elisp
does not honour the file header's lexical-binding directive — without it,
`marker' would be looked up dynamically at callback time and trigger a
void-variable error."
  (let ((initial (code-agent-org-get-org-property "ACP_SESSION_ID" t)))
    (lexical-let ((marker (point-marker)))
      (cons initial
            (lambda (session-id)
              (when (and session-id (marker-buffer marker))
                (condition-case err
                    (with-current-buffer (marker-buffer marker)
                      (save-excursion
                        (goto-char marker)
                        (org-entry-put nil "ACP_SESSION_ID" session-id)
                        (save-buffer)))
                  (error
                   (message "code-agent-org: failed to persist ACP_SESSION_ID: %s"
                            (error-message-string err))))))))))

(defun code-agent-org--pi-session-persistence ()
  "Read `:PI_SESSION_ID:` (inheritance-aware) and return (INITIAL-ID . SAVE-FN).

SAVE-FN writes the new id back to the *session-scope* heading (the
workspace heading, not the Instruction child) so sibling AI blocks
inherit the same Pi session.  ACP's analogue writes to the current
Instruction heading; that breaks inheritance across siblings.  For
Pi we want the id to be a workspace-level fact.

Captures the session-scope heading as a marker NOW (registry
construction time) so save-fn isn't sensitive to where point is
when Pi's handshake response lands."
  (let* ((initial (code-agent-org-get-org-property "PI_SESSION_ID" t))
         (scope-pos (or (code-agent-org--find-session-scope-heading)
                        (save-excursion
                          (when (ignore-errors (org-back-to-heading t))
                            (point))))))
    (lexical-let ((marker (and scope-pos (copy-marker scope-pos)))
                  (buf (current-buffer)))
      (cons initial
            (lambda (session-id)
              (when (and session-id marker (marker-buffer marker))
                (condition-case err
                    (with-current-buffer (marker-buffer marker)
                      (save-excursion
                        (goto-char marker)
                        (org-entry-put nil "PI_SESSION_ID" session-id))
                      ;; DELIBERATELY skip `save-buffer' here — the buffer
                      ;; is mid-query (response section markers are live;
                      ;; org-mode property writes interleave with token
                      ;; insertion).  Persistence-to-disk piggy-backs on
                      ;; the normal auto-save or the next user save.
                      (set-buffer-modified-p (buffer-modified-p)))
                  (error
                   (message "code-agent-org: failed to persist PI_SESSION_ID: %s"
                            (error-message-string err))))))))))

;; NOTE on reload semantics: `defvar' is idempotent — once
;; `code-agent-org-backend-registry' has a value, re-evaluating the
;; defvar form (e.g. via `literate-elisp-load') does NOT replace
;; the value with the new lambdas.  Without an explicit reset, edits
;; to any registry lambda (e.g. wiring up a new save-session-id-fn)
;; require a fresh Emacs to take effect — which makes iterative
;; dev painful and silently leaks the old lambdas.
;;
;; Fix: define the canonical entries in `--default-backend-registry'
;; and re-`setq' on every load.  Users who customized
;; `code-agent-org-backend-registry' at runtime via `add-to-list'
;; etc. will lose their additions on reload — they should subclass
;; the helper instead.
(defun code-agent-org--default-backend-registry ()
  "Return the canonical backend registry alist.
Called from the file body to (re)initialize the global registry on
every literate-elisp reload — this is what makes hot-edits to a
factory lambda actually take effect."
  `(("claude-code"   . ,(lambda (session-key _options)
                          (code-agent-claude-code-backend--create
                           :session-key session-key
                           :persistent-p code-agent-org-persistent-sessions)))
    ("opencode-acp"  . ,(lambda (session-key options)
                          (let ((persist (code-agent-org--acp-session-persistence)))
                            (code-agent-acp-opencode-create
                             :session-key session-key
                             :cwd (plist-get options :cwd)
                             :initial-session-id (car persist)
                             :save-session-id-fn (cdr persist)))))
    ("gemini-acp"    . ,(lambda (session-key options)
                          (let ((persist (code-agent-org--acp-session-persistence)))
                            (code-agent-acp-gemini-create
                             :session-key session-key
                             :cwd (plist-get options :cwd)
                             :initial-session-id (car persist)
                             :save-session-id-fn (cdr persist)))))
    ("codex-acp"     . ,(lambda (session-key options)
                          (let ((persist (code-agent-org--acp-session-persistence)))
                            (code-agent-acp-codex-create
                             :session-key session-key
                             :cwd (plist-get options :cwd)
                             :initial-session-id (car persist)
                             :save-session-id-fn (cdr persist)))))
    ("cmux"          . ,(lambda (session-key _options)
                          (code-agent-cmux-backend-create
                           :session-key session-key)))
    ("tmux"          . ,(lambda (session-key _options)
                          (code-agent-tmux-backend-create
                           :session-key session-key)))
    ("pi"            . ,(lambda (session-key options)
                          ;; Default-loaded by code-agent.el.  Reads
                          ;; provider/model from ~/.pi/agent/settings.json
                          ;; and persists the Pi-side session id to
                          ;; :PI_SESSION_ID: so respawn after subprocess
                          ;; death continues the same conversation.
                          (let ((persist (code-agent-org--pi-session-persistence)))
                            (code-agent-pi-backend-create
                             :session-key session-key
                             :cwd (plist-get options :cwd)
                             :session-id (car persist)
                             :save-session-id-fn (cdr persist)))))))

(defvar code-agent-org-backend-registry
  (code-agent-org--default-backend-registry)
  "Alist mapping CLAUDE_BACKEND string → constructor (session-key options).
Each constructor returns a backend struct.  Add new agents by appending
entries here.  Re-evaluating this defvar via reload does NOT replace
existing values (defvar semantics); a follow-up `setq' below forces
the refresh so iterative dev on a factory lambda just works.

ACP entries auto-wire the ACP_SESSION_ID org property for persistence;
the pi entry does the same with PI_SESSION_ID.  The cmux entry is a
facade — the legacy string-match branch in `code-agent-org-execute'
still handles the hot path; the backend exists for symmetry and for
future Phase 3b cut-over.")

;; Force-refresh on every literate-elisp reload (see defun docstring).
(setq code-agent-org-backend-registry
      (code-agent-org--default-backend-registry))

(defun code-agent-org--make-default-backend (session-key options)
  "Create the default backend for SESSION-KEY with OPTIONS.
Dispatches on the CLAUDE_BACKEND org property via
`code-agent-org-backend-registry'.  Unknown values fall back to
\"claude-code\" with a one-line `message' so the user knows to update
the property (e.g. \"json-stream\" → \"claude-code\")."
  (let* ((prop-value (code-agent-org-get-org-property "CLAUDE_BACKEND" t))
         (direct-hit (cdr (assoc prop-value code-agent-org-backend-registry)))
         (constructor (or direct-hit
                          (cdr (assoc "claude-code" code-agent-org-backend-registry)))))
    (when (and prop-value (not direct-hit))
      (message "CLAUDE_BACKEND=%S not in registry; falling back to claude-code."
               prop-value))
    (funcall constructor session-key options)))

(defun code-agent-org--resolve-backend (session-key options)
  "Return the backend for SESSION-KEY, invalidating the cache if the
=:CLAUDE_BACKEND:= org property changed since the cached backend was
constructed.

Without invalidation the session's =:backend= slot is sticky: setting
=:CLAUDE_BACKEND: pi= on a heading whose session previously ran on
=cmux= silently keeps dispatching to the old cmux backend.  This was
the user-reported 2026-05-25 bug.

Mechanism: cache both the backend struct (slot =:backend=) and the
=CLAUDE_BACKEND= string used to build it (slot =:backend-property=).
On every resolve, compare current property against cached property —
mismatch ⇒ `code-agent-backend-cleanup' on the stale struct +
rebuild via `code-agent-org--make-default-backend' + cache both new
slots atomically.

OPTIONS is forwarded to the constructor (plist with :cwd etc.)."
  (let* ((current-prop (code-agent-org-get-org-property "CLAUDE_BACKEND" t))
         (cached       (code-agent-org-session-get session-key :backend))
         (cached-prop  (code-agent-org-session-get session-key :backend-property)))
    (cond
     ;; Cache hit — property unchanged since last dispatch.
     ((and cached (equal current-prop cached-prop))
      cached)
     ;; Cache miss or property change — cleanup old (if any) + rebuild.
     (t
      (when cached
        (message "code-agent-org: CLAUDE_BACKEND changed (%s → %s); rebuilding backend"
                 (or cached-prop "?") (or current-prop "?"))
        (ignore-errors (code-agent-backend-cleanup cached)))
      (let ((fresh (code-agent-org--make-default-backend session-key options)))
        (code-agent-org-session-put session-key :backend fresh)
        (code-agent-org-session-put session-key :backend-property current-prop)
        fresh)))))

#+END_SRC

* Lifecycle Hooks

Hook functions for cleaning up persistent clients based on org lifecycle events.

#+BEGIN_SRC elisp
(defun code-agent-org--on-buffer-kill ()
  "Clean up active sessions and persistent clients when org buffer is killed.
Cancels active queries to prevent zombie CLI processes (F21),
then disconnects persistent clients.
Added to `kill-buffer-hook' (buffer-local) in `code-agent-org-mode'."
  ;; Cancel active queries first (F21: prevents zombie CLI processes)
  (when (and (bound-and-true-p code-agent-org--sessions)
             (hash-table-p code-agent-org--sessions)
             (> (hash-table-count code-agent-org--sessions) 0))
    (code-agent-org-cancel-all))
  ;; Disconnect persistent clients
  (when buffer-file-name
    (code-agent-org-persistent-registry-disconnect-buffer
     code-agent-org--persistent-registry (current-buffer))))

(defvar org-state) ; dynamically bound by Org in todo-state-change hooks

(defun code-agent-org--on-todo-state-change ()
  "Handle TODO state changes for session lifecycle.
When a section with CLAUDE_SESSION_ID is marked DONE or CANCELLED,
disconnect the associated persistent client.

Added to `org-after-todo-state-change-hook' (buffer-local) in `code-agent-org-mode'."
  (when (and (bound-and-true-p org-state)
             (member org-state '("DONE" "CANCELLED")))
    ;; Check if this heading has a CLAUDE_SESSION_ID
    (when-let* ((session-id (org-entry-get nil "CLAUDE_SESSION_ID" nil)))
      (let ((session-key (code-agent-org-current-session-key)))
        (when (code-agent-org-persistent-registry-alive-p
               code-agent-org--persistent-registry session-key)
          (code-agent-org-persistent-registry-disconnect
           code-agent-org--persistent-registry
           session-key
           (format "section marked %s" org-state)))))))
#+END_SRC

* Query-ID System

Query-IDs provide reliable, marker-free response tracking. Each query gets a
unique ID stored as an org property, enabling:
- Race-free callback validation (old queries ignored)
- Persistent response location (survives buffer kill/Emacs restart)
- Clear audit trail (every response traceable to its query)

(Query-ID generation lives in [[file:code-agent-org-response.org][code-agent-org-response.org]].)

*** Response Section Creation

Inserts a new =Response N= heading + skeleton at the right depth + tags — preserves marker validity across the insertion.

#+BEGIN_SRC elisp
(defun code-agent-org--create-response-section (session-key query-id query-type
                                            &optional parent-query-id recovery-reason
                                            loop-info)
  "Create a response section for SESSION-KEY with QUERY-ID.
QUERY-TYPE is 'normal or 'recovery.
For recovery queries, PARENT-QUERY-ID and RECOVERY-REASON should be provided.
LOOP-INFO is (ITERATION . MAX) for loop iterations, or nil.

Returns the position where content should be inserted (after properties)."
  (code-agent-with-span "create-response-section"
      (list :query-id query-id :query-type (symbol-name query-type)) nil
  (let* ((section-level (code-agent-org--effective-section-level session-key))
         ;; Response should be at SAME level as instruction (sibling), not child
         ;; section-level is the instruction heading level, so use it directly
         (response-level section-level)
         (stars (make-string response-level ?*))
         ;; Get instruction number from session or find by :claude_chat: tag
         ;; Note: code-agent-org--find-instruction-number returns nil if no :claude_chat: heading found
         (instr-num (or (code-agent-org-session-get session-key :instruction-num)
                        (code-agent-org--find-instruction-number)))
         (timestamp (format-time-string "%Y-%m-%d %H:%M"))
         ;; Build loop suffix for iteration numbering
         (loop-suffix (if loop-info
                          (format "(%d/%d)" (car loop-info) (cdr loop-info))
                        ""))
         ;; For recovery, use N.M numbering; for normal, just the number
         ;; If no instruction number found, omit the number from heading
         (response-num (cond
                        ((null instr-num)
                         ;; No instruction found - use timestamp-based identifier
                         (format-time-string "%H%M%S"))
                        ((eq query-type 'recovery)
                         (let ((recovery-count (or (code-agent-org-session-get session-key :recovery-count) 0)))
                           (code-agent-org-session-put session-key :recovery-count (1+ recovery-count))
                           (format "%s.%d" instr-num (1+ recovery-count))))
                        (t
                         (number-to-string instr-num))))
         (tags (if (eq query-type 'recovery)
                   ":ai_output:recovery:"
                 ":ai_output:"))
         (heading (format "%s Response %s%s (%s) %s" stars response-num loop-suffix timestamp tags)))
    (save-excursion
      ;; Insert heading
      (insert heading "\n")
      ;; Insert properties
      (insert ":PROPERTIES:\n")
      (insert (format ":QUERY_ID: %s\n" query-id))
      (insert (format ":QUERY_TYPE: %s\n" (symbol-name query-type)))
      (when (and (eq query-type 'recovery) parent-query-id)
        (insert (format ":PARENT_QUERY_ID: %s\n" parent-query-id)))
      (when (and (eq query-type 'recovery) recovery-reason)
        (insert (format ":RECOVERY_REASON: %s\n" recovery-reason)))
      (insert ":END:\n\n")
      ;; Reset content flag so first-token newline stripping works
      (code-agent-org-session-put session-key :response-has-content nil)
      ;; Return current position (where content will be inserted)
      (point)))))
#+END_SRC

*** Query-ID Based Response Lookup

Locates the response heading whose =:QUERY_ID:= matches — the primary path for mid-stream token insertion and Stop-hook finalisation.

#+BEGIN_SRC elisp
(defun code-agent-org--find-response-by-query-id (query-id)
  "Find response section by QUERY-ID property.
Returns the heading position, or nil if not found.
Widens the buffer to ensure the search covers the entire file,
even when the buffer is narrowed (e.g., via org-narrow-to-subtree)."
  (save-excursion
    (save-restriction
      (widen)
      (goto-char (point-min))
      (when (re-search-forward
             (format ":QUERY_ID: +%s *$" (regexp-quote query-id)) nil t)
        (org-back-to-heading t)
        (point)))))

(defun code-agent-org--find-response-end-by-query-id (query-id)
  "Find end of response section identified by QUERY-ID.
Returns position at end of the section subtree (before next sibling).
Uses `save-restriction'/`widen' so it works even when buffer is narrowed (F20)."
  (save-excursion
    (save-restriction
      (widen)
      (let ((heading-pos (code-agent-org--find-response-by-query-id query-id)))
        (when heading-pos
          (goto-char heading-pos)
          (org-end-of-subtree t)
          (point))))))
#+END_SRC

*** Marker-Free Token Insertion

Inserts marker-free token into the org buffer at the matching marker — preserves point + window-start.

#+BEGIN_SRC elisp
(defun code-agent-org--insert-at-response (session-key text)
  "Insert TEXT at end of response section for SESSION-KEY.
Uses query-id property lookup instead of marker.
Returns t if insertion succeeded, nil otherwise.
Uses `save-restriction'/`widen' so it works even when buffer is narrowed (F20)."
  (let ((query-id (code-agent-org-session-get session-key :query-id)))
    (when query-id
      (save-excursion
        (save-restriction
          (widen)
          (let ((heading-pos (code-agent-org--find-response-by-query-id query-id)))
            (when heading-pos
              (goto-char heading-pos)
            ;; Capture response section level for level-aware stop pattern
            (let* ((response-level (org-current-level))
                   ;; Only stop at headings at SAME or SHALLOWER level than
                   ;; the response section; deeper headings are content within it
                   (stop-pattern (format "^\\*\\{1,%d\\} " response-level)))
              (if (re-search-forward "^:END:" nil t)
                  (progn
                    ;; Skip past :END: to the blank line after it
                    (forward-line 1)
                    ;; Skip ONE blank line if present (the standard separator)
                    (when (looking-at "^$")
                      (forward-line 1))
                    ;; If we're now at a same-or-shallower heading, insert BEFORE it
                    (if (looking-at stop-pattern)
                        (progn
                          (forward-line -1)
                          (end-of-line)
                          (insert text)
                          t)
                      ;; Otherwise, find the end of content in this section
                      (let ((insert-pos (line-end-position)))
                        ;; Search forward for same-or-shallower heading or end of buffer
                        (while (and (not (eobp))
                                    (not (looking-at stop-pattern)))
                          (setq insert-pos (line-end-position))
                          (forward-line 1))
                        ;; insert-pos now points to end of last content line
                        (goto-char insert-pos)
                        (insert text)
                        t)))
                ;; No :END: found, fall back to end of heading line
                (end-of-line)
                (insert "\n" text)
                t)))))))))

(defun code-agent-org--handle-token-v2 (session-key text)
  "Handle incoming TEXT token for SESSION-KEY using query-id lookup.
Normalizes org headers, auto-breaks long lines, and inserts at response section.
This is the marker-free version using query-id."
  (let ((query-id (code-agent-org-session-get session-key :query-id)))
    (if (not query-id)
        ;; B1/F18: Warn instead of silently dropping tokens
        (message "Claude: token dropped for %s — nil query-id (recovery race?)" session-key)
      (let* ((target-level (1+ (code-agent-org--effective-section-level session-key)))
             (normalized-text (code-agent-org--normalize-headers-in-text text target-level))
             ;; Auto-break long lines
             (current-line-len (or (code-agent-org-session-get session-key :current-line-length) 0))
             (break-result (code-agent-org--auto-break-lines normalized-text current-line-len))
             (final-text (car break-result))
             (new-line-len (cdr break-result)))
        ;; Update line length state
        (code-agent-org-session-put session-key :current-line-length new-line-len)
        ;; Strip leading newlines from the very first token of a new response.
        ;; Claude's model often starts assistant text with "\n\n" which creates
        ;; unwanted blank lines after the :END: property drawer.
        (unless (code-agent-org-session-get session-key :response-has-content)
          (when (> (length final-text) 0)
            (setq final-text (string-trim-left final-text "\n+"))
            (when (> (length final-text) 0)
              (code-agent-org-session-put session-key :response-has-content t))))
        ;; Prepend newline separator between consecutive assistant messages.
        ;; :last-assistant-query-id stores the query-id of the most recent
        ;; assistant message's on-message callback.  When we see the SAME
        ;; query-id here it means a previous assistant message already
        ;; produced output in this query, so we insert a blank-line separator.
        ;; Cross-query stale values are harmless: different query-ids won't match.
        (let ((last-asst-qid (code-agent-org-session-get session-key :last-assistant-query-id)))
          (when (and (> (length final-text) 0)
                     last-asst-qid
                     (equal last-asst-qid query-id))
            ;; Clear so we only insert one separator per assistant message boundary
            (code-agent-org-session-put session-key :last-assistant-query-id nil)
            (setq final-text (concat "\n\n" final-text))))
        ;; Insert processed text using query-id lookup
        (when (> (length final-text) 0)
          (code-agent-org--insert-at-response session-key final-text))
        ;; Schedule fontification
        (code-agent-org--schedule-fontlock)))))
#+END_SRC

* Marker Lifecycle Management

Robust marker validation to prevent crashes when markers become invalid
during async operations. Markers can become invalid when their buffer is
killed or when they haven't been set to a position.

#+BEGIN_SRC elisp
(defun code-agent-org--marker-valid-p (marker)
  "Check if MARKER is still valid for use.
Returns non-nil if MARKER is:
- An actual marker object (not nil or other type)
- Associated with a buffer (not just created with `make-marker')
- Its buffer is still live (not killed)
- Has a valid position (not nil)

This should be called before any operation that uses a marker,
especially in async contexts where the buffer may have been killed."
  (and marker
       (markerp marker)
       (marker-buffer marker)
       (buffer-live-p (marker-buffer marker))
       (marker-position marker)))

(defmacro code-agent-org--with-session-marker (marker &rest body)
  "Execute BODY in the buffer of MARKER if it is valid, else return nil.
Switches to the marker's buffer using `with-current-buffer', so BODY
runs with the marker's buffer current.  If MARKER is nil, not a marker,
or its buffer has been killed, BODY is silently skipped and nil is returned."
  (declare (indent 1) (debug t))
  (let ((m (make-symbol "marker")))
    `(let ((,m ,marker))
       (when (code-agent-org--marker-valid-p ,m)
         (with-current-buffer (marker-buffer ,m)
           ,@body)))))
#+END_SRC

* Execution Status Property

Track execution state via org property for visibility.

#+BEGIN_SRC elisp
(defconst code-agent-org-exec-status-property "AI_EXEC_STATUS"
  "Org property name for tracking AI block execution status.")

(defun code-agent-org--set-exec-status (status &optional marker)
  "Set execution status property on current heading.
STATUS is one of: \"scheduled\", \"executing\", \"completed\", \"error\", or nil to clear.
If MARKER is provided, set status at marker position instead of point.
If marker is invalid (buffer killed), this function does nothing."
  (save-excursion
    (cond
     ;; Marker provided - validate before use
     ((and marker (code-agent-org--marker-valid-p marker))
      (set-buffer (marker-buffer marker))
      (goto-char marker)
      (org-back-to-heading t)
      (if status
          (org-entry-put nil code-agent-org-exec-status-property status)
        (org-entry-delete nil code-agent-org-exec-status-property)))
     ;; Marker provided but invalid - do nothing silently
     (marker nil)
     ;; No marker - use current buffer position
     (t
      (org-back-to-heading t)
      (if status
          (org-entry-put nil code-agent-org-exec-status-property status)
        (org-entry-delete nil code-agent-org-exec-status-property))))))

(defun code-agent-org--get-exec-status ()
  "Get execution status property from current heading."
  (save-excursion
    (org-back-to-heading t)
    (org-entry-get nil code-agent-org-exec-status-property)))

(defun code-agent-org--set-exec-status-for-session (session-key status)
  "Set exec STATUS for SESSION-KEY using custom-id lookup.
Returns non-nil if status was successfully set."
  (let ((custom-id (code-agent-org-session-get session-key :custom-id)))
    (when custom-id
      (save-excursion
        (when (code-agent-org--goto-block-by-custom-id custom-id)
          (code-agent-org--set-exec-status status)
          t)))))

(defun code-agent-org--get-exec-status-for-session (session-key)
  "Get current exec status for SESSION-KEY using custom-id lookup."
  (let ((custom-id (code-agent-org-session-get session-key :custom-id)))
    (when custom-id
      (save-excursion
        (when (code-agent-org--goto-block-by-custom-id custom-id)
          (code-agent-org--get-exec-status))))))
