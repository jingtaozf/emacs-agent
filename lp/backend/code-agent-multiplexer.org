* Overview
:PROPERTIES:
:CUSTOM_ID: multiplexer-overview
:END:

The agent-family branch of the tri-protocol split drives a CLI
subprocess over stdio and reads structured ACP events; the
multiplexer-family branch types prompts into a shell pane and
collects response text asynchronously through the Python
=workspace-bridge= adapter.  This module owns the multiplexer side
— the abstract base class plus Protocol 2b (multiplexer-wire)
generics that cmux and tmux subclasses implement.

Invariant: every multiplexer backend MUST extend
=code-agent-multiplexer-backend= and provide Protocol 2b methods
(send-text, capture-screen, wait-for-ready, etc.).  Shared
machinery — agent profile resolution, Python bridge contract,
verbose buffer ring — lives here so a third multiplexer (kitty,
zellij) drops in as a subclass without forking the contract.

* Claude Agent — Multiplexer Family Base
:PROPERTIES:
:LITERATE_ORG_BLOCK_KIND: atomic
:header-args:elisp: :tangle yes
:END:

Abstract base class for all terminal-multiplexer-driven backends
(cmux + tmux) plus the Protocol 2b multiplexer-wire generics.

This module owns the multiplexer-family branch of the tri-protocol
split. The agent-family branch lives directly on
=code-agent-backend= (lifecycle Protocol 1): agent backends drive a
CLI subprocess over stdio and read structured events; multiplexer
backends type prompts into a shell pane and pick up response text
asynchronously through the Python =workspace-bridge= adapter. The
shared abstractions — agent profile resolution, Python bridge
contract, verbose buffer machinery — live here.

*Implementation status*: Protocol 2b is currently only implemented
by =code-agent-tmux-backend=. The cmux subclass exists for symmetry
(=code-agent-cmux-backend= struct + base class wiring) but the live
cmux hot path still runs through [[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]]'s legacy
direct-CLI calls. The Protocol-2b shape is the planned target for the
cmux Phase 3b cut-over; until then, the 11 generic declarations below
serve as the documented contract a future cmux method set must honour.

** Multiplexer Base Struct

Shared state for any multiplexer-driven backend. Identity is the
multiplexer-assigned session id plus the pane/surface id inside it.
Status directory is the on-disk rendezvous with the Python bridge
(status files, request-id marker, from-emacs flag). Follower process
holds the =capture-pane= / =pipe-pane= stream subprocess; stream-sink
is the file it writes to.

Agent-profile resolution lives here (not per-concrete-multiplexer)
because cmux and tmux both launch the same set of agent CLIs
(Claude Code, Copilot, OpenCode) using the same launch patterns.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-multiplexer-backend
               (:include code-agent-backend (type :multiplexer))
               (:constructor nil)
               (:copier nil))
  "Abstract base for multiplexer-driven terminal backends.
Concrete subclasses: `code-agent-cmux-backend' (Phase 3),
`code-agent-tmux-backend' (Phase 4).  Do not instantiate directly.

Slot policy: only slots *every* multiplexer needs live here.
Multiplexer-specific niceties (cmux workspace colour, sidebar
metadata, tmux control-mode state) belong on the concrete subclass,
not the abstract base."
  (session-key            nil
   :documentation "Emacs session key `file::session-id' (shared identity with frontend).")
  (multiplexer-session-id nil
   :documentation "Session identifier as understood by the multiplexer.")
  (pane-id                nil
   :documentation "Pane / surface identifier within that session.")
  (status-dir             "/tmp/code-agent-status"
   :documentation "On-disk rendezvous dir for Python bridge side-channel.")
  (agent-profile          nil
   :documentation "Agent profile struct (claude/copilot/opencode)."))
#+END_SRC

** Protocol 2b Generics

The published wire protocol for multiplexers. Each generic is
declared here with a safe default; concrete multiplexers override.
tmux implements 9 of these (capture-screen + cli-path fall through
to the abstract defaults); cmux currently implements none.

*** Specialisation status (as of audit 2026-05-27)

| Generic | Default | tmux impl | cmux impl | Frontend callers |
|---------+---------+-----------+-----------+------------------|
| =mux-cli-path= | abstract | yes | no — pending Phase 3b migration | yes |
| =mux-launch-session= | abstract | yes | no | 2 |
| =mux-ensure-session= | abstract | yes | no | yes |
| =mux-send-text= | abstract | yes | no | 3 |
| =mux-send-key= | abstract | yes | no | 5 |
| =mux-capture-screen= | abstract | yes | no | 1 |
| =mux-session-status= | abstract | yes | no | 3 |
| =mux-rename= | abstract | yes | no | *0* — not yet wired |
| =mux-focus= | abstract | yes | no | *0* — not yet wired |

The 9 wired methods all dispatch through =cl-defgeneric= regardless
of how many backends specialise.  cmux's hot path still uses legacy
direct CLI calls (see [[file:code-agent-cmux-backend.org][code-agent-cmux-backend.org]] §"Two-Module Split"
for the Phase-3b migration plan); when migrated, cmux will add
specialisations for all 11 methods.

The two zero-caller rows (=mux-rename=, =mux-focus=) are forward
declarations — tmux has the implementation but the frontend hasn't
yet wired them through.  Removing them would re-litigate the
multi-backend rename + focus workspace when those frontend wires land.

** Shared helpers — ANSI strip + verbose cap

Both cmux and tmux run the same stream filter over pane output. The
ANSI-strip regex and the 256 KB verbose buffer cap (from the
2026-04-24 memory-leak fix) live here so both concrete multiplexers
inherit them for free. The cmux copies
=code-agent-org-cmux-verbose-buffer-max-size= and
=code-agent-org-cmux--verbose-strip-ansi= predated the multiplexer
extraction and were retired once the shared versions stabilised.

*** Strip ANSI escapes from a chunk

Terminal output arrives with color codes, cursor moves, and OSC
sequences mixed in.  This pure-text-out helper feeds the verbose
buffer machinery and the bridge that ferries response text into the
org buffer — both want plain text, so the strip happens here once.

#+BEGIN_SRC elisp
(defun code-agent-multiplexer--strip-ansi (chunk)
  "Best-effort strip of ANSI escape sequences + control chars from CHUNK.
Preserves newline/tab/CR for line-structured output."
  (replace-regexp-in-string
   "\x1b\\[[0-9;?]*[a-zA-Z]\\|\x1b\\][^\a\x1b]*\\(?:\a\\|\x1b\\\\\\)\\|[\x00-\x08\x0b\x0c\x0e-\x1f]"
   "" chunk))
#+END_SRC

*** Verbose buffer size ceiling

Without a cap the verbose buffer grows forever on long-running
sessions; commit 1f016b8 in the cmux backend was the leak that
motivated this knob.  Whole-line trim from the front so partial
escape sequences never get cut mid-byte.

#+BEGIN_SRC elisp
(defcustom code-agent-multiplexer-verbose-buffer-max-size (* 256 1024)
  "Ceiling (bytes) for each multiplexer verbose buffer.
When exceeded, whole lines are trimmed from the start.  Shared by
cmux and tmux verbose streams.  Set nil to disable (long sessions
will grow without bound — not recommended)."
  :type '(choice (const :tag "No cap (unbounded growth)" nil)
                 (integer :tag "Max bytes"))
  :group 'code-agent)
#+END_SRC
