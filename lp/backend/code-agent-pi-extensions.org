This file is the *single source of truth* for every TypeScript
extension installed into =~/.pi/agent/extensions/=. Each Pi
extension owns one top-level =* Extension: <name>= section with a
section-local =:header-args:typescript :tangle …:= drawer so the
tangle targets do not collide.

| Top-level section | Tangle target | What it does |
|-------------------+---------------+--------------|
| =* Extension: emacs-mcp= | =~/.pi/agent/extensions/emacs-mcp.ts= | Bridges Pi-side tool calls back to Emacs MCP (the user's live editor) |
| =* Extension: doom-loop-detector= | =~/.pi/agent/extensions/doom-loop.ts= | Catches token-repeat + same-arg tool-call doom loops, aborts the turn |

Both ship together — =make tangle-pi-extensions= writes both
=.ts= files in one Emacs batch invocation.

To add a new extension: copy the section-shape of either existing
extension (heading + =:CUSTOM_ID:= + =:header-args:typescript
:tangle ...:= drawer + prose preamble + src blocks), then teach
=Makefile= about the new output if you want CI to assert it.

** Overview
:PROPERTIES:
:CUSTOM_ID: pi-ext-overview
:END:

A Pi-side TypeScript extension that exposes a handful of *Emacs tools*
to whichever LLM Pi is driving. When Pi is the backend for an Emacs
=#+begin_src ai= block (via [[file:code-agent-pi-backend.org][code-agent-pi-backend.org]]), this
extension closes the loop:

#+begin_example
,#+begin_src ai      Emacs
   │                                                              ▲
   │  prompt                                            tool result│
   ▼                                                              │
pi --mode rpc ───► LLM ───► emacs_* tool call ──► this extension ─┘
                                                       │
                                                       │ POST /mcp
                                                       ▼
                                            emacs-mcp-server (port 9999)
                                                       │
                                                       ▼
                                            evalElisp on host Emacs
#+end_example

The LLM running inside Pi can now say "read buffer X", "get the
=CLAUDE_BACKEND= property of this heading", "run this elisp" — and
get a real answer from the user's live Emacs session, not a
hallucination.

Per the dual-audience reader principle: configuration constants live

| Env var | Default | Role |
|---------|---------|------|
| =EMACS_MCP_URL= | =http://localhost:9999/mcp= | Endpoint of the Emacs MCP HTTP server |
| =EMACS_MCP_TIMEOUT_MS= | =5000= | Per-call HTTP timeout |
| =EMACS_MCP_ALLOW_EVAL= | =1= (default-allow) | =0= → re-engage the confirm gate for =emacs_eval=.  Default flipped 2026-05-27 — pi-permission-system's =tools.emacs_eval= rule + =yoloMode= is the authoritative gate in this stack, so a second confirmation here was redundant and noisy. |

#+begin_src typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

const MCP_URL = process.env.EMACS_MCP_URL ?? "http://localhost:9999/mcp";
const MCP_TIMEOUT_MS = Number(process.env.EMACS_MCP_TIMEOUT_MS ?? "5000");
// Default-allow: the agent harness already gates emacs_eval through
// pi-permission-system (tools.emacs_eval, plus the global deny floor).
// Set EMACS_MCP_ALLOW_EVAL=0 to re-engage this redundant in-extension
// confirm prompt — useful only when you don't trust the harness's
// policy file.
const ALLOW_EVAL = process.env.EMACS_MCP_ALLOW_EVAL !== "0";
const VERBOSE = process.env.EMACS_MCP_VERBOSE === "1";

const vlog = (msg: string): void => {
	if (VERBOSE) process.stderr.write(`[emacs-mcp] ${msg}\n`);
};

** MCP HTTP client
:PROPERTIES:
:CUSTOM_ID: pi-ext-mcp-client
:END:

A single helper that POSTs a JSON-RPC 2.0 =tools/call= request and
returns the unwrapped result string. Errors are surfaced as thrown
=Error= objects whose message is shaped for direct return to the LLM.

The =emacs-mcp-server= treats every call as independent (no =initialize=
handshake required for stateless tool invocation), so we don't bother
with session tracking.

#+begin_src typescript
let nextRpcId = 1;

interface McpToolResult {
	content?: Array<{ type: string; text?: string }>;
	isError?: boolean;
}

async function callMcpTool(toolName: string, args: Record<string, unknown>): Promise<string> {
	const id = nextRpcId++;
	const body = JSON.stringify({
		jsonrpc: "2.0",
		id,
		method: "tools/call",
		params: { name: toolName, arguments: args },
	});
	vlog(`tools/call ${toolName} ${JSON.stringify(args).slice(0, 200)}`);

	const ac = new AbortController();
	const timer = setTimeout(() => ac.abort(), MCP_TIMEOUT_MS);
	let resp: Response;
	try {
		resp = await fetch(MCP_URL, {
			method: "POST",
			headers: { "Content-Type": "application/json" },
			body,
			signal: ac.signal,
		});
	} catch (err) {
		throw new Error(`Emacs MCP unreachable at ${MCP_URL}: ${err instanceof Error ? err.message : String(err)}`);
	} finally {
		clearTimeout(timer);
	}

	if (!resp.ok) {
		throw new Error(`Emacs MCP HTTP ${resp.status}: ${await resp.text()}`);
	}
	const payload = (await resp.json()) as {
		result?: McpToolResult;
		error?: { code?: number; message?: string };
	};
	if (payload.error) {
		throw new Error(`Emacs MCP error ${payload.error.code ?? ""}: ${payload.error.message ?? "unknown"}`);
	}
	const result = payload.result;
	if (!result) return "";
	const text = (result.content ?? []).map((c) => c.text ?? "").join("\n");
	if (result.isError) {
		throw new Error(`Emacs tool failed: ${text || "no detail"}`);
	}
	return text;
}
#+end_src

*** evalElisp wrapper
:PROPERTIES:
:CUSTOM_ID: pi-ext-evalelisp
:END:

Every high-level tool ultimately calls =evalElisp= with a precomputed
elisp expression — the MCP server only exposes =evalElisp= and
=report_invocation=, everything else is constructed here from elisp
primitives.

#+begin_src typescript
async function evalElisp(code: string): Promise<string> {
	return callMcpTool("evalElisp", { code });
}

/** Quote a JS string as an elisp string literal — escapes \ and ". */
function elispString(s: string): string {
	return `"${s.replace(/\\/g, "\\\\").replace(/"/g, '\\"')}"`;
}

*** emacs_org_get_property
:PROPERTIES:
:CUSTOM_ID: pi-ext-tool-getprop
:END:

Reads an org property at a given heading. =heading= can be either
the literal heading text (e.g. =* Test Dev Workspace=) or a
=CUSTOM_ID= prefixed with =#=. =buffer= names the org buffer.

#+begin_src typescript
const GETPROP_PARAMS = Type.Object({
	buffer: Type.String({ description: "Org buffer name, e.g. 'workspace-test.org'." }),
	heading: Type.String({
		description:
			"Either the heading text (e.g. '* Test Dev Workspace') or a CUSTOM_ID prefixed with '#' (e.g. '#e2e-test-dev-workspace').",
	}),
	property: Type.String({ description: "Property name (case-insensitive), e.g. 'CLAUDE_BACKEND'." }),
});

function registerGetPropTool(pi: ExtensionAPI): void {
	pi.registerTool({
		name: "emacs_org_get_property",
		label: "Org property",
		description:
			"Get an org property from a heading in a given org buffer. Returns the property value as a string, or empty string if absent.",
		parameters: GETPROP_PARAMS,
		async execute(_callId, { buffer, heading, property }) {
			const code = `
(with-current-buffer ${elispString(buffer)}
  (save-excursion
    (let ((case-fold-search t)
          (h ${elispString(heading)}))
      (goto-char (point-min))
      (condition-case nil
          (progn
            (cond
             ((string-prefix-p "#" h)
              (org-link-search (concat "#" (substring h 1))))
             (t (re-search-forward (concat "^" (regexp-quote h) "$"))))
            (or (org-entry-get nil ${elispString(property)} t) ""))
        (search-failed (format "ERROR: heading not found: %s" h))))))`;
			const out = await evalElisp(code);
			return { content: [{ type: "text", text: out }] };
		},
	});
}

*** emacs_org_navigate
:PROPERTIES:
:CUSTOM_ID: pi-ext-tool-nav
:END:

Returns the body (prose + first src block) of a specific heading.
Useful for an LLM to inspect a story, system-prompt, or workflow
section without dumping the entire buffer.

#+begin_src typescript
const NAVIGATE_PARAMS = Type.Object({
	buffer: Type.String({ description: "Org buffer name." }),
	heading: Type.String({
		description: "Heading text or '#custom-id' to navigate to.",
	}),
	max_chars: Type.Optional(
		Type.Number({ description: "Truncation cap on returned body (default 4000)." }),
	),
});

function registerNavigateTool(pi: ExtensionAPI): void {
	pi.registerTool({
		name: "emacs_org_navigate",
		label: "Org navigate",
		description:
			"Read the body of a specific org heading (everything between the heading and the next sibling/parent heading). Returns the body text, truncated to max_chars.",
		parameters: NAVIGATE_PARAMS,
		async execute(_callId, { buffer, heading, max_chars }) {
			const cap = max_chars ?? 4000;
			const code = `
(with-current-buffer ${elispString(buffer)}
  (save-excursion
    (let ((h ${elispString(heading)}))
      (goto-char (point-min))
      (condition-case nil
          (progn
            (cond
             ((string-prefix-p "#" h) (org-link-search (concat "#" (substring h 1))))
             (t (re-search-forward (concat "^" (regexp-quote h) "$"))))
            (let* ((start (line-beginning-position 2))
                   (end (save-excursion (org-end-of-subtree t t) (point)))
                   (body (buffer-substring-no-properties start end))
                   (cap ${cap}))
              (if (> (length body) cap)
                  (concat (substring body 0 cap) "\\n... (truncated)")
                body)))
        (search-failed (format "ERROR: heading not found: %s" h))))))`;
			const out = await evalElisp(code);
			return { content: [{ type: "text", text: out }] };
		},
	});
}

#+begin_src typescript
const BUFFER_READ_PARAMS = Type.Object({

*** emacs_buffer_list
:PROPERTIES:
:CUSTOM_ID: pi-ext-tool-list
:END:

Companion tool to =emacs_buffer_read=: lists buffer names (with
optional substring filter) so the LLM has a discovery handle.
Without this the LLM would have to guess buffer names, which never
worked reliably.

#+begin_src typescript
const BUFFER_LIST_PARAMS = Type.Object({
	pattern: Type.Optional(
		Type.String({ description: "Optional substring filter on buffer name." }),
	),
});

function registerBufferListTool(pi: ExtensionAPI): void {
	pi.registerTool({
		name: "emacs_buffer_list",
		label: "Buffer list",
		description:
			"List visible buffer names (excluding hidden buffers whose name starts with a space). Optional case-sensitive substring filter via the `pattern` argument.",
		parameters: BUFFER_LIST_PARAMS,
		async execute(_callId, { pattern }) {
			const code = `
(let ((pat ${pattern ? elispString(pattern) : "nil"}))
  (mapconcat
    'identity
    (sort
      (cl-remove-if-not
        (lambda (n)
          (and (not (string-prefix-p " " n))
               (or (null pat) (string-match-p (regexp-quote pat) n))))
        (mapcar 'buffer-name (buffer-list)))
      'string<)
    "\\n"))`;
			const out = await evalElisp(code);
			return { content: [{ type: "text", text: out }] };
		},
	});
}

*** session_start health check
:PROPERTIES:
:CUSTOM_ID: pi-ext-health
:END:

Probe the MCP server once when a Pi session starts. If unreachable
we warn — but don't block; the user may not have started the Emacs
MCP server yet, or may be using Pi standalone for an unrelated task.

#+begin_src typescript
function attachHealthCheck(pi: ExtensionAPI): void {
	pi.on("session_start", async (_event, ctx) => {
		// tools/list is a cheap probe and confirms both transport + dispatcher.
		const body = JSON.stringify({ jsonrpc: "2.0", id: "hc", method: "tools/list" });
		const ac = new AbortController();
		const timer = setTimeout(() => ac.abort(), 2000);
		try {
			const r = await fetch(MCP_URL, {
				method: "POST",
				headers: { "Content-Type": "application/json" },
				body,
				signal: ac.signal,
			});
			if (!r.ok) throw new Error(`HTTP ${r.status}`);
			vlog("MCP health check OK");
		} catch (err) {
			const msg = err instanceof Error ? err.message : String(err);
			vlog(`MCP health check FAILED: ${msg}`);
			if (ctx.hasUI) {
				ctx.ui.notify(
					`Emacs MCP unreachable at ${MCP_URL} (${msg}). emacs_* tools will fail until you start the server (M-x emacs-mcp-server-start).`,
					"warning",
				);
			}
		} finally {
			clearTimeout(timer);
		}
	});
}

*** Confirm gate for emacs_eval
:PROPERTIES:
:CUSTOM_ID: pi-ext-confirm
:END:

The =tool_call= event fires *before* a tool is executed.  Returning
=block: true= aborts the call.

Historically this gate ran by default and asked a y/n confirm on
every =emacs_eval=.  Pre-2026-05 the gate was the only thing in
front of arbitrary elisp; today the agent harness layers on
=pi-permission-system= ([[file:code-agent-pi-backend.org::*Setting up Pi on a fresh machine][per-setup instructions]]) which already
runs =tools.emacs_eval= through =pi-permissions.jsonc= +
=yoloMode=.  Two prompts on the same call was just noise, so the
default of =ALLOW_EVAL= is flipped to *allow*; set
=EMACS_MCP_ALLOW_EVAL=0= to re-engage this in-extension confirm
(useful when running a Pi without =pi-permission-system= installed
or with a deliberately-permissive policy and you still want
emacs_eval gated).

#+begin_src typescript
function attachConfirmGate(pi: ExtensionAPI): void {
	pi.on("tool_call", async (event, ctx) => {
		if (event.toolName !== "emacs_eval") return;
		if (ALLOW_EVAL) return;
		if (!ctx.hasUI) {
			// Headless run with no allowlist override → fail closed.
			return { block: true, reason: "emacs_eval blocked: no UI to confirm and EMACS_MCP_ALLOW_EVAL not set." };
		}
		const code = String((event.input as Record<string, unknown>).code ?? "");
		const preview = code.length > 240 ? code.slice(0, 240) + "..." : code;
		const ok = await ctx.ui.confirm("Allow emacs_eval?", preview);
		if (!ok) return { block: true, reason: "User declined emacs_eval." };
	});
}

** Why this exists
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-why
:END:

Pi's =session.prompt()= path has *no native doom-loop detection*.
The maintainer's stated design (=mariozechner.at 2025-11-30=) is
"doom-loop detection is available as an opt-in extension." This
file is that extension.

Two failure modes observed in practice ([[https://github.com/earendil-works/pi/issues/4338][pi#4338]] "Agent says
'working' but makes no progress"):

| Symptom | Mechanism | Where this extension catches it |
|---------+-----------+---------------------------------|
| Same =(tool, args)= called repeatedly | Tool returns same result, model re-decides to retry | =tool_call= handler counts hashed-arg suffix repeats, returns =block: true= once threshold tripped |
| Same prose sentence streamed over and over | Model token-level loop (low temperature, prior repetition, or prompt-driven) | =message_end= handler tokenises into sentences, suffix-counts identical ones |

Thresholds default to *5 tool repeats* / *10 sentence repeats* —
aligned with the Claude Code [[https://github.com/anthropics/claude-code/issues/4277][#4277]] spec for the same problem
shape. Tunable via =~/.pi/agent/settings.json= →
=extensions.doomLoop.*= so a user can dial them up for chatty
models or down if false positives appear.

When tripped:

1. =process.stderr.write("[doom-loop] ...\n")= surfaces a single
   line into the cmux verbose buffer (Emacs side reads pi's
   stderr via the =start-process= sentinel; users see it through
   =M-x code-agent-org-show-verbose=).
2. =ctx.abort()= cancels the current streaming turn, dropping
   back to =Agent.isStreaming = false=. The user's next prompt
   then starts cleanly.
3. For tool repeats, additionally =return { block: true, reason
   }= so Pi short-circuits the about-to-execute tool call —
   prevents one final wasted invocation.

** Configuration
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-config
:END:

Pi loads =~/.pi/agent/settings.json= at startup and exposes its
contents to extensions only indirectly — there is no
=pi.getConfig()=. The extension re-reads the file directly. Per
the 2026-05-27 settings-schema agreement, the config sits at a
top-level =doomLoop= key — *not* nested under =extensions=,
because Pi reserves the top-level =extensions= key for resource
discovery (=RESOURCE_TYPES = ["extensions", "skills", "prompts",
"themes"]= in =package-manager.js=) and crashes on startup if it
finds an object there instead of an array:

#+begin_src json
{
  "doomLoop": {
    "enabled": true,
    "toolThreshold": 5,
    "sentenceThreshold": 10,
    "minSentenceLength": 10,
    "ringSize": 20
  }
}
#+end_src

Missing keys fall back to the same defaults — extension survives
on a fresh =settings.json= without =doomLoop= at all.

#+begin_src typescript
import type {
	AgentMessage,
	AssistantMessage,
	ExtensionAPI,
	ExtensionContext,
	TextContent,
	ToolCallEvent,
	MessageEndEvent,
} from "@earendil-works/pi-coding-agent";
import * as crypto from "node:crypto";
import * as fs from "node:fs";
import * as os from "node:os";
import * as path from "node:path";

interface DoomLoopConfig {
	enabled: boolean;
	toolThreshold: number;
	sentenceThreshold: number;
	minSentenceLength: number;
	ringSize: number;
}

const DEFAULT_CONFIG: DoomLoopConfig = {
	enabled: true,
	toolThreshold: 5,
	sentenceThreshold: 10,
	minSentenceLength: 10,
	ringSize: 20,
};

function readConfig(): DoomLoopConfig {
	const settingsPath = path.join(os.homedir(), ".pi", "agent", "settings.json");
	try {
		const raw = fs.readFileSync(settingsPath, "utf8");
		const parsed = JSON.parse(raw) as { doomLoop?: Partial<DoomLoopConfig> };
		const fromFile = parsed.doomLoop ?? {};
		return { ...DEFAULT_CONFIG, ...fromFile };
	} catch {
		return DEFAULT_CONFIG;
	}
}

** Detector primitives
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-primitives
:END:

Three pure helpers do the actual detection — kept separate from
the hook wiring so they unit-test without an =ExtensionAPI=
instance.

=hashArgs= normalises the tool-input object via JSON
serialisation with sorted top-level keys, then takes the first 16
hex chars of a SHA-256 digest. Sorted keys mean
=ls({path:"/a", recursive:false})= and =ls({recursive:false,
path:"/a"})= hash identical — Pi may emit either ordering
depending on the model.

=suffixRepeatCount= walks back from the ring's tail counting how
many consecutive entries equal the last one. The "suffix" framing
is load-bearing: a sentence said 3 times → break for 5 turns →
said 3 more times is *not* a doom loop; only contiguous repeats
matter.

=pushBounded= caps the ring size so the detector stays O(1) per
event — without the bound, a long session accumulates every tool
call ever made.

#+begin_src typescript
interface ToolSig {
	name: string;
	argsHash: string;
}
interface SentenceSig {
	sentence: string;
}

function hashArgs(input: unknown): string {
	const obj = (input ?? {}) as Record<string, unknown>;
	const sortedKeys = Object.keys(obj).sort();
	const normalised = JSON.stringify(obj, sortedKeys);
	return crypto.createHash("sha256").update(normalised).digest("hex").slice(0, 16);
}

function suffixRepeatCount<T>(ring: readonly T[], eq: (a: T, b: T) => boolean): number {
	if (ring.length === 0) return 0;
	const last = ring[ring.length - 1];
	let n = 1;
	for (let i = ring.length - 2; i >= 0; i--) {
		if (!eq(ring[i], last)) break;
		n++;
	}
	return n;
}

function pushBounded<T>(ring: T[], item: T, cap: number): void {
	ring.push(item);
	while (ring.length > cap) ring.shift();
}
#+end_src

** Assistant-message prose extraction
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-extract
:END:

=AssistantMessage.content= is a heterogeneous array of
=TextContent | ThinkingContent | ToolCall= (per
=reference/pi/packages/ai/src/types.ts:279=). For doom-loop
purposes only the prose matters — thinking blocks and tool calls
are not user-visible repetition.

=splitSentences= is intentionally simple: split on =.?!= followed
by whitespace. Catches "I will do X. I will do X. I will do X."
but not list bullets or code blocks (which is fine — repeated
code blocks would re-hash to identical sentences anyway under
strict-equality compare).

#+begin_src typescript
function extractProse(msg: AgentMessage): string {
	if (msg.role !== "assistant") return "";
	const assistant = msg as AssistantMessage;
	const parts: string[] = [];
	for (const block of assistant.content) {
		if (block.type === "text") parts.push((block as TextContent).text);
	}
	return parts.join("\n");
}

function splitSentences(text: string): string[] {
	return text
		.split(/(?<=[.!?])\s+/)
		.map((s) => s.trim())
		.filter((s) => s.length > 0);
}
#+end_src

** Tool-call hook
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-tool-hook
:END:

Pi calls every registered =tool_call= handler *before* dispatching
the tool. Returning =block: true= short-circuits execution and
sends an error message back to the model as if the tool had
failed — exactly the signal we want to break the loop.

The hash is logged at debug-only volume to avoid filling stderr
under normal operation; only the threshold-trip line surfaces by
default.

#+begin_src typescript
function attachToolHook(pi: ExtensionAPI, cfg: DoomLoopConfig, toolRing: ToolSig[]): void {
	pi.on("tool_call", (event: ToolCallEvent, ctx: ExtensionContext) => {
		pushBounded(
			toolRing,
			{ name: event.toolName, argsHash: hashArgs(event.input) },
			cfg.ringSize,
		);
		const n = suffixRepeatCount(
			toolRing,
			(a, b) => a.name === b.name && a.argsHash === b.argsHash,
		);
		if (n >= cfg.toolThreshold) {
			const reason = `${n}× ${event.toolName} same-args`;
			process.stderr.write(`[doom-loop] tool repeat: ${reason} — aborting turn\n`);
			try {
				ctx.abort();
			} catch {
				// abort throws if already aborted; ignore.
			}
			return { block: true, reason: `doom-loop: ${reason}` };
		}
		return undefined;
	});
}
#+end_src

** Sentence-repeat hook
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-sentence-hook
:END:

=message_end= fires once per assistant message — after the full
content has streamed. Earlier candidates (=message_update=) fire
on every token chunk; that's expensive and unnecessary because
the sentence isn't fully formed until terminating punctuation
lands.

#+begin_src typescript
function attachSentenceHook(pi: ExtensionAPI, cfg: DoomLoopConfig, sentRing: SentenceSig[]): void {
	pi.on("message_end", (event: MessageEndEvent, ctx: ExtensionContext) => {
		if (event.message.role !== "assistant") return;
		const text = extractProse(event.message);
		for (const sentence of splitSentences(text)) {
			if (sentence.length < cfg.minSentenceLength) continue;
			pushBounded(sentRing, { sentence }, cfg.ringSize);
			const n = suffixRepeatCount(sentRing, (a, b) => a.sentence === b.sentence);
			if (n >= cfg.sentenceThreshold) {
				const preview = sentence.length > 60 ? `${sentence.slice(0, 60)}...` : sentence;
				process.stderr.write(
					`[doom-loop] sentence repeat ${n}×: "${preview}" — aborting turn\n`,
				);
				try {
					ctx.abort();
				} catch {
					// already aborted
				}
				break;
			}
		}
	});
}

** Extension entry point
:PROPERTIES:
:CUSTOM_ID: pi-ext-doom-loop-entry
:END:

Pi loads the default export and calls it with the
=ExtensionAPI=. If =enabled: false=, the extension registers
nothing — cheaper than having Pi load a no-op extension every
session.

#+begin_src typescript
export default function doomLoopExtension(pi: ExtensionAPI): void {
	const cfg = readConfig();
	if (!cfg.enabled) {
		process.stderr.write("[doom-loop] disabled by settings.json — skipping\n");
		return;
	}
	const toolRing: ToolSig[] = [];
	const sentRing: SentenceSig[] = [];
	attachToolHook(pi, cfg, toolRing);
	attachSentenceHook(pi, cfg, sentRing);
}
