* Overview
:PROPERTIES:
:CUSTOM_ID: acp-opencode-overview
:END:

This module exists so OpenCode can be driven through structured
ACP/JSON-RPC over stdio, sidestepping the alternative cmux-profile
path that mutates =opencode.jsonc=, =AGENTS.md=, and
=.opencode/plugins/= during a session.  A crash before the cmux
profile's =atexit= cleanup leaves the project in a half-modified
state; the direct-ACP path avoids that whole class of problem
because OpenCode reads its own config and we never touch it.

Invariant: every direct-ACP call spawns =opencode acp= on stdio,
relies on OpenCode's pre-existing =opencode auth login= credentials
(so no ACP =authenticate= RPC is needed), and never writes into the
target project's configuration files.  The factory =code-agent-acp-opencode-create=
is the only constructor; callers MUST NOT instantiate the generic
ACP backend directly with OpenCode-specific spawn-args.

* OpenCode ACP Profile

Per-agent configuration for OpenCode.  Provides a thin constructor
that presets =spawn-args=, auth handling, and environment for the
generic =code-agent-acp= backend.

OpenCode speaks ACP natively via =opencode acp= on stdio.  It uses
its own credentials from =opencode auth login=, so no ACP-level
=authenticate= RPC is needed.

** Two Integration Paths to the Same Agent

OpenCode is reachable through two coexisting integrations that share
zero code:

| Path | Mechanism | Best for |
|------+-----------+----------|
| *cmux profile* (=code-agent-org-cmux.org= → Agent Profiles) | OpenCode TUI inside a cmux pane, driven by =cmux send= / =cmux capture-pane= | watching the agent think in a terminal, mixed Emacs+terminal workflows |
| *Direct ACP* (*this module*) | =opencode acp= subprocess speaking ACP/JSON-RPC over stdio | structured token streaming, multi-turn programmatic use |

The cmux profile mutates =opencode.jsonc= / =AGENTS.md= / =.opencode/plugins/=
during a session and restores them via =atexit=; a crash before =atexit=
runs leaves the project in a partially-modified state.  Direct ACP avoids
the whole class of problem because OpenCode reads its own config and we
never touch it — that's the structural argument for picking this path
for anything beyond light interactive use.

** Open Questions Carried Forward

- *Session persistence across Emacs restart.* ACP exposes =session/load=
  with a sessionId, and OpenCode keeps server-side sessions. Could persist
  the sessionId into =OPENCODE_SESSION_ID= and call =session/load= on
  resume instead of =session/new=. Not wired today because every session
  reach we have is intra-Emacs-process so far.
- *Filesystem RPCs from agent to client.* ACP defines =fs/read_text_file=
  and =fs/write_text_file= so the agent can ask the client (us) to do the
  I/O — useful for honouring unsaved buffer edits or rejecting writes
  outside the project root. Not implemented; the default (OpenCode reads
  from disk) is fine for now.

** Customization

User-facing knobs.  Each =defcustom= is documented inline; the group name keeps Customize navigable for end users.

#+BEGIN_SRC elisp
(defgroup code-agent-acp-opencode nil
  "OpenCode ACP profile."
  :group 'code-agent-acp
  :prefix "code-agent-acp-opencode-")

(defcustom code-agent-acp-opencode-command '("opencode" "acp")
  "Command and args to launch OpenCode as an ACP server."
  :type '(repeat string)
  :group 'code-agent-acp-opencode)

(defcustom code-agent-acp-opencode-environment nil
  "Extra environment variables for the OpenCode subprocess.
List of \"NAME=VALUE\" strings.  Typical entries:
  \"OPENCODE_API_KEY=...\" if you use API-key auth instead of CLI login."
  :type '(repeat string)
  :group 'code-agent-acp-opencode)
#+END_SRC

** Class

A dedicated subclass exists so future OpenCode-only =cl-defmethod=
specialisations can dispatch on the receiver's class rather than on
an =agent-name= string.  Currently OpenCode shares all methods with
the abstract base.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-opencode-backend
               (:include code-agent-acp-backend (type :opencode))
               (:constructor code-agent-opencode-backend--create)
               (:copier nil))
  "ACP backend specialised for OpenCode.")
#+END_SRC

** Constructor

Single factory function — callers MUST go through this, not =make-instance= equivalents.

#+BEGIN_SRC elisp
(defun code-agent-acp-opencode-create (&rest args)
  "Create an ACP backend configured for OpenCode.
ARGS are passed to `code-agent-opencode-backend--create' after the
opencode-specific defaults.  Typical usage:

  (code-agent-acp-opencode-create :cwd \"/path\" :session-key \"sdd-...\")"
  (apply #'code-agent-opencode-backend--create
         :agent-name "opencode"
         :spawn-args code-agent-acp-opencode-command
         :environment code-agent-acp-opencode-environment
         :needs-authenticate nil
         :auth-request-maker nil
         args))
#+END_SRC

** Provide Feature

Single =provide= so the module can be =require=d.

#+BEGIN_SRC elisp
(provide 'code-agent-acp-opencode)

#+END_SRC
