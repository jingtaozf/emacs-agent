#+TITLE: lp/backend — Concrete Backends (Multiplexer + Pi extension)

Every module here is a concrete *backend* — an implementation that
satisfies a protocol declared in =lp/sdk/code-agent-backend.org=.  The
frontend (=lp/org/=, =lp/chat/=) NEVER branches on backend type;
dispatch flows through =cl-defmethod= on the backend instance.

One Elisp sub-family lives here: multiplexer drivers (cmux / tmux).
Pi is *not* a separate Elisp backend — it runs as a cmux agent
profile (=:AGENT_TYPE: pi= in =../org/code-agent-org-cmux.org=), the
same way Claude Code, Copilot, and OpenCode do.  Its TypeScript-side
extension still lives here since Pi loads it regardless of launch
mode.  (Both the ACP agent family — =code-agent-jsonrpc.org=,
=code-agent-acp*.org= — and the RPC-mode Pi backend —
=code-agent-pi-backend.org=, =code-agent-pi-ui.org= — were removed:
the pivot direction drops embedded-chat agent backends in favour of
org as a control plane for agents living in cmux/tmux terminals.)

* Modules

** Multiplexer family (terminal driver + workspace-bridge)

| File | Role |
|------+------|
| [[file:code-agent-multiplexer.org][code-agent-multiplexer.org]] | Abstract base + Protocol 2b generics (send-text / capture-screen / wait-for-ready).  cmux and tmux subclass this. |
| [[file:code-agent-cmux-backend.org][code-agent-cmux-backend.org]] | cmux concrete backend (macOS-native, Swift+Ghostty, =cmux= CLI). |
| [[file:code-agent-tmux-backend.org][code-agent-tmux-backend.org]] | tmux concrete backend (cross-platform, =tmux send-keys / capture-pane / pipe-pane=). |

** Pi extension (TypeScript, no Elisp backend of its own)

| File | Role |
|------+------|
| [[file:code-agent-pi-extensions.org][code-agent-pi-extensions.org]] | TypeScript Pi-side extensions tangled to =~/.pi/agent/extensions/{emacs-mcp,doom-loop}.ts= — emacs-mcp closes the MCP loop so Pi can call Emacs tools; doom-loop catches token-/tool-repetition loops natively.  Loaded by Pi itself, regardless of launch mode; today's only consumer is the cmux =:AGENT_TYPE: pi= profile. |

* Read order

1. [[file:code-agent-multiplexer.org][code-agent-multiplexer.org]] first — the abstract base of the
   multiplexer branch; concrete subclasses inherit ~80% of their
   shape from it.
2. The concrete subclass next — cmux or tmux.
3. [[file:code-agent-pi-extensions.org][code-agent-pi-extensions.org]] stands alone — it's TypeScript tangled
   for Pi's own runtime, not loaded into Emacs at all.

* Boundaries

- /backend/ → /sdk/: every module here =require=s
  [[file:../sdk/code-agent-backend.org][code-agent-backend.org]] for protocol generics.  Adding a new
  backend means adding a =cl-defstruct= here and =cl-defmethod=
  implementations of the relevant generics — nothing in /sdk/ or the
  frontend changes.
- /backend/ → /org/: frontend modules in /org/ never call into a
  concrete subclass directly; they call generics from /sdk/.  This
  is the rule that makes new backends drop in.
