* Overview
:PROPERTIES:
:CUSTOM_ID: orca-backend-overview
:END:

Orca (=com.stablyai.orca=) is a worktree-centric workspace app: it owns
a registry of git repos, spawns terminals inside them, and drives an
embedded browser.  Its CLI is the third multiplexer this SDK speaks to,
after cmux and tmux, and it is the one the user actually runs Claude
Code inside today.

Invariant: every orca-specific behaviour goes through =cl-defmethod= on
=code-agent-orca-backend=; the frontend never string-matches "orca".
Unlike the cmux backend — a thin facade over the legacy
=code-agent-org-cmux--*= body — this module implements Protocol 2b
directly, the way [[file:code-agent-tmux-backend.org][code-agent-tmux-backend.org]] does.

Four measured properties of the orca CLI shaped every design decision
below; each is called out at the section that depends on it.

| Measurement | Consequence |
|-------------+-------------|
| ≈230 ms per CLI invocation (process startup, not RPC) | identity is cached in slots + org properties; never re-queried per call |
| =terminal wait --for tui-idle= is *render quiescence*, not turn-complete | used for launch readiness only; completion still arrives via the =Stop= hook |
| A single ESC only leaves vi INSERT mode | cancel sends a mode-exit ESC *before* the agent profile's cancel keys |
| =--worktree path:= resolves registered worktree roots only | launch resolves the git top level and refuses politely rather than guessing |

*** Class

Orca identity is a pair: the *worktree* (=<repoId>::<absPath>=, stable
across app restarts) and the *terminal handle* (=term_<uuid>=, stable
only while the runtime lives).  Both are cached in slots so the hot
path never pays the 230 ms lookup, and both are mirrored into org
properties by the launch path so they survive an Emacs restart.

=multiplexer-session-id= inherited from the base holds the worktree id;
=pane-id= holds the terminal handle.  The extra slots below record
what the launch resolved so error messages can name it.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-orca-backend
               (:include code-agent-multiplexer-backend (type :orca))
               (:constructor code-agent-orca-backend--create)
               (:copier nil))
  "Concrete Orca-driven terminal backend.
Slots in addition to those inherited from
`code-agent-multiplexer-backend':
- `orca-cmd': executable path (defaults to the defcustom).
- `worktree-path': absolute path the worktree id resolved from, kept
  for diagnostics when a selector stops resolving."
  (orca-cmd      nil)
  (worktree-path nil))
#+END_SRC

*** Internal Helper — Run orca

Every orca command answers the same JSON envelope —
={"ok": true, "result": {...}}= or ={"ok": false, "error": {"code": …}}=
— so one helper parses it and hands callers either the =result= alist
or a =(:error . CODE)= cons.  Returning the error *code* rather than
signalling matters: =selector_not_found= and =terminal_handle_stale=
are both routine control flow here, not exceptions.

Callers pass =--json= implicitly; the helper appends it.

#+BEGIN_SRC elisp
(defun code-agent-orca--call (backend &rest args)
  "Invoke the Orca CLI synchronously with ARGS plus `--json'.
Returns the parsed `result' alist on success, or a cons
\(:error . CODE-STRING) when the envelope reports failure or the
process could not be run.  BACKEND supplies the CLI path."
  (let ((cli (or (and backend (code-agent-orca-backend-orca-cmd backend))
                 code-agent-orca-cli-path)))
    (with-temp-buffer
      (let ((rc (apply #'call-process cli nil (current-buffer) nil
                       (append args (list "--json")))))
        (goto-char (point-min))
        (condition-case nil
            (let* ((data (json-parse-buffer :object-type 'alist
                                            :array-type 'list
                                            :null-object nil
                                            :false-object nil)))
              (if (alist-get 'ok data)
                  (alist-get 'result data)
                (cons :error (or (alist-get 'code (alist-get 'error data))
                                 (format "exit-%s" rc)))))
          (error (cons :error (format "unparseable-output-exit-%s" rc))))))))

(defun code-agent-orca--error-code (reply)
  "Return the error code string when REPLY is an error cons, else nil."
  (and (consp reply) (eq (car reply) :error) (cdr reply)))
#+END_SRC

*** Internal Helper — Run orca asynchronously

Orca costs ≈230 ms per invocation because each call re-spawns a shell
wrapper; cmux's socket answers in ≈103 ms.  Emacs is single-threaded,
so anything not on a user-initiated critical path must not block it —
the same reasoning that bans =call-process= inside timers in
=.claude/rules/minimize-emacs-mcp-calls.md=.

This helper is the async escape hatch: fire and forget, with an
optional sentinel callback receiving the parsed result.

The sentinel is a *named function*, not a lambda over the enclosing
=let*=.  literate-elisp loads this file under dynamic binding — the
=lexical-binding: t= cookie is not honoured — so a lambda referencing
=buf= or =callback= finds both unbound by the time the process exits,
and the error surfaces from the =unwind-protect= cleanup as
=Symbol's value as variable is void: buf=.  The process object carries
what the sentinel needs instead: the output buffer is
=process-buffer=, the callback is a process property.

#+BEGIN_SRC elisp
(defun code-agent-orca--async-sentinel (proc event)
  "Hand PROC's parsed `--json' output to its stored callback on EVENT."
  (when (string-match-p "\\`\\(finished\\|exited\\|killed\\|deleted\\)" event)
    (let ((buf (process-buffer proc))
          (callback (process-get proc 'orca-callback)))
      (unwind-protect
          (when callback
            (condition-case err
                (funcall callback
                         (with-current-buffer buf
                           (goto-char (point-min))
                           (condition-case nil
                               (let ((data (json-parse-buffer
                                            :object-type 'alist
                                            :array-type 'list
                                            :null-object nil
                                            :false-object nil)))
                                 (if (alist-get 'ok data)
                                     (alist-get 'result data)
                                   (cons :error
                                         (or (alist-get 'code (alist-get 'error data))
                                             "unknown"))))
                             (error (cons :error "unparseable-output")))))
              (error (message "code-agent-orca async callback failed: %S" err))))
        (when (buffer-live-p buf) (kill-buffer buf))))))

(defun code-agent-orca--call-async (backend args &optional callback)
  "Invoke the Orca CLI with ARGS plus `--json' without blocking Emacs.
CALLBACK, when given, is called with the same value
`code-agent-orca--call' would have returned."
  (let* ((cli (or (and backend (code-agent-orca-backend-orca-cmd backend))
                  code-agent-orca-cli-path))
         (buf (generate-new-buffer " *orca-async*"))
         (proc (apply #'start-process "orca-async" buf cli
                      (append args (list "--json")))))
    (process-put proc 'orca-callback callback)
    (set-process-sentinel proc #'code-agent-orca--async-sentinel)
    proc))
#+END_SRC

** Worktree Resolution

Orca will only host a terminal inside a worktree it has registered.
A subdirectory of a registered repo fails, and so does an unregistered
git repo — both answer =selector_not_found=.  So resolution walks from
the caller's directory to the git top level, asks Orca about *that*,
and on failure hands the caller a precise instruction instead of a
generic error.

Registration is deliberately not automatic: =orca repo add= mutates the
user's app state and the CLI has no =repo rm=, so it is not something a
backend should do behind the user's back.

*** Resolve a worktree id from a directory

#+BEGIN_SRC elisp
(defun code-agent-orca--git-top-level (dir)
  "Return the git top level containing DIR, or DIR when it is not a repo."
  (let ((default-directory (file-name-as-directory (expand-file-name dir))))
    (with-temp-buffer
      (if (zerop (call-process "git" nil (current-buffer) nil
                               "rev-parse" "--show-toplevel"))
          (string-trim (buffer-string))
        (directory-file-name (expand-file-name dir))))))

(defun code-agent-orca--resolve-worktree (backend dir)
  "Return the Orca worktree id owning DIR.
Signals a `user-error' naming the exact `orca repo add' command when
Orca does not know the enclosing repository — registration mutates the
user's Orca state and is theirs to authorise."
  (let* ((root (code-agent-orca--git-top-level dir))
         (reply (code-agent-orca--call backend
                                       "worktree" "show"
                                       "--worktree" (concat "path:" root)))
         (code (code-agent-orca--error-code reply)))
    (cond
     ((null code)
      (let ((id (alist-get 'id (alist-get 'worktree reply))))
        (setf (code-agent-orca-backend-worktree-path backend) root)
        id))
     ((equal code "selector_not_found")
      (user-error
       "Orca does not know %s. Register it first: orca repo add --path %s"
       root root))
     (t (user-error "orca worktree show failed: %s" code)))))
#+END_SRC

*** Cached worktree lookup

The resolution above costs one 230 ms call.  Callers go through this
wrapper so it happens once per backend instead of once per operation.

The cache is per backend instance and nothing writes the id to the org
heading: the worktree is a *function of the project root*, so
re-deriving it is always right, while a recorded id goes wrong the day
the repo is removed and re-added under a fresh uuid.

#+BEGIN_SRC elisp
(defun code-agent-orca--worktree-id (backend)
  "Return BACKEND's worktree id, resolving and caching it on first use."
  (or (code-agent-multiplexer-backend-multiplexer-session-id backend)
      (let ((id (code-agent-orca--resolve-worktree backend default-directory)))
        (setf (code-agent-multiplexer-backend-multiplexer-session-id backend) id)
        id)))
#+END_SRC

** Terminal Handle Cache
:PROPERTIES:
:CUSTOM_ID: orca-handle-cache
:END:

The terminal handle is the opposite case: it cannot be re-derived.
=orca terminal list= reports =handle=, =ptyId=, =tabId=, =leafId= and
=incarnationId= — all minted at runtime — plus =title=, which is the
pty title the agent repaints (=✳ <current task>=), *not* the
=--title= the launch passed.  Orca exposes no user-settable tag to
match on, so "which terminal belongs to this workspace?" has exactly
one answer: the one we remembered.

Remembering it on the org heading was wrong twice over.  The handle
does not outlive the Orca process, so a value committed to git is
stale for every other machine and for this one after a restart; and
the heading is a *document*, which should not carry a uuid that means
nothing to a reader.  The status directory already holds this class of
per-session runtime state (=<id>.request-id=, =<id>.from-emacs=) and
has the matching lifetime — it lives in =/tmp=, so an Orca restart and
a reboot both clear it.

An Emacs restart, meanwhile, still finds the file and adopts the
running terminal, which is the case the property was actually earning
its keep for.

#+BEGIN_SRC elisp
(defvar code-agent-org-terminal-status-dir)

(defun code-agent-orca--handle-file (workspace-session-id)
  "Path of the file caching the Orca handle for WORKSPACE-SESSION-ID."
  (expand-file-name (concat workspace-session-id ".orca-terminal")
                    code-agent-org-terminal-status-dir))

(defun code-agent-orca--save-handle (workspace-session-id handle)
  "Cache HANDLE as the Orca terminal serving WORKSPACE-SESSION-ID."
  (when (and workspace-session-id handle)
    (make-directory code-agent-org-terminal-status-dir t)
    (with-temp-file (code-agent-orca--handle-file workspace-session-id)
      (insert handle))))

(defun code-agent-orca--read-handle (workspace-session-id)
  "Return the cached Orca handle for WORKSPACE-SESSION-ID, or nil."
  (when workspace-session-id
    (let ((path (code-agent-orca--handle-file workspace-session-id)))
      (when (file-exists-p path)
        (let ((val (string-trim (with-temp-buffer
                                  (insert-file-contents path)
                                  (buffer-string)))))
          (unless (string-empty-p val) val))))))

(defun code-agent-orca--forget-handle (workspace-session-id)
  "Drop the cached handle for WORKSPACE-SESSION-ID."
  (when workspace-session-id
    (let ((path (code-agent-orca--handle-file workspace-session-id)))
      (when (file-exists-p path) (delete-file path)))))
#+END_SRC

*** Protocol 2b — Launch Session

=terminal create --command= injects its argument as a command line into
the pane's interactive shell, so the shell prefix the launch builder
already emits — =unset VIRTUAL_ENV; set -a; . <envfile>; set +a; …= —
runs verbatim.  The spawned pane inherits =ORCA_WORKTREE_ID= and, more
usefully, does *not* inherit =CLAUDECODE=, so a nested =claude= starts
without the "inside another Claude Code session" refusal.

LAUNCH-CMD arrives as a list for Protocol 2b compatibility with tmux;
orca wants one string, so the parts are joined.

The tab title is the workspace heading text, via the same
=code-agent-org-terminal--tab-title= the cmux backend uses — several
agents run against one worktree, so "which org section is this?" is the
only question the tab strip can usefully answer.  The session key was
the first cut and reads as =/long/path/file.org::sdd-20260726-…=, which
is unique but unreadable at tab width.  =ignore-errors= covers the
non-org caller: Protocol 2b permits launching without a buffer, and
then the session key remains the honest fallback.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-mux-launch-session
  ((backend code-agent-orca-backend) launch-cmd)
  "Create an Orca terminal running LAUNCH-CMD and record its handle.
Returns the terminal handle string, or nil on failure."
  (let* ((worktree (code-agent-orca--worktree-id backend))
         (cmd (if (listp launch-cmd)
                  (mapconcat #'identity launch-cmd " ")
                launch-cmd))
         (title (or (ignore-errors (code-agent-org-terminal--tab-title))
                    (code-agent-multiplexer-backend-session-key backend)
                    "code-agent"))
         (reply (code-agent-orca--call backend
                                       "terminal" "create"
                                       "--worktree" (concat "id:" worktree)
                                       "--title" title
                                       "--command" cmd))
         (code (code-agent-orca--error-code reply)))
    (if code
        (progn (message "code-agent-orca: terminal create failed: %s" code) nil)
      (let ((handle (alist-get 'handle (alist-get 'terminal reply))))
        (setf (code-agent-multiplexer-backend-pane-id backend) handle)
        handle))))
#+END_SRC

*** Protocol 2b — Ensure Session

Returns the recorded handle only when Orca still has a *live* terminal
behind it.  Two distinct deaths have to be caught, and only one of them
is an error:

- An Orca restart invalidates the handle outright and =terminal show=
  answers =terminal_handle_stale=.
- Closing the tab does *not* invalidate the handle.  =terminal show=
  keeps answering =ok: true= — with =connected: false= and
  =writable: false=, and with the terminal gone from =terminal list=.
  Checking only the error code would report that corpse as a live
  session, so launch would "focus" a tab that no longer exists and
  every later send would vanish into it.

Either way the slot is cleared so the next launch creates a fresh
terminal, mirroring how the tmux backend treats a dead session.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-mux-ensure-session
  ((backend code-agent-orca-backend))
  "Return BACKEND's live terminal handle, or nil when there is none."
  (let ((handle (code-agent-multiplexer-backend-pane-id backend)))
    (when handle
      (let* ((reply (code-agent-orca--call backend
                                           "terminal" "show"
                                           "--terminal" handle))
             (terminal (unless (code-agent-orca--error-code reply)
                         (alist-get 'terminal reply))))
        (if (and terminal (alist-get 'connected terminal))
            handle
          (setf (code-agent-multiplexer-backend-pane-id backend) nil)
          nil)))))
#+END_SRC

*** Protocol 2b — Send Key

Orca has no key-name vocabulary; =terminal send --text= writes raw
bytes to the pty, so the keyword vocabulary the agent profiles already
speak maps onto control characters here.  =--interrupt= is Orca's own
one-byte Ctrl-C and is used for =:ctrl-c= so the intent stays legible
in the CLI log.

#+BEGIN_SRC elisp
(defconst code-agent-orca--key-bytes
  '((:enter       . "\r")
    (:escape      . "\033")
    (:ctrl-b      . "\002")
    (:ctrl-e      . "\005")
    (:ctrl-o      . "\017")
    (:shift-enter . "\033\r")
    (:tab         . "\t"))
  "Keyword → raw byte sequence written to the pty by `send-key'.
Orca exposes no key names, so every key is literal bytes.")

(cl-defmethod code-agent-mux-send-key
  ((backend code-agent-orca-backend) key)
  "Send named KEY to BACKEND's terminal as raw bytes."
  (when-let* ((handle (code-agent-multiplexer-backend-pane-id backend)))
    (if (eq key :ctrl-c)
        (code-agent-orca--call backend "terminal" "send"
                               "--terminal" handle "--interrupt")
      (let ((bytes (alist-get key code-agent-orca--key-bytes)))
        (if bytes
            (code-agent-orca--call backend "terminal" "send"
                                   "--terminal" handle "--text" bytes)
          (message "code-agent-mux-send-key: unknown key %S" key)
          nil)))))
#+END_SRC

*** Protocol 2b — Send Text

Two behaviours the wire forces, both measured rather than assumed:

- Orca writes =--text= straight to the pty, so a multi-line prompt
  would submit at the first newline.  Wrapping the payload in
  *bracketed paste* (=ESC [ 200 ~= … =ESC [ 201 ~=) makes the agent TUI
  treat it as one paste event; a two-line prompt verified as landing
  whole in Claude's input box with nothing submitted early.  The same
  wrapper carries a 200 000-byte payload, so there is no separate
  large-text path of the kind cmux needs.
- A vi-mode TUI in NORMAL mode would interpret the paste as commands,
  so INSERT mode is ensured first, exactly as the cmux path does.

Text is *not* submitted here — the caller decides, via =send-key
:enter=, so "typed" and "typed and submitted" stay distinguishable.

#+BEGIN_SRC elisp
(defun code-agent-orca--send-raw (backend text)
  "Write TEXT to BACKEND's terminal with no paste wrapper and no submit."
  (when-let* ((handle (code-agent-multiplexer-backend-pane-id backend)))
    (code-agent-orca--call backend "terminal" "send"
                           "--terminal" handle "--text" text)))

(defun code-agent-orca--ensure-insert-mode (backend)
  "Put a vi-mode agent TUI into INSERT mode before pasting into it."
  (let ((screen (code-agent-mux-capture-screen backend)))
    (unless (string-match-p "-- INSERT --\\|-- insert --" screen)
      (code-agent-orca--send-raw backend "i")
      (sleep-for 0.3))))

(cl-defmethod code-agent-mux-send-text
  ((backend code-agent-orca-backend) text)
  "Paste TEXT into BACKEND's terminal without submitting it."
  (let* ((clean (substring-no-properties (or text "")))
         (profile (ignore-errors (code-agent-org-cmux--get-agent-profile)))
         (vi-p (or (null profile)
                   (code-agent-org-cmux--agent-profile-vi-mode profile))))
    (when vi-p
      (code-agent-orca--ensure-insert-mode backend))
    (code-agent-orca--send-raw
     backend (concat "\033[200~" clean "\033[201~"))))
#+END_SRC

*** Protocol 2b — Capture Screen

=terminal read= answers plain text with no ANSI escapes, so unlike the
cmux and tmux paths there is nothing to strip.  Under a full-screen TUI
the cursor stream never advances — alt-screen redraws are not
scrollback — so a cursor-incremental read would return nothing useful
and the tail *is* the current screen.

#+BEGIN_SRC elisp
(defcustom code-agent-orca-capture-lines 120
  "Number of trailing terminal lines `capture-screen' requests."
  :type 'integer
  :group 'code-agent-orca)

(cl-defmethod code-agent-mux-capture-screen
  ((backend code-agent-orca-backend))
  "Return BACKEND's current terminal text as a string."
  (or (when-let* ((handle (code-agent-multiplexer-backend-pane-id backend)))
        (let* ((reply (code-agent-orca--call
                       backend "terminal" "read"
                       "--terminal" handle
                       "--limit" (number-to-string code-agent-orca-capture-lines)))
               (code (code-agent-orca--error-code reply)))
          (unless code
            (mapconcat #'identity
                       (alist-get 'tail (alist-get 'terminal reply))
                       "\n"))))
      ""))
#+END_SRC

*** Protocol 2b — Session Status

Screen-pattern classification against the active agent profile, the
same signals the cmux backend reads.  Busy is checked first: Claude
renders its input box *and* its spinner simultaneously, so a
ready-pattern match says nothing about whether a turn is in flight.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-mux-session-status
  ((backend code-agent-orca-backend))
  "Return :ready / :busy / :missing for BACKEND's terminal."
  (if (null (code-agent-multiplexer-backend-pane-id backend))
      :missing
    (let* ((screen (code-agent-mux-capture-screen backend))
           (profile (ignore-errors (code-agent-org-cmux--get-agent-profile)))
           (ready (if profile
                      (code-agent-org-cmux--agent-profile-ready-patterns profile)
                    '("-- INSERT --" "type a message")))
           (busy  (if profile
                      (code-agent-org-cmux--agent-profile-busy-patterns profile)
                    '("esc to interrupt" "Thinking" "Tool:"))))
      (cond
       ((string-empty-p screen) :missing)
       ((cl-some (lambda (re) (string-match-p re screen)) busy) :busy)
       ((cl-some (lambda (re) (string-match-p re screen)) ready) :ready)
       (t :busy)))))

** Launch Readiness

=terminal wait --for tui-idle= reports that the terminal stopped
emitting output, which is exactly right for "the TUI finished booting"
and exactly wrong for "the agent finished answering" — measured at
0.5 s into a query that ran for another twenty seconds.  It is
therefore used here and nowhere else; turn completion continues to
arrive through the =Stop= hook.

The wait runs asynchronously: at up to
=code-agent-orca-ready-timeout= seconds a synchronous call would
freeze Emacs for the whole boot.

CALLBACK reaches the reply translator through =apply-partially=, for
the dynamic-binding reason spelled out under the async helper — a
lambda closing over CALLBACK loses it before the process exits.

#+BEGIN_SRC elisp
(defun code-agent-orca--ready-reply (callback reply)
  "Reduce REPLY from `terminal wait' to a boolean and pass it to CALLBACK."
  (funcall callback
           (and (not (code-agent-orca--error-code reply))
                (eq t (alist-get 'satisfied (alist-get 'wait reply))))))

(defun code-agent-orca-wait-for-ready (backend callback)
  "Wait until BACKEND's agent TUI has finished booting, then call CALLBACK.
CALLBACK receives t when the terminal reached tui-idle, nil otherwise.
Never blocks Emacs."
  (if-let* ((handle (code-agent-multiplexer-backend-pane-id backend)))
      (code-agent-orca--call-async
       backend
       (list "terminal" "wait" "--terminal" handle
             "--for" "tui-idle"
             "--timeout-ms" (number-to-string
                             (* 1000 code-agent-orca-ready-timeout)))
       (apply-partially #'code-agent-orca--ready-reply callback))
    (funcall callback nil)))
#+END_SRC

** Cancellation

A single ESC does not cancel a running Claude turn — it leaves vi
INSERT mode, and the turn keeps going.  The second ESC is what
interrupts.  Rather than hard-code "twice", the mode-exit ESC is sent
because the profile says the TUI is vi-mode, and the cancel keys that
follow are whatever the profile declares.  A non-vi agent therefore
gets exactly its own cancel keys and no spurious escape.

#+BEGIN_SRC elisp
(defun code-agent-orca-cancel (backend)
  "Interrupt whatever BACKEND's agent TUI is currently doing."
  (let* ((profile (ignore-errors (code-agent-org-cmux--get-agent-profile)))
         (vi-p (or (null profile)
                   (code-agent-org-cmux--agent-profile-vi-mode profile)))
         (keys (if profile
                   (code-agent-org-cmux--agent-profile-cancel-keys profile)
                 '("escape"))))
    ;; Leave INSERT mode first — otherwise the TUI eats the cancel key.
    (when vi-p
      (code-agent-mux-send-key backend :escape)
      (sleep-for 0.2))
    (dolist (k keys)
      (code-agent-mux-send-key
       backend
       (cond ((member k '("escape" "Escape")) :escape)
             ((member k '("C-c" "ctrl-c"))    :ctrl-c)
             (t :escape))))))
#+END_SRC

*** Launch

Point is on (or inside) the workspace heading; =CLAUDE_SESSION_ID=
identifies the session and the launch command comes from the shared
builder, so what is left is Orca-specific: resolve the worktree, create

Idempotence is the contract: a session whose handle Orca still knows
is focused, not relaunched.  Readiness is awaited asynchronously —
a synchronous wait would freeze Emacs for the whole TUI boot — and the
handle travels into the readiness report through =apply-partially=,
since a lambda closing over it would not survive to the callback.

#+BEGIN_SRC elisp

                  "code-agent-org-terminal-base" ())

(defun code-agent-orca--persist-identity (backend workspace-session-id)
  "Cache BACKEND's terminal handle and register the session.
Nothing is written to the heading: the worktree re-resolves from the
project root and the handle lives in the status dir, which has the
matching lifetime — see [[#orca-handle-cache][Terminal Handle Cache]]."
  (let ((session-key (code-agent-org-current-session-key)))
    (code-agent-orca--save-handle
     workspace-session-id (code-agent-multiplexer-backend-pane-id backend))
    (when session-key
      (code-agent-org-session-put session-key :workspace-session-id workspace-session-id)
      (code-agent-org-session-put session-key :backend backend)
      (puthash workspace-session-id session-key
               code-agent-org-terminal--workspace-to-session-key))))

(cl-defmethod code-agent-org-backend-launch
  ((backend code-agent-orca-backend))
  "Launch — or focus — the Orca terminal for the org session at point."
  (let ((workspace-session-id
         (save-excursion (code-agent-org-terminal-goto-session-heading))))
    (unless workspace-session-id
      (user-error "No CLAUDE_SESSION_ID here — create a workspace section first"))
    ;; Adopt anything a previous Emacs left on the heading before deciding.
    (save-excursion
      (code-agent-org-terminal-goto-session-heading)
      (code-agent-org-backend-adopt-identity backend))
    (if (code-agent-mux-ensure-session backend)
        (progn
          (code-agent-mux-focus backend)
          (message "Orca terminal focused (%s)"
                   (code-agent-multiplexer-backend-pane-id backend)))
      (let* ((project-root (or (ignore-errors (code-agent-org-get-project-root))
                               default-directory))
             (default-directory project-root)
             (launch-cmd (code-agent-org-cmux--build-launch-command
                          (buffer-file-name) workspace-session-id project-root))
             (handle (code-agent-mux-launch-session backend launch-cmd)))
        (unless handle
          (user-error "Orca refused to create a terminal for %s" workspace-session-id))
        (code-agent-orca--persist-identity backend workspace-session-id)
        (message "Orca terminal %s launched; waiting for the agent TUI…" handle)
        (code-agent-orca-wait-for-ready
         backend
         (apply-partially #'code-agent-orca--report-ready handle))
        handle))))

** Worktree Management
:PROPERTIES:
:CUSTOM_ID: orca-worktree-management
:END:

Orca's unit of work is the worktree, and it already stores what a
management surface wants to show: board status, live terminal count,
agent state, lineage, linked issues.  =orca worktree ps= returns all of
it for every visible worktree in *one* call, so the org buffer can be a
view over Orca's state instead of a second copy of it — nothing here
writes an Orca fact back into a property.

The one binding that *is* persisted stays =:PROJECT_ROOT:=.  Everything
else is re-derived: which worktree a heading means, what branch it is
on, whether an agent is running.

Two limits found by measurement, both worth knowing before trusting
this surface:

- =ps= only reports worktrees Orca *lists*.  A worktree created with
  plain =git worktree add= resolves by path (after ~8 s of rescan) and
  can host terminals, but it stays out of =list= and =ps= unless its
  repo has =externalWorktreeVisibility: show= — a per-repo switch with
  no CLI setter.  =new-worktree= therefore warns before taking that
  route.
- =agents[].lastAssistantMessage= holds the *last completed* message
  and is cleared while the agent works, so it is a recovery source for
  a response Emacs missed, never the primary one.  The =Stop= hook
  still owns delivery.

#+BEGIN_SRC elisp
(declare-function code-agent-org-insert-workspace-heading
                  "code-agent-org" (name project-root &optional level))

(defun code-agent-orca--canon (path)
  "Return PATH in the canonical form used to compare worktree paths."
  (directory-file-name (file-truename (expand-file-name path))))

(defun code-agent-orca--ps ()
  "Return the rows of `orca worktree ps', or nil when the call fails."
  (let ((reply (code-agent-orca--call nil "worktree" "ps" "--limit" "200")))
    (unless (code-agent-orca--error-code reply)
      (alist-get 'worktrees reply))))

(defun code-agent-orca--ps-find (path &optional rows)
  "Return the `ps' row whose worktree is PATH, or nil."
  (let ((want (code-agent-orca--canon path)))
    (seq-find (lambda (row)
                (equal want (code-agent-orca--canon (alist-get 'path row))))
              (or rows (code-agent-orca--ps)))))

(defun code-agent-orca--repo-for-path (path)
  "Return the Orca repo record owning PATH — the longest matching prefix.
A submodule registered on its own must win over its superproject."
  (let* ((reply (code-agent-orca--call nil "repo" "list"))
         (repos (unless (code-agent-orca--error-code reply)
                  (alist-get 'repos reply)))
         (want (code-agent-orca--canon path))
         (best nil)
         (best-len -1))
    (dolist (repo repos best)
      (let ((rp (code-agent-orca--canon (alist-get 'path repo))))
        (when (and (string-prefix-p rp want) (> (length rp) best-len))
          (setq best repo best-len (length rp)))))))

(defun code-agent-orca--superproject (dir)
  "Return DIR's superproject working tree when DIR is a submodule, else nil."
  (let ((default-directory (file-name-as-directory (expand-file-name dir))))
    (with-temp-buffer
      (when (zerop (call-process "git" nil (current-buffer) nil
                                 "rev-parse" "--show-superproject-working-tree"))
        (let ((out (string-trim (buffer-string))))
          (unless (string-empty-p out) out))))))

(defun code-agent-orca--git (dir &rest args)
  "Run git ARGS in DIR, returning trimmed stdout, or nil on failure."
  (let ((default-directory (file-name-as-directory (expand-file-name dir))))
    (with-temp-buffer
      (when (zerop (apply #'call-process "git" nil (current-buffer) nil args))
        (string-trim (buffer-string))))))

(defun code-agent-orca--heading-roots ()
  "Map canonical =:PROJECT_ROOT:= → list of heading names across open org buffers.
This is how a worktree learns whether some heading already claims it."
  (let ((table (make-hash-table :test 'equal)))
    (dolist (buf (buffer-list))
      (with-current-buffer buf
        (when (and (derived-mode-p 'org-mode) buffer-file-name)
          (save-excursion
            (save-restriction
              (widen)
              (goto-char (point-min))
              (while (re-search-forward "^[ \t]*:CLAUDE_SESSION_ID:" nil t)
                (let ((root (org-entry-get nil "PROJECT_ROOT" t))
                      (head (substring-no-properties
                             (or (org-get-heading t t t t) "?"))))
                  (when root
                    (let ((key (code-agent-orca--canon root)))
                      (puthash key (cons head (gethash key table)) table))))))))))
    table))
#+END_SRC

*** Worktree dashboard

One =ps= call rendered as a table, with the org headings that claim

(defun code-agent-orca--row-line (row owners)

*** Creating a worktree

Two routes, and the choice is forced by where the checkout may live.
=orca worktree create= is the first-class one — Orca registers, names a
branch, records lineage, and reveals it in the UI — but it always
places the checkout under =~/orca/workspaces/<repo>/<name>=.  For a
submodule that is fatal: a checkout outside the superproject breaks
every relative path the meta-repo's literate sources tangle through.
So a submodule gets a plain =git worktree add= inside the repo's own
=.worktrees/=, at the price of Orca needing a rescan to notice it, and
of the repo's =externalWorktreeVisibility= deciding whether it ever
shows up in the UI at all.

Orca's own create leaves one idle shell in the new worktree.  It is
closed here rather than adopted, so that launching stays the single
path =code-agent-org-terminal-launch= already owns.

Either route needs the worktree's *own* repo registered.  Of
=edo-literate='s twenty submodules exactly one is, and a submodule
resolves against its superproject under longest-prefix matching, so
the check below compares the matched repo's path against the git top
level rather than trusting the match.

#+BEGIN_SRC elisp
(defun code-agent-orca--close-fallback-shells (worktree-id)
  "Close the idle shell Orca opens in a freshly created WORKTREE-ID."
  (let ((reply (code-agent-orca--call nil "terminal" "list"
                                      "--worktree" (concat "id:" worktree-id))))
    (unless (code-agent-orca--error-code reply)
      (dolist (term (alist-get 'terminals reply))
        (code-agent-orca--call nil "terminal" "close"
                               "--terminal" (alist-get 'handle term))))))

(defun code-agent-org-orca-new-worktree (name base)
  "Create a worktree named NAME off BASE and bind a new workspace heading to it.
Point must be inside a workspace whose =:PROJECT_ROOT:= names an
existing checkout; the new heading is inserted as its sibling."
  (interactive
   (let* ((root (or (code-agent-org-get-project-root) default-directory))
          (branch (or (code-agent-orca--git root "rev-parse" "--abbrev-ref" "HEAD")
                      "main")))
     (list (read-string "Worktree name: ")
           (read-string "Base branch: " branch))))
  (let* ((root (or (code-agent-org-get-project-root) default-directory))
         (top (code-agent-orca--git-top-level root))
         (repo (code-agent-orca--repo-for-path top))
         (super (code-agent-orca--superproject top))
         (visibility (and repo (alist-get 'externalWorktreeVisibility repo)))
         new-path note)
    (unless repo
      (user-error "Orca does not know %s. Register it first: orca repo add --path %s"
                  top top))
    ;; A registered *parent* is not registration.  `--repo-for-path' matches
    ;; the longest prefix, so a submodule of a known repo resolves to the
    ;; superproject and every later step would name the wrong repository —
    ;; the worktree would be created, the heading stamped, and only the
    ;; launch would fail, with `selector_not_found' against a path Orca was
    ;; never told about.  Orca registers submodules as repos in their own
    ;; right; demand that here, while the message can still name the fix.
    (unless (equal (code-agent-orca--canon (alist-get 'path repo))
                   (code-agent-orca--canon top))
      (user-error "Orca knows %s but not %s%s. Register it first: orca repo add --path %s"
                  (alist-get 'displayName repo) (abbreviate-file-name top)
                  (if super " — a submodule is a separate repo to Orca" "")
                  top))
    (if super
        ;; Submodule: the checkout has to stay inside the superproject tree.
        (let ((path (expand-file-name (concat ".worktrees/" name) top)))
          (unless (code-agent-orca--git top "worktree" "add" path "-b" name)
            (user-error "git worktree add failed for %s" path))
          (setq new-path path
                note (if (equal visibility "show")
                         "Orca will list it after its next rescan (~8s)"
                       (format "repo %s has externalWorktreeVisibility=%s — this worktree will NOT appear in Orca's UI or `worktree ps' until you turn that on"
                               (alist-get 'displayName repo) visibility))))
      ;; Standalone repo: let Orca own placement, naming and lineage.
      (let* ((current (code-agent-orca--ps-find top))
             (args (append (list "worktree" "create"
                                 "--repo" (concat "id:" (alist-get 'id repo))
                                 "--name" name
                                 "--base-branch" base)
                           (when current
                             (list "--parent-worktree"
                                   (concat "id:" (alist-get 'worktreeId current))))))
             (reply (apply #'code-agent-orca--call nil args))
             (code (code-agent-orca--error-code reply)))
        (when code (user-error "orca worktree create failed: %s" code))
        (let ((wt (alist-get 'worktree reply)))
          (setq new-path (alist-get 'path wt)
                note (format "branch %s"
                             (replace-regexp-in-string
                              "\\`refs/heads/" "" (or (alist-get 'branch wt) "?"))))
          (code-agent-orca--close-fallback-shells (alist-get 'id wt)))))
    (save-excursion
      (code-agent-org-insert-workspace-heading name new-path))
    (message "Worktree '%s' at %s (%s). Use C-c C-/ r to launch."
             name (abbreviate-file-name new-path) note)))
#+END_SRC

*** Importing worktrees Orca already has

A worktree created in Orca's own UI is invisible to the notebook until
a heading claims it.  This lists the unclaimed ones and stamps a
heading per selection, which is also the repair path when a heading is
deleted by hand.

#+BEGIN_SRC elisp
(defun code-agent-org-orca-import-worktrees ()
  "Insert a workspace heading for each Orca worktree no heading claims yet."
  (interactive)
  (let* ((rows (code-agent-orca--ps))
         (owners (code-agent-orca--heading-roots))
         (missing (seq-remove
                   (lambda (row)
                     (gethash (code-agent-orca--canon (alist-get 'path row)) owners))
                   rows)))
    (unless rows (user-error "orca worktree ps returned nothing"))
    (unless missing (user-error "Every worktree Orca lists already has a heading"))
    (let* ((labels (mapcar (lambda (row)
                             (format "%s/%s — %s"
                                     (or (alist-get 'repo row) "?")
                                     (or (alist-get 'displayName row) "?")
                                     (abbreviate-file-name (alist-get 'path row))))
                           missing))
           (chosen (completing-read-multiple "Import worktrees: " labels nil t))
           (count 0))
      (save-excursion
        (dolist (label chosen)
          (let* ((idx (seq-position labels label))
                 (row (and idx (nth idx missing))))
            (when row
              (code-agent-org-insert-workspace-heading
               (format "%s %s" (alist-get 'repo row) (alist-get 'displayName row))
               (alist-get 'path row))
              (setq count (1+ count))))))
      (message "Imported %d worktree(s) as workspace headings" count))))
#+END_SRC

*** Visiting a path the agent printed

Clicking a =path:line= in an Orca terminal cannot reach Emacs.  Orca
routes every click in its terminal to its own editor — measured
against three link forms in one pane: an OSC 8 hyperlink whose label
is a path, one whose label carries no path at all, and a bare
=org-protocol://= URL.  All three opened the Orca editor, and the CLI
exposes no editor setting to redirect them.

So the direction reverses: instead of the terminal pushing a file at
Emacs, Emacs pulls the paths out of the terminal.  =terminal read=
returns the pane's recent lines, the agent's =path:line= mentions are
picked out of them, and the newest ones are offered for completion —
which also beats clicking when a build just printed forty of them and
the interesting one has scrolled past.

#+BEGIN_SRC elisp
(defconst code-agent-orca--path-line-re
  "\\([~/.]?[[:alnum:]_./~+-]*[[:alnum:]_-]\\):\\([0-9]+\\)"
  "Match PATH:LINE the way agents, compilers and test runners print it.
Deliberately permissive — requiring an extension would drop
`Makefile:12', and it is the file-existence check in
`code-agent-orca--scan-paths' that separates a real hit from a
timestamp or a URL port.")

(defun code-agent-orca--scan-paths (lines root)
  "Return (LABEL FILE . LINE) for each PATH:LINE in LINES, newest first.
Relative paths resolve against ROOT, and anything that is not a real
file is dropped — terminal output is full of `foo.py:12'-shaped text
that names nothing on disk."
  (let ((seen (make-hash-table :test 'equal))
        (found nil))
    (dolist (line lines)
      (let ((start 0))
        (while (string-match code-agent-orca--path-line-re line start)
          (setq start (match-end 0))
          (let* ((raw (match-string 1 line))
                 (num (string-to-number (match-string 2 line)))
                 (file (expand-file-name raw (or root default-directory)))
                 (key (format "%s:%d" file num)))
            (when (and (file-regular-p file) (not (gethash key seen)))
              (puthash key t seen)
              (push (cons (format "%s:%d" (abbreviate-file-name file) num)
                          (cons file num))
                    found))))))
    found))

(defun code-agent-org-orca-visit-path ()
  "Open a PATH:LINE that this workspace's Orca terminal printed."
  (interactive)
  (let ((handle (save-excursion
                  (code-agent-org-terminal-goto-session-heading)
                  (code-agent-orca--read-handle
                   (org-entry-get nil "CLAUDE_SESSION_ID" t)))))
    (unless handle
      (user-error "No Orca terminal recorded for this workspace — launch it first"))
    (let* ((reply (code-agent-orca--call nil "terminal" "read"
                                         "--terminal" handle "--limit" "300"))
           (code (code-agent-orca--error-code reply)))
      (when code (user-error "orca terminal read failed: %s" code))
      (let* ((terminal (alist-get 'terminal reply))
             (root (or (code-agent-org-get-project-root) default-directory))
             (hits (code-agent-orca--scan-paths (alist-get 'tail terminal) root)))
        (unless hits
          (user-error "No path:line in the last 300 lines of that terminal"))
        (let* ((choice (completing-read "Visit: " (mapcar #'car hits) nil t
                                        nil nil (caar hits)))
               (target (cdr (assoc choice hits))))
          (find-file (car target))
          (goto-char (point-min))
          (forward-line (1- (cdr target))))))))
#+END_SRC

*** Dropping a worktree

=orca worktree rm --force= deletes the checkout, the branch and git's
registration in one go, so the guard matters more than the command:
uncommitted changes, or commits that survive nowhere else, make the
removal refuse rather than ask.

Checking =@{u}..HEAD= alone is not enough, and the E2E run proved it:
a worktree Orca creates starts on a fresh branch with *no upstream*,
so that command exits fatal, the check silently passes, and the first
commit made in the worktree would be deleted with it.  The fallback
asks git which branches contain HEAD — when the answer is "only this
one", the work exists nowhere else.

#+BEGIN_SRC elisp
(defun code-agent-orca--unsaved-commits (root)
  "Return a description of commits that would die with ROOT's branch, or nil."
  (let ((branch (code-agent-orca--git root "rev-parse" "--abbrev-ref" "HEAD")))
    (or (let ((ahead (code-agent-orca--git root "log" "--oneline" "@{u}..HEAD")))
          (when (and ahead (not (string-empty-p ahead)))
            (format "%d commit(s) its upstream has never seen"
                    (length (split-string ahead "\n" t)))))
        ;; No upstream configured — ask which branches carry HEAD instead.
        (let* ((contains (code-agent-orca--git
                          root "branch" "--contains" "HEAD"
                          "--format=%(refname:short)"))
               (names (and contains (split-string contains "\n" t))))
          (when (and names branch (equal names (list branch)))
            "commits that exist on no other branch")))))

(defun code-agent-org-orca-drop-worktree ()
  "Remove the worktree behind the heading at point, after safety checks."
  (interactive)
  (let* ((root (or (code-agent-org-get-project-root)
                   (user-error "No PROJECT_ROOT here")))
         (dirty (code-agent-orca--git root "status" "--porcelain"))
         (unsaved (code-agent-orca--unsaved-commits root))
         (branch (code-agent-orca--git root "rev-parse" "--abbrev-ref" "HEAD")))
    (when (and dirty (not (string-empty-p dirty)))
      (user-error "%s has uncommitted changes — commit or discard them first"
                  (abbreviate-file-name root)))
    (when unsaved
      (user-error "%s has %s on %s"
                  (abbreviate-file-name root) unsaved branch))
    (unless (yes-or-no-p (format "Delete worktree %s and branch %s? "
                                 (abbreviate-file-name root) branch))
      (user-error "Aborted"))
    (let* ((reply (code-agent-orca--call nil "worktree" "rm"
                                         "--worktree" (concat "path:" root)
                                         "--force"))
           (code (code-agent-orca--error-code reply)))
      (if code
          (user-error "orca worktree rm failed: %s" code)
        (message "Worktree %s removed. Archive its heading when you are done with it."
                 (abbreviate-file-name root))))))
