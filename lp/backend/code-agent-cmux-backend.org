* Overview
:PROPERTIES:
:CUSTOM_ID: cmux-backend-overview
:END:

The cmux multiplexer is fundamentally different from tmux: it
exposes a =claude-hook= subcommand, a sidebar status surface
(=set-status= / =set-progress= / =report_meta_block= / =markdown open=),
and a 100+-method dual-protocol (V1 text + V2 JSON-RPC) CLI guarded by
=cmuxOnly= PID-ancestry security.  This module is the
=code-agent-multiplexer-backend= subclass that adapts those
capabilities into Protocol 2b (multiplexer-wire) generics, so the
generic frontend code never branches on backend type.

Invariant: any code that needs cmux-specific behaviour goes through
=cl-defmethod= on =code-agent-cmux-backend=, never a string match on
"cmux" in the frontend.  This module is currently a thin facade — the
bulk of cmux-driving Elisp still lives in [[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]]
and Protocol 2b methods here delegate to =code-agent-org-cmux--*=;
the facade exists so a future Phase 3b cut-over can swap the legacy
direct calls for the protocol methods without touching callers.

* Claude Agent — cmux Backend
:PROPERTIES:
:LITERATE_ORG_BLOCK_KIND: atomic
:header-args:elisp: :tangle yes
:END:

Concrete multiplexer backend for cmux, the macOS-native terminal
multiplexer (Swift + Ghostty) with first-class Claude Code integration.
Subclass of =code-agent-multiplexer-backend= implementing Protocol 2b
(multiplexer wire) and Protocol 3 overrides specific to cmux.

** Why cmux Earned a Dedicated Backend

cmux is not "just another terminal" — three of its properties shaped
this backend's design:

- =claude-hook= CLI subcommand: cmux natively runs hook handlers on
  SessionStart / UserPromptSubmit / PreToolUse / Notification / Stop /
  SessionEnd. We coexist with cmux's built-in hooks (sidebar status,
  notification cache) instead of replacing them. =claude-hook= is
  registered in cmux's global settings; our =workspace-bridge= is
  registered in this plugin's =hooks.json=; both fire and they do not
  conflict.
- Rich sidebar API: =cmux set-status=, =set-progress=, =report_meta_block=,
  =markdown open= give us a per-workspace status surface that no other
  multiplexer offers. The Sidebar Feedback section in
  [[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]] uses this.
- 100+ CLI methods over a Unix-domain socket, dual-protocol (V1 text +
  V2 JSON-RPC, auto-detected). Reliable, scriptable, and the daemon
  exposes a =cmuxOnly= PID-ancestry security mode so any process not
  descended from cmux is refused. The CLI Gateway section in
  [[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]] documents the dialect.

** Two-Module Split: Facade Here, Legacy Body Elsewhere

Thin facade — the bulk of cmux-driving Elisp (launch pipeline,
send-text path, agent profiles, workspace colour, IDE server,
sidebar feedback, permission-needed alerts, session recovery) still
lives in
[[file:../org/code-agent-org-cmux.org][code-agent-org-cmux.org]] (2 000+ lines).
Protocol 2b / Protocol 3 methods below delegate to
=code-agent-org-cmux--*=.

The split is intentional and temporary: a later phase will fold the
legacy body up into this file once the multiplexer family stabilises
across cmux and tmux.  Until then, keeping the two layers separate
makes the wire surface cheaper to evolve.

** Setup

Three depth-3 sub-sections cover deps, the backend struct,
and the public factory wrapper.

*** Dependencies

Loaded eagerly at file evaluation time — symbols below assume every required feature is already provided.

#+BEGIN_SRC elisp
(require 'cl-lib)
(require 'code-agent-backend)
(require 'code-agent-multiplexer)
;; code-agent-org-cmux is the legacy module that owns the actual
;; cmux-driving code today; methods here delegate to it.
(declare-function code-agent-org-cmux-cancel
                  "code-agent-org-cmux" ())
(declare-function code-agent-org-cmux--send-text
                  "code-agent-org-cmux" (surface-id text &optional socket-path))
(declare-function code-agent-org-cmux--ensure-session
                  "code-agent-org-cmux" ())
#+END_SRC

*** Class

cmux-specific state: the Unix-domain socket path (when overridden),
the workspace UUID returned by =cmux new-workspace=, and cosmetic
niceties (workspace colour, icon) that cmux exposes but tmux does not.

#+BEGIN_SRC elisp
(cl-defstruct (code-agent-cmux-backend
               (:include code-agent-multiplexer-backend (type :cmux))
               (:constructor code-agent-cmux-backend--create)
               (:copier nil))
  "Concrete cmux-driven terminal backend.
Slots in addition to those inherited from
`code-agent-multiplexer-backend':
- `socket-path': overrides the auto-detected cmux CLI socket.
- `workspace-uuid': cmux's workspace identifier (distinct from the
  user-visible workspace heading name).
- `workspace-color': hex color for the sidebar pill (cmux only).
- `workspace-icon': SF Symbol name for the sidebar pill (cmux only)."
  (socket-path     nil)
  (workspace-uuid  nil)
  (workspace-color nil)
  (workspace-icon  nil))
#+END_SRC

*** Factory

Single factory function — callers MUST go through this, not =make-instance= equivalents.

#+BEGIN_SRC elisp
(defun code-agent-cmux-backend-create (&rest args)
  "Create a cmux backend.
ARGS are forwarded to `code-agent-cmux-backend--create'.  Typical
usage from `code-agent-org-backend-registry':

  (code-agent-cmux-backend-create
   :session-key session-key
   :status-dir \"/tmp/code-agent-status\")"
  (apply #'code-agent-cmux-backend--create args))
#+END_SRC

** Protocol Methods

Protocol 2b methods delegate to =code-agent-org-cmux--*=
(the legacy body still lives in =code-agent-org-cmux.org=);
Protocol 3 methods host cmux-specific behaviour the abstract
base can't carry.

*** Protocol 2b — delegation methods

Each Protocol 2b generic dispatches to the corresponding
=code-agent-org-cmux--*= function in the legacy module.

*** CLI Path

Resolves the multiplexer CLI executable path, honouring the per-backend defcustom override.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-mux-cli-path ((_backend code-agent-cmux-backend))
  (if (boundp 'code-agent-org-cmux-cli-path)
      (symbol-value 'code-agent-org-cmux-cli-path)
    "cmux"))
#+END_SRC

*** Ensure Session

Lazy-create the underlying mux session if one is not already running for this backend.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-mux-ensure-session
  ((_backend code-agent-cmux-backend))
  "Delegate to the legacy ensure-session routine (picks up or launches
a cmux workspace for the current session heading)."
  (code-agent-org-cmux--ensure-session))
#+END_SRC


*** Protocol 3 — cmux-specific overrides

No cmux-specific =execute-block= override today — org is the control
plane (define/launch/monitor workspaces via the transient menu);
prompt typing happens directly in the agent's terminal tab (=I=).
The legacy Emacs→cmux prompt-dispatch pipeline
(=code-agent-org-cmux--execute-ai-block= and its helpers) was
unreachable dead code (no keybinding, no menu entry, no caller of this
generic) and was removed along with =code-agent-org-block.org='s
=--find-instruction-number= / =--get-section-level= it depended on.
A future org→terminal dispatch would be rebuilt on =new-workspace= +
=cmux send=, not by resurrecting this method.

*** Open Terminal Tab

Surfaces the backing terminal pane to the user — opens a tab / focuses the surface.

#+BEGIN_SRC elisp
(cl-defmethod code-agent-org-backend-open-terminal-tab
  ((_backend code-agent-cmux-backend))
  "Raise cmux's workspace tab."
  (code-agent-org-cmux-open-tab))
#+END_SRC
