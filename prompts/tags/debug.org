You are performing *Systematic Debugging*. This is a disciplined 4-phase process
that finds root causes before attempting fixes.

** IRON LAW

#+begin_example
╔═══════════════════════════════════════════════════════════════╗
║  NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST              ║
║                                                               ║
║  Guessing wastes time and creates new bugs.                   ║
║  Quick fixes often mask deeper issues.                        ║
║  Evidence-based debugging finds real solutions.               ║
╚═══════════════════════════════════════════════════════════════╝
#+end_example

** The 4-Phase Process

*** Phase 1: ROOT CAUSE INVESTIGATION

*Goal*: Gather evidence about what's actually happening.

| Step | Action |
|------+--------|
| 1. Read errors COMPLETELY | Don't stop at first line - full stack trace |
| 2. Reproduce consistently | If can't reproduce, gather more data first |
| 3. Check recent changes | =git diff=, dependency updates, config changes |
| 4. Identify failure point | Where exactly does it fail? |

*For multi-layer systems*: Instrument each component boundary.
Verify data enters and exits each layer correctly.

#+begin_example
Multi-layer debugging:
  Request → [API Layer] → [Service Layer] → [Database]
            ↑ check       ↑ check           ↑ check

Add logging/assertions at each arrow to find where data goes wrong.
#+end_example

*Phase 1 Output*:

#+begin_example
Phase 1: Root Cause Investigation

Error: [exact error message]
Reproduction: [steps to reproduce]
Failure point: [where in code/system it fails]
Recent changes: [relevant git diff or "none"]
Observations: [what the evidence shows]
#+end_example

*** Phase 2: HYPOTHESIZE

*Goal*: Form testable theories based on evidence.

| Do | Don't |
|----+-------|
| Base hypothesis on Phase 1 evidence | Guess without evidence |
| Consider multiple possibilities | Fixate on first idea |
| Rank by likelihood | Jump to implementing a fix |
| Make hypothesis testable | Make vague theories |

*Phase 2 Output*:

#+begin_example
Phase 2: Hypotheses (ranked by likelihood)

1. [Most likely] Because: [evidence supporting this]
2. [Less likely] Because: [evidence supporting this]
3. [Possible] Because: [evidence supporting this]

Testing plan: [how to verify top hypothesis]
#+end_example

*** Phase 3: CONFIRM ROOT CAUSE

*Goal*: Verify the actual root cause with evidence.

| Step | Action |
|------+--------|
| 1. Test top hypothesis | Add instrumentation, logging, or test case |
| 2. Gather evidence | Does evidence support or refute hypothesis? |
| 3. If refuted | Move to next hypothesis, return to Phase 1 if needed |
| 4. If confirmed | Document the root cause with evidence |

*Phase 3 Output*:

#+begin_example
Phase 3: Root Cause Confirmed

Root cause: [exact cause]
Evidence: [what proves this is the cause]
Location: [file:line or component]

If hypothesis was wrong:
- Hypothesis X refuted because: [evidence]
- Returning to Phase 1/2 with new information
#+end_example

*** Phase 4: FIX

*Goal*: Apply minimal fix addressing root cause, verify it works.

*Only enter Phase 4 after Phase 3 confirms root cause.*

| Principle | Description |
|-----------+-------------|
| Minimal | Fix the root cause, nothing more |
| Targeted | Change only what's necessary |
| Verified | Confirm fix eliminates the symptom |
| Safe | Check for side effects |

*Phase 4 Output*:

#+begin_example
Phase 4: Fix Applied

Fix: [what was changed]
Files: [files modified]
Verification: [command run and result]
Side effects: [checked for X, Y - none found / found Z]
#+end_example

** Anti-Patterns to Avoid

| Anti-Pattern | Why It's Wrong | Instead |
|--------------+----------------+---------|
| "Try this and see" | Wastes time, may mask real issue | Investigate first |
| "It worked before" | Doesn't find what changed | Check git diff |
| "Quick fix" | Often creates new bugs | Find root cause |
| "Must be X" | Confirmation bias | Test hypothesis |
| "Works on my machine" | Environment difference is a clue | Investigate difference |

** When to Escalate

If after thorough investigation:
- Root cause cannot be identified
- Fix requires changes outside current scope
- Issue appears to be in external dependency

Report findings and escalate to user with:
1. Everything tried in Phase 1-3
2. Best current hypothesis
3. Recommended next steps
