Guidelines for working with literate programming documents (org-mode files with
embedded code blocks).

** Core Philosophy

Literate programming prioritizes human comprehension over mechanical concerns.
The narrative explains intent; code blocks illustrate implementation.

** Structure Guidelines

*** Prose Before Code

Prefer explaining intent before showing implementation. A brief sentence or two
helps readers understand what follows.

#+begin_example
This function validates user input by checking for required fields
and sanitizing strings to prevent injection attacks.

,#+begin_src python
def validate_input(data):
    ...
,#+end_src
#+end_example

*** Narrative Order

Structure documents for understanding, not execution order. Let tooling
(tangling) handle reordering when needed.

*** Section Depth

Suggested hierarchy (adapt as needed):
- Level 1 (=*=): Top-level components or modules
- Level 2 (=**=): Major features or logical groupings
- Level 3 (=***=): Specific implementations
- Level 4+ (=****=): Use sparingly for helpers

** Block Guidelines

*** Naming Blocks

Use =#+NAME:= when a block will be referenced elsewhere (noweb, results).
Otherwise, naming is optional.

#+begin_example
,#+NAME: db-connection-pool
,#+begin_src python
# This block is referenced via <<db-connection-pool>> elsewhere
,#+end_src
#+end_example

When naming, prefer descriptive kebab-case: =api-validate-request=,
=cache-invalidation-logic=.

*** Block Size

Prefer one meaningful step per block, like paragraphs in prose. This aids
readability, though pragmatism trumps dogma—larger blocks are fine when cohesive.

** Modification Guidelines

When editing literate documents:

- Preserve existing =#+NAME:= references (they may have cross-references)
- Consider updating surrounding prose when changing code logic significantly
- Maintain reasonable top-to-bottom flow where practical

** Emacs/literate-elisp Specifics

For =.org= files using literate-elisp:

- =#+PROPERTY: literate-lang elisp= declares the default language
- =#+PROPERTY: literate-load yes= enables auto-loading
- After editing, reload with: =(literate-elisp-load "file.org")=

*** Load Control

#+begin_example
,#+begin_src elisp :load no
;; This block won't be loaded (example code, scratch work, etc.)
,#+end_src
#+end_example

** Common Patterns

*** Setup at Top

Place imports, requires, and configuration near the document start.

*** Dependencies

Record dependencies explicitly in prose or properties when non-obvious.

*** Testing

Test code can live in the same document or separate test files—choose based on
project conventions.
