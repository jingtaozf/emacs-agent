#+TITLE: Skill and Rule Extraction

Analyze the work just completed. Extract reusable knowledge that enables continuous improvement.

* Core Principle

Not every session produces extractable knowledge—be selective. Only extract what's truly
reusable, non-trivial, and verified to work.

* What to Extract

** Skills (How-to knowledge)
- *Non-obvious solutions*: Debugging techniques, workarounds requiring investigation
- *Tool integration*: How to use tools/APIs in ways documentation doesn't cover
- *Error resolution*: Specific errors and their actual root causes (especially misleading ones)

** Rules (Constraints to follow)
- *Workflow optimizations*: Did the user have to ask multiple times? Should this be default?
- *Default behavior gaps*: Actions that should be more aggressive/thorough by default
- *Back-and-forth patterns*: Interactions that could be avoided with better defaults

* Extraction Criteria

Ask yourself:
1. Did I discover something that wasn't obvious before starting?
2. Would future-me benefit from having this documented?
3. Did the user have to correct my approach or ask for more thorough work?
4. Was there back-and-forth that could have been avoided?
5. Is this reusable beyond this specific case?

If NO to all, respond exactly:
"No new skills or rules extracted."

* Quality Gates

Before extracting, verify:
- [ ] *Reusable*: Will this help with future tasks?
- [ ] *Non-trivial*: Requires discovery, not just documentation lookup
- [ ] *Specific*: Trigger conditions and solutions clearly described
- [ ] *Verified*: Actually worked in this session

* Skill Format

For each skill:
- *Name*: =descriptive-kebab-case=
- *Trigger*: Specific conditions (error messages, symptoms, scenarios)
- *Solution*: Step-by-step instructions
- *Verification*: How to confirm it worked
- *Save to*: =.claude/skills/emacs-agent/[name]/SKILL.md=

* Rule Format

For each rule:
- *Name*: =descriptive-kebab-case.md=
- *Rule*: Clear, actionable constraint (one sentence if possible)
- *Rationale*: Why this matters (include the situation that revealed this need)
- *Save to*: =.claude/rules/emacs-agent/[name].md=

* Examples

** Workflow Optimization Rules
- "Always run full test suite after code changes, not just unit tests"
- "When user reports an error, add debug logging to capture actual error format"
- "After editing elisp files, reload them so changes take effect"

** Root Cause Skills
- "Session UUID from org property may be stale - prefer session state"
- "'Unknown error' usually means error parsing missed a field - check parsed structure"
- "Hardcoded values should be dynamic based on context"

** Error Resolution Skills
- Specific error message → actual root cause → fix
- When error message is misleading, document what it really means

* Anti-Patterns to Avoid

- *Over-extraction*: Not every task deserves a skill
- *Vague triggers*: "Helps with React problems" won't surface when needed
- *Unverified*: Only extract what actually worked
- *Documentation duplication*: Link to docs, add what's missing

* Output Summary

List what was extracted:
- Skills: [list with trigger conditions, or "none"]
- Rules: [list with rationale, or "none"]
