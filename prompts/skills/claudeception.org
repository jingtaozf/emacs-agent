#+TITLE: Skill and Rule Extraction

Analyze the work just completed. Look for knowledge that would improve future interactions.

* What to Extract

Extract knowledge that is:
- *Non-obvious*: Not easily found in documentation
- *Reusable*: Applies beyond this specific case
- *Verified*: Actually worked in this session

Pay special attention to:
1. *Workflow inefficiencies*: Did the user have to ask multiple times for something that should have been done proactively or more thoroughly?
2. *Root cause patterns*: Did debugging reveal a non-obvious cause that would help in similar situations?
3. *Default behavior gaps*: Should certain actions be more aggressive/thorough by default?
4. *Error recovery patterns*: How was a tricky error diagnosed and fixed?

* Extraction Criteria

Ask yourself:
1. Did I discover something that wasn't obvious before starting?
2. Did I learn a constraint or pattern that should always be followed?
3. Would this help someone facing a similar problem?
4. Did the user have to correct my approach or ask for more thorough work?
5. Was there back-and-forth that could have been avoided with better defaults?

If the answer is NO to all, respond exactly:
"No new skills or rules extracted."

* Skills (How-to solve problems)

* Rules (Constraints/patterns to follow)

For each rule:
- *Name*: =descriptive-kebab-case.md=

- *Rationale*: Why this matters (include the situation that revealed this need)
- *Save to*: =~/.claude/rules/emacs-agent/[name].md=

* Examples of Extractable Knowledge

** Workflow Efficiency Rules
- "Always run full test suite after code changes, not just unit tests"
- "When fixing a bug, verify the fix with a concrete test case before declaring done"
- "When user reports an error, add debug logging to capture the actual error format"

** Root Cause Patterns
- "Session UUID from org property may be stale - prefer session state"
- "Hardcoded values (like '***') should be dynamic based on context"
- "'Unknown error' usually means error parsing missed a field - check parsed structure"

** Default Behavior Rules
- "When implementing features, consider edge cases proactively"
- "Extraction/hooks should handle errors gracefully, not crash"
